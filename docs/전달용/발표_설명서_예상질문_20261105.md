# 설계심사 대비 — 발표·소프트웨어 설명서와 예상 질문 (11-05)

기준: **A 최종본**(`보고서_분담/KABOAT2026_설계보고서_SSF_A_최종본.docx`), **B 15차**(`…_SSF_B_15차수정본.docx`), 발표자료 A·B(12장). 이 문서의 숫자는 전부 두 보고서에 있는 값이다. 보고서에 없는 값은 만들어 말하지 않는다.

설계심사: 11-13(금), **대표자 5분 발표 + 10분 내외 질의**, 연구소·산업체 실무 심사위원 5명 이상. 보트 검사와 같은 시간대라 발표자와 검사 담당을 나눈다.

---

## 0. 답할 때 원칙 4가지

1. **숫자는 보고서 값만.** 기억이 안 나면 "보고서 표 Ⅲ-○에 있다"고 하고 페이지를 펼친다. 어림값을 지어 말하지 않는다.
2. **안 잰 것은 안 쟀다고 한다.** "수조(6×6 m)에서는 정속 구간이 없어 직진 속도는 실측하지 않았고, 대회 전 실해역에서 잰다"처럼 *무엇을 언제 잴지*까지 붙인다. 실해역 시험은 아직 안 했다.
3. **시뮬은 '경향'이라고 말한다.** 시뮬 수치는 실제 노드 코드를 돌렸지만 부표 배치·센서·운동은 모델이다. "물 위 실측 아님"을 먼저 말하면 공격받지 않는다.
4. **모르는 질문은 짧게 인정하고 근거 위치를 말한다.** "그 부분은 ○○가 담당해 답하겠다" 또는 "보고서 Ⅲ-5에 동작이 정리돼 있다".

## 1. 5분 발표 — 6장만 짚는다

12장을 5분에 다 말할 수 없다. 제출은 12장 그대로 두고, 아래 6장만 말하고 나머지는 질의 때 연다. 장마다 40~60초.

| 장 | 말할 내용 (한두 문장) |
|---|---|
| 1 표지 | 팀·배 이름만. 10초. |
| 3 제원·복원성 | A: 단동선 1.66×0.55 m, 34 kg, T200 2기. 경사시험 GM 0.17 m로 계산(0.145)보다 크게 나와 KG가 가정보다 낮다(0.13). B: 1.77×0.522 m, 30 kg, T200 4기 V자. 경사시험 GM 0.18 m, KG 0.27로 가정(0.15)보다 높지만 GM은 양수이고 롤 감쇠로 복원 확인. |
| 6 시스템 구성 | 노트북 1대가 ROS2 전체를 돈다. 센서 역할 분리: **카메라는 방향만, 거리는 LiDAR, GPS는 구역 사이 이동 방향만.** 게이트·부표·도크 위치는 카메라·LiDAR로 직접 인지한다. 모드 전환은 조종기 스위치만. |
| 8 비전·회피·제어 | 비전은 규칙 기반(HSV 색 + 윤곽 형상), 실측 화각 63.9°로 픽셀을 방위각으로. 회피는 LiDAR 갭 선택: 장애물을 배 반폭+여유만큼 부풀리고 0.83 m 이상 틈 중 목표 방위에 가장 가까운 각. 제어기는 PID가 아니라 각도 오차 → 좌우 PWM 차동. |

마무리 한 줄 예: "센서가 틀린 값을 낼 바에는 멈추게 설계했고, 시뮬로 정한 값은 대회 전 실해역에서 확인할 항목으로 정리해 두었습니다."

## 2. 소프트웨어 한 장 요약 — 이것만 이해하면 대부분 답이 된다

### 2.1 명령이 흐르는 길 (위 → 아래)

```
센서: LiDAR(/scan) · IMU(/imu/yaw_raw) · GPS(/ublox_gps_node/fix) · OAK 카메라
   │
   ├─ ssf_heading(yaw_mux) ── 보정한 헤딩 /imu/yaw (단독 발행)
   ├─ north_goal_angle ─────── 다음 WP 방위, 지금 임무 번호 /wp_mode, 경계 광선
   │      └ ship_goal_angle ── 목표 방위 − 헤딩 = /yaw_error
   ├─ 검출기 gate·turn·dock ─ 색·형상 → 방위각만 (/red_angle, /green_angle, /image_angle)
   │
   ▼ /wp_mode 가 정한 임무 노드 (ship_gate / ship_back / ship_dock)
   │      └ /candidate_angle  (일반 각도 또는 특수 코드)
   ▼ ship_direction ── LiDAR 갭 선택 회피 + 페일세이프 → /desired_angle
   ▼ motor_control ─── 각도 → 좌·우 PWM, 장애물 거리로 감속, 0.5 s 워치독
   ▼ ssf_bridge ────── USB 시리얼 → Arduino Mega → ESC → T200
```

- **/wp_mode를 바꾸는 노드는 north_goal_angle 하나.** WP 도착(반경 안에 dwell 초) 또는 시간 초과로 다음 WP로 넘어갈 때 바뀐다.
- **검출기는 담당 모드에서만 발행**한다. gate는 0·1, turn은 2·3, dock은 7.
- **각도 규약:** 0~360°, 0° = 진북, 시계방향. LiDAR 격자에서는 정면이 80, 왼쪽이 +.

### 2.2 특수 코드 (/candidate_angle · /desired_angle)

| 코드 | 뜻 | 누가 내나 |
|---|---|---|
| 5000 / 6000 | 제자리 우선회 / 좌선회 | ship_dock(탐색·정렬) |
| 20000 | 미션 없음 → GPS 목표 방위 + LiDAR 갭 회피로 스스로 진행 | 모드 5·8은 north_goal_angle, 게이트가 안 보이면 ship_gate, 부표 못 찾음·끝남은 ship_back, 후보각 1.0 s 끊기면 ship_direction 자신 |
| 50000 | 정지(STOP_HOLD) | 임무 노드·페일세이프 |
| 180 | 후진 요청 → ship_direction이 260으로 바꿔 냄 | ship_dock 후진 이탈 |

20000이 핵심이다. **임무 노드가 할 일이 없으면 GPS로 다음 WP를 향해 가면서 LiDAR로 피한다.** 임무 노드가 죽거나 멈춰도(1.0 s 무수신) 같은 동작으로 대체된다.

### 2.3 설계 원칙 "모르면 입을 다문다"

틀린 값을 내느니 발행을 멈추고, 그 침묵을 아래 노드가 잡아 감속·정지한다.
- GPS fix 없음·묵음(2.5 s) → 방위·거리·도착 판정 정지. /wp_mode와 시간 초과 진행은 유지.
- IMU 0.5 s 끊김 → /imu/yaw·/yaw_error가 멈춤 → ship_direction이 잡음.
- 카메라 표식 유실 2.0 s → 무효값 10000.
- 진단(/health_ok)은 **기록만** 하고 제어에 연결하지 않는다. 진단 오판으로 배가 서는 것을 막으려고.

### 2.4 노드별 핵심 (질문 대비용)

**헤딩 (ssf_heading/yaw_mux, Ⅲ-2.1)**
- 드라이버는 원시값 /imu/yaw_raw만 내고, yaw_mux가 보정해 /imu/yaw를 **혼자** 발행. 발행자가 둘이면 보정 전후 값이 번갈아 나와도 ROS는 오류를 안 내기 때문.
- 보정식 ψ = wrap360(s·ψ_raw + mount_offset + δ). 배마다 다른 값은 invert_yaw·mount_offset_deg 두 개뿐(ssf_heading_A/B.yaml). **값은 수조 정북 시험 후 기입 — 아직 비어 있음.**
- 대안 소스 cog_offset: GPS 진행 방향(COG)과 IMU 차이를 단위벡터로 평균. 산술평균은 359°와 1°를 180°로 만들어서 안 씀. 후진 표본은 /motor_reverse로 막음(후진만 이어지면 180° 틀린 채 수렴).

**GPS (north_goal_angle, Ⅲ-2.2)**
- RTK는 인터넷 NTRIP. 계정은 저장소 밖 ~/.ssf/. 파일 없으면 그 노드만 생략.
- fix 5단 필터: fix 검증(status<0, NaN, (0,0) 버림) → 공분산 2.0 → 점프(15 m/s 넘으면 멀티패스) → 적응형 스무딩 → 신선도 2.5 s.
- 경로 추종: 이전 WP P에서 목표 W로 가는 **경로선** 기준 LOS + 적분(ILOS). 조류에 밀려도 선으로 돌아온다. 전방주시 L = clamp(1.2·v, 2.0, 6.0) m, k_i 0.02, |I| ≤ 50.
- 도착 반경: 도킹 2.0 m, 위치유지·탐색 3.5 m, 그 외 속도별 2.5/3.5/4.5 m.
- 지나침: 경로선 방향으로 구간 길이를 넘었는데 반경 밖이면 WP 직접 방위로 되돌아옴.
- WP 녹화: 허가된 시험 주행 때 RTK FIXED에서 최근 2 s fix 평균으로 찍는다. 새 파일에 쓰고 검증 후 복사.
- 지오펜스: 경계 폴리곤까지 광선 161개를 가짜 LiDAR로 만들어 회피에 병합. **대회장 경계 좌표가 없어 지금은 꺼져 있다.**

**LiDAR (ship_direction, Ⅲ-2.3·4.4)**
- 수신 콜백은 저장만, 계산은 10 Hz 타이머. LiDAR가 끊겨도 발행(과 페일세이프)은 계속.
- 정면 ±80°만 사용. 탐지거리 3.0 m, 게이트 구간 2.0 m(좁아서 3.0이면 접촉 증가).
- 갭 선택: 이진 마스크 → 작은 잡음 제거 → 장애물을 atan((반폭+여유)/r) 각만큼 팽창 → 호 길이 ≥ 0.83 m 틈만 후보 → 목표 방위를 틈 안에 clamp해 가장 가까운 각. 후보가 둘 이상이면 벌점 두 가지를 더한 뒤 고른다(11-06): 직전 틱과 반대편 틈 +40°(편 유지), 정면과 틈 사이에 장애물이 끼는 틈 +90°(앞 가로지름 금지). 3자유도 시뮬 회피 접촉 A 46→20, B 47→24(20런).
- 틈이 없으면 0.5 s 후진 → 3.0 s 정지 후 재탐색. 뒤를 못 보니 계속 후진하지 않음.
- 조향 변화 한 틱 15° 제한(특수 코드는 즉시).
- 감속 신호에만 공간 중앙값 필터: 물보라 가짜 감속 36.8% → 8.9%(시뮬).

**비전 (검출기 3종, Ⅲ-2.4)**
- HSV 색 마스크 → 윤곽 → 면적·형상·화면 높이 띠 → 가장 큰 것 1개 → 확인 프레임 → 픽셀을 방위각으로 θ = −atan((x − cx)/fx).
- 화각 63.9° 실측(빨간 원 1 m 간격, 2.4 m). 공장 보정값 63.87°와 0.05° 이내. 640×360만 주면 가운데만 잘려 40.3°가 되는 함정을 찾아 ISP 1/3로 해결.
- 방위각 검증 오차 1° 이내(벽 2.0 m).
- 도킹 형상: 꼭짓점 3 = 삼각, 4~6 + extent·종횡비 = 사각, 7+ 또는 원형도 ≥ 0.82 = 원. 연속 3프레임 일치해야 확정.
- 목표 색·형상은 yaml 한 줄. 탐색 색은 `turn_color_mode3`(기본 빨강), 틀린 색이면 부팅 ERROR + 검출 안 함.

**임무 노드 (Ⅲ-4)**
- ship_gate: 빨강·초록 둘 다 보이면 중간, 하나면 그쪽 기준 오프셋, 없으면 20000(세 갈래).
- ship_back(위치유지·탐색): 카메라 색으로 부표 방위, LiDAR로 거리. 2.5 m ±0.4 m 유지(bang-bang), 규정 "5 m 이내 5 s" 충족하면 완료. 놓치면 5 s 정지 후 재탐색, LiDAR 거리 10 s 모름 또는 합계 60 s 넘으면 포기하고 다음 WP.
- ship_dock: INIT 3 s → SEARCH(제자리 우선회, 25 s) → ALIGN(표식 ±8°) → APPROACH(LiDAR 정면 ±15° 최소거리 1.0 m까지 직진) → CONTACT 3 s → BACKOFF(2.5 m까지 후진) → DONE(정지 유지).

**제어기 (motor_control, Ⅲ-4.6)**
- 20 Hz. offset = θ − 80 → 좌 base + s / 우 base − s. base 1360(ROS 기준 <1500 = 전진).
- 감속비 = min(근접비, 페일세이프 상한). 근접비는 1.2 m 이상 1.0, 그 안에서 0.7 + 0.3·d/1.2.
- 0.5 s 명령 무수신이면 중립. 펌웨어도 0.5 s 워치독.

**페일세이프 (Ⅲ-5)**
- 레벨 0 정상 / 1 경고(0.7 s 넘게 무신호, 연속 3회, 각도 유지·속도 0.7배) / 2 정지(3.0 s 또는 이상 스캔 즉시).
- 레벨 1에서 직진을 강제하지 않는 이유: 회피 중 직진하면 피하던 부표에 부딪힌다.
- 감시는 /scan과 /yaw_error 둘 다. /scan만 보면 IMU가 죽어도 마지막 각도로 계속 조향(시뮬에서 접촉 3회).
- 거짓 정지 방지 4가지: 단조 시계, 첫 수신 뒤 감시 시작, 3회 연속 조건, 복귀 즉시 해제.

## 3. 예상 질문과 답

### 3.1 선형·복원성

| 질문 | 답 |
|---|---|
| 작년 쌍동선에서 왜 단동선으로 바꿨나 | 쌍동선은 횡복원성이 유리하지만 연결 구조물·보강·수밀 관리가 늘어난다. 단동선은 구조가 단순해 제작·유지보수가 쉽고 내부 공간을 한 덩어리로 쓴다. 길이를 1.05 m에서 A 1.66 m·B 1.77 m로 늘려 파랑 대응과 직진성을 노렸다. |
| GM은 어떻게 확인했나 | 정수력 계산(KB+BM−KG 가정)과 수조 경사시험 둘 다 했다. 추 2.1 kg을 좌우로 옮겨 기울기를 재 GM = w·d/(W·tanθ). A 0.17 m, B 0.18 m. |
| 계산 GM과 시험 GM이 왜 다른가 | 계산은 KG를 0.15 m로 **가정**했기 때문이다. 시험 GM과 계산 KM으로 KG를 역산하면 A 0.13 m(가정보다 낮음), B 0.27 m(가정보다 높음). 시험값을 설계 근거로 쓴다. |
| B는 KG가 0.27이면 너무 높지 않나 | 가정보다 높지만 GM 0.18 m로 양수이고, 롤 감쇠 시험에서 10~15° 놓은 뒤 평균 11 s 안에 1° 이내로 돌아왔다. 종경사 GM_L도 2.5~2.8 m. |
| 흘수선 표시(100~110% 부력)는 어떻게 했나 | STL로 110% 배수량 수선을 계산했지만(A 115.3 mm, B 65.2 mm) STL과 실제 선체가 다르다. 그래서 **부상 시험 실측 평균 흘수**(A 81.7 mm, B 73.3 mm) 기준으로 표시하고 STL은 참고값으로 둔다. |
| STL 수선과 실측 흘수가 왜 다른가 | A는 STL이 1 m 축소 모델을 1.66배 확대한 형상이라 실제 선체와 차이가 난다(약 28 mm). 그래서 Cb도 STL 기준 0.37, 실측 흘수 기준 0.50 두 값을 적었다. B는 0.61 / 0.51. |
| A는 선수 흘수(105)가 선미(45)보다 깊다. 트림이 큰데 | 실측값이 맞다(재확인함). 원인 설명은 **팀 확인 필요** — 장비 배치에서 나온 선수 트림인지 답을 준비해 둘 것. 지어서 답하지 않는다. |
| 롤 주기 1 s는 믿을 만한가 | 폰 기울기계 샘플링이 0.5 s라 주기는 그 차수까지만 읽힌다. 보고서에도 그 한계를 적었다. 감쇠 시간(1° 이내까지)은 수 초 단위라 읽힌다. |
| 침몰방지 부력재는 | 전장품을 방수박스(개스킷·물끊기)에 넣고 관통부를 실란트로 마감했고 수조 수밀 시험을 했다. 규정은 배수량이 부족하면 부력재 추가인데, 전비 상태 건현이 A 최소 105 mm, B 최소 110 mm 남는다. |
| 방수박스가 왜 늘어났나 | 제작 후 탑재 공간이 부족해 갑판을 절개하고 3D 프린팅 연장부를 붙였다. A 480×300×200, B 535×300×200 mm. |
| A는 FRP, B는 카본섬유인 이유 | A는 촙 매트·얀 크로스 6층 FRP. B는 경량화·강성을 위해 카본섬유로 적층했다. 공용 재료(퍼티·수지 등)는 두 배가 반씩 나눴다. |

### 3.4 GPS·웨이포인트

| 질문 | 답 |
|---|---|
| 구성물 좌표를 모르는데 GPS로 어떻게 미션을 하나 | GPS 웨이포인트는 공지된 경기장 형상을 보고 **구역 사이 이동 방향**만 준다. 게이트·부표·도크의 위치는 카메라와 LiDAR로 직접 인지한다(경기규정 5.2). |
| 웨이포인트는 언제 찍나 | 허가된 시험 주행 때 현장에서 RTK FIXED가 잡힌 뒤 찍는다. 한 점은 최근 2 s 유효 fix 평균. |
| 왜 RTK가 필요한가 | 단독 측위 오차 ±3~5 m가 부표 간격보다 크다. |
| RTK가 끊기면 | fix가 2.5 s 넘게 없으면 방위·도착 판정을 멈춘다(배는 페일세이프로 감속·정지 쪽). /wp_mode와 **시간 초과 진행은 계속**하므로 GPS가 죽어도 임무는 넘어간다. |
| NTRIP 기준국은 | 측정 장소 30 km 이내 마운트포인트를 고른다. 예전에 199 km 떨어진 기준국을 골라 RTK가 안 잡힌 경험이 있다. |
| LOS만 쓰면 되지 왜 ILOS인가 | 조류·바람처럼 계속 미는 외란이 있으면 LOS는 경로선 옆에 정상 오차가 남는다. 적분항이 그것을 상쇄한다. 적분은 ±50으로 묶고 WP를 넘길 때 0으로 초기화. |
| 위치유지·탐색 도착 반경이 왜 3.5 m인가 | 부표 WP 근처에 오면 임무 노드(ship_back)가 카메라·LiDAR로 부표를 잡는다. 그동안은 dwell을 세지 않고, 끝나면 0.5 s 뒤 다음 WP로 간다. 그래서 **카메라가 부표를 3.5 m보다 멀리서 처음 잡아야** 한다 — 실해역 확인 목록에 있다. |
| 지오펜스는 | 경계 폴리곤까지 광선 거리를 가짜 LiDAR로 만들어 회피에 병합한다. 대회장 경계 좌표가 아직 없어 꺼져 있다. 헤딩이 얼거나 이미 밖이면 빈 배열(가두지 않게). |

### 3.6 장애물 회피

| 질문 | 답 |
|---|---|
| 갭 선택을 한 줄로 | 장애물을 배 반폭+여유만큼 부풀리고, 배가 지날 수 있는 틈(호 길이 ≥ 0.83 m) 중 목표 방위에 가장 가까운 각으로 간다. |
| 피하다가 왜 편을 안 바꾸나 | 매 틱 '목표에 가장 가까운 틈'만 고르면 배가 돌면서 목표가 정면으로 옮겨 와 반대편 틈이 0.2° 더 가까워지는 순간 편을 바꿔 장애물 앞을 가로지른다(관성 있는 3자유도 시뮬에서 드러남). 그래서 직전 편의 반대쪽 후보에 40°, 장애물 앞을 지나는 후보에 90° 벌점. 값은 시뮬 기준이고 yaml 로 0.0 이면 끔. |
| 0.83 m는 어디서 | 반폭 0.29×2 + clearance 0.25. clearance는 20 시드 스윕에서 정체 0 %인 값 중 접촉이 가장 적은 0.25. |
| 장애물 간격이 1.0 m인데 0.83 m면 빡빡하지 않나 | 맞다. 선회 중 유효 폭 W·cosθ + L·sinθ로 보면 A는 약 9°, B는 약 10° 이내로 정렬해야 통과한다. 이 한계를 보고서 Ⅲ-6.1에 적었고, 실제 통과 각도는 실해역에서 확인한다. |
| 틈이 없으면 | 0.5 s 후진 후 3.0 s 정지하고 다시 찾는다. 뒤를 못 보므로 계속 후진하지 않는다. |
| 물보라·반사 잡음은 | 짧은 장애물 구간(고립 1~3셀)은 지우고, 감속 신호에는 공간 중앙값 필터를 건다. 회피 마스크에는 필터를 걸지 않아 실제 부표를 놓치지 않게 했다. |
| 시뮬에서 접촉이 0이 아닌데 | 스윕 접촉 평균 1.32회/런은 접촉 판정을 반경 half_width 원으로 한 재구현 결과이고 동역학은 가정값이다. 실제 노드 코드 재현에서는 0.82회. 수치는 경향으로 본다. |

## 5. 주의 — 말하면 안 되는 것, 보고서와 코드가 다른 곳

- **도킹 웨이포인트:** "도킹 구역 안에는 웨이포인트를 찍으면 안 된다"는 이야기가 있어 규정 확인 전까지 **보고서·발표는 예전 도킹 설명**으로 되돌렸다. 질문을 받으면 보고서대로 답한다(표식을 카메라로 찾아 제자리 선회 후 직진). 칸 정면 접근점·칸 입구·이탈점 이야기는 꺼내지 않는다.
- **현재 코드는 보고서와 다르다:** 코드에는 아직 도킹 웨이포인트 4줄, ship_dock TRANSIT 상태, 표식 탐색 60 s, DONE 원인별 동작이 남아 있다(규정 확인 뒤 정리, 보류). 심사위원이 코드를 직접 보자고 하면 "규정 확인 중이라 보류한 변경"이라고 사실대로 말한다.
- **보고서에 없는 남은 문제(내부 공유용):** 부표 좌표에 둔 WP 사이를 지날 때 회피(감지 3 m)가 부표를 다 못 피해 시뮬에서 미션 부표 접촉이 남는다. 토너먼트 구간에서 드물게 장애물 사이에서 전진·후진을 반복한다. 먼저 꺼내지는 않되, 물으면 사실대로.
- **실측 아닌 것을 실측처럼 말하지 않는다:** 직진 속도, 선회 성능, 도킹 거리, 실해역 동작은 전부 아직이다. 시뮬 수치(200/200, 314 s, 66 %)는 "시뮬"을 붙여 말한다.
- **A 선수 트림 원인**은 팀이 확인한 답을 정해 둔다(3.1 표).

## 6. 용어 짧은 풀이

| 용어 | 뜻 |
|---|---|
| GM / KB / BM / KG | 메타센터 높이 / 부심 높이 / 메타센터 반경 / 무게중심 높이. GM = KB + BM − KG, 양수면 작은 기울기에 복원력. |
| Cb | 방형계수, 배수용적 ÷ (수선 길이 × 폭 × 흘수). |
| Fn | 프루드 수 V/√(gL). 0.35~0.4부터 조파 저항 급증. |
| RTK FIXED | 기준국 보정으로 cm급 위치가 확정된 상태. |
| NTRIP | 인터넷으로 RTK 보정 신호를 받는 방식. |
| XTE | 경로선에서 옆으로 벗어난 거리. |
| LOS / ILOS | 전방주시 유도 / 적분항을 더한 전방주시 유도. |
| dwell | WP 반경 안에 머물러야 다음으로 넘어가는 시간. |
| STOP_HOLD | 정지 명령(50000). |
| bang-bang | 범위를 벗어나면 일정 출력으로 되돌리는 켜고 끄는 제어. |
| HSV | 색상·채도·명도 색 공간. 조명 변화에 RGB보다 색 분리가 쉽다. |
| extent / 원형도 | 윤곽 면적 ÷ 외접 사각형 면적 / 4π·면적 ÷ 둘레². 형상 판정에 씀. |
| DDS 도메인 | ROS2 통신 그룹. 두 배를 다른 도메인에 둬 토픽이 섞이지 않게. |
