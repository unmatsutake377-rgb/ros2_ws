# 회신: 후진 쿨다운 / 180° rate limiter 제안 검토

> 받은 것: `후진쿨다운_수정제안서.md`, `180도매핑_임시완화_제안서.md`
> 기준: 저장소 최신 `src/ship_direction/ship_direction/ship_direction.py`, `blackbox.py`
> 한 줄 결론: **제안1(후진 쿨다운)은 실재 버그가 맞습니다 — 다만 제시한 A안은 출력이 안 바뀌는 no-op이라,
> 안전 관점의 C안으로 가야 합니다. 제안2(rate limiter)는 원안이 특수신호를 뭉개 위험했는데, "0~160°
> 구간에서만 적용" 하면 안전해지고 180° 증상 완화까지 됩니다. 로깅은 이미 blackbox가 합니다.**

두 제안 다 우리 최신 코드를 정확히 짚었습니다(발췌 라인도 실제와 일치).

## 1. 후진 쿨다운 dead code — ✅ 실재 버그, 단 A안은 no-op

### 지적은 맞습니다

`ship_direction.py` 656~659:
```python
if not candidates:
    final_angle = REVERSE_ANGLE          # 무조건 후진
    if now - self.last_reverse_time >= self.reverse_cooldown:
        self.last_reverse_time = now     # 타임스탬프만 갱신, final_angle 안 건드림
```
`reverse_cooldown` 파라미터를 선언(201줄)했지만 `final_angle`에 아무 영향이 없습니다. **dead code 맞습니다.**

### 그런데 제시한 A안은 출력이 안 바뀝니다 (no-op)

```python
if 쿨다운중: final_angle = REVERSE_ANGLE
else:        final_angle = REVERSE_ANGLE   # ← 두 분기 출력이 같음
```
두 분기 모두 `REVERSE_ANGLE`(260)이라 **현재 동작과 완전히 동일**합니다. 고친 게 아닙니다.

### 진짜 문제 — 연속 후진이 위험 (C안으로 가야 함)

코드 주석(125·497줄)에 명시돼 있습니다: **"north 광선은 전방 ±80°만 → 후진 중 뒤쪽 경계는 못 본다."**
즉 지금은 **뒤를 못 보며 계속 후진**합니다. 쿨다운의 원래 의도는 십중팔구 "잠깐 후진하고 멈춰서 다시
살펴본다"(제안서의 **C안**)입니다.

→ **권장: C안** — 후진 1회 후 쿨다운 동안 STOP(재탐색), 그 뒤 회피 경로 재평가.
   (A안은 무의미, B안은 이전값 유지라 후진 지속과 비슷.)
   구현 시 STOP은 이미 `STOP_HOLD`(50000) 신호가 있으니 그걸 쓰면 됩니다.

**우선순위:** 하드웨어 무관이라 실측 전 고칠 수 있음. 다만 "후진이 실제로 얼마나 자주·오래 걸리나"를
blackbox(`desired_angle`=260 빈도)로 같이 보면 튜닝이 정확해집니다.

## 2. 180° rate limiter — ⚠️ 원안 위험 → "0~160° 한정"으로 해결됨

### 원안의 문제 (raw `final_angle`에 그대로 적용 시)

`/desired_angle`은 **각도 + 특수신호가 섞인 프로토콜**입니다:
`260(후진)·5000·6000(SPIN)·20000(INVALID)·50000(STOP)`.

블라인드 15°/tick 제한이 정상조향(예 90) → STOP(50000) 전환을 15씩 기어가면:
```
90 → 105 → … → 260(후진!) → … → 5000(선회!) → … → 20000 → … → 50000
```
도중 값을 motor_control이 **후진·선회·무효로 순차 오해** → 배가 제멋대로 움직입니다(침묵 실패).

### 해결 — 팀 논의: "라이다 조향은 0~160°만" → 그 구간에서만 rate limit

특수신호는 전부 **161 초과**라 정상 조향(0~160°)과 자연히 구분됩니다. rate limiter를 **양쪽(prev·target)이
모두 0~160°일 때만** 적용하고, **특수신호는 통과**시키면 위 문제가 사라집니다.

**보너스:** 180° 급반전(정후방 목표 → 좌 10° vs 우 150°)은 **둘 다 0~160° 안**이라, 이 rate limiter가
그 급반전도 부드럽게 만듭니다. 즉 carve-out 버전은 **안전 + 180° 증상 완화**를 동시에 얻습니다.

### 마감 처리 3가지 (넣을 때 반드시)

1. **특수신호 통과 + limiter 상태 리셋** — 조향 90 → STOP → 조향 30 복귀 시, 30을 STOP 이전의 90에서
   기어오게 하면 안 됩니다. 특수신호를 만나면 `prev_final_angle`을 버려서 복귀 시 즉시 스냅.
2. **양쪽 다 정상구간일 때만 제한** — prev·target 중 하나라도 특수신호면 통과.
3. **`MAX_ANGLE_CHANGE_PER_TICK` 튜닝** — 발행주기를 곱해 실제 각속도 확인(20Hz면 15°=300°/s,
   10Hz면 150°/s). 실측으로 조정.

### 근본 180° 매핑은 여전히 보류 (전 결론 유지)

`회신_ship_direction_수정제안.md`에서 시뮬로 확인했듯, 180° 급반전은 **매핑 불연속이 원인이 아니라
정후방 목표의 물리적 대칭**이라, 매핑을 고쳐도 안 사라집니다. rate limiter는 그 **증상을 안전하게
완화**하는 것이지 원인 제거가 아닙니다(제안서도 이 점은 명확히 함 — 동의).

### 로깅(항목2)은 이미 되고 있음

`blackbox`가 `desired_angle`·`yaw_error`·`candidate_angle`을 이미 CSV로 로깅합니다(blackbox.py 87줄).
`ros2 bag`은 무해한 추가지만 **중복**이라 별도로 필요치 않습니다.

## 요약

| 제안 | 판정 | 조치 |
|---|---|---|
| 1. 후진 쿨다운 | ✅ 실재 버그 (A안은 no-op) | 의도 확정 후 **C안**(후진→STOP 재탐색, STOP_HOLD 사용). 안전상 가치 있음 |
| 2. rate limiter (원안) | ⚠️ 특수신호 뭉개 위험 | 그대로 넣지 말 것 |
| 2. rate limiter (0~160° 한정) | ✅ 안전해짐 + 180° 완화 | 마감 3가지(특수신호 통과·상태 리셋·튜닝) 지켜 추가 가능 |
| 2. 로깅 | 이미 blackbox가 함 | 중복, 불필요 |
| 근본 180° 매핑 | 물리적 대칭 (전 결론) | 보류 유지 |

**두 제안 다 좋은 발견입니다** — 특히 후진 dead code는 실전에서 눈감고 후진할 뻔한 걸 잡았고, rate
limiter는 "0~160° 한정"이라는 팀 통찰로 위험을 제거하면 첫 실기 테스트의 범용 안전장치로 쓸 만합니다.
