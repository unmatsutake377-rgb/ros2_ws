큰 그림 — 배 한 대 안에서 데이터가 도는 길

센서 값을 정리하는 노드들이 각도를 하나씩 만들고, 그 각도들이 ship_direction 한 곳에 모여 최종 조향각 1개가 되고, motor_control 이 그걸 좌/우 모터 세기로 바꾼다.

점선 /wp_mode = "지금 몇 번 임무인지". 이 숫자가 검출기와 임무 노드 중 누가 일할지 정한다(Ⅲ-3).
모든 게 각도로 흐른다속도나 위치를 제어하지 않는다. "어느 방향으로 갈래"를 계속 넘긴다.
큰 숫자 = 명령어각도 자리에 5000(우선회), 20000(미션 없음), 50000(정지), 10000(카메라 못 봄)이 오면 신호다.
모르면 입을 다문다센서가 이상하면 0 같은 가짜 값을 내지 않고 발행을 멈춘다. 그 침묵을 아래에서 잡아 배를 세운다(Ⅲ-5).
Ⅲ-1

시스템 구성

노트북(ROS2)이 머리, 아두이노가 손. 노트북은 "좌 몇, 우 몇" 숫자만 보내고 아두이노가 그대로 ESC 에 전달한다.

실제 동작
  • motor_control 이 좌/우 PWM 을 정하면 Motor_run = 오른쪽×10000 + 왼쪽 한 숫자로 합친다. 예: 우 1400, 좌 1600 → 14001600.
  • ssf_bridge 가 USB 시리얼로 아두이노에 쓰고, 펌웨어는 핀 12(좌)·11(우)로 그대로 내보낸다.
  • 0.5 s 동안 명령이 안 오면 아두이노가 스스로 1500(중립). 노트북이 멈춰도 배는 선다.
  • 모드(WAIT 0 / MANUAL 1 / AUTO 2)는 조종기 스위치로만 바뀐다. 노트북은 /boat_mode 로 읽기만 한다.
  • 추력 부호 함정: ROS 안에서는 1500 보다 작으면 전진, 실제 ESC 는 크면 전진. 뒤집는 곳은 ssf_bridge 딱 한 곳(invert_thrust_direction). 다른 데서 또 뒤집으면 배가 후진한다.
  • 두 배는 같은 코드. boat:=A / boat:=B 를 안 주면 launch 가 아예 안 뜬다(남의 배 설정으로 뜨는 실수 방지).

Ⅲ-2.1

헤딩(뱃머리 방향) — yaw_mux

IMU 가 주는 "아무 기준 각도"를 진북 기준 0~360° 로 바꾸는 번역기. /imu/yaw 는 이 노드 하나만 낸다.

왜 따로 노드를 만들었나
작년엔 IMU 드라이버가 켜진 순간 방향을 0° 로 잡았다. 동쪽을 보고 켜지면 동쪽이 0° — GPS 목표 방위(진북 기준)와 빼면 의미가 없다. 올해는 드라이버가 원시값 /imu/yaw_raw 만 내고 yaw_mux 가 보정해 /imu/yaw 를 낸다. 같은 토픽에 발행자가 둘이면 ROS 는 에러 없이 값을 섞어 버리므로, launch 가 드라이버 출력 이름을 못 박는다.
실제 동작 (기본 소스 imu_relative)

식: ψ = wrap360( s·원시값 + mount_offset_deg ) — s 는 invert 면 −1, 아니면 +1. 예: 원시값 120°, 오프셋 232.0 → 352°. wrap360 은 0~360 으로 접는다(370 → 10, −10 → 350). 50 Hz 발행, 원시값이 0.5 s 넘게 안 오면 발행을 멈춘다.

정북 정렬 — 배마다 한 번

  1. 나침반으로 배를 북쪽에 맞춘다. 나침반은 자북을 가리키고, 한국 자북은 진북보다 약 8° 서쪽 → 이때 뱃머리의 진북 방위는 약 352°.
  2. ros2 topic echo /imu/yaw 가 352 근처가 될 때까지 ssf_heading_A.yaml 의 mount_offset_deg 를 바꾼다. 반드시 소수점(37 ❌ 37.0 ✅ — 정수면 노드가 부팅하자마자 죽는다).
  3. 시계방향으로 90° 돌린다. 352 → 약 82(한 바퀴 넘어감)면 정상. 약 262 면 방향이 반대 → invert_yaw: true 로 바꾸고 1번부터.

대안 소스 cog_offset — 지금은 사용 금지

  • 아이디어: 곧게 달리는 중이면 GPS 의 "실제 지나간 방향(COG)" ≈ 뱃머리. COG − IMU 를 여러 번 재면 오프셋을 자동으로 안다.
  • 그냥 평균 내면 359° 와 1° 가 180° 가 된다. 그래서 각도를 화살표(단위벡터)로 바꿔 더하고, 화살표가 한 방향으로 잘 모일 때(R ≥ 0.9, 표본 30개 이상)만 쓴다.
  • 버리는 표본: 느릴 때(0.8 m/s 미만), 급선회 중(8°/s 초과), 후진 중(COG 가 뱃머리와 180° 반대 — /motor_reverse 로 안다).
  • 10-30 고친 버그(F11): 이 경로가 mount·invert 를 한 번 더 적용했다 → 수정(94ed89f), Ubuntu 405 테스트 통과. 물 위 북·동 두 구간 확인 전까지 사용 금지 유지.

Ⅲ-2.2

GPS — north_goal_angle

GPS 위치로 다음 웨이포인트 방위, 지금 몇 번 임무인지(/wp_mode), 경계선 위치를 0.5 s 마다 낸다.

① 받기 — RTK

그냥 GPS 는 ±3~5 m 틀려 부표 간격보다 크다. 기지국 보정(RTK)을 인터넷(NTRIP)으로 받아 ±1.5 cm(08-07 실측 FIXED ±0.015 m). 계정 파일(~/.ssf/)이 없으면 그 노드만 빠지고 나머지는 뜬다.

② 거르기 — 다섯 겹 필터 (작년 0겹)

작년 코드는 GPS 가 위치를 못 잡아 (위도 0, 경도 0) 을 줘도 그걸로 방위를 계산했다. 08-06 실제로 47.96° 라는 엉터리 방위가 나왔다.

겹하는 일예시
1 fix 검증상태 −1, (0,0), NaN, 범위 밖 → "위치 모름"위성 못 잡음 → 방위 발행 안 함
2 공분산수신기가 "자신 없음"(분산 > 2.0) → 그 한 번만 버림
3 점프15 m/s 넘는 순간이동 → 버림건물 반사로 10 m 튐
4 스무딩오차 작으면 천천히(α 0.15), 크면 빨리(α 0.80) 따라감흔들림은 줄이고 진짜 이동은 따라감
5 신선도받아들인 위치가 2.5 s 넘게 없으면 방위·경계 중단1 Hz 라 한 번 빠짐(2 s)은 버팀

③ 길 찾기 — LOS·ILOS (줄 따라가기)

  • 작년: "목표점을 똑바로 바라봐라" → 조류에 밀리면 휘어서 들어간다.
  • 올해: 이전 WP P → 목표 W 를 잇는 가상의 줄을 따라간다. XTE = 줄에서 옆으로 벗어난 거리.
  • 줄 위 앞쪽 L m 지점(L = 속도×1.2, 2~6 m)을 바라본다. 벗어날수록 줄 쪽으로 더 꺾는다.
  • 적분 I: 계속 한쪽으로 밀리면(조류) 그만큼 미리 반대로 꺾는다. WP 를 넘기면 0 으로.
  • 도착: 반경(도킹 2.0 m, 그 외 속도별 2.5~4.5 m) 안에 dwell 초 머무르면 다음 WP. 조종기가 AUTO 가 될 때까지 WP0 에서 대기.

④ 경계 — 지오펜스 = 가짜 LiDAR

정면 −80°~+80° 를 1° 간격으로 광선을 쏴서 "이 방향 경계까지 몇 m" 를 /geofence_state 로 낸다. ship_direction 이 진짜 LiDAR 와 가까운 쪽 값으로 합친다 → 경계가 그냥 벽이 되어 회피가 알아서 피한다. 헤딩·GPS 가 이상하면 빈 배열(벽 없음). 대회장 경계 좌표가 아직 없어 지금은 꺼져 있다.

Ⅲ-2.3

LiDAR — ship_direction 의 입력부

360° 스캔 중 앞쪽 160° 만 잘라 "각도별 거리 배열"로 쓴다.

  • 받기와 계산 분리: /scan 이 오면 저장만, 계산·발행은 10 Hz 타이머가 따로. LiDAR 가 죽어도 타이머는 돌아서 "죽었다"를 알아챈다. 작년엔 LiDAR 가 끊기면 조향 명령이 0회 → 마지막 명령으로 계속 갔다.
  • 최신만: 큐 깊이 1. 밀린 옛 스캔은 버린다.
  • 각도 격자: LiDAR 80° = 정면. 0~160 = 오른쪽 80° ~ 왼쪽 80°(80 보다 크면 왼쪽). 이 격자가 /desired_angle 까지 그대로 이어진다.
  • 물보라 거르기(감속용만): 주변 5칸 중 3칸 이상 값이 있어야 인정 → 시뮬에서 가짜 감속 36.8% → 8.9%. 회피 판단에는 안 건다(작은 부표를 놓칠까 봐).

Ⅲ-2.4

영상 — 검출기 3종

카메라 한 장에서 원하는 색 부표의 방위각 하나만 뽑는다. 거리는 안 쓴다(거리는 LiDAR 담당).

단계하는 일
① 입력최신 프레임 1장만(밀리면 버림)
② 색 분리HSV 로 바꿔 "빨강 범위" 픽셀만 남김. 빨강은 색상환 0° 근처라 [0-5]+[165-180] 두 범위
③ 후보덩어리 중 작은 것(40픽셀 미만) 버림 → 모양 검사 → 물 위 높이대만 → 가장 큰 것 하나
④ 모양(도킹)꼭짓점 수 + 원형도로 삼각/사각/원
⑤ 확인한 프레임 오탐에 안 튀게, 최근 프레임에서 N 번 같아야 확정(게이트·탐색 1, 도킹 연속 3)
⑥ 각도 변환θ = −atan((x − cx) / fx), fx = (W/2)/tan(화각/2). 화면 왼쪽이 +
⑦ 발행지금 /wp_mode 가 내 담당일 때만. 2 s 못 보면 무효값 10000
⑥ 각도 변환을 직접 움직여 보는 계산기. 코드 vision_geom.py 와 같은 식이다.
왜 이렇게
  • 작년엔 같은 초록 범위가 파일 3곳에 다르게 적혀 게이트 검출기는 보는데 도킹 검출기는 못 봤다 → vision.yaml 한 곳.
  • 작년엔 모드가 바뀔 때마다 검출기를 껐다 켰다(켜지는 동안 눈이 멂) → 3개 다 상주, 자기 모드에서만 일한다.
  • 화각을 71.5° 로 잘못 써 가장자리에서 최대 4.4° 틀렸다 → camera_info 로 80.32° 실측.

Ⅲ-4

임무별 알고리즘

4.1 게이트 — ship_gate

  • 빨강·초록 둘 다 보이면 가운데로.
  • 하나만 보이면 그 부표에서 게이트 안쪽으로 40° 틀어서(빨강은 왼쪽 규칙 red_on_port).
  • 둘 다 안 보이면 20000(미션 없음) → ship_direction 이 GPS 웨이포인트 방향으로 간다. 보고서 문구와 다름 — 정정 대기
  • 부표가 옆으로 75° 넘게 지나가면 통과 1회 → /gates_passed. 먼 게이트를 미리 세지 않게 6 m 안에서만.

4.2 위치유지 — ship_back

흰 부표 방위(카메라) + 거리(LiDAR)로 부표 근처를 유지. RTK 는 보조.

4.3 탐색 — ship_turn

빨강/초록이면 시계방향, 흰색이면 반시계로 부표 둘레를 돈다. 색을 잃으면 SEARCH 상태로 다시 찾는다. 토픽 이름 /image_color 를 바꿨다가 노드가 영원히 멈춘 적 있음 — 이름 고정.

4.4 장애물 회피 — ship_direction (가장 중요)

LiDAR 160° 배열에서 배가 지나갈 만큼 넓은 빈 틈을 찾고, 그중 목표 방향에 가장 가까운 각도를 고른다.

장애물 잡티(물보라) 부풀린 칸 통과 가능한 틈 — 진한 테두리 칸 = 목표 방향에 가장 가까운 통과 각도. 예시 장면이다(탐지거리 3.0 m, half_width 0.29, clearance 0.25).
  1. 흑백 칠하기: 3.0 m 안에 뭐가 있으면 막힘.
  2. 잡티 지우기: 1~3칸짜리 막힘은 물보라로 보고 지운다(진짜 부표는 수십 칸).
  3. 부풀리기: 배 폭만큼 장애물을 양옆으로 넓힌다. 가까울수록 각도로 많이. 배를 점으로 취급할 수 있게 된다.
  4. 폭 재기: 빈 구간의 실제 폭 ≥ 0.83 m(0.29×2 + 0.25) 인 틈만 후보.
  5. 고르기: 목표 방향이 틈 안이면 그대로, 밖이면 틈 가장자리 중 목표에 가까운 쪽.
  6. 틈이 없으면: 0.5 s 후진 → 3 s 멈춰 재탐색(뒤는 못 보니 계속 후진 안 함).
  7. 급변 금지: 0.1 s 에 15° 이상 안 바꾼다.

왜 0.25: 시뮬 2,400 판에서 1번배 폭(0.58 m) 기준 접촉이 가장 적고 막혀서 멈추는 일 0%.

4.5 도킹 — ship_dock

  • 당일 공지 표식(예: 파랑 삼각형)을 yaml 한 줄로 지정 → dock 검출기가 그 색·모양만 찾는다. 연속 3 프레임 같아야 확정.
  • 목표 오타면 부팅 때 ERROR + 도킹 모드에서 10000 + 5 s 마다 ERROR.
  • 위험: 파랑이 흐린 하늘과 비슷, 빨강·주황이 색상 3~5 에서 겹침 → 실외 조정 대상.

4.6 모터 — motor_control

각도를 좌/우 PWM 차이로 바꾼다. PID 아님. 20 Hz.

코드 motor_control.py 와 같은 계산(base 1360, max_diff 100, max_angle 81, 감속 시작 1.2 m, 최소 0.7배). ROS 안에서는 작을수록 전진 — 막대가 길수록 세게 앞으로.
  • 좌우 평균이 1500 보다 크면(후진) /motor_reverse = true → 헤딩 추정이 그 표본을 버린다.
  • steer_invert: 배선이 반대면 이것 하나로 조향·선회가 같이 뒤집힌다. 물 위 첫 시험에서 확정.
  • 5000 제자리 선회에는 감속을 안 건다 — 걸면 뒤로 밀리며 돈다.
