## 0. 시스템 개요

- 보드: **Arduino Mega 2560 R3 확정** (2026-07-28, 회로팀). 5V 보드 → RC 수신기 신호 **직결 가능, 레벨시프트 불필요**. USB 1개 = 브릿지 명령 수신 + 상태/디버그 송신 겸용. ⚠️ RC 입력은 인터럽트 핀(2,3,18,19,20,21)만 가능
- 모터: T200 스러스터 ×4 — 선수 좌/우(추진 보조) + 선미 좌/우. ESC PWM 1100~1900µs, 중립 1500µs
- 전원: 4S LiPo 14.8V → ESC 직결 / Due는 5V BEC로 **독립 전원** (노트북 USB 전원 의존 금지)
- RC: Flysky FS-i6 (6채널, 채널별 PWM 출력). 스로틀 / 조향 / 모드 3채널 사용
- 배 2척(A/B, 크기 다름) 공용 펌웨어 1벌

### 대회 3모드 → 펌웨어 2상태

| 대회 모드 | 펌웨어 상태 | 비고 |
|---|---|---|
| 자율운항 본경기 | AUTO | 노트북이 미션 구분 (wp_mode) |
| 자율 토너먼트 | AUTO | 동일 — 펌웨어는 구분 안 함 |
| 수동 토너먼트 | MANUAL | **노트북·센서 전부 하선 가능** (경량화). 펌웨어는 ROS 없이 단독 가동 |

## 1. 불가침 계약

### 1-1. [2026-07-25 아키텍처 변경] micro-ROS → 시리얼 브릿지

회로팀이 브릿지 노드(노트북에서 `Motor_run` 구독 → USB 시리얼 텍스트 전송)를 제작함.
**브릿지 코드는 수정하지 않고 수용**, 펌웨어 통신부를 micro-ROS에서 시리얼 파서로 교체했다.

```
노트북 motor_control ──(ROS Motor_run, 기존 계약 그대로)──▶ 브릿지 노드 ──USB──▶ 펌웨어
```

노트북측 토픽 계약(`Motor_run` = `pwm_r*10000+pwm_l`, 1500=중립, <1500=전진)은 **무변경** — 브릿지가 흡수.
이득: micro-ROS 라이브러리·에이전트·platform.txt 패치 전부 불필요.

### 1-2. 펌웨어 시리얼 프로토콜 (브릿지와의 계약 — 변경 시 양쪽 동시 수정)

| 방향 | 포트 (Mega 2560) | 형식 | 주기 |
|---|---|---|---|
| 명령 (브릿지→펌웨어) | USB, 115200 | `L<좌µs>,R<우µs>\n` 예: `L1400,R1600` | 명령 수신 시 |
| 상태 (펌웨어→노트북) | 같은 USB, 115200 | `S,모드,워치독,배ID,비상정지,FL,FR,RL,RR\n` | 10Hz |

Mega는 USB 1개라 명령·상태가 같은 포트를 씀. 브릿지는 읽기를 안 하므로 상태 줄 무해.
벤치에선 IDE 시리얼 모니터로 상태가 그대로 보임. 추후 상태를 ROS로 올리려면 브릿지에 읽기 추가(회로팀 협의).

- 명령 유효 범위 900~2100µs — 밖이거나 형식 불일치면 그 줄 폐기 (깨진 명령은 워치독을 못 먹임)
- 값 해석 = **패스스루** (리매핑 없음), 최종 출력은 출구 클램프 1100~1900
- 상태 줄의 필드 의미는 §2-7 표와 동일. 상태 수신용 노트북 노드는 추후 신규 작성 ("S,"로 시작하는 줄만 취함)

## 2. 설계 확정 사항 (7개 항목)

### 2-1. RC 캡처

- CHANGE 인터럽트 + ISR에서 핀 상태 판별: 상승엣지=시작시각 기록, 하강엣지=HIGH 폭 계산. LOW 구간 쓰레기 측정 원천 차단 (작년 방식의 결함 수정)
- `volatile` 관리. **Mega는 8비트라 4바이트 변수 읽기가 비원자적** → 메인 루프에서 읽을 때 인터럽트 잠깐 끄고 스냅샷 (`snapPulse`/`snapStamp` 헬퍼)
- 노이즈 수용 범위 **900~2100µs** (이 밖 = 폐기). 출력 제한은 출구 클램프가 담당 — 역할 분리
- RC 소실 처리: **MANUAL 중 0.5초 무갱신 → 중립** / AUTO 중 RC 무시 / 부팅 시 유효 모드 신호 전까지 중립
- ROS와 완전 독립 — micro-ROS 연결 실패/부재 시에도 RC 경로 가동, ROS는 백그라운드 재연결 (에이전트 ping 상태기계)

### 2-2. 4모터 분배

```cpp
struct MotorCfg { uint8_t pin; bool invert; int gain_num; };  // 게인은 정수 연산 (×gain_num/10)
MotorCfg motors[4];  // [선수L, 선수R, 선미L, 선미R]
// 출력 = 1500 + (명령 - 1500) × gain,  invert면 편차 부호 반전
```

- 좌측 명령 → 선수L+선미L / 우측 명령 → 선수R+선미R (페어 제어 — 노트북은 2채널 그대로)
- 선수 게인 시작값 0.7, **물 위 튜닝** (§5 근거: 트림/후류/부하)
- **배 ID = 상보 2핀** (DIP 스위치 권장):
  - 핀1=GND: A배 / 핀2=GND: B배 / 둘 다 open 또는 둘 다 GND: **고장 → 전 모터 중립 고정 + 에러 표시**
  - 선 빠짐이 "엉뚱한 배"가 아니라 "고장"으로 판정되는 인코딩
- 부팅 시 점검 LED로 정체성 표시: 1회 깜빡=A, 2회=B, 연속 빠른 점멸=고장. 출항 전 체크리스트 항목

### 2-3. RC 수동 믹싱

```
스로틀편차 = 스로틀펄스 - 1500   (중립 데드밴드 ±20µs)
조향편차   = (조향펄스 - 1500) × steer_scale   (steer_invert_rc면 부호 반전)
좌 = 1500 + 스로틀편차 + 조향편차
우 = 1500 + 스로틀편차 - 조향편차
```

- 포화는 출구 클램프에 위임 — 풀스로틀 직진 속도 보존
- 믹싱 결과는 AUTO 명령과 같은 관문(2-2)을 통과 — 수동/자율 동일 출력 경로

### 2-4. 표시등 (룰북 규정 반영)

- **[2026-07-29] 룰 표시등 = WS2812 주소지정형 스트립 (잠정 확정 — 회로팀 납땜 그림 기준)**
  - 스트립 전체를 한 색으로: 🔴 빨강=비상정지(최우선) / 🟢 초록=수동 / 🟡 노랑=자율 / 소등=대기
  - Din 핀 1개(펌웨어 기본 40) + 5V + GND. 픽셀 수·전원 용량 실물 확정 (⚠️풀백색 기준 픽셀당 ~60mA)
  - **RC 간섭 대책**: WS2812 전송(`show()`) 중 인터럽트가 잠깐 꺼짐 → **색이 바뀔 때만 전송** (매 주기 금지)
  - 컴파일 플래그 `LED_USE_WS2812` — 0으로 내리면 예비안(단색 LED 3개+트랜지스터)으로 복귀. 라이브러리: Adafruit NeoPixel
- **점검 LED 1개 (별도, 단순 LED 유지)**: 부팅 배 ID 깜빡임, 워치독 발동 표시 — 스트립과 분리해 독립 생존
- 기각: 부저, GPS lock LED, **방향지시등 (2026-07-28 회로팀 결정으로 미채택 확정 — 코드에서 제거됨)**

### 2-5. ESC arm + 출구 클램프

- 부팅: attach → 전 ESC 1500 출력 → `arm_hold_ms`(기본 2000, 벤치 확정) 유지 → 이 동안 모든 명령 무시 → 완료 후 수용
- **출구 클램프 단일화**: ESC 쓰기 직전 한 곳에서 `constrain(1100, 1900)` — 전역 고정
- 작년 결함 수정: `writeMicroseconds(0)` arm 위반, 자율 경로 무클램프, 부팅 중 0µs 출력
- **미채택**: 슬루 리미터 (더미 코드 방지. 물 위에서 전압 강하/리셋 관찰 시 "비대칭 슬루(중립 방향 즉시, 중립 이탈만 제한)" 설계로 추가 — 약 15줄)

### 2-6. 워치독 (AUTO 전용)

- 유효 수신(`>10000000` 통과)만 시각 기록. AUTO && 500ms(노브) 무수신 → 좌/우 중립
- MANUAL에선 비활성 (RC 두절 처리 별도 — 2-1)
- 복구: 새 유효 명령 수신 즉시 자동 해제 (래치·확인조건 없음)
- 부팅 후 첫 명령 전 중립

### 2-7. 상태 보고 `/firmware_status`

- Int32MultiArray, **10Hz 고정 발행** (명령 무관 = heartbeat 겸용, 노트북 헬스체크가 링크 확인 가능)
- **배열 인덱스 계약 (연결 작업 때 노트북 세션과 최종 확정, 이후 변경 금지):**

| 인덱스 | 내용 |
|---|---|
| 0 | 모드 (0=중립대기, 1=MANUAL, 2=AUTO) |
| 1 | 워치독 발동 (0/1) |
| 2 | 배 ID (0=A, 1=B, 2=고장) |
| 3 | 비상정지 감지 (0/1) |
| 4~7 | 최종 ESC 출력 µs [선수L, 선수R, 선미L, 선미R] — 게인·반전·클램프 통과 후 실제값 |

## 3. 비상정지 (룰북 §8 — 회로 담당 영역)

- 규정: 추진 **전원 차단**, 버튼식 + 무선식 둘 다 의무. **펌웨어 중립 로직으로 대체 불가** (전원 차단 ≠ 중립 신호)
- 버튼식: 배터리→ESC 라인에 고전류 물리 차단 스위치
- 무선식: **독립 회로** — FS-i6 여유 채널 → RC 스위치 모듈 → 고전류 릴레이. Due를 거치지 않음 (제어기 사망과 무관하게 작동)
- Due는 릴레이 상태를 입력 핀으로 감지만 함 (빨간등 + `/firmware_status`)
- 펌웨어 중립 로직(워치독·RC failsafe)은 별개 층으로 유지

## 5. 선수 게인이 노브인 물리적 근거

1. **트림**: 선수 추력이 뱃머리를 박는 방향으로 작용 가능 (장착 깊이 의존) — 게인 낮추면 완화
2. **후류 간섭**: 선미 프로펠러가 선수 후류를 먹으면 효율 하락 — 배치로 1차 방어, 게인으로 2차 조정
3. **배터리 부하**: 게인 1.0 = 4모터 풀부하. 0.7이면 선수 페어 부하 경감
4. 조향은 좌우 간격이 결정 — 앞뒤 출력비의 영향 작음

→ 최적값은 물 위에서만 확정 가능. 시작 0.7.
