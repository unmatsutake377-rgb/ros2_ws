## 0. 보고서에 쓸 때 틀리기 쉬운 것 🚨
1. **오늘 쓴 PoE 어댑터는 벤치용 AC 어댑터**(RISUNIC RP028-4800320Z, 220 V 입력, 802.3af, **10/100 전용**)다. 배에 실을 DC 인젝터(PSE5502G 계열, 기가비트)는 **아직 미도착** — "인젝터 결선 완료" 로 쓰지 말 것.
2. **OAK 화각은 63.9°** (640×360). 스펙 69° 는 센서 전체 값. 양식의 "사양 69°" 옆에 실측 63.9° 를 적는다.
3. 드라이버 기본 설정으로 640×360 을 요청하면 **가운데만 잘려 화각 ~40°**. 축소 비율 `i_isp_num: 1`·`i_isp_den: 3` 이 있어야 전체 화면(`tools/oak/oak_640x360_full.yaml`).
   → fps·CPU·복구 시험은 잘린 화면으로 했다(해상도가 같아 결론 유효). 화각·각도 검증은 전체 화면.
4. `vision.yaml`·`ssf_tools.yaml` 은 **아직 D455 그대로**. OAK 는 시험용 yaml 을 덧붙여 돌렸다. 전환은 D455 비교 뒤 별도 계약.
5. 도킹 도형 시험은 **준비만 됐고 본시험 전**이다(§6).

## 2. 센서 전부 + OAK 10분 연속 (통과)
라이다·IMU·GPS·D455·OAK·비전 3종·healthcheck 동시: OAK 30.0 · D455 30.0 · 라이다 11.2 Hz · IMU 100 Hz · GPS 1 Hz · 비전 처리 29.5 fps.
USB 끊김 0, 노드 사망 0, CPU 여유 83 %. 최대 공백 IMU 0.34 s · 비전 0.33 s 한 번.

## 3. 복구 시간
정상 종료 뒤 재시작 → 14~17 s 에 비전 복구. **드라이버가 강제 종료되면 ~85~90 s 재연결 안 됨**(카메라가 옛 연결을 붙잡음, `DEPTHAI_WATCHDOG` 로도 안 줄어듦) → 경기 중 드라이버 사망 = 약 1.5 분 비전 공백.

## 4. 화각 실측 (통과) — 사진 01·02
빨간 원 2장, 중심 간격 1.00 m, 렌즈–벽 2.40 m. 원 간격 213.8 px(60장 흔들림 0.27 px) → **63.9°**, camera_info 63.87° 와 0.01° 차.
잘린 화면에선 436.6 px → 40.3°. 렌즈 왜곡 오차 최대 약 1°.

## 6. 도킹 도형 인식 — ⏳ 본시험 전 (사진 04 = 예비)
- 예비 관찰: 화면 왼쪽 끝의 빨간 원(면적 605 px²)이 30장 중 **2장 사각형으로 오판**. 원형도 0.83 이 원 기준 0.82 에 걸려 있다 → 작거나 가장자리 표식에서 흔들림.
- 본시험 준비물: `도킹시험_도형_A4.pdf` (빨강 사각·삼각·원 + 초록 사각, 각 15 cm).
- 절차: 렌즈 높이, 2.0 m(가능하면 3 m 이상도), 왼쪽부터 빨강 사각·삼각·원·초록 사각 40 cm 간격 →
  ① `python3 tools/oak/dock_label.py <out.png> 60` (도형마다 판정 표시 사진 + 60장 판정 표)
  ② 도킹 노드를 `target_shape` Square/Triangle/Circle 로 각각 + `/wp_mode=7` → `/image_angle` 이 해당 도형 각도인지 ③ 목표 도형 가리면 10000.
  OAK 드라이버: `ros2 launch depthai_ros_driver camera.launch.py camera_model:=OAK-1-POE params_file:=tools/oak/oak_640x360_full.yaml` (ROS_DOMAIN_ID 78, 끄고 다시 켤 땐 10 s 대기).
