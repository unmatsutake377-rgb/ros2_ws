# Ⅲ. 소프트웨어

## 1) 시스템 구성

### 1.1) 플랫폼
- 선내 연산: Lenovo IdeaPad Slim 3 (Ubuntu 22.04, ROS2 Humble). 두 배가 각자 노트북·DDS 도메인을 가진다.
- 하위 제어: Arduino Mega 2560 R3 — ssf_bridge 가 USB 시리얼로 L/R PWM(µs)을 보내고, 펌웨어가 ESC 2채널(핀 12 좌 / 11 우)로 내보낸다({{ESC_FANOUT}}). 명령 500 ms 무수신 시 펌웨어가 자동 중립.
- 모드 전환은 조종기 스위치뿐(WAIT 0 / MANUAL 1 / AUTO 2). 노트북이 모드를 바꾸는 경로는 두지 않는다.
- 추력 부호: ROS 내부는 <1500 = 전진, 실물 ESC 는 >1500 = 전진. 반전은 ssf_bridge 한 곳(invert_thrust_direction).
- 배 구분: 두 배는 같은 코드·같은 대회 launch 를 쓰고, 배마다 다른 값은 launch 인자 두 개로 고른다. `boat:=A|B` 는 기본값이 없는 필수 인자로 IMU 장착값 파일 `ssf_heading_<boat>.yaml` 을 고르고, `gps_config` 는 수신기 설정 파일을 고른다 [근거: src/launch_files/launch/launch_files.launch.py:74-79]. {{BOAT_NO}}는 `ros2 launch launch_files launch_files.launch.py boat:={{BOAT}}` 로 띄우고, 수신기 설정은 {{GPS_CFG}} 이다. `gps_config` 기본값은 `zed_f9p_rover.yaml` 이고 C94-M8P 를 다는 배는 `gps_config:=c94_m8p_rover.yaml` 을 붙인다 [근거: docs/기준/1번배_구성.md:14-15] [근거: docs/기준/1번배_구성.md:26]. `boat` 가 빠지거나 A/B 가 아니면 launch 가 거부되고, 배별 파일이 없으면 어떤 노드도 띄우기 전에 launch 전체를 세운다 [근거: src/launch_files/launch/launch_files.launch.py:26-32] [근거: src/launch_files/launch/launch_files.launch.py:84-86].

## 2) 센서 처리

### 2.1) 좌표계·헤딩
헤딩은 웨이포인트 목표 방위와 빼서 조향 오차를 만드는 기준값이고, 지오펜스 광선의 방향도 정한다 [근거: src/ship_goal_angle/ship_goal_angle/ship_goal_angle.py:112] [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:35]. 각도 규약은 전 구간 같다: 0~360°, 0° = 진북, 시계방향 증가 [근거: src/ssf_heading/ssf_heading/heading_logic.py:20-21]. 올해는 드라이버가 보정 없는 원시값을 `/imu/yaw_raw` 로만 내고, 새 패키지 `ssf_heading` 의 `yaw_mux` 가 보정해 `/imu/yaw` 를 단독 발행한다 [근거: src/ssf_heading/ssf_heading/yaw_mux.py:1-14]. 한 토픽에 발행자가 둘이면 보정 전·후 값이 번갈아 나와도 ROS 는 오류를 내지 않으므로, 대회 launch 가 드라이버의 `yaw_topic` 을 명시하고 드라이버는 `/imu/yaw` 로 설정되면 경고한다 [근거: src/launch_files/launch/launch_files.launch.py:109-113] [근거: src/iahrs_driver_ros2-main/iahrs_driver/src/iahrs_driver.cpp:92-96].

| 토픽 | 발행 → 구독 | 주기 |
|---|---|---|
| `/imu/yaw_raw` | iahrs_driver → yaw_mux | 100 Hz [근거: src/iahrs_driver_ros2-main/iahrs_driver/src/iahrs_driver.cpp:213] |
| `/ublox_gps_node/fix_velocity`, `/motor_reverse` | ublox_gps_node, motor_control → yaw_mux (COG 추정, 후진 게이트) | 수신기 측, 0.05 s [근거: src/ssf_heading/config/ssf_heading.yaml:82-83] [근거: src/motor_control/motor_control/motor_control.py:90] |
| `/imu/yaw`, `/heading_status` | yaw_mux → ship_goal_angle, north_goal_angle, ship_turn / healthcheck | 50 Hz / 변화 시·1 s [근거: src/ssf_heading/config/ssf_heading.yaml:16] [근거: src/ssf_heading/ssf_heading/yaw_mux.py:185-190] |
| `/yaw_error` | ship_goal_angle → ship_direction | 20 Hz [근거: src/ship_goal_angle/config/ship_goal_angle.yaml:4] |

**보정식과 소스.** yaw_mux 는 ψ = wrap360(s·ψ_raw + `mount_offset_deg` + δ) 를 적용한다(s = −1 은 `invert_yaw`) [근거: src/ssf_heading/ssf_heading/heading_logic.py:87-93]. 편각 δ 는 자기북 기준 소스에만 넣는다. 듀얼 GPS·COG 는 이미 진북 기준이라 편각을 더하면 약 8° 이중 보정이 된다 [근거: src/ssf_heading/ssf_heading/heading_logic.py:39-46]. 기본 소스 `imu_relative` 는 원시 yaw 에 고정 오프셋을 더하며, 기준축이 임의라 편각도 오프셋이 흡수한다 [근거: src/ssf_heading/config/ssf_heading.yaml:14] [근거: src/ssf_heading/ssf_heading/heading_logic.py:32,42]. 대안 `cog_offset` 은 GPS COG 와 IMU 의 차 e_i = COG − ψ_imu 를 단위벡터로 누적(반감기 감쇠)해 오프셋을 추정하고, 신뢰도 R = ‖Σ‖/n 과 표본 수가 기준을 넘을 때만 발행한다. 산술평균은 359° 와 1° 를 180° 로 만들어 쓰지 않는다 [근거: src/ssf_heading/ssf_heading/heading_logic.py:157-158] [근거: src/ssf_heading/ssf_heading/heading_logic.py:221-265]. 저속·급선회·후진 표본은 버린다. 후진만 이어지면 180° 틀린 채 R = 1.0 으로 수렴하므로 `/motor_reverse` 로 따로 막는다 [근거: src/ssf_heading/ssf_heading/heading_logic.py:164-170] [근거: src/ssf_heading/ssf_heading/heading_logic.py:203-219]. 이 추정치에는 그날의 평균 게걸음각이 섞인다 [근거: src/ssf_heading/ssf_heading/heading_logic.py:150-155]. `dual_gps`·`imu_absolute` 는 입력이 배선되지 않아 0 대신 발행을 멈춘다 [근거: src/ssf_heading/ssf_heading/heading_logic.py:361-371].

**배별 장착값과 정북 정렬.** 배마다 다른 값은 `invert_yaw`·`mount_offset_deg` 두 개뿐이며 `ssf_heading_{{BOAT}}.yaml` 에 둔다. launch 는 공통 → 배별 순서로 넘겨 뒤 파일 값이 이기고, 벤치 실행도 같은 `boat` 인자를 요구한다 [근거: src/launch_files/launch/launch_files.launch.py:11-18] [근거: src/ssf_heading/launch/ssf_heading.launch.py:56-58]. 배별 파일에 두 키 외의 값(안전 스위치 등)이 들어가거나 `mount_offset_deg` 를 정수로 적으면(yaw_mux 부팅 즉시 사망) 정적 테스트가 잡는다 [근거: src/ssf_heading/config/ssf_heading_A.yaml:8-14] [근거: src/ssf_heading/test/test_boat_config.py:7-14]. 정렬은 배를 나침반으로 정북에 맞추고 `/imu/yaw` 가 목표값을 읽을 때까지 `mount_offset_deg` 를 조정한다. 자기 나침반은 자북을 가리키고 `imu_relative` 는 편각을 쓰지 않으므로 목표값은 0 이 아니라 진북 기준 뱃머리 360 + 편각(한국 약 352)이다. 이어 시계방향 90° 회전에서 값이 증가하는지로 `invert_yaw` 를 정한다 [근거: src/ssf_heading/config/ssf_heading_A.yaml:16-25].

### 2.2) GPS RTK
GPS 처리는 외부 드라이버 `ublox_gps`·`ntrip_client` 와 우리 노드 `north_goal_angle` 로 이뤄진다. `north_goal_angle` 은 다음 웨이포인트 방위 `/north_goal_angle_tp`, 임무 번호 `/wp_mode`, 경계 광선 `/geofence_state` 를 0.5 s 주기로 낸다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:180-184] [근거: src/north_goal_angle/config/north_goal_angle.yaml:4]. 설계 원칙은 "모르면 입을 다문다"이다.

#### 수신기와 RTK 보정
단독 측위 오차(±3~5 m)가 부표 간격보다 커서 웨이포인트에는 RTK 가 필요하다 [근거: docs/절차/웨이포인트_녹화절차.md:31]. 보정은 인터넷 NTRIP 으로 받아 UHF 안테나를 달지 않는다 [근거: docs/전달용/하드웨어_배치_요구사항.md:85]. `ntrip_client` 는 수신기 드라이버보다 2.0 s 늦게 뜨고, 계정은 저장소 밖(~/.ssf/) 파일에서 읽는다. 파일이 없으면 예외 없이 그 노드만 생략한다 — 예외가 나면 메인 launch 전체가 내려가기 때문이다 [근거: src/launch_files/launch/launch_files.launch.py:135-138] [근거: src/ntrip_client/launch/ntrip_client_launch.py:13-16]. 세션이 끊기면 5 s 간격 최대 10회 재연결한다 [근거: src/ntrip_client/launch/ntrip_client_launch.py:101-105]. 외부 드라이버는 설정만 바꿨다: 두 배 해상 모델 `sea`, EEPROM 저장 없이 RAM 적용, ZED-F9P 용 이동국 파일 신설, 메인 launch 의 `gps_config` 전달 [근거: src/ublox/ublox_gps/config/c94_m8p_rover.yaml:21] [근거: src/ublox/ublox_gps/config/zed_f9p_rover.yaml:5-6] [근거: src/launch_files/launch/launch_files.launch.py:125-130].

#### fix 검증·필터·신선도
작년 코드는 fix 상태를 보지 않고 위경도를 대입했다. 드라이버는 fix 가 없어도 status −1, 위경도 0.0 인 메시지를 계속 내므로, 2026-08-06 실기에서 fix 없이 위도 0°·경도 0° 기준 방위 47.96° 가 발행됐다 [근거: src/north_goal_angle/north_goal_angle/gps_guard.py:3-13]. 올해는 fix 를 다섯 층으로 거른다.

#### 웨이포인트와 LOS·ILOS 유도
웨이포인트는 `config/waypoints.yaml` 의 `{구역, lat, lon, mode, dwell}` 목록이다. 로더가 좌표 범위(빈칸 0.0, 위경도 뒤바뀜)·mode·dwell 을 검사해 틀리면 몇 번째 항목이 왜 틀렸는지 남기고 노드를 세운다 [근거: src/north_goal_angle/north_goal_angle/waypoint_loader.py:42-91] [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:224-248]. 대회장 좌표는 `waypoint_recorder` 가 최근 2.0 s 의 유효 fix 를 평균해 녹화한다 [근거: src/north_goal_angle/north_goal_angle/waypoint_recorder.py:86-112].

작년의 직접 방위는 조류에 밀리면 경로로 돌아오지 못하고 비스듬히 접근했다 [근거: src/north_goal_angle/north_goal_angle/los_logic.py:3-6]. 올해는 이전 웨이포인트 P 에서 목표 W 로 가는 경로선을 기준으로 한다.
- 경로선 이탈: XTE = d(P, 배)·sin(ψ(P→배) − ψ(P→W)), 양수는 오른쪽으로 밀린 것 [근거: src/north_goal_angle/north_goal_angle/los_logic.py:45-56].
- 전방주시: L = clamp(1.2·v, 2.0, 6.0) m. 빠를수록 멀리 봐 완만하게 복귀한다 [근거: src/north_goal_angle/north_goal_angle/los_logic.py:38-42] [근거: src/north_goal_angle/config/north_goal_angle.yaml:7-9].
- 목표 방위: ψ_d = ψ(P→W) − atan2(XTE + k_i·I, max(0.1, L)) [근거: src/north_goal_angle/north_goal_angle/los_logic.py:67-71].
- ILOS 적분: I ← I + XTE·Δt, |I| ≤ 50(anti-windup), k_i = 0.02. 조류·바람처럼 계속 미는 외란을 상쇄한다. 웨이포인트를 넘길 때 P 를 갱신하고 I 를 0 으로 되돌린다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:479-481] [근거: src/north_goal_angle/config/north_goal_angle.yaml:10-11] [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:548-549].
- 도착 반경: 도킹(mode 7) 2.0 m, 그 외 속도 2 m/s 미만 2.5 m, 5 m/s 미만 3.5 m, 그 이상 4.5 m. 반경 안에 dwell 초 머무르면 다음 웨이포인트로 넘어간다 [근거: src/north_goal_angle/north_goal_angle/los_logic.py:75-83] [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:538-554].

LOS 이득은 초기값이며 물 위에서 튜닝한다 [근거: src/north_goal_angle/config/north_goal_angle.yaml:9-10]. `require_boat_mode_auto` 가 true 이면 RC 모드가 AUTO 일 때만 웨이포인트가 전진하고, 그 전까지 타이머·dwell·적분·경로 시작점을 초기화해 AUTO 전환 순간 WP0 부터 시작한다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:498-511].

#### 지오펜스 생성
경계 최근접점 방향으로 원뿔을 막으면 40 × 40 m 경기장 모서리에서 대각선을 향한 배의 정면이 두 원뿔 사이로 열린다. 광선 방식은 정면 경계 거리가 그대로 벽이 되고 튜닝 파라미터도 없다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:18-25]. 상대방위 −80°~+80° 를 1° 간격으로, 절대 방위 `/imu/yaw` + 상대방위 방향 광선과 경계 폴리곤 변의 최근접 교점 거리(30 m 초과는 inf)를 구해 `[−80, 1, r0 … r160]` 으로 낸다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:391-401] [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:409-410]. fix 없음·stale, `/imu/yaw` 0.5 s 초과, 배가 이미 경계 밖이면 빈 배열을 낸다. 헤딩이 얼면 "없는 벽"이 배를 가두고, 이미 밖이면 경계가 복귀로를 막기 때문이다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:350-401]. 부팅 5 s 뒤 구독자가 0 이면 ERROR 를 낸다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:413-420]. 대회장 경계 좌표가 아직 없어 `geofence_polygon` 은 비어 있다(꺼짐) [근거: src/north_goal_angle/config/north_goal_angle.yaml:39-41].

### 2.3) LiDAR 처리
`rplidar_node` 의 `/scan` 은 `ship_direction` 이 받아 갭 선택 회피(Ⅲ-4.4), 감속 신호, 지오펜스 병합, 센서 감시(Ⅲ-5)에 쓴다 [근거: src/ship_direction/ship_direction/ship_direction.py:262-276]. 회전수는 드라이버 파라미터로 바꿀 수 없어 개체마다 실측값이 다르다. {{BOAT_NO}}는 {{LIDAR}} 이다 [근거: docs/기준/CLAUDE_상세.md:117-125] [근거: docs/문제와작업/라이다_고장진단_20260818.md:76-77]. 이 절은 신호 처리만 다룬다.

- **수신과 계산의 분리.** `scan_callback` 은 스캔을 저장만 하고 계산·발행은 10 Hz 타이머 `control_cb` 가 한다. 그래서 LiDAR 가 끊겨도 발행은 계속된다 [근거: src/ship_direction/ship_direction/ship_direction.py:74-79] [근거: src/ship_direction/ship_direction/ship_direction.py:515-547]. `/scan` 구독은 BEST_EFFORT·depth 1 로 묵은 스캔이 쌓이지 않게 한다 [근거: src/ship_direction/ship_direction/ship_direction.py:62-66].
- **정면 정렬.** LiDAR 프레임 80° 를 선수 정면으로 두고 0~160°(정면 ±80°)만 쓴다. 인덱스는 메시지의 Δθ 로 매번 계산하므로 각분해능이 다른 두 개체에 같은 코드가 돈다 [근거: src/ship_direction/ship_direction/ship_direction.py:23] [근거: src/ship_direction/ship_direction/ship_direction.py:723-735].
- **inf·nan 처리.** 측정 없음은 회피 마스크에서는 빈 셀, 빈 구간 가장자리 거리로는 `detection_distance`, 감속 신호에서는 유효점 제외로 다룬다 [근거: src/ship_direction/ship_direction/ship_direction.py:755-761] [근거: src/ship_direction/ship_direction/ship_direction.py:26-32] [근거: src/ship_direction/ship_direction/failsafe.py:53-56]. `detection_distance` 는 기본 3.0 m, 게이트 구간(`wp_mode` 0·1) 2.0 m 다 [근거: src/ship_direction/ship_direction/ship_direction.py:385-389].
- **감속 신호의 공간 median.** 인덱스마다 창 [i−2, i+2](커널 5)의 유효점이 3개 이상이면 위쪽 중앙값을, 미만이면 고립 반사로 버리고, 그 최소값과 각도를 `/obstacle_distance_array` 로 낸다 [근거: src/ship_direction/ship_direction/failsafe.py:31-35] [근거: src/ship_direction/ship_direction/ship_direction.py:578-584]. 이 필터는 감속 신호에만 걸고 회피 마스크에는 걸지 않아 회피 접촉 성능을 바꾸지 않는다 [근거: src/ship_direction/ship_direction/ship_direction.py:154-160]. 시뮬(시드 20, 물보라 30%)에서 가짜 감속이 36.8% → 8.9% 로 줄었고 접촉은 전 조건 0 이었다 [근거: src/ship_direction/config/ship_direction.yaml:39]. 버린 점 수는 `/obstacle_reject_count` 로 내 물보라 대리 지표로 기록한다 [근거: src/ship_direction/ship_direction/failsafe.py:17-20].
- **지오펜스 병합과 경계 정지.** 자율 회피 구간에서는 셀마다 대응하는 경계 광선을 찾아 ranges = min(real, geofence) 로 병합한다. 병합이 마스크 생성 전이라 경계도 장애물과 같은 팽창·갭 선택을 거친다 [근거: src/ship_direction/ship_direction/ship_direction.py:619-631]. 빈 배열이나 2.0 s 넘게 묵은 경계는 병합하지 않는다 [근거: src/ship_direction/ship_direction/ship_direction.py:603-609]. 임무 노드가 조향하는 후보각·제자리 선회 구간은 병합할 마스크가 없어 하드 가드를 둔다. 최근접 경계가 2.0 m 안이고 그 방위가 의도한 진행 방향(후보각, 선회는 0°) ±60° 안이면 STOP_HOLD 를 낸다 [근거: src/ship_direction/ship_direction/ship_direction.py:661-676] [근거: src/ship_direction/ship_direction/ship_direction.py:694-699].

| ⑦ 발행·게이트 | /wp_mode 가 담당 모드일 때만 발행, stale 2 s → 정지. dock 목표 색·형상이 유효값 밖이면 기동 시 ERROR, 검출 없이 모드 7 에서만 무효값 10000 + 5 s 주기 ERROR [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:179-188] [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:175-198] | active_wp_modes: gate [0,1] / turn [2,3] / dock [7] |

- **거리는 쓰지 않는다.** 카메라는 방위각만 내고 거리는 LiDAR 전방 섹터 최소거리로 얻는다(핀홀 거리 추정의 실해역 오차 회피) [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:70-72]. 방위각은 화면 왼쪽이 + 이고 왜곡 보정은 하지 않는다. 화각은 해상도별 센서 크롭에 딸려 있어 `color_profile` 을 바꾸면 `hfov_deg` 도 바꾼다 [근거: src/color_shape_detector/color_shape_detector/vision_geom.py:73-77] [근거: src/color_shape_detector/config/vision.yaml:31-40].
- **확인과 유예.** 창 안 다수결이 아니라 이번 프레임 key 가 최근 창에 N 회 이상일 때만 확정해, 흰색 각도를 빨강으로 잘못 내는 일이 없다 [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:112-114]. 미확정이면 2.0 s 안의 마지막 확정값을, 아니면 무효값 10000.0 을 낸다. 침묵하면 소비자가 "사라졌다"로 읽기 때문이다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:206-216].
- **모드 게이팅.** 판정은 콜백 맨 앞이라 비활성 검출기는 영상 변환도 하지 않는다. turn 과 dock 이 같은 `/image_angle` 을 내므로 담당 모드가 겹치지 않는지, 첫 발행이 게이트 뒤인지를 정적 테스트가 검사한다 [근거: src/color_shape_detector/color_shape_detector/mode_gate.py:78-103] [근거: src/color_shape_detector/test/test_detector_gate_order.py:1-5].
- **카메라.** OAK-1 PoE 는 뎁스가 없지만 거리는 LiDAR 가 재고, D455 도 뎁스를 켜면 USB 에서 떨어져(2분간 13회) 끄고 쓰므로 잃는 기능이 없다 [근거: src/launch_files/launch/launch_files.launch.py:216-221]. 진동에 강한 고정초점, HFOV 45° 인 32MP 대신 69° 표준형을 골랐다 [근거: docs/전달용/구매_목록.md:76].

## 3) 전체 임무 상태기계
/wp_mode 값이 담당 노드를 정하고, 검출기는 해당 모드에서만 발행한다. /wp_mode 2 s 이상 stale 이면 검출기 발행 정지. `/wp_mode` 를 바꾸는 것은 `north_goal_angle` 하나다. 현재 웨이포인트의 mode 를 매 주기 내고, 도착(반경 안 dwell) 또는 시간 초과로 다음 웨이포인트로 넘어갈 때 값이 바뀐다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:453] [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:490]. fix 가 없어도 `/wp_mode` 는 계속 낸다. 멈추면 검출기 3종이 모두 꺼지기 때문이다. 대신 fix 없이는 도착 판정을 하지 않는다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:458-460].

| wp_mode | 임무 | 임무 노드 | 검출기 → 발행 | dwell / 시간 초과 |
|---|---|---|---|---|
| 0, 1 | 게이트 시작·끝 (항로추종) | ship_gate | gate → /red_angle, /green_angle | 3 s / 120 s |
| 2 | 위치유지 | ship_back | turn(white) → /image_angle | 3 s / 120 s |
| 3 | 탐색 (부표 선회) | ship_turn | turn(red) → /image_angle, /image_color | 3 s / 90 s |
| 5 | 장애물 회피 | 없음 — ship_direction 순수 회피 | 없음 | 50 s / 120 s |
| 7 | 도킹 | ship_dock | dock → /image_angle | 60 s / 150 s |
| 8 | 토너먼트 자율 회피 | 없음 | 없음 | 60 s / 없음 (마지막 WP) |

dwell 은 `waypoints.yaml`, 시간 초과는 WP 하나당 값으로 `wp_timeout_modes`·`wp_timeout_sec` 에 둔다 [근거: src/north_goal_angle/config/waypoints.yaml:20-30] [근거: src/north_goal_angle/config/north_goal_angle.yaml:35-36]. 시간 초과는 위치와 무관하게 다음 웨이포인트로 넘기는, GPS 가 죽어도 진행하는 유일한 수단이다 [근거: src/north_goal_angle/config/north_goal_angle.yaml:27-29]. 도킹 150 s 는 ship_dock 선형 최악 약 129 s 와 dwell 60 s 보다 크게 잡았다 [근거: src/north_goal_angle/north_goal_angle/wp_timeout.py:29]. 값이 비었거나 0 이하·NaN·길이 불일치면 출발 전에 노드를 세운다 [근거: src/north_goal_angle/north_goal_angle/wp_timeout.py:43-54]. 2026-10-29 이전에는 시간 초과가 목록 순번에 묶여 있어 회피 두 번째 WP 와 도킹에 시간 초과가 없었다 [근거: 커밋 b337ad8].

특수 명령 코드(/candidate_angle·/desired_angle): 5000 우선회, 6000 좌선회(예약), 20000 미션 없음 → 전진 폴백(모드 5·8 만), 50000 정지. 20000 은 담당 임무 노드가 없는 모드 5·8 에서 `north_goal_angle` 이 낸다. 작년에는 도킹 노드가 모드 9 로 잡혀 침묵하던 것을 덮느라 모드 7 에도 냈다. 도킹 노드를 7 로 고치면 한 토픽에 발행자가 둘이 되므로 두 수정을 한 커밋으로 묶었다 [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:4-10] [근거: 커밋 0b854c1].

## 4) 임무별 알고리즘

### 4.1) 항로추종 — ship_gate
- 검출기가 빨강·초록 부표 방위각을 내면 두 방위의 중간을 목표로, 한쪽만 보이면 그쪽 기준 오프셋, 둘 다 없으면 탐색 모드(3분기 폴백).
- 거리는 LiDAR 전방 섹터 최소거리. 통과 수는 /gates_passed 로 기록.
(상태 전이 그림, 실측 통과 성공률 — Ⅱ-5 표와 연결)

### 4.2) 위치유지 — ship_back
- LiDAR 로 부표 거리를 유지하고 RTK 는 폴백. PD 미채택(체인이 각도 기반). 흰색 부표 방위는 검출기 turn(white).

### 4.3) 탐색 — ship_turn
- 검출기 turn 은 모드 2 에서 흰색, 모드 3 에서 빨강 부표만 찾는다. ship_turn 은 /image_color 가 red/green 이면 시계 방향, white 면 반시계로 부표 중심 선회. 색 유실 시 SEARCH 상태 유지(토픽 이름 /image_color 고정 — 개명하면 영구 정지한 이력).

### 4.4) 장애물 회피 — ship_direction
`/candidate_angle` 이 20000(미션 없음)이면 LiDAR 갭 선택으로 조향각을 정한다 [근거: src/ship_direction/ship_direction/ship_direction.py:722]. 그 밖의 명령은 먼저 처리한다. 50000 이거나 `wp_mode` 4 진입 후 5 s 이내면 STOP_HOLD, 5000·6000 은 그대로 통과, 일반 후보각은 LiDAR 각 격자(정면 80)로 옮기고 0~160° 밖이면 STOP_HOLD 다 [근거: src/ship_direction/ship_direction/ship_direction.py:686-689] [근거: src/ship_direction/ship_direction/ship_direction.py:702-720].

LiDAR 스캔에서 안전 구간(연속 빈 셀)을 찾는 순서는 다음과 같다.
- 이진 마스크: 병합 거리 r 이 `detection_distance` 미만이면 장애물 [근거: src/ship_direction/ship_direction/ship_direction.py:754-761].
- 잡음 정리: 길이 `int(n × max_spike_ratio)` 셀 이하 장애물 구간을 지우고 경계 `border_margin` 셀을 깎는다. 고립 1~3셀은 사라지고 회피 거리의 실제 부표(약 30셀)는 남는다 [근거: src/ship_direction/ship_direction/ship_direction.py:830-861] [근거: src/ship_direction/test/test_avoidance_filters.py:105-143].
- 팽창: 장애물 구간 최근접 거리 r_min 으로 m = max(1, round(atan((half_width + clearance)/r_min)/Δθ)) 셀씩 양옆을 넓힌다 [근거: src/ship_direction/ship_direction/ship_direction.py:881-897].
- 폭 판정: 빈 구간 (s, e) 마다 호 길이 arc = Δθ·r_edge·(e−s) 가 min_required_width = half_width×2 + clearance 이상인 구간만 후보로 남긴다. r_edge 는 양 끝 중 가까운 쪽 거리다. 먼 쪽으로 재면 실제보다 넓게 보이기 때문이다 [근거: src/ship_direction/ship_direction/ship_direction.py:39-50] [근거: src/ship_direction/ship_direction/ship_direction.py:786-788].
- 후보 선택: 각 후보 구간 안으로 목표 방위를 잘라 넣어(clamp) 목표에 가장 가까운 각을 고르고(동률이면 호가 긴 구간), 그 각을 /desired_angle 로 고정주기 발행한다 [근거: src/ship_direction/ship_direction/ship_direction.py:799-808] [근거: src/ship_direction/ship_direction/ship_direction.py:822-823].
- 경로 없음: 후진 0.5 s 후 3.0 s STOP_HOLD 로 재탐색하고, 그래도 없으면 반복한다. 뒤쪽은 보지 못하므로 계속 후진하지 않는다 [근거: src/ship_direction/ship_direction/ship_direction.py:471-504] [근거: src/ship_direction/ship_direction/ship_direction.py:813-816].
- 변화율 제한: 0~160° 정상 조향값은 한 틱에 15° 까지만 바꾸고 특수 신호는 즉시 통과시킨다 [근거: src/ship_direction/ship_direction/ship_direction.py:438-466].

| 파라미터 | 값 | 근거 |
|---|---|---|
| half_width | 0.29 m | {{HALF_WIDTH_REASON}} [근거: src/ship_direction/config/ship_direction.yaml:61-65] |
| clearance | 0.25 m | 20 시드 스윕 최적 (Ⅲ-6.1) [근거: src/ship_direction/config/ship_direction.yaml:71] |
| min_required_width | 0.83 m | 0.29×2 + 0.25 |
| detection_distance 기본 / 게이트 | 3.0 / 2.0 m | 시뮬 스윕 [근거: src/ship_direction/config/ship_direction.yaml:57-58] |
| min_obstacle_cells | 1 | 3 이면 작은 부표를 무시한다 (두 배 공용) [근거: src/ship_direction/config/ship_direction.yaml:75] |
| temporal 투표 | OFF | 시드 20: OFF 접촉 19/20, ON 20/20 — 무익 [근거: src/ship_direction/config/ship_direction.yaml:47-53] |
| rear_obstacle_ignore | 제거 | 물보라 0.3 m 하나가 1.6 m 부표를 통째 삭제한 결함 [근거: src/ship_direction/config/ship_direction.yaml:81-82] |
| 후진 / 재탐색 | 0.5 / 3.0 s | 뒤를 못 보므로 계속 후진 대신 정지 후 재탐색 [근거: src/ship_direction/config/ship_direction.yaml:77-78] |
| rate_limit_max_deg_per_tick | 15° (150°/s) | 실측 후 튜닝 [근거: src/ship_direction/config/ship_direction.yaml:80] |

### 4.5) 도킹 — ship_dock
- 도크 3개 중 당일 지정 표식(삼각·원·사각 × 빨강·주황·노랑·초록·파랑·흰색)을 찾는다. 검출기 dock 이 target_color·target_shape 와 일치하는 후보의 방위각만 발행한다. 목표는 yaml 한 줄로 바꾼다 [근거: src/color_shape_detector/config/vision.yaml:169-174] [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:20-26]. 목표가 유효값 밖이면 기동 시 ERROR, 검출 없이 도킹 모드에서만 무효값 10000 을 내고 5 s 마다 ERROR 로 다시 알린다(다른 모드에서는 발행하지 않는다). 2026-10-28 이전에는 이 분기가 모드 게이트보다 앞이라 모드 2·3 에서도 10000 이 섞여 turn 검출기의 방위를 지웠다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:175-198] [근거: 커밋 ff289f7]. 도크 간격 1.0 m.
- 표식 판정: 마스크는 목표 색 하나로 만들고, 컨투어마다 형상을 판정해 목표와 다르면 버린다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:248-279]. 꼭짓점 3 → Triangle(원형도 ≥ 0.82 면 노이즈), 4~6 → extent > 0.4·종횡비 0.6~1.4 면 Square(원형도 ≥ 0.82 면 Circle), 7 이상 → Circle(원형도 < 0.60 이면 노이즈)이다 [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:71-94]. 통과 후보 중 화면 높이 0.15~0.55 안의 면적 최대 하나를 쓰고, key = (색, 형상) 이 연속 3 프레임 같아야 확정한다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:284-293] [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:131-135].
- 임계(원형도·extent·확인 프레임)는 감이 아니라 `tools/dock_eval.py` 혼동행렬 수치로 정한다. 실외 캘리브레이션 대상 위험은 둘이다: `hsv.blue` 가 S 18~60·V 160~200 이라 흐린 하늘에 가깝고, 빨강(H 0~5)과 주황(H 3~20)이 H 3~5 에서 겹친다 [근거: tools/dock_eval.py:5-8] [근거: docs/문제와작업/비전_개선후보_20261027.md:62-63].
- 접안 거리는 LiDAR 전방 섹터 최소거리 → ⚠️ 도크 규격 확정 후 contact_dist_m.

### 4.6) 제어기 — motor_control
PID 가 아니라 각도 기반 차동 조향이다. 상류 체인(/candidate_angle → /desired_angle)이 이미 "가야 할 방위" 를 주므로 제어기는 그 각도 오차를 좌·우 PWM 차동으로 바꾸고, 전방 장애물 거리와 페일세이프 레벨로 속도만 깎는다. 20 Hz 고정주기 타이머.

| /desired_angle | 분기 | 좌/우 PWM (ROS 기준, <1500 = 전진) | 감속 적용 |
|---|---|---|---|
| ≥ 50000 | 정지 STOP_HOLD | 1500 / 1500 | — |
| 20000 ~ 50000 | 미션 없음 → 전진 폴백 | base_pwm / base_pwm (1360) | ○ |
| 5000 (6000) | 제자리 우선회 (좌선회) | spin_forward_pwm ± spin_diff = 1600 / 1400 (1400 / 1600) | × (감속 걸면 뒤로 밀리며 돎) |
| −1 ~ 161 (정면 = 80) | 정상 조향 | offset = θ − 80, diff = abs(offset) / max_angle × max_diff(100) → base ∓ diff | ○ |
| 161 ~ 5000 | 후진 | reverse_pwm / reverse_pwm (1590) | × |
| 명령 0.5 s 무수신 | 워치독 | 1500 / 1500 | — |

감속비 = min(장애물 근접비, 페일세이프 상한). 근접비는 전방 최근접 거리 d 에 대해 d ≥ 1.2 m 이면 1.0, 그 아래서 0.7 + 0.3·d/1.2 로 선형. 페일세이프 레벨 1 이면 0.7. 적용은 PWM 을 중립 쪽으로 당기는 식 1500 + (PWM − 1500)·ratio.
- steer_invert 하나가 조향과 SPIN 을 함께 뒤집는다(배선 반대 대비). ⚠️ 물 위 첫 시험에서 확정 — 가장 흔한 사고.
- PD 미채택 근거: 체인이 각도 기반이라 속도 상태가 없고, 각도 오차의 미분은 LiDAR 10 Hz·헤딩 노이즈를 증폭한다. 작년 SPIN 버그(순항 속도로 원을 그려 도크 충돌)는 중심 PWM 을 1500 으로 분리해 해결.
- 출력 PWM 좌우 평균이 1500 보다 크면 `/motor_reverse` 를 참으로 내 헤딩 COG 추정의 후진 게이트로 쓴다(Ⅲ-2.1) [근거: src/motor_control/motor_control/motor_control.py:162-164].

## 5) 페일세이프
- 4중 장치: time.monotonic() / ARMED(센서 1회 수신 후 감시) / 연속 N회(failsafe_confirm_n 3) / 히스테리시스 + 자동 복구.
- `ship_direction` 의 `SensorWatch` 가 `/scan` 과 `/yaw_error` 의 신선도를 함께 보고 가장 나쁜 센서가 레벨을 정한다. `/scan` 만 보면 IMU 가 죽어도 마지막 `/yaw_error` 로 계속 조향한다(시뮬: 정지율 0%, 접촉 3회) [근거: src/ship_direction/ship_direction/failsafe.py:114-127] [근거: src/ship_direction/ship_direction/ship_direction.py:106-110]. 평가는 독립 타이머(watchdog_cb, 10 Hz)에서 한다 — 센서가 죽으면 콜백이 안 불리므로 [근거: src/ship_direction/ship_direction/ship_direction.py:399-402].

| 레벨 | 진입 조건 | /desired_angle | 속도 |
|---|---|---|---|
| 0 정상 | — | 계산한 각도 | 100% |
| 1 경고 | 경과 > failsafe_warn_sec 0.7 s (연속 3회) | 계산한 각도 그대로 — 회피 중 직진 강제는 피하던 부표에 부딪힌다 | 0.7 배 |
| 2 정지 | 경과 > failsafe_stop_sec 3.0 s (연속 3회), 또는 이상 스캔(angle_increment 0·음수·NaN) 즉시 | STOP_HOLD 로 덮어씀 | 정지 |

[근거: src/ship_direction/config/ship_direction.yaml:14-21] [근거: src/ship_direction/ship_direction/failsafe.py:133-143] [근거: src/ship_direction/ship_direction/ship_direction.py:90-92]

- 위치·헤딩 소스는 모르면 침묵한다. IMU 가 끊기면 `/imu/yaw`·`/yaw_error` 가 멈춰 위 감시가 잡고(Ⅲ-2.1), 받아들인 GPS fix 가 2.5 s 넘게 없으면 방위·지오펜스가 멈추되 `/wp_mode` 와 시간 초과 진행은 유지한다(Ⅲ-2.2) [근거: src/north_goal_angle/north_goal_angle/north_goal_angle.py:423-441]. 지오펜스가 2.0 s 넘게 묵으면 병합하지 않는다.
- 비전: `/wp_mode` 가 끊기면 검출기가 발행을 멈추고, 표식 유실 2.0 s 뒤에는 무효값 10000 을 낸다. 도킹 목표 오타는 모드 7 에서만 10000 + 주기 ERROR 로 드러난다(Ⅲ-4.5).
- motor_control 명령 워치독 0.5 s, 펌웨어 워치독 0.5 s, 부팅 시 중립. 접촉기 보조접점 → Mega 핀 38 로 비상정지 상태를 노트북이 안다.
- 진단(온도·헤딩 상태)은 로그만. /health_ok 는 제어에 물리지 않는다 — 거짓 정지 금지.
- TTC 비상제동은 해로워서 폐기, 시간 투표는 무익해서 OFF.

## 6) 시뮬레이션 및 시험 결과

### 6.1) 시뮬레이션 스윕 (tools/sim, 20 시드 × 폭 5 × clearance 6 × 탐지거리 2 × 게이트폭 2 = 2,400 런)
`tools/sim` 은 `ship_direction`·`motor_control` 로직 재구현, 가짜 LiDAR 부표 월드, 2025 규정 70×20 m 전 코스로 이뤄진다 [근거: tools/sim/README.md:7-9]. 폭마다 정체(구간 미도달) 런 비율이 가장 낮고 그다음 접촉이 적은 clearance 를 골랐다 [근거: tools/sim/sweep_s1.py:92-94].

| 0.50 | 0.25 | 0.30 | 0.85 | 0% |

half_width 0.29 에서 clearance 별 접촉은 0.20 → 1.95, 0.25 → 1.32, 0.30 → 1.46(정체 2%), 0.35 → 정체 28%, 0.45 → 정체 50% 로, 접촉이 가장 적은 0.45 는 절반이 정체라 고르지 않았다 [근거: src/ship_direction/config/ship_direction.yaml:71]. 작년 값 half_width 0.45 는 1.15 m 갭을 요구해 접촉 3.0 회·정체 1.5 회였다(1차 단일 시드 스윕) [근거: docs/문제와작업/S1_half_width_스윕/README.md:25]. 최적점의 갭 요구(half_width×2 + clearance)는 0.78~0.90 m 에 모인다 [근거: docs/문제와작업/S1_half_width_스윕/README.md:72]. 한계도 있다. 접촉 판정이 반경 half_width 원이라 측면 접촉을 못 잡고, 동역학은 가정값이며, 시간 투표·지오펜스 병합은 시뮬에 없다 [근거: tools/sim/README.md:13-15]. 선회 중 유효 폭 W·cosθ + L·sinθ 는 1번배 치수(W 0.58, L 1.66)로 10° 에서 0.86 m, 15° 에서 0.99 m 라 갭 요구 0.83 m 는 약 9° 이내로 정렬했을 때만 맞는다 — 1 m 안팎 틈은 시뮬이 못 잡는 영역이라 수조 게이트 시험으로 확인한다 [근거: docs/문제와작업/S1_half_width_스윕/README.md:76-81].
