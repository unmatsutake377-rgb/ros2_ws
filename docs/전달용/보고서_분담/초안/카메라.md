## 2.4) 영상 처리 파이프라인
검출기 3종(`basic_image_subscribergate`·`basic_image_subscriberturn`·`basic_image_subscriberdock`)은 같은 처리 순서를 따르고, 각자 `/wp_mode` 를 보고 자기 담당 모드에서만 일한다 [근거: src/launch_files/launch/launch_files.launch.py:219-224] [근거: src/color_shape_detector/config/vision.yaml:111-117]. 색 범위·최소 면적·확인 프레임·화각은 모두 `config/vision.yaml` 한 곳에서 읽는다 [근거: src/color_shape_detector/config/vision.yaml:51-58]. 작년에는 같은 색이 파일 3곳에 다른 값으로 박혀 있어, 같은 초록 부표를 게이트 검출기는 보고 도킹 검출기는 못 보는 상태였다 [근거: src/color_shape_detector/color_shape_detector/hsv_ranges.py:7-11].

검출기는 **방위각만** 낸다. 거리는 소비 노드가 LiDAR `/scan` 으로 구한다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:70-72]. 아래 표는 처리 7단계를 코드와 대조해 고친 것이다.

### 2.4.4) 처리 알고리즘
**색 분리.** HSV 범위는 정수 6개(lo H,S,V · hi H,S,V)가 한 범위이고, 여러 범위는 이어 붙인다 [근거: src/color_shape_detector/config/vision.yaml:60-62]. 범위마다 `inRange` 마스크를 OR 로 합치고 `medianBlur(3)` 로 점 노이즈를 지운 뒤 외곽 컨투어만 찾는다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:250-255]. turn 은 모드에 따라 찾는 색을 좁혀 mode 2 는 흰색, mode 3 은 빨강만 본다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberturn.py:164-169] [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberturn.py:235-252].

**후보 거르기.** 면적이 `min_area_px` 보다 작으면 버린다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:259-261]. gate·turn 은 `require_shape` 가 true(기본)면 꼭짓점 4~8, extent > 0.4, 종횡비 0.6~1.4 를 요구하고 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:268-279], false 면 대신 solidity = 면적/볼록껍질 면적 ≥ `min_solidity` 만 본다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:286-289] [근거: src/color_shape_detector/color_shape_detector/vision_geom.py:93-105]. 규정 부표에는 형상 규정이 없어, 파도에 반쯤 가린 부표를 꼭짓점 조건으로 버리지 않도록 만든 선택지다. 측정 전이라 기본값은 기존 동작(true)이다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:155-158]. 중심은 기본 경로에서 꼭짓점 평균, false 경로에서 질량중심을 쓴다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:298-305]. 이어 중심 y 가 화면 높이의 `y_zone_lo`~`y_zone_hi` 밖이면 버린다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:308]. 남은 후보 중 색별로 면적이 가장 큰 것 하나를 고른다. 같은 크기 표식이면 큰 쪽이 가까운 쪽이라는 가정이다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:240-241] [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:318-326].

**방위각.** 화각에서 초점거리를 구해 핀홀 모델로 바꾼다.

- fx = (W/2) / tan(hfov/2), θ = −atan((vX − W//2) / fx) [deg] [근거: src/color_shape_detector/color_shape_detector/vision_geom.py:66] [근거: src/color_shape_detector/color_shape_detector/vision_geom.py:79-81]
- W 는 파라미터가 아니라 매 프레임 영상에서 읽으므로 해상도가 바뀌어도 식은 유지된다. 단 화각은 해상도별 센서 크롭에 딸려 있어 `color_profile` 을 바꾸면 `hfov_deg` 도 같이 바꿔야 한다 [근거: src/color_shape_detector/config/vision.yaml:25-28] [근거: src/color_shape_detector/config/vision.yaml:37-40].
- 부호는 왼쪽이 + 로, `/candidate_angle` 계열과 같은 규약이다 [근거: src/color_shape_detector/color_shape_detector/vision_geom.py:73-77].
- 왜곡 보정은 하지 않는다. D455 실측 왜곡 기여분은 가장자리에서 0.4° 이고, 광각 카메라를 붙이면 rectified 토픽이나 `cv2.undistortPoints` 가 필요하다 [근거: src/color_shape_detector/config/vision.yaml:31-34].

**확인과 유예.** `DetectionConfirmer` 는 최근 `confirm_window` 프레임의 key 를 덱에 담고, 이번 프레임의 key 가 그 안에 `confirm_frames` 번 이상이면 확정한다 [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:127-153]. 미검출(None)은 창에 남을 뿐 카운트를 지우지 않고, 다른 key 가 들어오면 창을 비운다 [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:144-148]. 창 안 다수결이 아니라 이번 프레임 key 만 돌려주므로, turn 이 이번 프레임 흰색 각도를 빨강으로 잘못 내 `ship_turn` 이 반대로 도는 일이 없다 [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:112-114]. `confirm_window` 를 지정하지 않거나 N 보다 작게 주면 N 으로 보정되어 옛 "연속 N" 과 같게 동작한다 [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:129-132]. 확정되지 않은 프레임은 발행하지 않고 fallback 으로 넘긴다. fallback 은 마지막 확정값이 `grace_period_s` 안이면 그 값을, 아니면 10000.0 을 낸다. 토픽이 침묵하면 소비자가 "사라졌다" 로 읽기 때문이다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:344-348] [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:206-216].

**모드 게이팅.** `ModeGate` 는 `/wp_mode` 를 한 번도 못 받았거나(`no_wp_mode`), 2.0 s 넘게 끊겼거나(`wp_mode_stale`), 담당 외 모드면(`other_mode`) 비활성으로 판정한다 [근거: src/color_shape_detector/color_shape_detector/mode_gate.py:38-40] [근거: src/color_shape_detector/color_shape_detector/mode_gate.py:58-67]. 모르면 발행하지 않는다는 원칙이다. 틀린 방위를 내보내느니 침묵이 낫다고 보고, 대신 앞의 두 경우는 5 s 간격 WARN 으로 알린다 [근거: src/color_shape_detector/color_shape_detector/mode_gate.py:21-23] [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:184-188]. 판정이 콜백 맨 앞이라 비활성 노드는 영상 변환조차 하지 않는다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscribergate.py:176-178].

## 4.5) 도킹 — 표식 판정
- 목표 표식은 `target_color`·`target_shape` 파라미터이고 당일 공지값을 yaml 한 줄로 바꾼다. 유효값은 색 6종(red·orange·yellow·green·blue·white), 형상 3종(Triangle·Square·Circle)이다 [근거: src/color_shape_detector/config/vision.yaml:169-174] [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:20-26].
- 오타 등 유효값 밖이면 부팅 때 ERROR 를 내고 검출을 하지 않는다. 담당 모드(7)에서만 매 프레임 10000.0 을 내고 5 s 마다 ERROR 로 원인을 다시 알린다. 그 외 모드에서는 발행하지 않아 turn 검출기의 `/image_angle` 을 덮지 않는다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:110-128] [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:175-198]. 2026-10-28 이전에는 이 분기가 모드 게이트보다 앞이라 모드 2·3 에서도 10000 이 섞였다 [근거: 커밋 ff289f7].
- 마스크는 목표 색 하나로만 만든다. 컨투어마다 `classify_shape` 로 형상을 판정해 목표 형상과 다르면 버린다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:248-279].
- 형상 판정: 면적 < 80 px², 꼭짓점 < 3, 바운딩박스 폭·높이 ≤ 0 이면 판정하지 않는다 [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:60-65].
- 꼭짓점 3 → Triangle. 단 원형도 ≥ 0.82 면 노이즈로 버린다 [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:71-74].
- 꼭짓점 4~6 → extent > 0.4 이고 종횡비 0.6~1.4 일 때 Square. 원형도 ≥ 0.82 면 Circle 로 돌린다 [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:77-86].
- 꼭짓점 7 이상 → Circle. 단 원형도 < 0.60 이면 울퉁불퉁한 노이즈로 버린다. 그 밖은 판정 없음(None) [근거: src/color_shape_detector/color_shape_detector/dock_logic.py:89-94].
- 통과 후보는 중심(꼭짓점 평균)의 y 가 화면 높이 0.15~0.55 안이어야 하고, 그중 면적 최대 하나의 방위각을 쓴다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:284-293].
- 확인은 key = (색, 형상) 으로 연속 3 프레임이 같아야 확정한다. dock 은 `confirm_window` 를 선언하지 않아 창 방식이 아닌 연속 N 이다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:131-135] [근거: src/color_shape_detector/config/vision.yaml:104-105]. 확정 프레임만 발행하고, 아니면 2.0 s 유예 동안 마지막 값, 이후 10000.0 을 낸다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:221-237].
- 판정 임계(원형도·extent·확인 프레임)는 감이 아니라 `tools/dock_eval.py` 혼동행렬 수치로 정하도록 되어 있으나, 실영상 혼동행렬은 ____ 이다 [근거: src/color_shape_detector/config/vision.yaml:178] [근거: tools/dock_eval.py:5-8].
- 확인된 위험 두 가지는 실외 캘리브레이션 대상이다 [근거: docs/문제와작업/비전_개선후보_20261027.md:62-63]. 첫째, `hsv.blue` 는 S 18~60·V 160~200 이라 선명한 파란 표식보다 흐린 하늘에 가깝다. 둘째, 빨강(H 0~5)과 주황(H 3~20)이 H 3~5 에서 겹친다.
- `/image_angle` 을 받은 뒤의 접근 제어와 접안 거리(`contact_dist_m`)는 `ship_dock` 담당(Ⅲ-4, 팀장)이고, 거리는 LiDAR 전방 섹터에서 얻는다 [근거: src/color_shape_detector/color_shape_detector/basic_image_subscriberdock.py:66-67].
