## 3. 배포 방법

1. 저장소 접근 권한을 준다. `git pull` 만 하면 이 폴더와 스크립트가 다 있다.
2. 담당자에게 메시지 한 통: "`docs/전달용/보고서_분담/` 의 `00_` 두 개와 `0N_<센서>.md` 를 읽고, 공통 작성규칙 5절 프롬프트로 써서 `원고_<센서>_<이름>.md` 와 그림 PNG 를 ____ 까지 보내 줘."
3. 웹 AI 를 쓰는 사람에게는 아래 명령 하나를 알려 준다.

```bash
cd ~/ros2_ws && git pull && tools/report_pack.sh imu
```

🚨 **보안 두 가지**
- 압축 파일로 코드를 넘길 때는 홈 폴더의 `.ssf` 폴더가 섞이지 않았는지 본다. 저장소 안에는 계정이 없다.
- `src/ntrip_client` 의 작년 대비 diff 는 아무에게도 주지 않는다. 작년 NTRIP 계정이 평문으로 커밋 기록에 남아 있다. 묶음 스크립트는 이 diff 를 일부러 뺀다.

## 5. 원고가 오면 — 검수 순서

1. **양식 확인.** 8항목과 부록 3개가 있나. 없으면 바로 돌려보낸다.
2. **근거 대조.** `[근거: 파일:행]` 을 실제 줄과 맞춰 본다. 원고 파일을 Claude 세션에 주고 "근거 대조해 줘" 라고 하면 줄 단위로 맞는지, 근거 없는 수치가 있는지 표로 돌려준다.
3. **출처 확인.** 외부 드라이버 내부 구현을 우리 것처럼 쓴 문장이 없나. 개선점 표의 커밋 번호가 실제로 있나.
4. **겹침 정리.** 각 원고의 부록 C(겹치는 내용)를 모아, 지시서의 경계표대로 한 곳에만 남긴다.
5. **빈칸 모으기.** 부록 B(확인 필요)를 하나의 실측 목록으로 합친다. 수조·야외 시험 계획에 넣는다.
6. **반영.** `tools/make_report_docx.js` 의 Ⅲ장 부분을 고치고 A·B 를 다시 만든다. 근거 표시는 이때 지운다. A배·B배 차이는 원고의 부록 A 를 보고 생성기의 배별 값에 넣는다.

생성기는 `docx` 모듈(9.13.0)이 필요하다. 저장소 밖 아무 폴더에 한 번 설치하고 그 경로를 `NODE_PATH` 로 준다. 반영 작업은 Claude 세션에 맡겨도 된다.

```bash
mkdir -p ~/node_docx && cd ~/node_docx && npm install docx@9.13.0
```

```bash
cd ~/ros2_ws && NODE_PATH=~/node_docx/node_modules node tools/make_report_docx.js docs/전달용/KABOAT2026_보고서_양식_SSF_A.docx A
```

## 6. 자주 생길 문제

| 증상 | 원인 | 대처 |
|---|---|---|
| 원고에 그럴듯한 정확도·성공률 수치 | AI 가 지어냄 | 근거 없는 수치는 `____` 로 바꾼다 |
| "Slamtec 드라이버는 내부적으로 …" 같은 설명 | 외부 코드 설명 | 삭제. 토픽·주기만 남긴다 |
| 작년 보고서와 문장이 비슷함 | AI 가 기존 문서를 베낌 | 표절 위험. 다시 쓰게 한다 |
| 두 원고가 지오펜스를 각자 설명 | 경계 미준수 | GPS 는 생성, LiDAR 는 병합만 |
| 토픽 이름이 바뀌어 있음 (`/imu_yaw` 등) | AI 가 다듬음 | 코드 표기로 되돌린다 |
