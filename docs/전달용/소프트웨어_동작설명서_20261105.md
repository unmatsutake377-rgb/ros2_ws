# 소프트웨어 동작 설명서 — 코드가 실제로 어떻게 굴러가나

**기준: 2026-11-05 GitHub에 올라간 현재 코드.** 보고서(A 최종본·B 15차)와 다른 곳은 ⚠️ 로 표시했다. 숫자는 코드에 적힌 값이다.
대상: 코딩을 안 해 본 팀원. 처음부터 순서대로 읽으면 된다.

## 0. 한 문단 요약

배 안의 노트북 한 대가 센서(LiDAR·IMU·GPS·카메라) 값을 받아 "지금 어느 쪽으로 얼마나 세게 갈지"를 0.05~0.1초마다 새로 계산하고, 그 결과를 USB 선으로 아두이노에 보낸다. 아두이노는 그 값을 추진기 속도 신호로 바꿔 ESC(모터 드라이버)에 넣는다. 조종기 스위치가 AUTO일 때만 노트북 명령이 추진기로 가고, MANUAL이면 사람이 조종기로 몬다. 센서가 끊기거나 값을 믿을 수 없으면 틀린 명령을 내는 대신 **멈춘다.**

## 1. 먼저 비유로 보는 큰 그림

| 사람 몸 | 배 | 하는 일 |
|---|---|---|
| 눈 | OAK 카메라 | 부표·표식의 **색과 모양**을 보고 "몇 도 방향에 있다"만 알려 준다 |
| 박쥐의 초음파 | LiDAR | 주변 360°까지의 **거리**를 잰다 (코드는 앞쪽 ±80°만 씀) |
| 나침반 감각 | IMU | 뱃머리가 어느 방위를 보는지(**헤딩**) |
| 지도 앱 | GPS (RTK) | 지금 위치 → 다음 목적지까지 **방위와 거리** |
| 뇌 | 노트북 (ROS2) | 위 정보를 모아 갈 방향과 세기를 정한다 |
| 척수 | 아두이노 메가 | 뇌 명령과 조종기 신호 중 하나를 골라 근육에 전달 |
| 근육 | ESC + T200 추진기 | 실제로 물을 민다 |
| 반사 신경 | 비상정지(접촉기) | 버튼·리모컨을 누르면 소프트웨어와 무관하게 전기를 끊는다 |

### ROS2를 회사 메신저로 비유하면

- **노드(node)** = 직원 한 명. 각자 한 가지 일만 한다. 예: "GPS 담당", "회피 담당".
- **토픽(topic)** = 단톡방. 이름이 `/scan`, `/wp_mode` 처럼 `/` 로 시작한다.
- **발행(publish)** = 단톡방에 글 올리기. **구독(subscribe)** = 그 방 알림 받기.
- 한 직원이 올린 글을 여러 직원이 동시에 읽을 수 있다. 직원끼리 직접 전화하지 않고 늘 단톡방으로만 말한다.
- **타이머** = 직원이 "0.1초마다 한 번씩" 일하는 습관. 그래서 각 노드는 정해진 주기로 결과를 계속 올린다.
- **파라미터 / yaml** = 직원 업무 수첩. 숫자 설정값(예: 탐지 거리 3.0 m)을 코드 밖 파일에 적어 둔 것.

## 2. 꼭 알아야 할 약속 5가지

### 2.1 각도는 두 가지 방식이 있다
- **지도 방위:** 0~360°, 0° = 정북, 시계방향으로 커짐. GPS·IMU가 쓴다.
- **LiDAR 격자 각도:** 정면 = **80**, 왼쪽이 + (80보다 크면 왼쪽, 작으면 오른쪽), 쓰는 범위 0~160. 회피·제어기가 쓴다.

### 2.2 특수 코드 — 각도 자리에 들어가는 "약속된 숫자"
각도를 보내는 토픽(`/candidate_angle`, `/desired_angle`)에 아래 숫자가 오면 각도가 아니라 **명령**이다.

| 숫자 | 뜻 |
|---|---|
| 5000 | 제자리에서 오른쪽으로 돌아라 |
| 6000 | 제자리에서 왼쪽으로 돌아라 |
| 20000 | "임무 없음" — GPS 목적지 방향으로 가면서 LiDAR로 알아서 피해라 |
| 50000 | 멈춰라 (STOP_HOLD) |
| 180 | 뒤로 가라 (회피 노드가 260으로 바꿔 전달) |
| 10000 | (카메라 쪽) "표식이 안 보인다" |

**20000이 가장 중요하다.** 할 일이 없는 임무 노드는 20000을 내고, 그러면 배는 GPS로 다음 목적지를 향해 가면서 장애물을 피한다.

### 2.3 추진 세기는 PWM(µs) 숫자로 말한다
- 1500 = 정지(중립). 1100~1900 사이로 세기를 정한다.
- **노트북 안(ROS)에서는 1500보다 작을수록 전진**이다. 예: 1360 = 기본 전진.
- 실제 ESC는 반대로 1500보다 클수록 전진이라, `ssf_bridge` 한 곳에서만 `3000 − 값`으로 뒤집어 보낸다. (1360 → 1640)
- 다른 곳에서 또 뒤집으면 두 번 뒤집혀 원래대로 돌아가는 사고가 나서, 뒤집는 곳을 한 군데로 정했다.

### 2.4 "모르면 입을 다문다"
센서 값을 믿을 수 없을 때 0 같은 가짜 값을 내지 않고 **아예 글을 올리지 않는다.** 그러면 아래쪽 노드가 "글이 끊겼다"를 보고 감속·정지한다. 가짜 값을 내면 아래 노드가 진짜로 믿고 엉뚱한 곳으로 가기 때문이다.

### 2.5 임무 번호 `/wp_mode`
웨이포인트(목적지)마다 임무 번호가 붙어 있고, 지금 가는 웨이포인트의 번호가 곧 "지금 무슨 임무 중인가"다.

| wp_mode | 임무 | 일하는 노드 | 카메라 검출기 |
|---|---|---|---|
| 0, 1 | 게이트(항로추종) 시작·끝 | ship_gate | gate (빨강·초록) |
| 2 | 위치유지 | ship_back | turn (흰색) |
| 3 | 탐색(지정 색 부표 앞 위치유지) | ship_back | turn (기본 빨강, 당일 공지 색으로 변경) |
| 5 | 장애물 회피 | 없음 → north_goal_angle 이 20000 | 없음 |
| 7 | 도킹 | ship_dock | dock (지정 색·모양) |
| 8 | 토너먼트 자율 회피 | 없음 → 20000 | 없음 |

`/wp_mode`를 바꾸는 노드는 **north_goal_angle 하나뿐**이다. 각 임무 노드와 검출기는 `/wp_mode`를 보고 자기 번호일 때만 일한다.

## 3. 전원을 켜고 출발하기까지 — 실제 순서

### 3.1 아두이노가 먼저 깬다 (배터리·USB 연결 시)
1. 시리얼(USB 통신)을 115200 속도로 연다.
2. **배 ID를 읽는다.** 핀 34·36을 보고 A인지 B인지 정한다(둘 다 비어 있으면 A). 보드 위 디버그 LED를 1번(A)·2번(B) 깜빡여 알려 준다. 둘 다 GND에 물려 있으면 "고장"으로 보고 계속 중립.
3. **ESC 무장:** 좌·우 ESC에 1500(정지)을 2초 동안 넣는다. ESC는 처음에 중립 신호를 받아야 작동 준비가 된다.
4. 그다음에야 조종기 수신기 신호 읽기를 켠다. 그래서 켜는 순간 스틱이 기울어져 있어도 배가 튀어 나가지 않는다.
5. LED 스트립은 **꺼짐(WAIT)**. 조종기 모드 신호를 한 번이라도 받기 전까지는 무조건 정지다.

### 3.2 노트북에서 실행
```
ros2 launch launch_files launch_files.launch.py boat:=A     (B 배는 boat:=B)
```
- **`boat:=` 는 반드시 써야 한다.** 빠뜨리거나 A·B가 아니면 아무것도 안 켜고 거부한다.
- 그 배의 IMU 장착값 파일(`ssf_heading_A.yaml` 또는 `_B`)이 없으면 역시 아무것도 안 켜고 멈춘다.
- 켜지는 노드(거의 동시에 뜬다):

| 순서 | 노드 | 역할 |
|---|---|---|
| 1 | yaw_mux | IMU 원시값 → 보정한 헤딩 |
| 2 | rplidar | LiDAR 드라이버 |
| 3 | iahrs_driver | IMU 드라이버 (원시값 `/imu/yaw_raw` 만 냄) |
| 4 | ublox | GPS 드라이버 |
| 5 | ntrip_client | RTK 보정 수신 — **2초 늦게** 뜬다. 계정 파일(~/.ssf/)이 없으면 이 노드만 빠진다 |
| 6 | north_goal_angle | 웨이포인트·임무 번호·GPS 방위 |
| 7 | ship_goal_angle | 방위 오차 계산 |
| 8 | oak (카메라) | 꺼지면 20초 뒤 자동 재시작. 패키지가 없으면 건너뜀 |
| 9 | 검출기 gate·turn·dock | 카메라 영상 → 색·형상 방향 |
| 10 | ship_gate, ship_dock, ship_back, ship_turn | 임무 노드 |
| 11 | ship_direction | 회피 + 최종 방향 결정 + 페일세이프 |
| 12 | motor_control | 방향 → 좌·우 추진 세기 |
| 13 | ssf_bridge | USB로 아두이노와 대화. `/dev/ttyMEGA` 가 있을 때만 뜬다 |
| 14 | blackbox | 주요 값을 0.1초마다 CSV로 기록. 실행 인자 `record:=false` 면 안 뜬다(기본은 켬) |

- `ssf_bridge`는 포트를 연 뒤 **2초 기다린다**(포트를 열면 아두이노가 재부팅되기 때문). 그다음 정지 명령(1500/1500)부터 보낸다.
- 기록 도구 blackbox는 대회 실행에 **들어 있다**(11-05부터). 진단 도구 healthcheck·mission_monitor는 **없다** — 필요하면 따로 켠다(5.13).

### 3.3 조종기를 켜고 MANUAL로 출발점까지
- 조종기 모드 스위치(2단, SwD)가 아래면 **MANUAL(초록)**, 위면 **AUTO(노랑)**. 비상정지가 걸리면 다른 색보다 우선해서 **빨강**.
- MANUAL에서는 아두이노가 조종기 스틱만 본다. 노트북 명령은 무시한다.
- 이 동안 north_goal_angle은 방위·거리·임무 번호는 계속 계산해 올리지만, **웨이포인트를 넘기지 않는다**(AUTO 대기). 시간 초과 시계도 0으로 붙잡아 둔다.

### 3.4 AUTO로 스위치를 올리는 순간
- 아두이노가 노트북 명령을 추진기로 보내기 시작한다.
- north_goal_angle이 시계를 켜고 WP0부터 진행한다. 경로선 시작점은 "AUTO로 바꾼 순간 배의 위치"다.
- ⚠️ **도중에 MANUAL로 뺐다가 다시 AUTO로 올리면 WP0이 아니라 하던 웨이포인트부터 이어 간다.** 처음부터 다시 하려면 노드를 다시 실행해야 한다. (11-05부터 코드 로그도 '처음 AUTO 면 WP0, 재진입은 현재 WP 부터'로 정정. 보고서 문장은 수정안 77에 대기.)

## 4. 0.1초 동안 일어나는 일 — 숫자로 따라가기

**상황:** 장애물 없는 물 위, 회피 구간(mode 5). 뱃머리는 정북에서 30°(헤딩 30°), 다음 웨이포인트는 50° 방향.

| 단계 | 노드 | 하는 일 | 이 예의 값 |
|---|---|---|---|
| ① | iahrs_driver | IMU 원시값을 100 Hz로 낸다 | /imu/yaw_raw |
| ② | yaw_mux | 장착 보정을 더해 50 Hz로 낸다 | /imu/yaw = 30 |
| ③ | north_goal_angle | GPS로 다음 WP 방위를 0.5초마다 계산. mode 5라 20000도 같이 낸다 | /north_goal_angle_tp = 50, /candidate_angle = 20000 |
| ④ | ship_goal_angle | 목표 − 헤딩 = 오차, 20 Hz | /yaw_error = 20 (오른쪽으로 20°) |
| ⑤ | ship_direction | 20000이니 갭 선택. 앞이 비어 있어 목표 방향 그대로. 격자 각도로 바꾸면 80 − 20 = 60 | /desired_angle = 60 |
| ⑥ | motor_control | 60은 정면 80보다 20 오른쪽 → 차이 = 20/81×100 ≈ 24 | 왼쪽 1336, 오른쪽 1384 (ROS 기준, 작을수록 셈) |
| ⑦ | ssf_bridge | 3000 − 값으로 뒤집어 USB 전송 | `L1664,R1616` |
| ⑧ | 아두이노 | AUTO이고 명령이 0.5초 안에 왔으니 그대로 ESC로 | 왼쪽이 더 세게 → 배가 오른쪽으로 돈다 |

**앞에 장애물이 0.6 m에 있으면:** motor_control이 감속비 = 0.7 + 0.3 × 0.6/1.2 = 0.85를 곱해 1500 쪽으로 당긴다. 예: 1336 → 1500 + (1336 − 1500) × 0.85 ≈ 1361.

## 5. 노드 하나하나

각 노드를 "하는 일 / 받는 것 / 내는 것 / 동작 순서 / 문제가 생기면" 순서로 적었다.

### 5.1 yaw_mux — 뱃머리 방향 정리 담당 (`src/ssf_heading`)
- **하는 일:** IMU 원시 방향에 배마다 다른 보정값을 더해, 전체 시스템이 쓰는 헤딩 `/imu/yaw`를 **혼자** 낸다.
- **받는 것:** `/imu/yaw_raw`(IMU), GPS 속도, `/motor_reverse`(후진 중인지).
- **내는 것:** `/imu/yaw` 50 Hz, `/heading_status`(상태 글, 바뀔 때·1초마다).
- **동작:** 보정식 = 0~360으로 감기(부호 × 원시값 + 장착 오프셋). 기본 방식은 `imu_relative`.
- **왜 혼자 내나:** 한 단톡방에 두 명이 같은 이름으로 올리면 보정 전·후 값이 번갈아 섞여도 ROS는 오류를 안 낸다. 그래서 드라이버는 원시값 방에만 올리게 했다.
- **문제가 생기면:** 원시값이 0.5초 넘게 안 오면 `/imu/yaw`를 **안 낸다**(2초마다 경고). → 5.3·5.9에서 정지로 이어진다.
- ⚠️ **현재 A·B 장착값은 둘 다 0(측정 전).** 수조 정북 시험 뒤 `ssf_heading_A/B.yaml`에 넣어야 진짜 정북 기준이 된다.

### 5.2 north_goal_angle — 길잡이·임무 진행 담당 (`src/north_goal_angle`)
가장 하는 일이 많다. **0.5초마다 한 번** 아래를 순서대로 한다.

**① GPS 거르기 (받을 때마다)**
1. 쓸 수 없는 위치 버리기: 상태 < 0, 숫자 아님, (0,0), 위경도 범위 밖. 이러면 "위치 없음" 상태가 된다.
2. 한 프레임만 버리기: 오차 추정이 2.0 넘음, 직전 위치에서 초속 15 m 넘게 순간이동(전파 반사).
3. 부드럽게: 오차가 작으면 새 값을 조금씩(15%), 크면 많이(80%) 반영.
4. 신선도: 받아들인 위치가 **2.5초** 넘게 없으면 "묵음". 방위·거리·지오펜스·도착 판정을 멈춘다(5초마다 ERROR). **임무 번호와 시간 초과 진행은 계속한다.**

**② 웨이포인트 목록 읽기 (켤 때 한 번)**
- 파일 `config/waypoints.yaml`. 한 줄 = {이름, 위도, 경도, 임무 번호, dwell}.
- 위도 33~39, 경도 124~132, 임무 번호 0·1·2·3·5·7·8, dwell ≥ 0이 아니면 **몇 번째 줄이 왜 틀렸는지 말하고 노드가 안 뜬다.**
- 지금 파일 내용(좌표는 작년 대회장 기준 자리 표시):

| 순번 | 이름 | 임무 | dwell |
|---|---|---|---|
| 0 | WP0 게이트 시작 | 0 | 3.0 s |
| 1 | WP1 게이트 끝 | 1 | 3.0 s |
| 2 | WP2 위치유지 | 2 | 0.5 s |
| 3~5 | WP3~5 탐색 부표 | 3 | 0.5 s |
| 6~7 | WP6~7 회피 | 5 | 1.0 s |
| 8~9 | 도킹 접근 10 m · 6 m | 5 | 1.0 s |
| 10 | WP8 도킹 칸 입구 | 7 | 1.0 s |
| 11 | WP9 도킹 이탈 | 7 | 1.0 s |
| 12 | WP10 토너먼트 | 8 | 3.0 s |

- ⚠️ 8~11번 도킹 네 줄은 **"현장 교체" 자리 표시**다. 도킹 구역 안 웨이포인트 규정이 확인될 때까지 **보류**(보고서·발표에는 이 내용을 넣지 않았다).

**③ 길 따라가기 (LOS·ILOS)**
- 목적지를 곧장 보고 가면 물살에 밀려 옆으로 비스듬히 들어간다. 그래서 **이전 웨이포인트 → 다음 웨이포인트를 잇는 선**을 따라간다.
- 선에서 옆으로 벗어난 거리(XTE)를 재고, 앞쪽 2~6 m(빠를수록 멀리) 지점을 보며 선으로 돌아오는 방향을 정한다.
- 물살처럼 계속 미는 힘은 벗어난 거리를 쌓아(적분) 조금씩 더 꺾어 상쇄한다. 쌓는 양은 ±50으로 묶고, 웨이포인트를 넘길 때 0으로 비운다.
- **지나쳤을 때:** 선 방향으로 이미 목적지를 넘었는데 도착 반경 밖이면, 선 대신 목적지를 직접 보고 되돌아온다.

**④ 도착 판정**
- 도착 반경: 위치유지·탐색(2·3) **3.5 m**, 도킹(7) 2.0 m, 나머지는 속도에 따라 2.5 / 3.5 / 4.5 m.
- 반경 안에 **dwell 초 동안 계속** 있어야 도착이다.
- 2·3번 임무는 특별 규칙: 임무 노드(ship_back)가 부표를 잡고 일하는 동안(20000이 아닌 값을 내는 동안)에는 dwell을 세지 않는다. ship_back이 끝나서 20000을 내거나 1초 넘게 조용하면 그때부터 0.5초를 센다.

**⑤ 시간 초과**
- 웨이포인트 하나에 들어간 뒤 아래 시간이 지나면 **위치와 상관없이** 다음으로 넘어간다. GPS가 죽어도 경기가 진행되는 유일한 장치다.

| 임무 | 0 | 1 | 2 | 3 | 5 | 7 | 8 |
|---|---|---|---|---|---|---|---|
| 시간 초과 | 120 s | 120 s | 120 s | 90 s | 120 s | 150 s | 없음(마지막) |

**⑥ 내는 것**
- `/north_goal_angle_tp`(다음 WP 방위), `/goal_distance`(거리) — 위치가 신선할 때만.
- `/wp_mode` — 위치가 없어도 **항상**. (멈추면 검출기 3종이 다 꺼지기 때문)
- `/candidate_angle = 20000` — 임무 5·8일 때만(그 임무엔 담당 노드가 없으니 대신 낸다).
- `/geofence_state` — 경계선. ⚠️ **대회장 경계 좌표가 없어 지금은 꺼져 있다(빈 값).**
- `/wp_remaining_time` — 남은 시간.

**⑦ 마지막 웨이포인트를 지나면**
- `/wp_mode`·방위·거리를 멈춘다. 마지막이 임무 8이라 20000은 계속 낸다. 방위가 끊기니 5.3 → 5.9로 이어져 배는 정지 쪽으로 간다.

### 5.3 ship_goal_angle — 방향 오차 계산 담당 (`src/ship_goal_angle`)
- **하는 일:** "가야 할 방위 − 지금 뱃머리 방위" = `/yaw_error`. 20 Hz.
- **문제가 생기면:** 헤딩이 0.5초, 목표 방위가 2.0초 넘게 안 오면 **안 낸다.** 이 침묵을 ship_direction이 잡아 감속·정지한다(5.9).

### 5.4 카메라 검출기 3종 — 눈 담당 (`src/color_shape_detector`)
gate·turn·dock 세 노드가 **같은 순서**로 영상을 처리한다. 카메라는 OAK-1 PoE, 640×360 영상.

1. **문지기:** `/wp_mode`가 내 담당 번호가 아니거나 2초 넘게 안 오면 영상을 아예 처리하지 않는다(아무것도 안 냄).
2. **색 거르기:** 영상을 HSV(색상·채도·밝기)로 바꾸고 색 범위 안 픽셀만 흰색으로 남긴다. 작은 점 잡음은 중앙값 필터로 지운다.
3. **덩어리 찾기:** 흰 덩어리의 윤곽선을 찾고, 너무 작은 것(40픽셀, 도킹은 80픽셀 미만)은 버린다.
4. **모양·높이 검사:** 화면 높이의 일정 띠(대략 위 10~15% ~ 55%) 안에 있는 것만 남긴다. 부표 밑 물 반사나 하늘을 거르기 위해서다.
5. **가장 큰 것 하나**를 고른다.
6. **확인:** 게이트·위치유지는 1프레임, 도킹은 **3프레임 연속** 같은 결과여야 믿는다.
7. **방향으로 바꾸기:** 화면 가로 위치 → 각도. 화면 가운데가 0°, 왼쪽이 +. 화각 63.9°(직접 잰 값)로 계산한다.
8. **잠깐 안 보이면:** 2초까지는 마지막 각도를 계속 내고, 그 뒤에는 10000(안 보임). **임무 번호가 바뀌면 그 즉시 마지막 각도와 확인 창을 버린다**(11-06 수정). 그전에는 위치유지(흰)에서 탐색(빨강)으로 넘어가도 2초 동안 흰 부표 각도가 계속 나가서 ship_back이 흰 부표를 탐색 부표로 잡았다(발견 7).

| 검출기 | 담당 임무 | 찾는 것 | 내는 토픽 |
|---|---|---|---|
| gate | 0, 1 | 빨강·초록 부표 | `/red_angle`, `/green_angle` |
| turn | 2, 3 | 2번=흰색, 3번=`turn_color_mode3`(기본 빨강) | `/image_angle`, `/image_color` |
| dock | 7 | `target_color`·`target_shape`(기본 빨강 사각) | `/image_angle` |

- **탐색 색이 당일 바뀌면** `vision.yaml`의 `turn_color_mode3` 한 줄만 바꾼다. red·green·white 외의 글자를 넣으면 켤 때 ERROR가 나고 **그 임무에서는 아무것도 안 낸다**(엉뚱한 색으로 대신 찾지 않음).
- **도킹 모양 판정:** 꼭짓점 3개 = 삼각, 4~6개 = 사각(동그란 정도가 0.82 이상이면 원), 7개 이상 = 원.
- 도킹 목표 색·모양이 틀린 글자면 도킹 임무에서만 10000을 계속 내고 5초마다 ERROR.

### 5.5 ship_gate — 게이트 통과 담당 (임무 0·1)
0.1초마다 빨강·초록 각도를 보고 셋 중 하나를 낸다.
1. **둘 다 안 보임** → 20000 (GPS로 가라).
2. **둘 다 보이고 벌어진 각도가 5~80°** → 두 부표의 **가운데** 방향.
3. **하나만 보이거나 쌍이 이상함** → 보이는 부표에서 40° 비켜 간 방향. 빨강이 왼쪽(좌현) 규칙이라 빨강이면 그보다 오른쪽, 초록이면 그보다 왼쪽.

- **통과 세기(`/gates_passed`):** 두 부표가 앞쪽 ±28° 안에 들어오면 "준비", 그 뒤 부표가 ±28° 밖으로 벗어나면(옆으로 지나감) 1개로 센다. 같은 게이트를 두 번 세지 않도록 LiDAR 거리로 확인한다.

### 5.6 ship_back — 위치유지·탐색 담당 (임무 2·3)
0.1초마다 아래 상태 중 하나에 있다.

| 상태 | 하는 일 | 내는 값 | 다음 |
|---|---|---|---|
| INIT | 시작 1초 대기 | 20000 | → SEARCH |
| SEARCH | 카메라에 부표가 보일 때까지 GPS로 접근 | 20000 | 보이면 → HOLD. 20초 넘으면 경고 1번(계속 찾음) |
| HOLD | 부표 2.5 m 앞 유지 | 아래 표 | 성공·포기 → DONE |
| DONE | 끝 | 20000 (계속) | north가 다음 WP로 |

**HOLD에서 거리별 행동** (방향은 카메라, 거리는 그 방향의 LiDAR 최소거리):
- 2.9 m보다 멀다 → 부표 쪽으로 전진.
- 2.1 m보다 가깝다 → 180(후진).
- 그 사이 → 멈춤(50000).
- 거리를 모르겠다 → 멈춤. 10초 넘게 모르면 포기(DONE).

**끝나는 조건:**
- 성공: 부표에서 **5 m 이내에 5초 연속** (규정).
- 부표를 2초 넘게 놓침 → **5초 멈춰서** 다시 찾는다(SEARCH). 다시 보이면 이어서 HOLD.
- ship_back은 각도만 보고 색은 확인하지 않는다. 모드가 바뀐 직후 이전 부표 각도가 섞여 오지 않게 하는 건 검출기 쪽(모드 변경 시 유예 폐기, 11-06)이 맡는다. INIT 1초는 그 방어가 아니다.
- HOLD와 재탐색 멈춤을 합쳐 60초가 넘으면 포기(DONE).
- 임무 번호가 2→3처럼 바뀌면 처음(INIT)부터 다시.

### 5.7 ship_turn — 부표 돌기 (옵션, 지금은 꺼짐)
- 2025 규정의 "부표를 한 바퀴 도는 탐색"용. 실행 때 `search_behavior:=orbit`을 줘야만 켜진다. 기본값(`hold`)에서는 아무것도 안 낸다.

### 5.8 ship_dock — 도킹 담당 (임무 7)
⚠️ **현재 코드는 보고서·발표 설명과 다르다.** 보고서·발표는 예전(10차) 설명으로 되돌렸고, 코드는 도킹 웨이포인트 규정이 확인될 때까지 보류 중이다. 아래는 **지금 코드가 실제로 하는 일**이다.

| 상태 | 하는 일 | 내는 값 | 다음 |
|---|---|---|---|
| TRANSIT | GPS로 도킹 칸 쪽 접근 | 20000 | 목적지까지 12 m 미만(신선한 값, 임무 7 진입 1초 뒤부터) → INIT |
| INIT | 3초 멈춰 흔들림 가라앉히기 | 50000 | → SEARCH |
| SEARCH | 제자리 오른쪽으로 돌며 표식 찾기 | 5000 | 보이면 → ALIGN. **60초** 못 찾으면 → DONE |
| ALIGN | 표식이 정면 ±8° 안에 올 때까지 제자리 회전 | 5000/6000 | → APPROACH. 놓치면·15초 → SEARCH |
| APPROACH | 표식 방향으로 전진. 거리는 LiDAR 정면 ±15° 최소거리 | 각도 | 1.0 m 이하 → CONTACT. 30초 → BACKOFF |
| CONTACT | 3초 멈춤(접안) | 50000 | → BACKOFF |
| BACKOFF | 후진 | 180 | 앞 거리 2.5 m 이상 → DONE. 8초 → DONE |
| DONE | 끝 | 아래 표 | — |

- APPROACH 중 다시 맞추기: 1.5 m보다 멀 때만, 표식이 25° 넘게 벗어나거나 처음 3 m 안에 들어올 때 8° 넘게 벗어나 있으면 ALIGN으로 돌아간다.
- 거리를 모를 때(11-06 수정): APPROACH는 멈추되 30초 타임아웃은 계속 세서 BACKOFF로 빠진다. CONTACT는 거리와 무관하게 3초 뒤 BACKOFF. BACKOFF는 스캔이 오는데 앞에 반환이 없으면(벽에 바짝 붙음) 그대로 후진하고, LiDAR 자체가 끊겼으면 멈춘다. 그전 코드는 셋 다 거리를 모르면 멈춘 채 타이머도 안 돌아서, 벽에 닿아 LiDAR 최소 측정거리 아래로 들어가면 150초 갇혔다(시뮬3자유도_발견 발견 1).

| DONE 이유 | 내는 값 |
|---|---|
| 정상 후진 이탈 | 20000 → 다음 WP로 |
| 표식 못 찾음(60초) | 멈춤 → 이탈 웨이포인트(WP9)로 넘어가면 20000 |
| 후진 시간 초과 등 | 임무 7이 끝날 때까지 멈춤 |

보고서(예전 설명)와 다른 점: TRANSIT 상태가 있음, 탐색 25초가 아니라 60초, DONE이 항상 정지가 아님.

### 5.9 ship_direction — 최종 방향 결정 + 회피 + 안전 (`src/ship_direction`) ★ 가장 중요
0.1초마다 두 가지 일을 **따로** 한다. 하나는 방향 계산(control), 하나는 센서 감시(watchdog). 따로 도는 이유는 LiDAR가 끊겨도 감시는 계속 돌아야 하기 때문이다.

**① 받은 후보각(`/candidate_angle`)을 우선순위대로 처리**
1. 50000이면 → 멈춤.
2. (지오펜스가 켜져 있을 때) 경계가 2 m 안이고 가려는 방향 ±60° 안이면 → 멈춤.
3. 5000·6000이면 → 그대로 통과(제자리 회전).
4. 180이면 → 후진 신호 260으로 바꿈. 단 0.5초 넘게 새로 안 오면 멈춤(뒤를 못 보니까).
5. 보통 각도면 → 격자 각도(정면 80)로 바꾸고, 0~160 밖이면 멈춤.
6. **20000이면 → 갭 선택(아래 ②).** 단, 켜진 뒤 `/yaw_error`를 **한 번도 못 받았으면** 갈 방향을 모르니 멈춤(50000) + 5초마다 ERROR. (11-05 추가 — 그전에는 0을 '정면이 목표'로 읽어 뱃머리 방향으로 계속 갔다)
7. **후보각이 1.0초 넘게 안 오면** → 20000으로 간주(GPS + 회피로 계속 감). 임무 번호가 바뀌는 순간도 20000부터.

**② 갭 선택 — 장애물 사이 빈틈 고르기**
1. LiDAR 거리에서 정면 ±80°만 쓴다(격자 0~160).
2. 3.0 m(게이트 구간 0·1은 2.0 m)보다 가까운 칸 = 장애물, 나머지 = 빈칸.
3. 1~3칸짜리 외톨이 장애물(물보라·반사)은 지운다.
4. **장애물 부풀리기:** 배가 중심점이라고 생각하고, 장애물을 배 반폭(0.29 m) + 여유(0.25 m) 만큼 양옆으로 넓힌다. 가까울수록 더 넓은 각도로 부푼다.
5. 남은 빈칸 덩어리 중 **실제 폭이 0.83 m 이상**인 것만 통과 가능한 틈으로 본다.
6. 각 틈 안에서 GPS 목표 방향에 가장 가까운 각을 고른다. 여러 틈이면 목표에 가장 가까운 틈 — **단, 두 가지 벌점을 더한 뒤 고른다**(11-06): ① 직전에 피하던 쪽과 반대편 틈에는 40°를 더해 **피하던 편을 유지**하고(한 틈만 보이면 적용 안 함), ② 그 틈으로 가려면 정면과 틈 사이에 장애물이 끼는(= 장애물 앞을 가로지르는) 틈에는 90°를 더해 **가로지르지 않게** 한다. 배가 돌면서 목표가 정면으로 옮겨 와도 편을 바꾸지 않는다(시뮬에서 회피 접촉 절반 이하). 끄려면 ship_direction.yaml 의 `side_hysteresis_deg`·`cross_penalty_deg` 를 0.0 으로.
7. **틈이 하나도 없으면** → 0.5초 후진 → 3초 멈춰서 다시 찾기 → 반복. (선택 기능, 기본 꺼짐 11-06: `side_escape_deg` 를 60.0 으로 켜면 가장 가까운 장애물이 정면에서 15~60° 옆이고 정면·비킬 쪽이 비어 있을 때 후진 대신 반대쪽으로 60° 비킨다. 게이트 구간은 제외. 실배 확인 뒤 켠다 — `docs/절차/현장_조정표_20261106.md`)
8. 마지막으로 **급격한 꺾임 방지:** 한 번(0.1초)에 15°까지만 바꾼다(특수 코드는 즉시).

**③ 페일세이프 — 센서 감시**
- `/scan`(LiDAR)과 `/yaw_error`(헤딩·GPS 오차) 두 개를 본다. 각각 **한 번 받은 뒤부터** 감시한다.
- 둘 중 더 오래 끊긴 쪽 기준으로:

| 레벨 | 조건 (3번 연속 확인) | 배 동작 |
|---|---|---|
| 0 정상 | — | 그대로 |
| 1 경고 | 0.7초 넘게 안 옴 | 각도는 유지, 속도 0.7배 |
| 2 정지 | 3.0초 넘게 안 옴, 또는 LiDAR 값이 이상함(즉시) | 멈춤 |

- 센서가 돌아오면 **바로** 레벨 0으로 복귀.
- 레벨 1에서 직진을 강제하지 않는 이유: 피하던 부표 쪽으로 직진해 부딪히기 때문.
- LiDAR를 한 번도 못 받았으면 아무것도 안 낸다 → motor_control이 0.5초 뒤 중립.
- 한 번도 안 온 `/yaw_error`는 감시 대상이 아니다(켜자마자 거짓 정지를 막으려고). 대신 ①-6 규칙으로 20000일 때만 멈춘다. 이때 `/failsafe_level`은 0이라 계기판엔 정상으로 보이고, 원인은 ERROR 로그로 본다.

**④ 내는 것:** `/desired_angle`(최종 방향), `/obstacle_distance_array`(앞쪽 가장 가까운 거리 — 감속용, 잡음 거른 값), `/failsafe_level`.

### 5.10 motor_control — 방향을 추진 세기로 (`src/motor_control`)
0.05초(20 Hz)마다 마지막으로 받은 `/desired_angle`을 좌·우 세기로 바꾼다. (ROS 기준: 1500보다 작을수록 전진)

| 받은 값 | 뜻 | 왼쪽 / 오른쪽 |
|---|---|---|
| 50000 이상 | 멈춤 | 1500 / 1500 |
| 20000~50000 | 그냥 전진 | 1360 / 1360 |
| 5000대 | 제자리 우회전 | 1400 / 1600 |
| 6000대 | 제자리 좌회전 | 1600 / 1400 |
| −1~161 | 보통 조향 | 정면 80 기준 차이 × 100/81 만큼 좌우 차이. 예: 161(최대 왼쪽) → 1460 / 1260 |
| 161~5000 (260 등) | 후진 | 1590 / 1590 |

- **감속:** 앞 장애물이 1.2 m보다 가까우면 0.7~1.0배, 페일세이프 레벨 1이면 0.7배. 둘 중 작은 값을 전진 세기에 곱한다. 제자리 회전·정지에는 안 건다.
- **목표 근접 감속(11-06 추가):** 다음 웨이포인트까지 거리(`/goal_distance`)가 8 m 안으로 들어오면 전진 중심 세기를 줄이기 시작해 3 m에서 절반(1360 → 1430)이 된다. 좌우 차이는 그대로 둬서 선회는 오히려 더 잘 된다. 거리를 2초 넘게 못 받으면 감속 없음. 제자리 회전·후진·정지에는 안 건다. 3자유도 시뮬에서 마지막 WP 주위를 도는 문제(발견 5)와 부표 앞에서 미끄러지는 문제(발견 2)를 줄이려고 넣었고, 8 m·3 m·0.5배는 가정 계수 기준이라 수조 실측 뒤 다시 맞춘다.
- **워치독:** 첫 명령을 받기 전, 또는 마지막 명령이 0.5초보다 오래되면 1500/1500.
- **`/motor_reverse`:** 좌우 평균이 1500보다 크면(뒤로 가는 중) 참. 헤딩 보정(5.1)이 후진 중 자료를 버리는 데 쓴다.
- 보내는 형식: `Motor_run` 하나에 오른쪽 × 10000 + 왼쪽을 붙여 보낸다(예: 13841336 = 오른쪽 1384, 왼쪽 1336).

### 5.11 ssf_bridge — 노트북 ↔ 아두이노 통역 (`src/ssf_bridge`)
- `Motor_run`을 받아 좌·우로 나누고, **3000 − 값**으로 뒤집어 `L1664,R1616` 같은 글자를 USB로 보낸다.
- 아두이노가 0.1초마다 보내는 상태줄 `S,모드,워치독,배ID,비상정지,...`를 읽어 `/boat_mode`(0 WAIT·1 MANUAL·2 AUTO), `/boat_estop`, `/boat_cmd_watchdog`, `/boat_id`로 올린다.
- **USB가 끊기면:** 오류를 남기고 1초 뒤 다시 연결을 시도한다. 끊긴 동안 명령은 버려지고(아두이노는 0.5초 뒤 스스로 중립), 상태 토픽은 그냥 멈춘다.
- 종료(Ctrl+C) 때 정지 명령을 보내고 포트를 닫는다.

### 5.12 아두이노 펌웨어 — 척수 (`arduino/ssf_boat/ssf_boat.ino`)
- **0.05초마다** 아래를 판단, 0.1초마다 상태줄을 노트북에 보낸다.

| 모드 | 조건 | 추진기로 가는 것 |
|---|---|---|
| WAIT | 켠 뒤 조종기 모드 신호를 아직 한 번도 못 받음 | 1500 (정지) |
| MANUAL | 모드 스위치 신호 1500 이하 | 조종기 스틱. 오른쪽 스틱 위아래 = 전후, 왼쪽 스틱 좌우 = 회전. 0.5초 넘게 스틱 신호가 없으면 정지 |
| AUTO | 모드 스위치 신호 1500 초과 | 노트북 명령. **0.5초 넘게 안 오면 정지**(워치독) |

- 출력은 1100~1900으로 자른다. 왼쪽 신호는 핀 12, 오른쪽은 핀 11. B 배는 한 신호가 같은 쪽 ESC 2개에 같이 들어간다.
- **비상정지 감지(핀 38):** 접촉기 보조접점을 읽어 LED를 빨강으로 바꾸고 상태줄로 노트북에 알린다. 실제로 전기를 끊는 것은 접촉기(하드웨어)이고, **아두이노는 차단 경로에 없다.**
- 모드 신호가 도중에 끊기면 **마지막 모드를 유지**한다(팀 결정: 조종기 신호 두절로 모드를 바꾸지 않음). 조종기 수신기 자체는 신호 두절 때 스틱을 중립으로 내도록 설정했다.

### 5.13 기록·진단 도구 (`src/ssf_tools`) — blackbox만 대회 실행에 포함, 나머지는 따로 켠다
- **healthcheck:** 2초마다 LiDAR·헤딩·GPS·카메라가 오는지, 임무 번호에 맞는 노드가 있는지 확인. `/health_ok`를 내지만 **제어에는 연결하지 않았다**(진단이 틀려서 배가 서는 일을 막으려고).
- **blackbox:** 주요 값을 0.1초마다 `~/ssf_logs/blackbox_날짜.csv`에 기록. 경기 뒤 분석용. **대회 실행에 포함**(`record` 기본 켬). 🚨 `ssf_tools.launch.py`를 또 띄우면 기록기가 2개 떠 같은 파일을 덮어쓰니 같이 쓰지 않는다. 시간당 약 14 MB(추정).
- **mission_monitor:** 화면에 현재 모드·임무·거리·RTK·페일세이프를 0.5초마다 보여 주는 계기판.

## 6. 코스 한 바퀴 이야기로 따라가기

1. **출발 전:** MANUAL로 출발점까지 몬다. north는 WP0 방향을 계산만 하고 기다린다.
2. **AUTO 전환:** WP0(임무 0, 게이트 시작). 카메라 gate 검출기가 켜진다. ship_gate가 빨강·초록 가운데로 조향하고, 안 보이면 20000이라 GPS로 간다. 게이트 끝(WP1)까지 같은 방식. 게이트 구간은 탐지거리를 2.0 m로 줄여 좁은 게이트에서 괜히 피하지 않게 한다.
3. **WP2 위치유지(임무 2):** turn 검출기가 흰 부표를 찾는다. 안 보이면 ship_back이 20000이라 GPS로 다가간다. 보이면 2.5 m 앞에서 전진·후진·정지를 반복해 5 m 안 5초를 채운다. 끝나면 20000 → north가 0.5초 뒤 다음 WP로.
4. **WP3~5 탐색(임무 3):** turn 검출기가 공지 색 부표를 찾고 ship_back이 같은 방식으로 그 앞에서 유지한다.
5. **WP6~7 회피(임무 5):** 담당 노드가 없어 north가 20000을 낸다. ship_direction이 LiDAR 틈을 골라 장애물 사이를 지난다.
6. **도킹(임무 7):** 5.8 표대로. (규정 확인 전까지 웨이포인트 배치는 보류)
7. **WP10 토너먼트(임무 8):** 시간 초과 없이 20000으로 자율 회피.
8. **끝:** 마지막 WP를 지나면 방위가 끊겨 페일세이프로 멈춘다. 조종기로 MANUAL 전환해 회수.

어느 임무든 **시간 초과**가 지나면 위치와 상관없이 다음으로 넘어간다.

## 7. 고장 났을 때 — 누가 알아채고 배는 어떻게 되나

| 상황 | 알아채는 곳 | 배 동작 |
|---|---|---|
| LiDAR 선이 빠짐 | ship_direction 감시 | 0.7초 감속 → 3초 정지. 다시 꽂으면 바로 정상 |
| IMU 끊김 | yaw_mux 침묵 → ship_goal_angle 침묵 → ship_direction | 감속 → 정지 |
| RTK·GPS 끊김 | north_goal_angle (2.5초) | 방위가 끊겨 감속 → 정지. 임무 번호와 시간 초과는 계속 |
| 카메라 끊김 | 검출기가 2초 뒤 10000 | 임무 노드가 "안 보임"으로 처리(게이트는 20000, 위치유지는 재탐색·포기) |
| 부팅부터 GPS fix·IMU 없음 | ship_direction (`/yaw_error` 한 번도 없음) | 20000 구간은 정지 + 5초마다 ERROR. 게이트가 보일 때·도킹·위치유지처럼 임무 노드가 각도를 주는 구간은 그대로 |
| 임무 노드가 죽음 | ship_direction (1초) | 20000으로 대체 → GPS + 회피로 계속 |
| 노트북 프로그램이 멈춤 | motor_control·아두이노 워치독 (0.5초) | 정지 |
| USB 선 빠짐 | 아두이노 워치독 (0.5초) | 정지. bridge는 1초마다 재연결 시도 |
| 조종기 꺼짐 | 수신기 페일세이프 | 스틱 중립. 모드는 마지막 값 유지 |
| 위험 상황 | 사람 | 비상정지 버튼 또는 무선 리모컨 → 접촉기가 추진 전원 차단(소프트웨어와 무관) |

## 8. 알아 두면 좋은 주의점

- **헤딩 보정값이 아직 0이다.** 수조 정북 시험 후 배마다 `ssf_heading_A/B.yaml`에 기입.
- **지오펜스는 꺼져 있다.** 대회장 경계 좌표가 생기면 `north_goal_angle.yaml`의 `geofence_polygon`에 넣는다.
- **웨이포인트 좌표는 현장에서 새로 찍는다.** 녹화 도구는 `~/ssf_logs/waypoints_recorded.yaml`에 저장하고 기존 파일은 안 건드린다. 확인 후 `config/waypoints.yaml`로 옮긴다.
- **위치유지·탐색 웨이포인트는 부표 바로 옆에서 찍는다.** 도착 반경 3.5 m가 그 전제다. 카메라가 부표를 3.5 m보다 멀리서 처음 잡아야 위치유지가 된다(실해역 확인 항목).
- **탐색 색 공지 후** `vision.yaml`의 `turn_color_mode3` 변경. **도킹 표식 공지 후** `target_color`·`target_shape` 변경.
- **MANUAL→AUTO 재진입은 이어서 진행**(3.4).
- **11-05부터 대회 실행이 노드 yaml을 실제로 읽는다**(ship_direction·motor_control·ship_gate·ship_dock·ship_back·ship_turn). 현장에서 yaml을 고치면 바로 대회값이 된다. 그래서 ① 고친 뒤 꼭 커밋 ② **숫자 모양을 그대로**(3.0을 3으로, 1360을 1360.0으로 바꾸면 그 노드가 켜질 때 죽는다) ③ 없는 이름을 쓰면 조용히 무시된다. ship_back·ship_turn은 실행 인자(`search_behavior`)가 yaml보다 우선한다.
- 펌웨어 주석이 코드와 반대로 적혀 있던 곳("< 1500 = AUTO", 모드 핀 18)은 11-05에 정정했다. 실제는 > 1500 = AUTO, 핀 19. 주석만 바뀌어 다시 올릴 필요는 없다.

## 9. 용어 풀이

| 용어 | 쉬운 뜻 |
|---|---|
| ROS2 | 로봇 프로그램들을 단톡방 방식으로 엮어 주는 틀 |
| 노드 / 토픽 | 일하는 프로그램 하나 / 그들이 글을 주고받는 단톡방 |
| Hz | 1초에 몇 번. 10 Hz = 0.1초마다 |
| yaml | 설정값을 적어 두는 텍스트 파일 |
| PWM (µs) | 추진 세기 신호. 1500 정지, 그보다 멀수록 세다 |
| ESC | 추진기 모터에 전기를 세기 맞춰 넣어 주는 장치 |
| 헤딩 | 뱃머리가 가리키는 방위 |
| RTK / NTRIP | 기준국 보정으로 cm급 위치를 얻는 방법 / 그 보정을 인터넷으로 받는 방식 |
| 웨이포인트(WP) | 미리 찍어 둔 목적지 좌표 |
| dwell | 목적지 반경 안에 머물러야 도착으로 치는 시간 |
| LOS / ILOS | 경로선 위 앞쪽 점을 보며 따라가는 방법 / 물살 보정(적분)을 더한 것 |
| XTE | 경로선에서 옆으로 벗어난 거리 |
| HSV | 색상·채도·밝기로 색을 나누는 방식. 조명이 바뀌어도 색 구분이 쉽다 |
| 갭 선택 | LiDAR로 장애물 사이 빈틈을 찾아 그쪽으로 가는 방법 |
| 페일세이프 | 고장 나도 안전한 쪽(감속·정지)으로 가게 하는 장치 |
| 워치독 | "일정 시간 소식이 없으면 멈춘다"는 감시 타이머 |
| STOP_HOLD | 멈춤 명령(50000) |
| 지오펜스 | 경기장 경계를 가상의 벽으로 만들어 넘지 않게 하는 기능 |
