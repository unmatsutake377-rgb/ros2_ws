ship_direction 작년 → 올해 변경 대조표

팀원이 작년 코드를 한 줄씩 공부한 노트를 기준으로, 올해 무엇이 왜 바뀌었는지 정리했습니다. 공부가 헛되지 않게, 이해를 최신으로 맞춥니다.

먼저: 작년 코드 공부한 것 정말 잘했습니다. 그 이해가 인수인계에 큰 도움이 됩니다. 다만 아래 5개 값은 올해 이미 바뀌었으니, 노트를 이 표로 갱신하면 새 코드를 볼 때 안 헷갈립니다.

1. 바뀐 파라미터 5개 (핵심)

파라미터작년(노트)올해왜 바꿨나 (시뮬 근거)
rear_obstacle_ignore_margin 1.0
(뒤쪽 장애물 무시)		 삭제 🚨 이게 진짜 부표를 지우는 버그였습니다. 물보라 반사 0.3m 하나가 최근접점을 끌어내리면, 실제 1.6m 부표가 17셀 → 0셀로 통째로 사라졌습니다. "튜닝값"이 아니라 결함이라 제거.
min_obstacle_cells 3 1 3이면 작은 부표(점 1~2개)가 무시됩니다. 1로 낮추고, 대신 dilate(팽창)로 배 폭만큼 안전여유를 줍니다.
base_detection_distance 1.8m 3.0m 1.8m는 시뮬에서 8/8 충돌, 3.0m는 5/8 통과. 멀리 봐야 미리 피합니다. (게이트 구간만 2.0m로 짧게 — 아래 참고)
mode2_detection_distance 1.8m
("작년에 죽은 코드")		 제거 노트에도 "죽은 코드"라 적혀 있습니다. 올바른 지적. 실제로 제거했습니다.
candidate 5000 / 6000 특수값 규약 확정 5000 = 우선회, 6000 = 좌선회로 못 박았습니다. (작년엔 ship_dock이 "오른쪽 회전"으로 5000을 보내는데 motor_control은 왼쪽으로 처리 = 반대였음)

2. 🚨 "탐지거리 늘리면 벽까지 인식" — 팀원 고민에 대한 답

노트의 "고민거리": "탐지거리 3~5m로 늘리면 멀리 있는 부표나 경기장 벽면까지 전부 장애물로 인식"
→ 타당한 걱정이었습니다. 그래서 시뮬로 재봤고, 답이 나왔습니다:
걱정실제
"멀리 볼수록 데이터가 폭발한다"❌ 아닙니다. 탐지거리는 임계값일 뿐, 계산량은 거리와 무관(스캔당 0.15ms, CPU 0.1%). LiDAR는 어차피 25m까지 다 봅니다.
"벽을 장애물로 인식한다"경기장 벽은 geofence(경계 방어)가 따로 처리합니다. 회피 로직이 벽을 볼 필요 없음.
"부표를 미리 다 장애물로 본다"그게 목적입니다. 미리 봐야 피합니다. 단, 게이트 구간만 2.0m로 짧게 — 좁은 문에선 양쪽 부표를 다 막으면 오히려 못 지나가서요.
결론: 팀원 걱정은 옳았고, 그 걱정을 측정으로 풀어서 "3.0m가 최적"임을 확인했습니다. 데이터 폭발도 벽 문제도 없습니다.

3. 그대로 유지된 것 (노트가 정확함)

항목상태
__init__.py는 0바이트여도 삭제 금지유지 노트 설명 정확합니다.
CANDIDATE_INVALID = 20000 (카메라 놓침 → yaw_error 폴백)유지 개념 그대로. 정확히 이해하셨습니다.
STOP_HOLD = 50000 (정지/HOLD)유지
half_width=0.45, clearance (배 반폭 + 여유)값만 clearance 0.15 → 0.25 (시뮬 스윕 최적). half_width는 배 완성 후 실측.
비상 후진 (전방 막히면 3초 후진)유지

4. 노트의 작은 오탈자 하나

self.debug_interval = 1.0을 "뒤쪽 장애물 무시 여유 거리"로 주석했는데, 복붙 실수입니다. 실제로는 "디버그 출력 간격(1초)"입니다. (바로 위 rear_obstacle_ignore_margin 설명이 잘못 복사됨) 사소하지만 나중에 헷갈릴 수 있어 짚어둡니다.

5. 왜 이렇게 바꿨나 — 한눈에

올해 작업의 원칙은 "모든 변경을 시뮬로 재서 확인"입니다.
  • rear_margin 삭제 · cells 1 · detection 3.0 → 전부 시뮬 측정으로 결정 (추측 아님)
  • 작년 종합임무 0점의 원인이 이 회피 결함들 + 도킹 사망(mode 9) + 위치유지 가짜였습니다
  • 시뮬에서 접촉 3.0회 → 0.2회로 개선 확인
팀원 노트 + 이 대조표를 같이 보면, 작년 코드와 올해 코드를 완벽히 연결해서 이해할 수 있습니다.
