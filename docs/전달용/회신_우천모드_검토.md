**새로 잘 넣은 것 (v1 지적 외 — 방향 맞음):**
- **mode 최소 유지시간** (`min_mode_time`, rain_mode_manager 197·203줄) — ✅ 모드 진동 방지

- 라이다 신뢰도 정교화(width/distance/point 가중), sensor_fusion 다방면 비교 — 설계 방향 좋음

**그러나 전부 무의미 — 죽은 파이프라인 위에 얹힘:**
- ① 때문에 `rain_mode_manager`가 모드 전환 자체를 못 함 → hold time·복귀 로직 안 탐
- ② 때문에 `lidar_object_detector` 물체 0개 → `sensor_fusion`이 `len(lidar_objects)==0`에서 즉시 return → 신뢰도·다방면 비교 실행 안 됨

**다음 우선순위 (이것부터):**
1. ① 라이다 노이즈 개수 세서 `/lidar_noise` 발행 — 없으면 나머지 전부 무의미
2. ② `current_cluster=[]`를 `else` 블록 안으로 (1줄)
3. ④ 279줄 `math.degrees(lidar_angle)` + 프레임 오프셋, 673줄과 일치

①② 고쳐야 위 새 기능들이 비로소 검증 가능합니다. base drift(우리 최신 color_shape_detector 아님)도 여전하니 통째 머지는 금물입니다.

## 1. 지금 상태 — 3노드 다 실행 불가 (실측 전 코드리뷰로 확인)

배 위에서 헤매기 전에, 지금 코드로는 우천모드가 **작동 자체를 안 합니다.** 버그 4개:

### ① `/lidar_noise` 를 발행하는 노드가 없음 → 우천모드 전체가 죽어 있음  🚨 최우선

`rain_mode_manager`와 `sensor_fusion` 둘 다 `/lidar_noise`를 **구독**하는데,
저장소 어디에도 이걸 **발행**하는 코드가 없습니다 (발행되는 건 `/camera_noise`뿐).

```python
# rain_mode_manager.check_mode()
if len(self.lidar_history) < 10:
    return          # /lidar_noise 가 안 와서 이 deque 는 영원히 10개를 못 채움
```

→ `check_mode`가 항상 여기서 return → **모드가 절대 0→1로 안 바뀝니다.** 비 감지의 핵심이 inert.
   일기장의 "라이다 노이즈 개수 저장"이 코드로 안 들어왔습니다.

### ② `lidar_object_detector` 클러스터링 붕괴 (lidar_object_detector.py:85)

```python
if abs(r - prev_range) < self.max_gap:
    current_cluster.append((i, r))          # 76: 클러스터에 점 추가
else:
    if len(current_cluster) >= self.min_points:
        clusters.append(current_cluster)
current_cluster = []                        # 85: indent 12 = if/else 밖 → 매 루프 리셋
current_cluster.append((i, r))
```

추가하자마자 다음 줄에서 리셋됩니다. **클러스터가 1점을 절대 못 넘김** → `min_points=3` 영원히 미달
→ `objects`는 항상 빈 배열. **물체를 0개 검출합니다.**
(부가로 클러스터 기준이 `abs(r - prev_range)` = 거리차뿐이라, 같은 거리의 서로 다른 부표 2개가
한 덩이로 묶입니다. 제대로 하려면 (각도,거리)→(x,y) 유클리드 거리로 묶어야 합니다.)

### ③ publish 언팩 크래시 — ②를 고치는 순간 터짐 (lidar_object_detector.py:151)

```python
objects.append((center_angle, center_distance, confidence))   # 3-튜플로 저장
...
for angle, distance in objects:                               # 2개로 언팩 → ValueError
    msg.data.append(confidence)                               # confidence 는 앞 루프 누수 변수
```

지금은 objects가 비어 있어 안 터지지만, ②를 고치면 **첫 물체에서 즉사**합니다.

### ④ `sensor_fusion` 각도 프레임 불일치 (sensor_fusion.fusion)

```python
error = abs(cam_angle - math.degrees(lidar_angle))
```

`cam_angle`은 카메라 기준(정면 0 근처), `lidar_angle`은 `scan.angle_min` 기준(우리 배치에선
80°가 정면)입니다. **오프셋 없이 그냥 뺍니다** → 같은 물체인데 각도가 안 맞아 매칭이 전부 틀립니다.
우리가 `desired = 80 + rel`로 늘 신경 쓰는 바로 그 프레임 문제입니다.

## 2. 고쳐서 쓰면 이득이 있나 — 솔직한 비용/이득

버그를 다 고쳤다고 가정하고, **우리한테 실제로 뭐가 새로 생기나**를 따졌습니다.

### ✅ 진짜 새 이득 — 딱 하나: 카메라↔라이다 교차검증

카메라가 헛 부표를 봤는데 그 각도에 라이다 클러스터가 없으면 버리는 로직. 물보라·반사 오검출을
걸러냅니다. **이건 비 올 때만이 아니라 맑은 날에도 이득입니다.** (단 ④ 프레임정렬 + ② 클러스터링이
선행돼야 작동)

### ⚠️ 이미 있어서 추가이득이 적은 것

- **라이다 노이즈 제거**: 우리 `median_min` 필터가 이미 물보라 스파이크를 버립니다. 측정치로
  가짜감속 36.8% → 8.9%, 버린 스파이크 수는 D6(`/obstacle_reject_count`)로 blackbox에 이미 기록 중.
  우천모드의 노이즈 처리는 이걸 재발명하는 셈입니다.
- **장애물 회피**: ship_direction이 이미 라이다 단독 + median으로 돕니다. 비가 와도 그대로 작동하며,
  우천모드가 여기 더 얹을 게 없습니다.

### ❌ 구조상 무용한 것

- **"비 오면 라이다 비중↑ 카메라↓"**: 발상은 좋지만, **gate 미션의 핵심은 색**입니다
  (빨강↔초록 사이 통과). 라이다 클러스터는 "뭔가 있다"만 알지 **빨강인지 초록인지 모릅니다.**
  즉 카메라가 완전히 블라인드되면 라이다-only로는 gate를 **못 합니다.** 가중치를 낮춰도 색 정보를
  대체할 수단이 없습니다. 우천모드가 카메라 대신 세울 수 있는 건 항법/회피뿐인데, 그건 이미 됩니다.

### 요약표

| 우천모드 기능 | 우리한테 새로운가 | 판정 |
|---|---|---|
| 카메라↔라이다 교차검증(오검출 제거) | 새로움 | ⭐ 값짐, **날씨 무관** |
| 라이다 노이즈 처리 | 이미 median 필터 | 중복 |
| 라이다 단독 회피 | 이미 ship_direction | 중복 |
| 비 오면 카메라↓·라이다↑ | 새롭지만 gate=색 | 구조상 무용 |

## 3. 제안 — 통째 채택은 비용>이득. 둘 중 택

3노드 우천 시스템을 지금 통째로 넣는 건 **비용(버그4개 + 재이식 + 소비자 배선 + 임계값 튜닝 +
새 침묵실패 표면)이 이득을 넘습니다.** 게다가 대회에 비가 안 오면 ROI가 0입니다. 대신:

**A. 최소·안전 (권장 1순위)** — 우천 *감지*만 살려 신호로 로깅, 제어는 안 건드림.
`/lidar_noise`·`/camera_noise`·`/rain_mode`를 blackbox에 물립니다. 배 위에서 **"비가 실제로
우리를 얼마나 망가뜨리나"를 먼저 측정**합니다. 데이터 없이 대응부터 짜는 건 추측입니다
(우리 원칙: 측정으로 결정). 임계값(20%, 10회 등)도 이 실측으로 확정합니다.

**B. 값진 한 조각만 추출** — 우천모드 전체 말고, **카메라↔라이다 교차검증 로직 1개만** 뽑아
우리 gate 최신 base에 이식합니다(프레임 정렬 포함). 이건 맑은 날에도 오검출을 줄여줍니다.

두 갈래는 배타적이지 않습니다. A로 데이터를 쌓고, 교차검증(B)을 넣어 오검출을 줄이는 조합이
가장 현실적입니다.
