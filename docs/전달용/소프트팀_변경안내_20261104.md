# 소프트팀 변경 안내 (11-04) — 전체 코스 결함 수정 C1~C6

GitHub 에 올라간 코드 기준이다. 근거·결정 기록: `docs/문제와작업/계약서_전체코스_20261104.md`.
모든 수치는 Mac 단위 테스트(792개 통과)와 2D 시뮬(실제 노드 코드, 가정 모델) 결과이고 **물 위 실측이 아니다.**

## 1. 받아서 할 일 (Ubuntu)
```bash
cd ~/ros2_ws && git pull --no-rebase
colcon build --symlink-install
colcon test && colcon test-result --verbose     # lint 포함
```
- 웨이포인트 녹화기도 **빌드한 뒤에** 쓴다(빌드 전에는 mode 2·3 dwell 로 3.0 을 제안한다).
- 부팅 스모크에서 시작 로그 확인:
  - ship_back: `hold_max=60.0s`, `reacquire_stop=5.0s`
  - north_goal_angle: 끝에 `mode [2, 3] 도착 반경 3.5m.`
  - image_subscriber_turn: `turn 목표 색: mode 2=white, mode 3=red`
- flake8 은 Mac 에서 못 돌렸다. `colcon test` 에서 줄 길이(E501) 경고가 나오면 알려 달라(예전부터 있던 101~108자 줄 몇 개).

## 2. 무엇이 바뀌었나
| 묶음 | 노드 | 바뀐 동작 |
|---|---|---|
| C1 | ship_direction | /candidate_angle 이 1.0 s 넘게 안 오거나 /wp_mode 가 바뀌면 20000(GPS 주행 + LiDAR 회피)으로 대체. 진입 시 ERROR |
| C2 | north_goal_angle | WP 를 지나치면 경로선 대신 직접 방위로 복귀. mode 2·3 은 담당 노드가 손 뗀 동안(20000 수신 또는 1 s 무수신)만 dwell 을 셈. 코스 끝나고 마지막 WP 가 mode 5·8 이면 20000 유지 |
| C3 | waypoints.yaml | dwell: mode 2·3 0.5, mode 5·7 1.0, WP10 3.0. 도킹 네 줄(접근 10 m·6 m mode 5, WP8 입구·WP9 이탈 mode 7) 기본 포함 — **⚠️ 현장 교체** |
| C4 | ship_dock | mode 7 진입 = TRANSIT(20000, GPS 로 접근) → /goal_distance 12 m 미만이면 도킹 시작. 표식 탐색 25 → 60 s. DONE: 후진 이탈이면 20000(다음 WP), 표식 못 찾으면 WP9 로 넘어갈 때까지 정지 후 20000 |
| C5 | ship_back | 부표 획득은 카메라 색으로만. 못 찾으면 SEARCH 20000(20 s 넘으면 WARN 1회). LiDAR 거리 10 s 모르면 포기, HOLD 총 60 s 넘으면 포기 → DONE 20000 |
| 결정 3 | north_goal_angle | mode 2·3 도착 반경 3.5 m(파라미터 `arrive_radius_hold_modes_m`) — 끝나면 부표로 더 들어가지 않고 바로 다음. 녹화 파일 mode 2·3 dwell > 1.0 이면 시작 때 WARN |

| C6 | 검출기 turn | 목표 색 파라미터 `turn_color_mode2`(white)·`turn_color_mode3`(red). 틀린 색이면 부팅 ERROR + 그 모드 검출 안 함(빨강으로 대체하지 않음) |

시뮬(200 시드): 코스 시간 중앙값 1085 s → 314 s, 도킹 칸 안 접안 0 → 200/200, WP 시간 초과 0, 거짓 정지 0.

## 3. 대회장 절차에서 달라진 것
1. **웨이포인트 녹화**: `docs/절차/웨이포인트_녹화절차.md`
   - mode 2·3 WP 는 **부표 바로 옆(부표 좌표)** 에서 찍는다(3.5 m 반경이 이 전제).
   - 녹화 파일에는 도킹 네 줄이 없다 → WP7 과 WP10 사이에 끼워 넣는다(§3 🚨).
   - 옛 녹화 파일이면 mode 2·3 dwell 을 0.5 로 고친다.
2. **도킹 목표 칸 공지 뒤**: `docs/절차/도킹_칸별_웨이포인트.md` — `tools/dock_wp.py` 출력 네 줄로 통째 교체.
3. **탐색 색 공지 뒤**: `src/color_shape_detector/config/vision.yaml` 의 `turn_color_mode3` 를 공지 색(red/green/white)으로 바꾸고 `ros2 param get /image_subscriber_turn turn_color_mode3` 확인.
4. **수조·연습에서 잴 것**: 카메라가 부표를 **처음 잡는 거리**(3.5 m 보다 멀어야 위치유지·탐색이 된다. 안에서 처음 잡으면 1 s 안에 다음 WP 로 넘어감). 그 밖 항목은 `docs/절차/tank_test_plan.html`.

## 4. 알려진 남은 문제 (보고서에는 안 넣음)
- 부표 좌표에 둔 WP 사이를 지날 때 회피(감지 3 m)가 부표를 다 못 피해 시뮬에서 미션 부표 접촉이 남는다.
- 토너먼트 구간(마지막 WP, 시간 초과 없음)에서 드물게 장애물 사이에 갇혀 전진·후진을 반복한다(수정 전 코드도 같음).
