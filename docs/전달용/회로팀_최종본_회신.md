# 회로팀께 — 소프트팀 회신 (2026-08-13)

> 검토한 자료: 「회로 최종 정리」(글) + **시스템 블록도 · 배치 손그림**
> 이전 회신: `회로팀_전원문서_검토.md` (2026-07-25)

문서 잘 봤습니다. 용어 설명부터 조립 순서·점검 체크리스트까지 **처음 보는 사람이
따라갈 수 있게** 쓰여 있어서 좋았습니다. 블록도도 전체 구조가 한눈에 들어옵니다.

아래는 **소프트팀이 펌웨어를 확정하려면 답이 필요한 것들**입니다.
저희가 임의로 정하면 나중에 실물과 어긋나서, 지금 여쭙습니다.

# ■ 답변 부탁드리는 것 — 5가지

## Q1. 🚨 MD-30A 는 지금 **어디에** 있습니까? (가장 중요)

두 자료가 서로 다릅니다.

| 자료 | MD-30A 위치 |
|---|---|
| 글 문서 §3 | `릴레이 → **MD-30A** → 스러스터` — **추진 경로 안** |
| 블록도 | `4s Lipo → 전원차단회로 → ESC` — **안 나옴** |

**어느 쪽이 현재 설계인가요?** 이 답에 따라 뒤가 정반대로 갈립니다.

### 추진 경로에 있다면 — 전류가 부족합니다

| | |
|---|---|
| MD-30A 허용 | **30 A** |
| T200 개당 순간 (14.8V) | 약 **25 A** |
| 계통당 스러스터 | **2개** |
| **계통당 필요** | **약 50 A** |

필요량이 한계의 **1.7배**입니다. 풀스로틀에서 컨버터가 전류 제한에 걸리거나 보호 차단됩니다.
그게 **경기 중에** 일어납니다.

### 그리고 애초에 필요가 없습니다

**T200 + ESC 는 배터리 14.8V 직결이 정상**입니다.
속도 조절은 **ESC 가** 합니다 — 전압을 낮춰서 조절하는 방식이 아닙니다.
아두이노가 ESC 에 `1100~1900µs` 펄스를 보내면 ESC 가 출력을 만듭니다.

**컨버터가 실제로 필요한 곳은 아두이노·수신기의 5V** 입니다. 거긴 전류가 작아 충분합니다.

```
권장 : 배터리 → EC5 → 릴레이 → ESC → T200        (14.8V 직결)
                        └→ MD-30A → 아두이노·수신기 5V
```

### 소프트팀이 이 답을 기다리는 이유

기판의 **M 커넥터(아두이노 핀 18)** 가 *"컨버터에 신호를 보내 스러스터 전압을 조절"*
하는 용도로 배선돼 있습니다.

- **컨버터를 옮기면** → M 은 **필요 없어집니다.** 핀 18이 비어 RC 배선이 쉬워집니다
- **그대로 두면** → M 제어 기능을 **펌웨어에 새로 만들어야** 합니다

지금은 **만들지 않았습니다.** 없어질 기능을 미리 만들면 잘못된 구조를 코드로 굳히게 되어서요.

## Q2. 🚨 신호 GND 를 공통으로 이을 수 있습니까?

글 문서 §13-⑤ 에 이렇게 적혀 있습니다:

> *"좌우 전원선을 서로 연결해서는 안 된다"*

**굵은 전원선은 그 말이 맞습니다.** 분리 유지가 좋습니다.
그런데 **신호 GND 는 반대로 반드시 이어야 합니다.**

### 왜 그런가

아두이노가 ESC 에 보내는 건 **PWM 펄스**입니다. 그런데 "전압" 은 혼자 존재하지 않습니다 —
항상 **어떤 기준점에 대해 몇 V** 이고, 그 기준점이 GND 입니다.

```
아두이노가 "5V 펄스" 를 보낸다
   ↓
좌측 ESC 는 "자기 GND 기준으로" 그 전압을 읽는다
   ↓
두 GND 가 안 이어져 있으면 → 기준이 다르다 → 읽은 값에 의미가 없다
```

전압계 탐침 한쪽을 아무 데도 안 대고 전압을 재는 것과 같습니다.

### 배선

```
   배터리A (+) ━━━━━━┓
                     ┃   ┌──────────┐
   배터리A (−) ━━━━━━┻━━━┥ 좌 ESC ×2 ┝━━━ 좌 스러스터 2개
                         └────┬─────┘
                              │ 신호선 + 신호GND ────┐
                                                     │
                                           ┌─────────┴─────────┐
                                           │   Mega 2560       │ ← GND 가 여기서 만난다
                                           │   + LED 스트립 GND │
                                           └─────────┬─────────┘
                              ┌ 신호선 + 신호GND ────┘
                         ┌────┴─────┐
   배터리B (−) ━━━━━━┳━━━┥ 우 ESC ×2 ┝━━━ 우 스러스터 2개
                     ┃   └──────────┘
   배터리B (+) ━━━━━━┛

   ━━━  굵은 전원선 : 좌우 **분리 유지**   ✅ 문서대로
   ───  가는 신호선 : GND **공통**         🚨 반드시
```

ESC 3핀 커넥터(신호 / ＋ / GND) 중 **GND 를 Mega GND 에** 연결하면 됩니다.
전류가 흐르는 굵은 선이 아니라 **가는 신호선 한 가닥**입니다.

### 🚨 LED 스트립도 같습니다

LED 전원을 `AA×3(4.5V)` 로 분리하신 건 좋은 판단인데, **데이터선의 기준점은 여전히 공통**이어야 합니다.

```
AA×3 (+)  ──→ 스트립 +
AA×3 (−)  ──┬─→ 스트립 GND
            └─→ **Mega GND**     🚨 이게 빠지면 색이 틀어지거나 안 켜진다
Mega 핀 40 ──→ 스트립 Din
```

### 부탁

문서 §13-⑤ 를 **"굵은 전원선에 한정"** 으로 고쳐 주십시오.
지금 문장 그대로면 조립하는 사람이 신호 GND 도 안 잇습니다. 그러면 **ESC 가 안 돌고,
원인 찾기도 어렵습니다.**

## Q3. 🚨 무선 비상정지 부품을 확보하셨습니까? (규정)

블록도에는 `전원 차단 회로` 하나만 있어 **버튼식인지 무선식인지 구분이 안 됩니다.**
손그림에 `원격` 이라 적힌 모듈이 그것인가요?

**룰북 §8 은 버튼식 + 무선식 둘 다 의무**입니다. 성능이 아니라 **출전 자격** 문제입니다.

```
FS-i6 여유 채널 → RC 스위치 모듈 → 고전류 릴레이 → 추진 전원 차단
```

🚨 **아두이노를 거치지 않아야 합니다.** 제어기가 죽어도 작동해야 하기 때문입니다.
아두이노는 **릴레이 상태를 감지만** 합니다(핀 38) — 차단은 회로가 직접 합니다.

부품 후보: `docs/전달용/부품_추천목록.md` §3

## Q4. 🚨 비상정지 버튼 하나가 **양쪽을 동시에** 끊습니까?

배터리가 2개이므로 차단 회로도 2개입니다.

**한쪽만 끊기면 살아있는 쪽 추력만 남아 배가 제자리에서 돕니다.**
비상정지가 오히려 위험을 만드는 상황이 됩니다.

→ 버튼 1개(그리고 무선 1채널)가 **좌·우 차단 회로를 함께** 열도록 배선되어야 합니다.

## Q5. ESC 신호선이 **4가닥 독립**입니까, 2가닥을 **분배**해서 4개에 넣습니까?

블록도의 `모터 제어 PWM × 2 → ESC × 4` 를 두 가지로 읽을 수 있습니다.

| 방식 | 뜻 | 선수/선미 추력 비율 조절 |
|---|---|---|
| **(가) 4가닥 독립** | 아두이노가 ESC 4개에 각각 다른 신호 | ✅ **가능** |
| (나) 2가닥 분배 | 좌 신호 하나를 좌측 ESC 2개에 함께 연결 | ❌ 불가 (선수·선미가 항상 같은 출력) |

**펌웨어는 (가)를 전제로 만들어져 있습니다.** 선수 스러스터는 선미의 70% 로 시작하도록
게인이 들어가 있고, 이 값을 물 위에서 조절할 계획입니다. 이유는 세 가지입니다.

- **트림** — 선수 추력이 강하면 뱃머리가 물에 박혀 물을 퍼올립니다(항력↑, 카메라·LiDAR 에 물튀김)
- **후류 간섭** — 선수 프로펠러가 휘저은 물을 선미가 먹으면 효율이 떨어집니다
- **배터리 부하** — 선수를 100% 로 쓰면 계통당 순간 전류가 그만큼 커집니다

(나)로 배선되면 이 조절 수단이 **물리적으로 사라집니다.** 코드로는 되돌릴 수 없습니다.

### 부탁

**(가) 4가닥 독립을 권장드립니다.** 추가 비용이 거의 없습니다.

- ESC 신호선은 전류가 흐르지 않는 **가는 선**입니다 (굵기·발열 무관)
- Mega 2560 은 디지털 핀이 **54개**이고 현재 15개 정도만 씁니다 — 핀은 남습니다
- 이미 (나)로 납땜하셨다면, 신호선 2가닥만 더 뽑으면 (가)로 바뀝니다

만약 (나)로 확정하신다면 알려만 주십시오 — 펌웨어의 게인을 모두 같게 맞추고,
"선수 게인 튜닝 불가" 를 설계문서에 못박아 두겠습니다. (나중에 "왜 이 조절이 안 되지" 로
헤매지 않도록)

# ■ 그림에서 고쳐 주셨으면 하는 것 (답변 불필요)

## ① 블록도가 배터리를 1개로 그렸습니다

```
실제(팀 확인) : 배터리 2개, 좌우 독립
블록도        : 4s Lipo 1개, 전원 차단 회로 1개
```

**2계통으로** 고쳐 주십시오. 위 Q4(동시 차단)가 그림에 드러나야 합니다.

## ② `Arduino Due` → **Mega 2560**

**2026-07-28 에 Mega 2560 R3 으로 확정**됐고 지금 실물도 Mega 입니다. 그림만 낡았습니다.

Due 는 3.3V 보드라 RC 신호에 **레벨시프트가 필요**했는데, Mega 는 5V 라 **직결 가능**합니다.
**부품이 달라지므로** 표기를 맞춰야 합니다.

## ③ LED 4.5V 가 빠듯합니다

WS2812 스트립 8픽셀 기준:

| | |
|---|---|
| 풀백색 소비 | 8 × 60mA = **480 mA** |
| AA 알칼라인 3개 | 4.8V(새것) → **3.6V(소진)** |

**전압이 떨어지면 색이 틀어지거나 아예 안 켜집니다.** 480mA면 AA 가 빨리 닳습니다.
**경기 중 규정 표시등이 꺼지면 문제**가 됩니다.

→ **4s Lipo 에서 5V UBEC** 로 따는 편이 안정적입니다.
  (라우터 전원용 UBEC 를 검토 중이니 함께 보시면 좋겠습니다)

# ■ 좋았던 점 — 블록도에서 확인된 것

| 항목 | |
|---|---|
| `ESC × 4` 명시 | ✅ 이전 회신의 지적이 반영됐습니다 |
| `T200 × 4` | ✅ 스러스터 4개로 정리됐습니다 |
| LED 전원 분리 (`AA×3`) | ✅ 추진 전원과 섞이지 않아 좋습니다 |
| **`모터 제어 PWM × 2` → `ESC × 4`** | ✅ 펌웨어의 **좌/우 페어 제어**와 정확히 일치합니다 |

특히 마지막 항목 — **신호 2개로 4개를 모는 구조**가 저희 펌웨어 설계와 맞아떨어집니다.
좌 명령이 좌측 2개로, 우 명령이 우측 2개로 갑니다.

# ■ 소프트팀 쪽 진행 상황 (참고 — 조치 불필요)

실물 Mega 로 확인한 배선입니다.

| Mega 핀 | 기판 실제 | 상태 |
|---|---|---|
| 2, 3 | RC 수신기 | ✅ 정상 수신 중 |
| 4 (·5) | RC 수신기 | 🚨 **읽을 수 없는 핀** — 아래 참고 |
| 10 | ESC 우(R) | 신호 대기 |
| 13 | ESC 좌(L) | 신호 대기 |
| 18 | M (컨버터 제어) | Q1 답에 따라 결정 |

🚨 **Mega 에서 RC 펄스 폭을 잴 수 있는 핀은 `2, 3, 18, 19, 20, 21` 뿐입니다.**
   나머지 핀은 코드가 읽을 방법이 없습니다(외부 인터럽트 미지원).
   → RC 3채널이 저 6개 안에 있어야 하므로 **RC 선 한 가닥을 옮겨야 합니다.**
     목적지는 Q1 답에 달려 있습니다(M 이 없어지면 핀 18, 남으면 19/20/21).

**ESC 출력 핀은 아무 핀이나 되므로** 펌웨어를 기판(10·13)에 맞추겠습니다.
핀표 확정은 **Q1 답이 오면** 한 번에 하겠습니다.

### 이미 처리한 것

- 🚨 **핀 5 출력 충돌 제거** — 기판에서 핀 5 에 RC 신호가 들어오는데 펌웨어가 같은 핀을
  ESC 출력으로 몰고 있었습니다(출력끼리 마주 봄). 펌웨어 쪽을 비워 해소했습니다.
- 펌웨어 업로드·동작 확인 완료. RC 모드 채널로 **자율/수동 전환**까지 실물 검증했습니다.
