## 2-1. 계통별 묶음 — 같이 사야 같이 돌아간다

우선순위(P0/P1)는 **언제** 사느냐이고, 아래는 **무엇과 함께** 쓰느냐다.
한 묶음 안에서 하나만 빠져도 그 계통이 통째로 안 돈다.

### A. OAK 카메라 계통
```
배터리 ⊕ ─ 2A 퓨즈 ─▶ PoE 인젝터 ─ 동봉 2m Cat5e ─▶ OAK-1 PoE
                          └─ LAN ─▶ AX88179 어댑터 ─▶ 노트북
```
**P0 #2 카메라 ×2 · P0 #3 인젝터 ×2 · P0 #4 어댑터 ×2 · P1 #10 중 2A 퓨즈**
Cat5e 는 OAK 동봉이라 안 산다. 🚨 **인젝터는 접촉기 「앞」에서 딴다** — 비상정지는 추진만 끊는다.

### B. D455 조종 카메라 계통
```
D455 ─ USB 3.0 C↔A(≤1m) ─▶ 노트북 (또는 허브)
```
**P0 #5 케이블** · 본체는 보유 1대 — ⚠️ 배당 1대면 하나 더 필요(§5 #6). 정해지면 케이블 수량도 따라간다.

### C. 라이다 계통

**P0 #6 XH2.54 5핀 하네스** (현역 2대 수리용) · **P0 #7 A3 케이블 6핀/5핀** (단선된 3번째를 살려 **예비** 확보)

⚠️ **물리 라벨은 구매에서 뺐다(09-17)** — 마스킹 테이프 + 유성펜으로 갈음. 표시 작업 자체는 남는다:
```
D5F1ED93…  "1248 / 0.275"
80BFED95…  "1439 / 0.250"
단선품      "케이블 단선 — 쓰지 말 것"   ← 이게 핵심
```
세 대가 겉으로 똑같아 **죽은 개체를 집어 또 진단하는 일이 두 번** 있었다. 단선품 표시가 제일 값싼 해결이다.
(각분해능 차이 자체는 현재 `min_obstacle_cells: 1` 에서 실질 영향 없음 — `하드웨어_배치_요구사항.md` §2-4)

### F. 주 전력 — **구매 없음** (09-17)
실리콘선·SP커넥터·EC5 모두 제외. 주 전력 재배선은 08-25 에 끝났고 09-07 물 위 시험을 통과했다.
⚠️ 인젝터·허브 급전은 새로 따는 자리다 — 가는 선이 모자라면 그때 보충.


### G. 제어 전원 — **노트북 USB 유지** (2026-09-17 확정)
```
노트북 USB ─▶ Mega 5V ─┬─▶ 수신기 +5V
                        └─▶ WS2812 스트립 +5V (핀 16)
```
**구매 없음.** 노트북을 **자율·수동 모두 배에 싣는다**(팀 확정 09-17)니 USB 경로가 끊길 일이 없다.
종전 UBEC 근거였던 "수동 토너먼트에 노트북 하선" 이 취소됐다.

🚨 **그래서 아두이노 USB 직결이 더 중요해졌다.** Mega·수신기·LED 가 **전부 이 한 경로**에 매달린다.
허브를 거치면 수신기가 4.09V 까지 떨어진다(최소 4.0V). 노트북 본체 포트에 직결할 것 — `하드웨어_배치_요구사항.md` §2-3.

⚠️ **남은 제약 하나: LED 밝기 상한 40.** USB 폴리퓨즈 0.5A 때문이다.
**한낮 야외에서 룰 표시등이 보이는지 시험**해야 한다(규정 4.2 = 보트 검사 항목).
안 보이면 그때 UBEC 를 산다 — §3 조건부.


### H. 마스트·기구 — **구매 없음** (09-17)
필라멘트·나사·글랜드·그로밋 전부 제외(재고 갈음 또는 외부 출력).
⚠️ **박스·갑판 관통부 방수는 실란트 마감**으로 간다는 뜻이다 — 글랜드 대안(`마스트_요구사항.md` §2-5).
관통부 A·B·C 는 여전히 **드립 루프**를 줘야 한다.


### I. GPS — **구매 없음** (09-17)
🚨 **접지판은 사지 않을 뿐, 없어도 되는 것이 아니다.**
u-blox 매뉴얼이 **Ø100~150mm 금속판**을 RTK FIXED 조건으로 요구한다(F9P Integration Manual §4.4).
수면 반사(멀티패스)가 아래에서 오는데 갑판 높이 안테나엔 접지판이 곧 FIXED 유지 조건이다.
→ **알루미늄/강판 조각으로 자체 제작.** 자석은 알루미늄에 안 붙으니 **나사 2개로 고정**.


### J. 배 ID — **배선하지 않는다** (2026-09-17 확정)

**회로는 두 배 동일하게 간다. 핀 34·36 은 둘 다 열어 둔다.** 구매도 배선도 없다.

**왜 안 해도 되나** — 배 ID 를 **실제로 분기에 쓰는 곳이 하나도 없다**(전수 확인):

| 어디 | 하는 일 | 동작 영향 |
|---|---|---|
| 펌웨어 | 부팅 깜빡임 1회(A)/2회(B)/8회(FAULT) | 없음 |
| 펌웨어 | FAULT 면 중립 | **핀 둘 다 GND 일 때만** — 미배선은 FAULT 가 아니다 |
| `ssf_bridge` | `/boat_id` 토픽 발행 | 없음 |
| `mission_monitor` | 화면에 표시 | 없음 (구독자는 이것뿐, 분기 없음) |

- **ESC 신호가 2가닥**(좌 12 / 우 11)이라 1번배 2기 / 2번배 4기 차이를 펌웨어가 모른다.
- **배별 추력 범위 분기가 현재 펌웨어에 없다.** 작년 `It_is_Aship` 이 하던 일이고,
  지금은 **노트북 yaml** 에서 한다 — 노트북이 배당 1대라 그 설정은 이미 갈려 있다.
- 미배선이면 양쪽 다 `DEFAULT_BOAT_ID BOAT_A` 로 읽히는데, **아무 데도 영향이 없다.**

⚠️ **다시 필요해지는 조건** — 아래 중 하나라도 생기면 그때 점퍼 한 가닥(A=34 / B=36)을 추가한다:
1. 펌웨어에 **배별 분기**를 넣게 될 때 (추력 범위·게인 등)
2. 두 배의 블랙박스를 **한 파일로 합쳐** 분석하게 될 때 (지금은 노트북별로 갈려 있다)
3. 배를 바꿔 실을 수 있는 아두이노를 **한 대로 돌려쓸** 때


---

⚠️ **퓨즈홀더(P1 #10)는 A·E·G 세 계통에 걸친다.** 2A ×2(인젝터) + 3A ×2(허브·UBEC) + 예비로 잡아야 한다.
