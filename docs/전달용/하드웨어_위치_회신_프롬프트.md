# 하드웨어 적정 위치 회신 프롬프트 — 담당자별 (2026-09-16)

> **쓰는 법:** 각 담당자는 아래 **[공통]** 과 **자기 담당 절**만 복사해서 Claude(또는 ChatGPT)에 붙여넣고, 물어보는 대로 답한다.
> 끝나면 Claude 가 만들어 준 **회신 블록**을 그대로 팀장(소프트)에게 보낸다. 팀장은 회신을 `하드웨어_배치_요구사항.md` §6 과 `tools/cad/mast.py` 에 반영한다.
> **모르는 건 "모름"** 으로. 추측한 숫자가 제일 해롭다 — 자로 잰 값, 데이터시트 값, 사진만 받는다.
> 회신 마감: 마스트 프린트 전 (IMU 치수가 제일 급함 — 프린트를 막고 있음).

## [공통] — 모든 담당자가 먼저 붙여넣는 부분

```
너는 자율운항 보트(KABOAT 대회, 길이 1.66m/1.70m, 폭 0.58m/0.43m) 하드웨어 배치를 정리하는 조수다.
나는 이 팀에서 <담당 하드웨어> 를 맡고 있다. 팀장이 "네 하드웨어가 배 어디에, 어떻게 달려야 하는지" 를 정해진 양식으로 달라고 했다.

규칙:
1. 아래 [이미 정해진 것] 은 바꾸지 마라. 내가 바꾸고 싶으면 회신 블록 맨 끝 "이의" 란에 이유와 함께 적는다.
2. 나한테 [물어볼 것] 을 한 번에 한두 개씩 물어라. 내가 "모름" 이라고 하면 그대로 "모름" 으로 적고 넘어가라. 절대 네가 숫자를 추측해서 채우지 마라.
3. 치수는 mm, 각도는 °, 무게는 g. 데이터시트 값이면 (DS), 자로 잰 값이면 (실측), 사진에서 읽은 값이면 (사진) 을 붙여라.
4. 다 끝나면 [회신 블록] 양식을 그대로 채워서 코드 블록 하나로 출력해라. 양식 항목을 빼거나 이름을 바꾸지 마라.

[이미 정해진 것 — 2026-09-16 기준]
- 갑판(FRP) 을 선체 위에 덮는다. 방수 박스는 갑판 아래 선체 안, 박스 뚜껑 = 해치(갑판 면에 노출). 비상버튼은 뚜껑 위.
- 마스트: 3D 프린트(PETG/ASA), 갑판 위 최고점 ≤ 220mm, 중심선, 선수가 좁아지기 직전(1번 배 선미에서 **≥1264mm**(09-17: 베이스 147.8 깊이 + 해치 이격 30), 2번 배 ≈1130mm(미확정)). FRP 갑판 관통 M5×4 + 뒷면 와셔/백플레이트.
- 마스트에 올라가는 것: **OAK-1 PoE 카메라(꼭대기, 중심 갑판 +175, 아래 11°)**, **RealSense D455(아래 선반 갑판 +85, 아래 15°)**, **IMU(베이스 블록 포켓 — 베이스 우현(+X) 쪽, 케이블은 관 쪽(−X) Ø8 터널로 중앙 구멍에 합류)**. 그 외는 안 올린다.
- 소프트 쪽 사실: 조향 후보는 LiDAR **전방 ±80°(0~160°)** 만 쓴다(`ship_direction` LIDAR_FORWARD_DEG=80). IMU 는 **z축 위(UP)**, 헤딩은 자기(N4) — 절차 `docs/문제와작업/N4_mag_heading_B_준비.md`. GPS 헤딩(Moving Baseline)은 **현재 계획에 없음**(안테나 1개).
- LiDAR(RPLIDAR A3): 선수 끝 중심선, **갑판에 직접**(회전면 갑판 +30mm). 1번 배는 높이 조절 슬롯 ±100mm.
- GPS 안테나: 해치가 아닌 고정 갑판, 금속 접지판 위, 마스트 꼭대기 ✗.
- IMU 는 자기 헤딩을 쓴다 → 모터·ESC·배터리 굵은 선·PoE 인젝터에서 300mm 이상.
- RC 수신기와 LTE 라우터/안테나는 선미 양현 반대쪽, ≥500mm 이격.
- 마스트 케이블: 베이스 중앙 Ø22 구멍 → 갑판 밑 → 박스 앞면 구멍(실란트 마감).
- 부표 높이·지름, 파고, 도크 표식 높이는 운영측 문의 중(답 전엔 잠정).

```

- 배 A/B 둘 다 같은 IMU 인가(WT901C 얘기가 문서에 있음 — 지금 실물이 뭔가).
- 마스트 베이스에 넣으면 갑판 위 5~25mm 높이, 선체 중심선, 마스트 x 위치(선미에서 1130~1264mm)가 된다. 무게중심에서 앞으로 200~400mm 떨어진 자리인데 문제 있나(진동·가속도 팔길이).

## LiDAR 담당 (RPLIDAR A3)

```
<담당 하드웨어> = LiDAR RPLIDAR A3. 선수 끝 중심선, 갑판에 직접 놓는다(기둥 없음). 회전면 = 갑판 +30mm 잠정. 1번 배는 ±100mm 높이 슬롯 마운트를 프린트한다. A3 는 방수가 아니다.

[물어볼 것]
- 본체 외형 Ø×H, 회전면(레이저 창) 이 바닥에서 몇 mm 인가 (DS 또는 실측).
- 바닥 고정 구멍 위치·지름·나사 규격. 어댑터 보드/케이블이 어느 면으로 나오나, 케이블 길이(≤2m 필요), USB 인지 5V 별도인지.
- 선수 판 내폭이 얼마 이상이어야 놓이나(본체 + 케이블 굽힘).
- 후방 사각: 마스트 기둥(40mm 각관, LiDAR 뒤 ≈250~400mm → 정후방 ≈±4~5°)이 가려진다. **조향은 전방 ±80° 만 쓰므로 정후방 사각은 회피에 무관** — 대신 **±80° 안에 갑판 위 물체(GPS 안테나·표시등·비상버튼·마스트 베이스)가 회전면(갑판 +30) 위로 올라오면 안 된다.** 그런 물체가 있나, 있으면 방위·거리.

## GPS 담당 (ZED-F9P / C94-M8P + 안테나)

```
<담당 하드웨어> = GPS 안테나 + 수신기. 안테나는 해치가 아닌 고정 갑판, 금속 접지판(≥100mm) 위. 수신기는 방수 박스 안. **Moving Baseline(안테나 2개)은 현재 계획에 없다** — 헤딩은 IMU 자기. MB 를 쓰자는 제안이면 회신 "이의" 란에 근거와 함께(안테나 2개째 구매 금지 전까진).

[물어볼 것]
- 안테나 모델(A배/B배 각각), 외형 Ø×H, 고정 방식(자석/나사/양면), 케이블 길이·커넥터(SMA/TNC), 케이블 굽힘 반경.

## 카메라 담당 (OAK-1 PoE + RealSense D455)

```
<담당 하드웨어> = 카메라 2대. OAK-1 PoE(자율 비전) 마스트 꼭대기, 뒷면 M4×4(가로 45 / 세로 37.5), 아래 11°, 롤 0, 중심 갑판 +175mm, RJ45 그랜드 아래. D455(수동 조종 화면) 마스트 아래 선반 갑판 **+85mm**(09-16: 95→85, OAK 그랜드와 12mm 여유), 아래 15°, 벨크로 + 1/4-20.

[물어볼 것]
- OAK: 데이터시트 외형 81.9×81.9×31, M4 간격 45/37.5, RJ45 그랜드 돌출 — 실물 도착 전이니 DS 로 확인. 그랜드가 아래로 나오면 케이블 최소 굽힘 반경으로 선반과 간섭 없나(그랜드 끝 갑판 +97, 선반 +85 → 12mm, 선반 앞쪽 40mm 물림·뒤쪽 36×24 케이블 노치).
- 각도 11°: 세로 화각 55° 기준 수평선이 화면 위 30%, 물 51%, 갑판 19%. 동의하나. 도크 표식이 수면 위 몇 cm 에 붙느냐에 따라 근접(1~2m) 시 표식이 화면 위로 빠질 수 있다(1m 에서 수면 +65cm 까지 보임) — 표식 높이가 오면 각도를 몇 도로 타협할지 의견.
- D455 **0°**(2026-09-17 변경, 원래 15°): LiDAR 가 마스트 240mm 앞에 있어 15° 면 화면 35~49% 를 가린다. 0° 면 58~72% 로 내려가고 뱃머리는 여전히 보인다. 동의하나. 무게(≈350g)가 선반에 걸리는 게 걱정되면 광각 웹캠 대안 의견.
- 롤 0 을 어떻게 맞추고 확인할지(수평계, 화면 수평선). 각도 확정 후 마운트에 표시선.

## 선체 담당 (갑판·마스트 장착·LiDAR 자리)

```
<담당 하드웨어> = 선체·FRP 갑판·마스트 장착. 마스트 v2 STL(4부품) 과 조립 STEP 은 docs/전달용/마스트_stl/ 에 있다(IMU 실측 전 프린트 보류).
