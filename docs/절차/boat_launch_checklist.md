## 🎮 조종기 켜는 순서 — 안 맞으면 **전파를 아예 안 쏜다** (2026-08-13 추가)

FS-i6 는 켤 때 아래가 안 맞으면 **송신을 시작하지 않는다.** 화면에 이렇게 뜬다:

> `place all switches in their up position and lower the throttle`

```
① 스위치 SWA~SWD 를 전부 **위**로
② 스로틀 스틱을 **맨 아래**로
```

🚨 **이때 수신기는 출력이 0이다.** 아두이노에서 보면 RC 채널이 **전부 무신호**로 보이고,
   모드가 `대기(0)` 에서 안 움직인다 — **배선이 끊긴 것과 증상이 똑같다.**
   실제로 08-13 에 이것 때문에 배선을 의심하며 시간을 썼다.

→ **"RC 가 하나도 안 잡힌다" 면 배선보다 조종기 화면을 먼저 볼 것.**
   한 채널만 안 잡히면 배선, **전부 안 잡히면 조종기**일 가능성이 높다.

## 🛑 먼저 외울 것 — 배 세우는 법 3가지 (2026-08-10 추가)

> **물에 넣기 전에 이걸 먼저 읽는다.** 세우는 법을 모르는 채로 띄우지 않는다.
> 아래는 전부 **이미 되는 동작**이다. 새로 만든 기능이 아니라 코드에서 확인한 것이다.

| 순서 | 방법 | 걸리는 시간 | 조건 |
|---|---|---|---|
| **1** | 조종기 모드 스위치를 **MANUAL 쪽으로** + 스틱 중립 | 즉시 | 조종기가 닿을 것 |
| **2** | 노트북에서 **`Ctrl+C`** (launch 또는 브릿지) | **500ms 이내** | 네트워크가 살아 있을 것 |
| **3** | 배의 **비상정지 버튼** | 즉시 | 배에 손이 닿을 것 |

### 왜 2번이 되는가 — 펌웨어 워치독

```c
// ssf_boat.ino
if (autoCmdStamp != 0 && (now - autoCmdStamp) < CMD_TIMEOUT_MS) { ... }
else { watchdogActive = true; }   // 명령 500ms 무수신 → 중립
```

자율(AUTO) 중에 **명령이 끊기면 펌웨어가 스스로 중립**으로 잡는다.
그래서 노트북에서 노드를 끄는 것만으로 배가 선다. 브릿지는 종료할 때 중립을 한 번 더 박는다.

### 🚨 두 링크가 서로를 백업한다 — 그래서 둘 다 재야 한다

| 상황 | 세울 수 있나 |
|---|---|
| 조종기 닿음 | ✅ 1번 |
| 조종기 안 닿음, 네트워크 살아있음 | ✅ **2번** |
| 네트워크 끊김, 조종기 닿음 | ✅ 1번 |
| 둘 다 끊김 | ❌ **3번(손이 닿아야 함)뿐** |

이게 위 "통신 거리 시험"에서 **조종기와 노트북을 동시에** 재야 하는 또 하나의 이유다.
어느 하나만 커버되는 거리에서는 백업이 없다.

### ⚠️ 모드 전환은 노트북으로 못 한다 — 그게 맞다

모드는 **조종기 채널 3**이 정하고 펌웨어가 판정한다(`snapPulse(2) < 1500` → AUTO).
노트북에는 모드를 바꾸는 통로가 **일부러 없다.**

- 두 곳에서 모드를 정하면 **조종기 스위치 위치가 배 상태를 뜻하지 않게 된다**
- 비상 상황엔 명령어 타이핑이 아니라 **물리 스위치**여야 한다
- 수동 토너먼트는 **노트북 없이** 도는 설계다 (`ssf_boat.ino` 헤더)

**대신 모드를 '보는' 것은 된다** → 아래 미션 모니터.

### 지금 무슨 모드인지 확인 (배 LED 는 멀면 안 보인다)

```bash
ros2 run ssf_tools mission_monitor
```

`🟢 수동 (RC)` / `🟡 자율 (AUTO)` / `⚪ 대기` 가 그대로 뜬다.
🚨 `🚨 브릿지 끊김` 이 뜨면 자율 명령이 이미 멈춘 것이다 — 곧 중립이 된다는 예고다.

## 준비 (물에 넣기 전)

- 잔잔한 물, 바람 약한 날 (물결·바람이 있으면 측정이 오염됨)
- 사방 20m 이상 열린 공간
- 블랙박스가 켜져 있는지 확인 → `~/ssf_logs/` 에 CSV가 쌓이는지

## 📡 통신 거리 시험 — **System-ID 보다 먼저** (2026-08-07 추가)

> **왜 먼저인가:** 이 시험이 실패하면 웨이포인트를 찍는 것 자체가 불가능하다.
> System-ID 는 배를 물가 근처에서 흔드는 거라 통신이 짧아도 되지만,
> **대회 준비의 다음 단계(좌표 녹화)는 코스 전역을 커버해야 한다.**

### 커버해야 하는 거리

`config/waypoints.yaml` 기준 코스 크기: **남북 106m · 동서 65m · 최대 두 지점 116m**.
물가 한쪽에서 조작하면 **최대 약 116m**. 여유를 봐서 **150m 까지** 시험한다.

### 🚨 두 링크가 **동시에** 살아 있어야 한다

```
배를 지점에 댄다         →  조종기 (FS-i6 / 2.4GHz AFHDS 2A)
그 순간 Enter 를 누른다   →  SSH (네트워크)
```
하나만 되면 못 찍는다. 조종기만 되면 배는 가는데 좌표를 못 찍고,
SSH 만 되면 배를 못 움직인다. **반드시 같이 시험할 것.**

### 🚨 FS-iA6 는 텔레메트리가 없다

수신기가 **FS-iA6**(확정, 2026-08-07)다. `FS-iA6B` 와 달리 **i-BUS·텔레메트리가 없어
RSSI(신호 세기)를 볼 수 없다.** 즉 **링크 여유를 실시간으로 알 방법이 없고, 끊기고 나서야 안다.**
→ 그래서 이 실측이 유일한 근거다. "카탈로그에 500m 라고 써 있으니 되겠지" 는 안 된다.

### 절차 (배 두 명 필요 — 조종 1, 노트북 1)

1. 물가에 노트북 담당이 자리를 잡고 **거리계(폰 GPS·줄자·거리앱)** 를 준비한다.
2. 배를 **25m 씩 멀리** 보내며 각 지점에서 아래 셋을 **동시에** 확인한다.

| 확인 | 방법 | 실패 신호 |
|---|---|---|
| **조종기** | 스로틀·조향을 좌우로 흔들어 배가 즉시 반응하나 | 반응 지연·무반응·제멋대로 |
| **SSH** | `ros2 topic hz /scan` 이 끊김 없이 나오나 | 멈춤·끊김 |
| **NTRIP/RTK** | `/ublox_gps_node/navpvt` 의 `carrSoln` 이 **2(FIXED)** 유지되나 | float·none 으로 떨어짐 |

3. **처음 실패한 거리를 기록한다.** 그게 실효 거리다.
4. 안전 여유를 위해 **실효 거리의 70%** 를 운용 한계로 잡는다.

```bash
# 노트북 쪽에서 계속 띄워두고 보는 것
ros2 topic hz /scan
ros2 topic echo /ublox_gps_node/navpvt --once | grep -E "num_sv|flags"
```

### 거리를 깎아먹는 것 (실패하면 여기부터 본다)

| 원인 | 대응 |
|---|---|
| **안테나가 수면에 가깝다** | 프레넬 존이 물에 잘린다. **수신기 안테나를 최대한 높이** — 가장 싸고 효과 큼 |
| **대회장 2.4GHz 혼잡** | 다른 팀 조종기 여러 대 + 노트북·핫스팟이 같은 대역. 우리 WiFi 를 **5GHz 로** 몰면 경쟁이 준다 |
| **배 안 자기간섭** | 수신기 안테나와 WiFi/LTE 안테나를 **떨어뜨린다** |
| 안테나 방향 | 수신기 두 안테나를 **서로 직각**으로, 송신기와 평행하지 않게 |

### 실패했을 때

거리가 부족해도 **대회 준비 기간에 하는 작업이라 시간 여유는 있다.** 대안:
- 배를 **끈으로 끌어** 각 지점에 대고 찍는다
- 작은 보트로 따라가며 찍는다
- 물가를 옮겨 다니며 **가까운 쪽에서** 나눠 찍는다

## 🎯 System-ID 주행 (배를 '일부러 흔든다')

**⚠️ 핵심: 그냥 미션 주행하면 안 됩니다.** 순항만 하면 관성·추력이 안 나옵니다.
아래처럼 **명령을 확 바꿔가며** 여러 동작을 해야 배의 물리가 데이터에 남습니다.

각 동작 사이에 **완전히 멈춰서 2초** 대기 (스텝 응답을 깨끗하게).

### ① 직진 스텝 (관성·추력) — 3회
```
정지 → [순항 PWM] 확 넣고 8초 유지 → 중립(정지)
정지 → [더 빠른 PWM] 확 넣고 8초 → 중립
정지 → [순항] 넣고 → 중립으로 '탁' 끊고 미끄러지는 것 관찰
```
👉 속도가 **서서히 오르는 곡선** + 명령 끊고 **미끄러지는 거리**를 봅니다.

### ② 선회 스텝 (회전 관성) — 3회
```
정지 → [한쪽 조향] 확 넣고 6초 유지 → 중립
정지 → [반대쪽 조향] 확 넣고 6초 → 중립
정지 → [제자리 선회] 넣고 한 바퀴 → 중립
```
👉 뱃머리가 **서서히 도는 곡선**을 봅니다.

### ③ 직진 캘리브레이션 (모터 불균형·조향 부호) — 1회
```
정지 → [양쪽 같은 순항 PWM] 넣고 15초 직진
```
👉 배가 한쪽으로 휘면 → 모터 불균형. **얼마나 휘는지**로 보정값을 뽑습니다.

### ④ 조향 부호 확인 (눈으로) — 30초
```
SPIN_RIGHT(제자리 우선회) 명령을 한 번 준다
→ 오른쪽으로 돌면 정상.  왼쪽으로 돌면 steer_invert 뒤집기.
```

**전체 5~10분.** 끝나면 블랙박스 CSV가 완성됩니다.

## 왜 이게 결정적인가

지금 시뮬은 관성이 없어서 **튜닝값(clearance, orbit 반경, 위치유지 게인)을 못 믿습니다.**
제가 clearance 0.45로 틀렸던 이유가 정확히 이겁니다.

**이 CSV로 시뮬을 보정하면, 그때부터 시뮬 튜닝이 실물에서도 맞습니다.**
남은 2주간의 시뮬 작업이 전부 '진짜'가 됩니다.
