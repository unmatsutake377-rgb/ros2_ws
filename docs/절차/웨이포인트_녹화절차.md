```bash

#    q     → ~/ssf_logs/waypoints_recorded.yaml 로 저장
#    🚨 WP7 다음 점(토너먼트)은 엔터 금지 — mode 8·dwell 3·이름 직접 입력. 도킹 네 줄은
```

## 1. 찍기 전에 — RTK 가 잡혔는지 먼저 본다

**단독 GPS(±3~5m)로 찍으면 웨이포인트가 무의미하다.** 부표 간격보다 오차가 크다.
RTK FIXED(±1.5cm)를 확인하고 시작한다.

```bash
ros2 topic echo /ublox_gps_node/navpvt --once     # carrSoln 이 2(FIXED) 인가
```
또는 `healthcheck` 의 `GPS/fix ✅` 확인. `⚠️` 면 fix 가 없는 것이다(`NOFIX`).

⚠️ **NTRIP 이 붙어 있어야 RTK 가 된다 → 인터넷이 필요하다.**
대회장에 WiFi 가 없으면 **휴대폰 핫스팟**을 켠다. 데이터는 약 1KB/s 라 부담 없다.

🚨 **마운트포인트는 '측정 장소' 기준으로 고른다.**
2026-08-07 에 `waypoints.yaml` 좌표(마산)를 대회장으로 가정하고 `CHWN`(창원)을 골랐는데,
실제 시험 장소(세종)에서 **199km** 였다. 그 상태로는 RTK 가 안 된다.
소스테이블은 **인증 없이** 받을 수 있으니 현장에서 다시 계산하면 된다:
```bash
curl -s --http0.9 http://gnssdata.or.kr:2101/ | grep '^STR;'   # 9,10번째 필드가 위/경도
```
30km 이내를 고른다. 설정은 `~/.ssf/ntrip_credentials.yaml` 의 `mountpoint`.

## 2. 배가 물에 있으면 — SSH 로 붙는다

배는 헤드리스다(CLAUDE.md 3-3). 물가의 노트북/폰에서 SSH 로 접속해
`waypoint_recorder` 를 실행하고, **배를 RC 로 지점에 댄 뒤 Enter** 를 누른다.

```
[물가] 노트북/폰  --WiFi-->  [배 안] 노트북
                                  └ waypoint_recorder 실행
```
접속은 물가 MacBook → Tailscale → 배 노트북 SSH. Tailscale IP 는 고정이다(10-29 세팅).
   설정·tmux·안 될 때: **`맥북_원격조작_설명서.md`**. ⏳ MacBook → 배 SSH 실접속은 아직 미확인(10-30).

## 3. 찍는 법

```bash
ros2 run north_goal_angle waypoint_recorder
```

시작하면 **미션 번호표**와 **템플릿**(기존 `config/waypoints.yaml`, 절대경로·개수)이 뜬다. 지점마다 템플릿 순서대로
"다음 예상: WP0 게이트 시작 mode 0 dwell 3" 을 보여 주므로, 배치가 작년과 같으면 **엔터만 치면 된다**(11-04 추가).

```
[Enter=추가 / l=목록 / d N=삭제 / r N=재캡처 / q=종료] > ⏎
  표본 20개 평균 → lat 35.1862375, lon 128.5655118 (최대 공분산 0.01)
  다음 예상: WP0 게이트 시작 mode 0 dwell 3
  mode(미션번호)? [엔터=0] ⏎
  dwell(머무는 초)? [엔터=3] ⏎
  구역 이름(엔터=WP0 게이트 시작)? ⏎
  ✔ WP0 추가됨 (총 1개)
  다음에 찍을 곳: WP1 게이트 끝 mode 1 dwell 3
```
다른 번호를 넣고 싶으면 숫자를 치면 된다. 없는 번호(4·6·9)를 넣으면 **다시 물어본다**(캡처는 유지).

🚨 **mode 2·3 WP 는 부표 바로 옆(부표 좌표)에서 찍는다** — 도착 반경 3.5 m 고정(ship_back 유지 거리 2.9 m 밖)의 근거가 이 전제다(계약서_전체코스_20261104 §10 추가 결정 3).
🚨 **비전이 부표를 3.5 m 보다 먼 곳에서 처음 잡아야 한다**(그 안에서 처음 잡으면 ship_back 이 SEARCH 20000 인 채로 0.5~1 s 뒤 다음 WP 로 넘어간다) — 수조·연습에서 비전 첫 획득 거리를 잰다(같은 계약서 추가 결정 6).

🚨 **도킹 네 줄은 녹화로 찍지 않는다 — WP7 다음에서 엔터만 치면 안 된다.**
템플릿(`config/waypoints.yaml`, 13줄)은 WP7 뒤에 도킹 네 줄(접근 10m·6m, WP8 입구, WP9 이탈)이 있고, 녹화 도구는
**순번**으로 기본값을 낸다. 그래서 WP7 을 찍은 뒤 다음 점(토너먼트 회피)에서
`다음 예상: WP8 도킹 접근 10m mode 5 dwell 1` 이 뜬다. 여기서 엔터만 치면 토너먼트 점이 **mode 5·dwell 1.0·
이름 '도킹 접근 10m'** 로 저장되고, 저장 때 비교도 순번 8 의 mode(5)가 같아 **경고가 안 뜬다.**
1. WP0~WP7 은 템플릿대로 찍는다(엔터).
2. 토너먼트 회피 점: mode **8**, dwell **3**, 이름 **`WP10 토너먼트 회피`** 를 **직접 입력**한다.
3. `q` 로 저장한다. 개수 다름(기록 9개 / 템플릿 13개)·mode 다름 경고가 뜨는 것이 정상이다.
4. 저장된 `~/ssf_logs/waypoints_recorded.yaml` 의 **WP7 줄과 WP10 줄 사이**에 `tools/dock_wp.py` 가 찍은 목표 칸
   네 줄을 붙여 넣는다(`도킹_칸별_웨이포인트.md` §3·§4). 결과는 13줄, mode 순서
   `[0, 1, 2, 3, 3, 3, 5, 5, 5, 5, 7, 7, 8]`.
5. §5 대로 `waypoints_file:=` 로 먼저 태워 로그의 `미션 순서(mode)` 가 위 순서인지 본다.
템플릿을 못 읽으면 "템플릿 없음(사유)" 가 뜨고 기본값 없이 직접 입력한다. 다른 템플릿: `ros2 run north_goal_angle waypoint_recorder --template=/경로/파일.yaml`.
`q` 저장 때 템플릿과 개수·mode 순서가 다르면 ⚠️ 경고를 보여 주되 **저장은 한다**(수조처럼 일부만 찍을 때 정상).

| 키 | 동작 |
|---|---|
| `Enter` | 현재 위치를 새 WP 로 추가 (→ mode, dwell, 이름 — 템플릿 기본값은 엔터) |
| `l` | 목록 보기 |
| `d N` | N번 삭제 |
| `r N` | N번을 현재 위치로 재캡처 (mode/dwell 유지) |
| `q` | 저장·종료 |

**지점마다 몇 초 머무른 뒤 Enter.** 최근 2초 표본을 평균내 지터를 줄인다.
누르면 `표본 23개 평균 → lat ..., lon ... (최대 공분산 0.00)` 이 뜬다.
공분산이 크면 RTK 가 불안정한 것이니 다시 찍는다.

### mode (미션번호) — 이 표에서만 고른다

| mode | 내용 | dwell(현재값) |
|---|---|---|
| 0 | 게이트 시작 | 3.0 |
| 1 | 게이트 끝 | 3.0 |
| 2 | 위치유지 | 0.5 |
| 3 | 탐색 부표 — 기본(search_behavior hold)은 부표 앞 위치유지, orbit 이면 선회. 부표 수만큼 반복 | 0.5 |
| 5 | 회피 구간(비전 없음, ship_direction 순수 회피) 시작·끝, 도킹 접근점 2개 | 1.0 |
| 7 | 도킹 — WP8 칸 입구·WP9 이탈점 | 1.0 |
| 8 | 토너먼트 회피 (종합임무 WP10). 토너먼트 레인 파일은 §3a — dwell 0.5 | 3.0 |

도킹 네 줄(접근 10 m·6 m, WP8 입구, WP9 이탈)은 녹화로 찍지 않고 `tools/dock_wp.py` 출력으로 끼워 넣는다
→ §3 의 🚨 순서, `도킹_칸별_웨이포인트.md`.

🚨 **`4`·`6`·`9` 는 없는 모드다.** 작년에 `ship_dock` 이 `9` 로 선언돼 **도킹이 1년 내내
침묵**했다(3-1). 넣으면 저장 직전 검증이 거부한다 — 확인됨:
```
🚨 검증 실패: 0번째 웨이포인트 '': 미션번호 9 는 허용값 [0,1,2,3,5,7,8] 에 없다.
🚨 검증 실패: 0번째 웨이포인트 '': 머무는시간 -5.0 이 음수다.
```

### dwell (머무는 초)
**도착 반경 안에 들어온 뒤 몇 초 머물다 다음으로 넘어갈지.**
도착 반경은 고정 3m 가 아니다 — 도킹(mode 7) 2.0m, 위치유지·탐색(mode 2·3) 3.5m 고정(`arrive_radius_hold_modes_m`),
그 밖은 속도 2 m/s 미만 2.5m · 5 m/s 미만 3.5m · 그 이상 4.5m (`los_logic.get_arrive_radius`).
dwell 은 도착 판정 여유다. 예전 회피·도킹 50/60초는 근거가 확인되지 않아 1.0 초로, 토너먼트(8)는 3.0 초로
줄였다(11-04, `docs/문제와작업/계약서_전체코스_20261104.md` §2-2·§10).
위치유지·탐색(mode 2·3)은 담당 노드(ship_back)가 손 뗀 동안만 dwell 을 센다(`dwell_wait_modes`).
mode 2·3 은 반경 3.5m(ship_back 유지 거리 2.5±0.4m 밖)·dwell 0.5초 — ship_back 이 끝나면(20000) 부표로
들어가지 않고 바로 다음 WP 로 간다(11-04, 같은 계약서 §10 추가 결정 3).
🚨 **재빌드(colcon build) 후 녹화** — 녹화 도구 템플릿이 share 경로(`install/`)를 읽어 재빌드 전엔 mode 2·3 dwell
**3.0 을 제안**한다. **옛 녹화 파일(`~/ssf_logs/waypoints_recorded.yaml`)의 mode 2·3 dwell 은 0.5 로 고칠 것.**
안 고치면 north 시작 때 WARN(`… dwell > 1s: WP… — 옛 녹화 파일일 수 있음 — DONE 뒤 dwell 동안 부표 쪽으로 감,
0.5 권장`)이 뜬다. 값은 그대로 쓰므로 ship_back 이 끝난(20000) 뒤 dwell 동안 부표 쪽으로 간다(같은 계약서 §10
결정 6 보충 ③).
도킹은 WP8→WP9 가 7→7 이라 north 가 WP9 로 넘어가도 ship_dock 이 리셋 없이 이어서 도킹한다.
※ 도달 못 해도 타임아웃으로 넘어간다. 타임아웃은 **WP 의 mode** 로 정해진다(10-29 b337ad8, 그 전엔 목록 순번이었다):
   게이트·위치유지·회피(mode 0·1·2·5) = WP 하나당 120 s, 부표(3) = 90 s, 도킹(7) = 150 s, 토너먼트(8) = 없음.
   → 웨이포인트를 끼워 넣거나 순서를 바꿔도 타임아웃은 mode 를 따라간다. 값은 `config/north_goal_angle.yaml` 의
   `wp_timeout_modes` / `wp_timeout_sec`(🚨 sec 는 전부 `.0` — 정수가 섞이면 노드가 죽는다).
   타임아웃 시계에는 dwell 이 포함된다 — timeout ≤ dwell 이면 부팅 때 WARN 이 뜬다(도착으로는 못 넘어간다).

### 구역 이름
동작에는 영향이 없다. **에러 메시지에 찍힌다** — 오타가 났을 때 "몇 번째" 가 아니라
"어느 지점" 인지 바로 알 수 있다. 대회장에서는 알아볼 수 있게 적을 것.

## 3a. 토너먼트 레인별 녹화 (11-09 추가, 계약서_토너먼트분리_20261109 §9-8)

토너먼트는 종합임무와 **다른 파일**로 돈다(`course:=tournament`). 레인마다 따로 찍어 **노트북에만** 둔다.

```bash
# 녹화 — 레인마다 출력 경로를 따로 준다(기본 ~/ssf_logs/waypoints_recorded.yaml 을 덮지 않게)
ros2 run north_goal_angle waypoint_recorder ~/ssf_logs/waypoints_tournament_<배>_<레인>.yaml \
    --template=$HOME/ros2_ws/install/north_goal_angle/share/north_goal_angle/config/waypoints_tournament.yaml
#   예: ~/ssf_logs/waypoints_tournament_A_1.yaml
#   🚨 --template= 뒤에는 ~ 대신 $HOME (= 뒤의 ~ 는 셸이 안 풀어 준다)
```
- 출력 경로는 **위치 인자**(첫 번째), 템플릿은 `--template=` (`waypoint_recorder.py` parse_cli). 템플릿은 `config/waypoints_tournament.yaml`(2점: 출발 근처·결승선 너머 3 m, 전부 mode 8·dwell 0.5) — 재빌드 뒤 share 경로.
- 🚨 **전부 mode 8.** 하나라도 다른 mode 가 있으면 `course:=tournament` 에서 north 가 ERROR(`웨이포인트 내용 오류`)를 내고 출발하지 않는다.
- **마지막 점 = 결승선 너머 약 3 m, dwell 0.5.** 마지막 WP 를 지나면 north 가 `/candidate_angle` 50000 을 내 바로 멈춘다(도착 반경 2.5 m 안 + dwell 0.5 s). 그 정지 지점이 경기장 경계(`north_goal_angle_tournament.yaml` `geofence_polygon`) 안이어야 한다.
- 레인 코스에 맞춰 점을 더 찍으면 템플릿과 개수 다름 경고가 뜬다 — 저장은 되고 정상이다.
- 🚨 **저장소 파일(`config/waypoints_tournament.yaml`)에 복사·덮어쓰지 않는다.** 적용은 `waypoints_file:=` 인자로만. 어느 파일을 썼는지는 `현장_조정표_20261106.md` §4 에 적는다.

```bash
# 먼저 north 단독으로 확인 — course:=tournament 를 꼭 준다(단독 launch 는 안 주면 main)
ros2 launch north_goal_angle north_goal_angle_launch.py course:=tournament \
    waypoints_file:=$HOME/ssf_logs/waypoints_tournament_A_1.yaml
#   로그: 코스 tournament: 웨이포인트 N개 로드: <경로> / 미션 순서(mode): [8, 8, …]

# 경기 — 대회 launch
ros2 launch launch_files launch_files.launch.py boat:=A course:=tournament \
    waypoints_file:=$HOME/ssf_logs/waypoints_tournament_A_1.yaml
```
- 판 사이에는 launch 를 재시작한다(웨이포인트 순번을 되돌리지 않는다). 시작 로그 확인은 `boat_launch_checklist.md` 코스 절.

```bash
    waypoints_file:=$HOME/ssf_logs/waypoints_recorded.yaml
```
로그에 `웨이포인트 N개 로드: <경로>` 와 `미션 순서(mode): [...]` 가 찍힌다. **개수와 순서를 눈으로 확인.**

이 단계에서 문제가 보이면 다시 찍으면 된다 — 실전 파일은 그대로다.

확정된 뒤에만 복사한다:
```bash
cp ~/ssf_logs/waypoints_recorded.yaml ~/ros2_ws/src/north_goal_angle/config/waypoints.yaml
cd ~/ros2_ws && colcon build --symlink-install --packages-select north_goal_angle
```
⚠️ **재빌드를 빼먹으면** `install/` 의 옛 파일을 읽는다. 로그의 경로로 확인할 것.
