# Claude Code ↔ 검토 — 왕복 작업 절차서

**Claude Code 가 고치고 → 여기서 검증하고 → 다시 고친다.** 한 바퀴가 한 노드입니다.

---

## 🚀 최초 1회 세팅

### 1. 되돌릴 수 있게 만든다 (제일 먼저)

```bash
cd ~/ros2_ws
git init
git add -A
git commit -m "작년 대회 최종본 (수정 전 기준선)"
```

**이게 없으면 노드별 교체의 최대 장점(문제 시 롤백)이 사라집니다.**

### 2. 맥락을 넘긴다

`CLAUDE.md` 를 **`~/ros2_ws/CLAUDE.md`** 로 복사합니다.
Claude Code 는 이 파일을 **매 세션 자동으로 읽습니다.** 여기에 하드웨어, 검증된 버그 8개,
교체 우선순위, 금지사항이 전부 들어 있습니다.

```bash
cp CLAUDE.md ~/ros2_ws/CLAUDE.md
cd ~/ros2_ws && claude
```

## 🔁 한 바퀴 (노드 1개)

### ① Claude Code 에 시킨다

세션을 열고 이렇게 말합니다:

```
CLAUDE.md 를 읽고, 0단계(ssf_tools)부터 시작하자.
한 번에 노드 하나만. 끝나면 커밋하고 git diff 를 보여줘.
```

**중요:** 단계 번호를 명시하세요. "전부 고쳐줘" 라고 하면 통째로 갈아엎습니다.

### ② 결과를 가져온다

Claude Code 가 끝내면 **세 가지**를 챙깁니다:

```bash
cd ~/ros2_ws
git diff HEAD~1 --stat        # 뭐가 바뀌었나
colcon build --symlink-install # 빌드는 되나
```

**가져올 것:** 바뀐 `.py` 파일 + `git diff` 출력 + Claude Code 가 설명한 "왜 바꿨는지"

### ③ 검증한다 (여기서)

바뀐 파일을 주시면 자동으로 4단계 검사를 돌립니다:

```bash
python3 review/review_node.py <바뀐파일.py>
```

| 검사 | 무엇을 보나 |
|---|---|
| **① 요구 계약** | *있어야 할 것이 있는가* — 필수 구독/발행/파라미터, 금지 패턴 |
| **② 정적 위험** | `time.time()`, 맨몸 `except:`, `subprocess`, 문법 오류 |
| **③ 혼합 호환성 시뮬** | **새 노드 + 옛 노드**를 실제로 구동. 배가 움직이나? 접촉이 줄었나? |
| **④ 로직 회귀** | 기존 22개 테스트가 여전히 통과하나 |

**하네스 자체를 검증했습니다:**
새 코드 **8/8 통과**, 작년 코드(버그 있음) **8/8 검출**.
"작년과 같은가" 가 아니라 **"있어야 할 것이 있는가"** 를 묻기 때문입니다.

### ④ 고칠 게 있으면 다시 ①로

지적사항을 그대로 Claude Code 에 붙여넣으면 됩니다.
**통과하면 다음 단계로.**

---

## 📋 단계별 체크리스트

| 단계 | 대상 | 완료 조건 |
|---|---|---|
| ☐ **0** | `ssf_tools` 신규 (blackbox + healthcheck) | `~/ssf_logs/*.csv` 가 생기고, 출발 전 한 줄 진단이 뜬다 |
| ☐ **1** | `ship_goal_angle` | 발행 주기 20Hz. 리뷰 통과 |
| ☐ **2** | `motor_control` | `/obstacle_distance_array` 구독 확인. **감속이 살아난다** |
| ☐ **3** | `ship_direction` | 시뮬 접촉 수 감소. `watchdog_cb` 독립 타이머 존재 |
| ☐ **4** | `iahrs_driver` + 펌웨어 | 🚨 **벤치 확인 필수** (아래) |
| ☐ **5** | 비전 묶음 ⚛ (4개 동시) | `basic_image_*.py` 전부 삭제됨 |
| ☐ **6** | 미션 노드 4종 | `wp_mode` 매핑표 검사 통과 |

---

## 🚨 4단계는 시뮬로 못 잡는다 — 벤치 확인 필수

`iahrs_driver` 의 0점화 제거는 yaw 의 **의미를 바꿉니다** (상대각 → 절대방위).
**부호나 오프셋이 틀리면 배가 정반대로 갑니다.**

**배가 없어도 지금 할 수 있는 것:**

```bash
# 1) IMU 를 손에 들고 정북을 향하게 한 뒤
ros2 topic echo /imu/yaw
#    → 0 근처가 나와야 한다. 아니면 그 값이 mount_offset_deg 다.

# 2) 시계방향으로 90° 돌린다
#    → 90 으로 가야 한다. -90 으로 가면 invert_yaw 를 뒤집는다.
```

**조향 좌/우 부호도 반드시 벤치에서 확인하세요.** 배선이 반대면 **모든 게 무의미합니다.
가장 흔한 사고입니다.**

## 💬 Claude Code 에 그대로 붙여넣을 프롬프트

**0단계 (첫 작업):**
```
CLAUDE.md 를 먼저 읽어줘.

0단계: ssf_tools 패키지를 새로 만들자.
 - blackbox: 10Hz 로 CSV 로깅 (wp_mode, GPS, yaw, yaw_error, candidate,
   desired_angle, pwm_r/l, 장애물거리, 페일세이프, 게이트통과수 등)
 - healthcheck: 2초마다 센서 생존 여부 + wp_mode 매핑표 검사 → /health_ok 발행

두 노드 모두 '구독만' 한다. 기존 토픽에 발행하면 안 된다.
끝나면 colcon build 하고 커밋한 뒤 git diff 를 보여줘.
```

**2단계 예시:**
```
2단계: motor_control 을 고치자.

지금 /desired_angle 만 구독한다. /obstacle_distance_array 를 구독해서
장애물이 가까우면 감속하도록 만들어줘 (작년엔 이 선이 끊겨 있었다).

- slow_start_dist=1.2, min_speed_ratio=0.7 (시뮬 최적값)
- cmd_timeout_sec=0.5 : 명령 끊기면 중립(1500)
- PWM 값은 전부 파라미터로 (배가 A/B 두 척이다)
- time.time() 대신 time.monotonic()

토픽 이름은 바꾸지 말 것. 끝나면 커밋하고 diff 를 보여줘.
```

## ⚠️ Claude Code 가 하기 쉬운 실수

| 실수 | 왜 문제인가 | 예방 |
|---|---|---|
| **한 번에 다 고침** | 어디서 깨졌는지 못 찾는다 | 프롬프트에 "**한 번에 노드 하나만**" 을 매번 넣기 |
| **토픽 이름 개명** | 옛 노드와 섞이는 중간 상태가 깨진다 | "**토픽 이름은 바꾸지 말 것**" |
| **값 하드코딩** | 배가 2척인데 한 척은 못 쓴다 | "**전부 파라미터로**" |
| **커밋 안 함** | 롤백 불가 | "**끝나면 커밋하고 diff 보여줘**" |
| **`ship_last` 지우면서 폴백도 같이 날림** | 담당 노드 없는 모드에서 배가 멈춘다 | `north_goal_angle` 이 폴백을 맡는지 확인 |

## 🎯 지금 병목은 코드가 아닙니다

코드는 **할 만큼 했습니다.** 진짜 남은 일:

1. **배를 빨리 만들어서 실측** — 선폭·순항속도·선회응답. **모든 파라미터가 여기 묶여 있습니다.**
2. **조향 좌/우 부호 벤치 확인** — 반대면 모든 게 무의미
3. **카메라 확정** — OAK-1(단안) 이면 거리는 반드시 LiDAR 에서. OAK-D 면 뎁스 재사용 가능
4. **HSV 를 대회장 조명에서 재튜닝** — 물 위 반사 때문에 실내 값은 절대 안 맞습니다
5. **LiDAR 장착 높이 = 부표 높이** — 안 맞으면 부표를 못 봅니다
6. **IMU 를 모터·배터리에서 멀리** — 지자기 간섭 = 방위가 통째로 틀어집니다
