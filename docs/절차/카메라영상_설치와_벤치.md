# 카메라 영상 링크 — 두 노트북 설치 절차 + 벤치 (가상 링크 → 실링크)

> 작성: 2026-09-14 · 설계 근거: `docs/문제와작업/수동조종_카메라영상_설계.md`
> 역할: **모니터링 노트북 = 물가(지금 쓰는 Mac)** / **배 노트북 = Ubuntu 22.04 (IdeaPad)**
> 순서: 0 각자 설치 → 1 각자 혼자 루프백 → 2 둘을 같은 WiFi 로 묶어 실링크 → 3 물가 거리 시험에 얹기

---

## 0. 설치 (한 번만)

### 0-A. 배 노트북 (Ubuntu 22.04)

```bash
sudo apt install -y gstreamer1.0-tools gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
     gstreamer1.0-plugins-bad gstreamer1.0-plugins-ugly gstreamer1.0-libav gstreamer1.0-x \
     v4l-utils python3-gi gir1.2-gstreamer-1.0 gir1.2-gst-plugins-base-1.0 chrony
cd ~/ros2_ws && chmod +x tools/cam_*.sh tools/cam_*.py
# 확인 — 넷 다 나와야 한다
for e in x264enc clockoverlay avdec_h264 rtpjitterbuffer; do gst-inspect-1.0 $e >/dev/null && echo "$e ok"; done
python3 -c "import gi; gi.require_version('Gst','1.0'); gi.require_version('GstApp','1.0'); from gi.repository import Gst, GstApp; print('gi ok')"
```
- `gstreamer1.0-x` 가 `clockoverlay` 를 담고 있다. 빠지면 "no element clockoverlay".
- 🚨 배 노트북은 **어댑터를 뽑은 채** 운용한다. 설치 후 `./tools/boat_boot.sh --check` 를 어댑터 뽑고 한 번 더 돌려 CPU 거버너가 performance 로 남는지 확인(절전 프로필로 바뀌면 `powerprofilesctl set performance`).
- `chrony` 는 시계 동기용(벤치 지연값의 전제). `chronyc tracking` 에서 `System time` 오차가 수 ms 면 됨.
- 🚨 **`python3` 이 시스템 파이썬(3.10)인지 확인** — `which python3` → `/usr/bin/python3`. conda/pyenv 파이썬이 잡혀 있으면 `gi` 를 못 찾는다(`ImportError: _gi`). 그땐 `/usr/bin/python3 tools/...` 로 명시.

### 0-B. 모니터링 노트북 (Mac)

```bash
brew install gstreamer pygobject3          # gstreamer 하나로 base/good/bad/ugly/libav 다 온다 (2024+ 통합 포뮬러)
gst-inspect-1.0 clockoverlay >/dev/null && echo clock ok
gst-inspect-1.0 avdec_h264  >/dev/null && echo avdec ok
/opt/homebrew/bin/python3 -c "import gi; gi.require_version('Gst','1.0'); gi.require_version('GstApp','1.0'); from gi.repository import Gst, GstApp; print('gi ok')"
```
- 🚨 Mac 에서 `gi` 는 **brew 파이썬**에만 붙는다. 벤치 스크립트는 `/opt/homebrew/bin/python3 tools/cam_bench_rx.py` 로 실행(인텔 Mac 은 `/usr/local/bin/python3`). 시스템 `python3` 로 돌리면 `_gi` ImportError.
- `cam_view.sh` 는 파이썬 불필요(gst-launch 만). 화면은 `autovideosink` → Mac 에선 `osxvideosink` 가 잡힌다.
- 시계: 시스템 설정 → 일반 → 날짜와 시간 → "자동으로 설정" 켜기.
- 방화벽(시스템 설정 → 네트워크 → 방화벽)이 켜져 있으면 첫 실행 때 "수신 연결 허용" 팝업 → 허용.

### 0-C. 저장소에 넣기

zip 을 `ros2_ws` 루트에 풀면 `docs/`·`tools/` 자리에 들어간다. 커밋 하나: `tools: 카메라 영상 스트림/벤치 스크립트 추가 (제어 경로·토픽 계약 무변경)`.
Mac 에도 같은 저장소를 clone 해 두면 `tools/` 가 그대로 있다.

## 1. 각자 혼자 — 루프백 (하드웨어 0)

배·Mac 각각 터미널 두 개. 자기 자신에게 쏘고 받는다. **여기서 안 되면 네트워크 문제가 아니다.**

```bash
# 터미널 1 (수신)
python3 tools/cam_bench_rx.py --secs 30            # Mac: /opt/homebrew/bin/python3
# 터미널 2 (송신, 가상 공 패턴)
python3 tools/cam_bench_tx.py --host 127.0.0.1 --secs 25
```
합격: 수신 `30 fps`, `latency p50 < 10ms`, `bad 0`. (인코딩+디코딩만의 비용이 이 값이다.)

배 노트북은 실카메라로도 한 번: `python3 tools/cam_bench_tx.py --host 127.0.0.1 --source v4l2 --dev $(v4l2-ctl --list-devices | grep -A3 -i realsense | grep video | head -1 | tr -d ' ')`
⚠️ 이때 `camera.launch.py` 는 꺼 둔다(장치 점유 충돌). 여기서 지연이 +50~100ms 뛰면 **그게 카메라 캡처 지연**이고 무선과 무관하다.

### 1-B. 가상 무선 링크 (아직 하드웨어 0)

`cam_bench_netsim.py` 가 UDP 프록시로 지연·지터·유실을 넣는다. 터미널 세 개:

```bash
python3 tools/cam_bench_netsim.py --in 5601 --out 127.0.0.1:5600 --delay 20 --jitter 15 --loss 2   # 5GHz 100m 흉내
python3 tools/cam_bench_rx.py --secs 30 --jitter 30
python3 tools/cam_bench_tx.py --host 127.0.0.1 --port 5601 --secs 25
```

**2026-09-14 사전 벤치 결과 (컨테이너 루프백, 640x480@30, 1500kbps, 키프레임 0.5s)** — ⚠️ 실링크 대체 아님, "코드가 이 조건에서 어떻게 버티나" 확인용:

| 가상 링크 | 편도지연±지터 / 유실 | 지터버퍼 | fps | 지연 p50 / p90 / p99 / max (ms) | 깨진 프레임 |
|---|---|---|---|---|---|
| 루프백(링크 없음) | 0 / 0 | 30 | 30.0 | 3 / 7 / 9 / 61 | 0 |
| 5GHz 근거리 | 5±3 / 0.2% | 30 | 30.0 | 10 / 12 / 103 / 243 | 0 |
| 5GHz 원거리 100m | 20±15 / 2% | 30 | 30.0 | 33 / 41 / 325 / 484 | 0 |
| LTE + Tailscale | 60±25 / 1% | 60 | 30.0 | 78 / 87 / 292 / 594 | 0 |
| LTE 나쁨 (800kbps) | 120±60 / 5% | 100 | 30.0 | 168 / 383 / 1085 / 1239 | 2 |

읽는 법:
- **p50 ≈ 링크 편도지연 + 10ms.** 인코딩·전송·디코딩 자체는 10ms 미만이다. 실링크에서 여기에 **카메라 캡처(USB, 통상 50~100ms)** 가 얹힌다 → 5GHz 에서 총 100~150ms, LTE 에서 150~250ms 예상(⚠️ 실측).
- **p99/max 는 패킷 유실 뒤 키프레임까지 화면 일부가 묵는 시간**이다. 키프레임 1초 간격일 때 LTE p99 가 1.6s, max 3.2s 까지 튀었고, **0.5초로 줄이니 292/594ms** 로 떨어졌다(0.17초까지 줄여도 더 안 좋아짐: 286/346). 그래서 `cam_stream.sh` 의 `key-int-max` 를 FPS/2 로 확정했다.
- 유실 5% 이상이면 p90 이 380ms — 조종에 쓰기 어렵다. 이 구간은 **영상을 믿지 말고 조종기로 정지**하는 게 절차다.
- 지터버퍼는 링크 지터의 1.5~2배가 적당했다. 5GHz 에 60ms 로 키우면 p90 이 오히려 3배 나빠졌다(대기만 늘고 이득 없음).

## 2. 둘을 묶어 — 실링크 (같은 방, 같은 WiFi)

두 노트북을 **같은 5GHz WiFi**(배 라우터가 없으면 임시로 집/학교 공유기)에 붙인다.

```bash
# Mac: 내 IP 확인
ipconfig getifaddr en0             # 예 192.168.0.23  (Tailscale 쓰면 100.x.y.z — tailscale ip -4)
# Mac (수신)
/opt/homebrew/bin/python3 tools/cam_bench_rx.py --secs 60 --show     # --show 로 화면도 본다
# 배 (송신) — 먼저 가상 소스, 되면 실카메라
python3 tools/cam_bench_tx.py --host <MacIP> --secs 55
python3 tools/cam_bench_tx.py --host <MacIP> --secs 55 --source v4l2 --dev /dev/videoN
```
그 다음 **본 스트림**으로 같은 걸: Mac `./tools/cam_view.sh` ↔ 배 `./tools/cam_stream.sh <MacIP>`. 좌상단 시계가 흐르고, 배에서 Ctrl-C 하면 시계가 멈추는지 본다.

| 확인 | 합격 | 안 되면 |
|---|---|---|
| Mac 에 프레임 도착 | rx 로그에 fps 찍힘 | Mac 방화벽 / 같은 서브넷인지 / 공유기 "AP 격리(클라이언트 분리)" 꺼졌는지 |
| 지연 p50 (가상 소스) | < 60ms | 2.4GHz 에 붙었나(5GHz 강제) / 지터버퍼 |
| 지연 p50 (실카메라) | < 200ms | 카메라 캡처 병목 → 해상도 424x240·fps 15 로 낮춰 비교 |
| 배 CPU | `top` 에서 gst 30% 미만/코어 | VAAPI 검토(설계문서 §9) |
| 시계 동기 | `chronyc tracking` 오차 < 10ms | 오차가 크면 지연값에 그대로 섞인다 — 스톱워치법으로 교차확인 |

Tailscale 로 묶을 때: 양쪽 `tailscale status` 에서 상대가 `direct` 로 보이면 랜 직결, `relay` 면 DERP 경유(+수십 ms). 벤치를 **두 경우 다** 남겨 둔다 — 대회장에서 어느 쪽이 될지 모른다.

## 3. 물가 — 통신 거리 시험에 얹기

`boat_launch_checklist.md` 의 25m 단위 거리 시험 표에 4번째 행 추가:

| 확인 | 방법 | 실패 신호 |
|---|---|---|
| **영상** | Mac `cam_bench_rx.py` 를 켜 두고 각 지점에서 5초 로그 한 줄 기록 (fps · p50 · p90 · bad) | fps < 20 · p90 > 300ms · bad 가 계속 증가 |
| **노트북 배터리 %** | 배 노트북은 충전 미연결 운용. 시험 시작·끝 % 와 경과 시간 기록 → 소모율(%/h) | 20%/h 넘으면 라운드 사이 충전 계획 필요 |

기록은 `docs/결과분석/통신거리_실측_YYYYMMDD.md` 에 거리별 표로. **처음 p90 이 300ms 를 넘는 거리**가 영상의 실효 거리다. 조종기·SSH·RTK 실효거리와 같이 놓고 **가장 짧은 것의 70%** 가 운용 한계(체크리스트 원칙 그대로).

## 4. 흔한 실패

| 증상 | 원인 | 조치 |
|---|---|---|
| `ImportError: cannot import name '_gi'` | gi 가 다른 파이썬 버전에 설치됨 | 배: `/usr/bin/python3`, Mac: `/opt/homebrew/bin/python3` 로 실행 |
| `no element "clockoverlay"` | 배: `gstreamer1.0-x` 누락 / Mac: 옛 분리 포뮬러 | apt 설치 / `brew reinstall gstreamer` |
| rx 에 `(바코드 없음 — 송신 안 옴?)` | 패킷이 안 옴 | 방화벽 · IP 오타 · 포트 · AP 격리 |
| `Device or resource busy` (v4l2) | realsense 노드가 장치 점유 | `camera.launch.py` 끄거나 `ros` 모드 |
| `YUYV 를 내는 /dev/video 노드가 없다` (OAK 로 바꾼 뒤) | OAK PoE 는 v4l2 장치가 아님 | `ros` 모드(+`CAM_TOPIC`) 또는 `oak` 모드 — 설계문서 §2 표 |
| 지연이 수 초로 뜸 | 양쪽 시계 불일치 | NTP 확인. 루프백에서 정상이면 확실히 시계 문제 |
| 화면은 오는데 시계가 몇 초 전 | 지터버퍼 과대 / 수신측 sync=true 로 바꿨음 | `cam_view.sh` 기본값 복원 |
