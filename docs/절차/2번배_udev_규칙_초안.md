# 2번배 노트북 udev 규칙 — CP2102 어댑터 충돌 회피 (2026-10-07)

> 🚨 **1번배 노트북은 이 문서와 무관하다.** 1번배 라이다에는 **유일 시리얼 어댑터**
> (`0addfc38…`)가 가므로 `99-ssf.rules` 의 기존 줄이 그대로 `/dev/ttyLiDAR` 를 잡는다.
> 이 문서는 **2번배 노트북**에만 적용된다.

## 확정 사실 (2026-10-07 팀장 답변)

| 질문 | 답 | 결과 |
|---|---|---|
| 2번배에 IMU 가 있는가 | **있다** | 2번배 노트북에서 충돌이 **반드시** 난다 |
| 유일시리얼 어댑터 `0addfc38…` 는 어느 배 | **1번배 라이다** | 2번배 라이다·IMU 는 **둘 다 0001** |
| 신규 A3 출처 | 17만원 매물 (lidar_id 로 모델 0x31 · FW 1.25 확인 = 진품 A3) | 구매목록 반영 |

→ 2번배는 **포트 고정 외에 길이 없다.** 아래 절차대로.

## 문제

2번배에 갈 라이다 어댑터(신규 A3, `918A9AF2`)와 2번배 IMU 어댑터가 **둘 다**
`ATTRS{serial}=="0001"`, 제품명 `CP2102 USB to UART Bridge Controller` 로 **완전히 같다.**
→ `ATTRS{serial}` 로는 못 가른다. 시리얼 규칙을 쓰면 **먼저 잡히는 쪽이 둘 다 가져간다.**
(1번배에서 `/dev/IMU → 라이다` 로 재현됨 — launch 하면 IMU·라이다 동시 사망.)

## 해법: 물리 포트 고정 (`KERNELS==`)

**어느 USB 구멍에 꽂느냐로 구분한다.** 그 순간부터 **꽂는 자리가 규칙**이 되므로
배선도에 "라이다=이 포트 / IMU=저 포트" 를 반드시 적는다.

### 1) 먼저 포트 경로를 실측한다 (2번배 노트북에서)

라이다·IMU 를 **쓸 자리에 꽂은 상태**로:

```bash
bash ~/ros2_ws/tools/udev_port_of.sh    # 장치마다 KERNELS 값 + 시리얼이 유일한지 찍는다
python3 ~/ros2_ws/tools/lidar_id.py     # A3 로 응답하는 포트 = 라이다 (IMU 는 무응답)
```

하나씩 꽂으면서 돌리면 어느 줄이 새로 생겼는지로 장치를 구분할 수 있다.

예 (1번배에서 관측된 값 — 2번배는 다를 수 있다): 라이다 `3-1.4.2` · IMU `3-1.2`.

### 2) 규칙 작성 — 템플릿의 `____` 를 실측 KERNELS 로 채운다

완성 템플릿: **`docs/절차/udev_2번배_템플릿.rules`** (GPS·Mega 줄까지 포함). 핵심 두 줄:

```
# 🚨 2번배: 어댑터 시리얼이 둘 다 0001 이라 물리 포트로 고정한다 (2026-10-07)
#    KERNELS 값은 2번배 노트북에서 `udevadm info -a` 로 실측해 채울 것.
#    ⚠️ 라이다·IMU 를 늘 같은 USB 구멍에 꽂아야 한다 — 바꾸면 이름도 바뀐다.
SUBSYSTEM=="tty", KERNELS=="____라이다포트____", SYMLINK+="ttyLiDAR"
SUBSYSTEM=="tty", KERNELS=="____IMU포트____",    SYMLINK+="IMU"
```

### 3) 적용·검증

```bash
sudo udevadm control --reload-rules && sudo udevadm trigger
ls -l /dev/ttyLiDAR /dev/IMU        # 각기 다른 ttyUSB 를 가리켜야 한다
python3 ~/ros2_ws/tools/lidar_id.py # ttyLiDAR 가 A3 로 응답하는지
```

🚨 `/dev/ttyLiDAR` 와 `/dev/IMU` 가 **같은 ttyUSB** 를 가리키면 실패다 — 포트를 잘못 짚은 것.

## 대안 (쓰지 말 것 권장)

유일 시리얼 어댑터(`0addfc38…`)를 **2번배 라이다**에 주면 시리얼 규칙으로 끝난다.
그러나 그 어댑터는 **1번배 라이다 몫으로 확정**(2026-10-07)이라 쓸 수 없다.
