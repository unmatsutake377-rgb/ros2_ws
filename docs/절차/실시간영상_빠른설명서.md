# 실시간 영상 빠른 설명서 — 배 D455 → 물가 MacBook (한 장, 2026-10-30)

> 이것만 보고 켤 수 있게 줄인 판. 코드가 하는 일·모드·설치·세부 문제 해결은 `수동조종_영상_설명서.md`.
> 영상은 조종과 완전히 따로다 — 화면이 죽어도 **조종기(RC) 조종은 그대로** 된다.

## 0. 주소·장치 (바뀌면 여기만 고친다)

| 기기 | Tailscale IP | D455 컬러 장치 | 확인 |
|---|---|---|---|
| 물가 MacBook Air (받는 쪽) | **100.93.158.11** | — | 10-29 |
| 1번배 노트북 | 100.84.57.20 | `/dev/video6` (참고용) | 10-29 |
| 2번배 노트북 (`ssfb`) | 100.119.219.33 | `/dev/video6` (참고용) | 10-30 (처음 video0 을 잡아 검은 화면 → video6 지정으로 정상) |

🚨 **장치 번호는 고정이 아니다.** D455 를 뽑았다 꽂거나, 다른 D455 로 바꾸거나, 허브가 순간 끊기면 번호가 바뀌거나 사라진다
(10-30 2번배: video6 으로 켜 둔 채 D455 를 바꿔 끼우자 `Cannot identify device '/dev/video6'` 반복). → 평소엔 **번호 없이** 켠다(§1-②).

## 1. 켜기 — 순서대로

**① MacBook — 받는 창 먼저**
```bash
cd ~/ros2_ws && ./tools/cam_view.sh
```
`UDP 5600 대기` 가 나오면 됐다. 창은 영상이 와야 뜬다.

**② 배 노트북 — 보내기** (물 위면 MacBook 에서 `ssh boat-a` → `tmux attach -t ssf` 안에서. `맥북_원격조작_설명서.md`)
```bash
cd ~/ros2_ws && ./tools/cam_stream.sh 100.93.158.11
```
- 번호 없이 켜면 스크립트가 **켜는 순간** RealSense 컬러 장치를 찾는다. 그래서 D455 를 **먼저 꽂고 5 초 뒤** 켠다.
- 자동으로 못 찾을 때만 §3 으로 번호를 찾아 `CAM_DEV=/dev/videoN` 을 앞에 붙인다.
- 자율 launch 가 떠 있어서 `Device busy` 가 나오면: `./tools/cam_stream.sh 100.93.158.11 ros`
- 뒤의 IP 는 **MacBook 주소**. 배 자기 주소를 넣으면 안 뜬다.

**③ 로그 확인 — 이 줄이 맞아야 한다**
```
  장치    : /dev/video6 (Intel(R) RealSense(TM) Depth Ca)
```
`Integrated Camera` 면 노트북 내장 웹캠이다 → 검은 화면. §3.

**④ 화면 확인**
- **좌상단 시계 = 배 시각**, 우하단 = MacBook 시각. 둘 다 흐르면 정상.
- **좌상단 시계가 멈추면 화면을 믿지 말 것** (영상이 멈춘 것).

## 2. 끄기
- 양쪽 터미널에서 **Ctrl-C 한 번** → `■ 중지 (Ctrl-C)`.
- 영상 창의 X 는 끄는 게 아니다(3 초 뒤 다시 뜬다).

## 3. 검은 화면일 때 (10-30 2번배에서 실제로 겪음)

1. 배 노트북 로그의 `장치 :` 줄을 본다. `/dev/video0` 또는 `Integrated Camera` → **내장 웹캠을 잡았다.**
2. D455 가 USB 에 잡혔나:
   ```bash
   lsusb | grep -i realsense          # 8086:0b5c ... RealSense ... 455 가 나와야 함
   ```
   안 나오면 케이블·**허브 포트 전원 버튼**·USB 3(파란) 포트.
3. 컬러 장치 번호 찾기 — `'YUYV'` 가 나오는 것이 컬러:
   ```bash
   for d in /dev/video*; do echo "== $d $(cat /sys/class/video4linux/$(basename $d)/name)"; v4l2-ctl -d $d --list-formats 2>/dev/null | grep -E "\[[0-9]+\]"; done
   ```
   (D455 는 장치를 6개 만든다: `Z16` = 뎁스, `GREY`/`UYVY` = 적외선, `YUYV` = **컬러**)
4. **송신을 Ctrl-C 로 끈 뒤** 그 번호로 다시 켠다: `CAM_DEV=/dev/videoN ./tools/cam_stream.sh 100.93.158.11`.
   (`CAM_DEV` 로 켠 송신은 그 번호만 계속 찾는다 — 장치가 바뀌면 끄고 다시 켜야 한다)
5. 그래도 검으면: 렌즈 덮개·보호필름, 방이 너무 어두운지, 켠 직후 5 초(노출 맞추는 중).

> 왜 내장 웹캠으로 갔나: 스크립트는 이름에 RealSense 가 든 컬러 장치를 먼저 찾고, **없으면 아무 카메라나** 잡는다.
> 켜는 순간 D455 장치가 없었다(꽂은 직후, 또는 카메라 노드가 쥐고 있어 장치가 사라짐). `CAM_DEV` 로 지정하면 이 문제가 없다.

## 4. 자주 나오는 것

| 보이는 것 | 할 일 |
|---|---|
| `Cannot identify device '/dev/videoN'` + 로그 `장치 : /dev/videoN ()` (이름 빈칸) | 그 번호의 장치가 **지금 없다.** 송신 Ctrl-C → `lsusb \| grep -i realsense` → §3 으로 번호 다시 찾기. 허브 아래 장치들이 같이 끊기면(`dmesg` 에 `error -71`·`disconnect` 여러 개) 허브 전원 의심 — D455 를 노트북 파란 포트에 직접 |
| `❌ 이미 돌고 있는 송신/수신이 있다` | 안내된 `kill <번호>` 로 옛 것을 끄고 다시. 두 개면 영상이 섞여 계속 깨진다 |
| 창이 아예 안 뜸 | 보낸 IP 가 MacBook 주소인지 · 두 기기 `tailscale status` · 배 폰 핫스팟 켜짐 |
| 회색 화면, 우하단 시계만 흐름 | 송신 Ctrl-C 후 다시 켜기. `videotestsrc` 같은 시험 명령이 남았으면 먼저 끄기 |
| 계속 깨짐 | 송신 `... 100.93.158.11 v4l2 424 240 30 600` · 수신 `CAM_JITTER_MS=120 ./tools/cam_view.sh` |
| `Device or resource busy` | 카메라 노드가 D455 를 쥠 → 끝에 `ros` |
| MacBook 에서 `No such element` | 터미널 앞에 `(base)` 면 `conda deactivate` 후 다시 |
| 두 배를 동시에 보고 싶다 | 2번배는 포트를 나눈다: 송신 `CAM_PORT=5601 …cam_stream.sh…`, MacBook 에 수신 하나 더 `CAM_PORT=5601 ./tools/cam_view.sh` (⚠️ 아직 안 해 봄) |

## 5. 확정 설정 (옵션 없이 치면 이 값)
