# 회로팀 설명서 — 배 전장(電裝) 시스템의 전체 그림과 만들어야 할 것들

> 대상: 회로 제작 담당. 사전 지식 없음을 전제로 처음부터 설명한다.
> 이 문서 = "왜 이렇게 만드는가"의 설명서. 실제 연결 사양(표)은 `회로_요구사항서.md`에 있다.
> 둘 중 하나만 본다면: **만들 때는 요구사항서, 이해할 때는 이 문서.**

---

## 1. 배경 — 지금 무슨 일이 벌어지고 있나

- 우리 팀은 **KABOAT 자율운항선박 대회**에 나간다. 배 2척(A배/B배)을 새로 만드는 중.
- 배의 "머리"는 배에 실리는 **노트북**(경로 계산, 자율운항 판단), "손발"은 **Arduino Due**라는 소형 컴퓨터 보드(모터 제어)다.
- 작년 대회 코드를 물려받았는데, 분석 결과 **회로/펌웨어 쪽에 사고 요인이 여럿** 있었다 (뒤에 사례 나옴). 올해는 코드를 새로 짰고, 그 코드가 전제하는 회로를 이 문서로 정리했다.
- 소프트웨어(코드)는 이미 작성·검증 단계다. **회로가 이 문서/요구사항서와 다르게 만들어지면 코드가 통째로 헛돈다** — 그래서 만들기 전에 읽어달라는 것.

## 2. 전체 시스템 — 등장인물과 관계

```
[RC 조종기] ~무선~ [수신기] ──PWM 신호 3개──▶ ┌─────────────┐
                                              │ Arduino Due │──PWM 신호 4개──▶ [ESC ×4] ──▶ [T200 모터 ×4]
[노트북] ◀──USB(명령/보고)──────────────────▶ │  (펌웨어)    │──▶ [표시등 LED들]
                                              └─────────────┘
[4S 배터리 14.8V] ──▶ ESC 전원 (비상정지 스위치 2개 경유)
                 └──▶ 5V 변환(BEC) ──▶ Due 전원
```

각자 역할:

| 부품 | 역할 | 비유 |
|---|---|---|
| RC 조종기+수신기 (Flysky FS-i6) | 사람의 수동 조종 신호 | 리모컨 |
| Arduino Due | 신호를 받아 모터 4개에 분배하는 심판 | 척수/반사신경 |
| 노트북 | 자율운항 계산 (카메라·LiDAR·GPS 처리) | 뇌 |
| ESC | "얼마나 돌아라" 신호를 실제 모터 전력으로 변환 | 근육의 힘 조절 |
| T200 | 물속 추진 모터 (선수 2 + 선미 2) | 손발 |
| 표시등 | 배 상태를 밖에서 보게 함 (대회 규정) | 표정 |

**신호의 공용어 = PWM 펄스폭.** 이 시스템의 거의 모든 신호는 "1000~2000 마이크로초(µs) 길이의 전기 펄스"다. 1500µs = 중립(정지), 거기서 멀어질수록 강한 명령. 수신기→Due도, Due→ESC도 같은 방식.

## 3. 경기 3종류와 운용 — 회로에 주는 영향

| 경기 | 배에 싣는 것 | 회로 관점 포인트 |
|---|---|---|
| 자율운항 본경기 | 전부 (노트북+센서+Due) | 노트북–Due USB 연결 필요 |
| 자율 토너먼트 | 전부 | 동일 |
| 수동 토너먼트 | **Due+수신기+ESC만** (노트북·센서 하선 = 경량화로 속도↑) | 🚨 **Due가 노트북 없이 살아야 함** |

마지막 줄이 회로 요구 하나를 만든다: **Due 전원은 노트북 USB가 아니라 배터리에서 독립적으로**(5V BEC). 노트북을 내리면 USB 전원도 사라지기 때문. 부수 효과로, 자율운항 중 노트북이 재부팅돼도 Due는 계속 산다.

## 4. 만들어야 할 것 — 무엇을 / 어떻게 / 왜

### ① Due 독립 전원 (5V BEC)

- **무엇**: 14.8V → 5V 변환 모듈 1개, Due 전원 입력에 연결
- **어떻게**: 시판 BEC/스텝다운 컨버터 (5V 3A급이면 충분)
- **왜**: §3 — 노트북 하선 운용. USB는 데이터 전용으로 강등

### ② RC 입력 레벨 시프트 (🚨 제일 실수하기 쉬운 곳)

- **무엇**: 수신기 신호 3개 각각에 저항 2개짜리 전압 분배 (예: 직렬 10kΩ + GND로 20kΩ → 5V가 3.3V로)
- **왜**: **Due는 3.3V 보드다. 흔한 Arduino(UNO, 5V)와 다르다.** 수신기는 5V 전원을 받으면 신호도 5V로 내보낸다. 직결하면 Due 입력 핀이 손상된다. 조용히, 서서히 망가지는 경우도 있어서 "됐다가 안 됐다가" 하는 최악의 고장이 된다

### ③ 배 ID 회로 (DIP 스위치 1개 + 선 2개)

- **무엇**: Due 핀 2개를 각각 GND로 내릴 수 있는 스위치. **A배는 1번만 ON, B배는 2번만 ON**
- **왜**: 펌웨어는 두 배 공용 1벌인데, 배마다 모터 방향·튜닝값이 다르다. 어느 배인지를 **코드가 아니라 배(회로)가 알려주는** 구조다. 이유:
  - 작년 사고: 코드 안에 "A배냐 B배냐" 분기가 있었는데 오타로 **1년 내내 죽어 있었다.** 아무 에러도 없이 B배가 A배 설정으로 돌았다
  - 스위치 방식이면 "잘못된 코드를 업로드하는 실수" 자체가 불가능해진다
  - **왜 핀 2개인가**: 1개면 "선이 빠짐"과 "B배"가 구분이 안 된다. 2개면 "정확히 하나만 ON"이 정상이고, 나머지는 전부 고장으로 판정돼 배가 안전하게 멈춘다. **고장이 시끄럽게 드러나는 설계**
- 참고: 내부 풀업을 쓰므로 외부 저항 불필요. 스위치–GND만 연결

### ④ 표시등 4종

- **무엇**: 룰 표시등 3개(초록/노랑/빨강) + 점검 LED 1개 (+ 선택: 방향지시등 2개)
- **어떻게**: 룰 표시등은 **주광에서 보이는 고휘도 LED + 트랜지스터 구동** (Due 핀은 전류가 약해서 직결 금지). 점검 LED는 소형이라 저항 하나로 직결 가능
- **왜**:
  - 룰 표시등: **대회 규정 의무.** "원격조종=초록, 자율=노랑, 비상정지=빨강" — 색과 의미가 규정에 박혀 있다. 심사위원이 본다. 외부에서 잘 보이는 위치에
  - 점검 LED: 물 위의 배는 화면이 없다. 부팅 때 깜빡임 횟수로 "나 A배(1회)/B배(2회)/고장(빠른 연속)"을 알리고, 주행 중엔 통신 두절 경보를 깜빡인다. **물가에서 눈으로 하는 디버깅 수단**
  - 방향지시등(선택): 배가 "돌려는 의도"를 보여줌 — 자율운항 디버깅에 유용. **자리가 없으면 빼도 됨** (코드 스위치로 끔). 색은 파랑/흰색 — 규정색과 헷갈리면 안 되니까

### ⑤ 비상정지 2계통 (대회 규정 의무)

- **무엇**: (a) 버튼식 — 배터리→ESC 라인의 고전류 물리 스위치, (b) 무선식 — 수신기 여유 채널 → RC 스위치 모듈 → 고전류 릴레이로 같은 라인 차단
- **왜 "전원 차단"인가**: 규정 원문이 "추진시스템 **전원을 차단**"이다. 소프트웨어로 모터를 멈추는 건 인정 대상이 아니다 — 소프트웨어가 죽으면 같이 죽으니까
- **🚨 왜 Due를 거치면 안 되나**: 비상장치의 철칙 = **멈추려는 대상(제어기)에 의존하지 않는다.** Due가 폭주해서 멈추고 싶은 상황에서, 비상정지가 Due를 거치면 무용지물. 그래서 수신기→릴레이 직결의 독립 회로
- Due에는 릴레이 상태를 알려주는 감지선 1개만 연결 (빨간등 켜는 용도)

### ⑥ 인터페이스 보드 (위 회로들을 모으는 곳)

- **무엇**: Due 위에 얹는 만능기판(쉴드) 1장. 레벨시프트 저항, LED 구동부, DIP 스위치, 커넥터들을 여기 모음
- **왜**: 낱개 점퍼선으로 하면 배 진동에 빠지고, 빠진 선이 §③ 같은 고장을 만든다. 한 장에 모으면 배선이 구조물이 된다

### ⑦ 공통 사항

- **GND 통일**: 수신기·Due·ESC·BEC의 GND는 전부 이어져야 한다. PWM 신호는 GND 기준 전압이라, GND가 분리되면 신호가 "떠서" 오동작한다
- **고전류 경로**: T200 4개 풀출력 = 순간 수십 A. 배터리→비상스위치→릴레이→ESC 구간은 굵은 선 + 정격 넉넉한 커넥터
- **0번·1번 핀 사용 금지**: Due의 USB 통신과 겹침. 나머지 핀은 자유 배정 (요구사항서 §7 표에 기입해서 회신)

## 5. 설계 전체를 관통하는 원칙 (왜 이렇게까지 하나)

작년 시스템의 실패는 전부 **"조용한 고장"**이었다:

- 도킹 기능이 코드 오타로 **1년간 침묵** — 에러 한 줄 없이 그냥 안 했다
- A/B배 구분 분기가 죽은 채 시즌 완주 — 아무도 몰랐다
- 통신이 끊겨도 모터가 마지막 명령으로 **계속 돌았다** — 멈출 방법이 수동 전환뿐

그래서 올해 원칙: **고장은 시끄럽게, 실수는 불가능하게.**
배 ID 2핀(고장이 드러남), 표시등(상태가 보임), 비상정지 독립회로(최후 수단은 아무에게도 의존 안 함), 레벨시프트(망가질 경로 차단) — 전부 이 원칙의 구현이다. "부품 몇 개 아끼기"보다 "고장 경로 하나 지우기"를 우선했다.

## 6. 제작 후 검증 체크리스트 (회로팀 셀프 점검용)

1. [ ] 수신기 신호선 3개 전압 실측 — **3.3V 이하**인가 (레벨시프트 확인)
2. [ ] GND 연속성 — 수신기/Due/ESC/BEC 사이 테스터로 도통 확인
3. [ ] 배 ID — 스위치 1번만 ON일 때 / 2번만 ON일 때 / 둘 다 OFF일 때 부팅 LED 깜빡임이 각각 1회/2회/빠른 연속인가
4. [ ] 비상정지 — 버튼과 무선 각각으로 ESC 전원이 실제로 끊기는가 (**프로펠러 빼고** 테스트)
5. [ ] Due 단독 부팅 — 노트북 없이 배터리만으로 Due가 켜지고 LED가 동작하는가
6. [ ] ESC 4개 — 부팅 약 2초 후 arm 비프음이 4개 모두 나는가

⚠️ 모든 모터 테스트는 **프로펠러 제거 상태**로 시작. T200은 물 밖 장시간 구동 금지(수냉 구조).

## 7. 용어 사전

| 용어 | 뜻 |
|---|---|
| PWM (펄스폭) | 전기 신호를 "켜져 있는 시간 길이"로 표현하는 방식. 여기선 1000~2000µs |
| µs (마이크로초) | 100만분의 1초 |
| ESC | 전자변속기. PWM 명령을 받아 모터에 흘릴 전력을 조절 |
| BEC | 고전압 배터리에서 5V 등 저전압을 뽑는 변환기 |
| 레벨 시프트 | 5V 신호를 3.3V 회로가 안전하게 읽도록 낮추는 것 |
| arm | ESC가 "정상 신호 확인, 가동 준비 완료" 상태가 되는 절차 |
| 풀업 | 핀을 평소 HIGH로 잡아두는 내부 저항. 스위치로 GND에 내리면 LOW — "연결 안 됨"과 "OFF"를 구분 가능하게 함 |
| micro-ROS | 노트북(ROS2)과 Arduino가 USB로 대화하는 통신 규약 |
