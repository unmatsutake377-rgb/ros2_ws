# 에이전트 팀 모드 운영 규칙

> Claude Code 의 서브에이전트(`.claude/agents/ssf-*.md`)로 **역할을 나눠** 변경을 처리하는 방법.
> 목적은 속도가 아니라 **조용히 깨지는 변경을 커밋 전에 잡는 것**이다.
> 지금까지 사람이 별도 환경에서 하던 "토픽 계약 대조 + 혼합 호환성 시뮬 + 로직 테스트"(CLAUDE_상세.md §7) 중
> **토픽 계약 대조와 로직·lint 테스트**를 Claude Code 안으로 가져온다. 시뮬은 §2 조건일 때 따로 돌리고,
> 외부 검토를 대체하지 않는다.

## 1. 언제 팀 모드를 쓰나

**쓴다** (하나라도 해당하면):
- 두 개 이상 노드에 걸치는 변경, 또는 원자 묶음(CLAUDE.md §1-1·§4) 변경
- 토픽·메시지 타입·QoS·특수 상수·`wp_mode` 를 추가하거나 소비 방식을 바꾸는 변경
- 페일세이프, `motor_control`, `ssf_bridge`, `ssf_heading` 처럼 배를 멈추거나 움직이는 체인의 **동작** 변경
- Davidson 이 "팀 모드로" 라고 지시한 경우

**안 쓴다**: 문서만 바꾸는 작업, 로그 문구·주석·오타·테스트 추가처럼 **동작이 안 바뀌는** 수정(체인 노드여도).
이때는 지금처럼 메인 세션이 직접 하고 CLAUDE.md §7 절차를 따른다. 팀 모드는 서브에이전트마다 CLAUDE.md 를 다시 읽어 비용이 몇 배 든다.

**겹치거나 애매하면**: 값·분기·토픽·QoS·타이머·파라미터가 하나라도 바뀌면 팀 모드. 그래도 애매하면 메인 세션이 Davidson 에게 한 줄로 묻는다.

## 2. 흐름

| 단계 | 누가 | 하는 일 | 파일 수정 |
|---|---|---|---|
| ① 계약 | `ssf-contract` | 변경 계약서 작성 | 없음 |
| ② 승인 | **Davidson** | 계약서 확인, "사람이 정해야 할 것" 답변 | — |
| ③ 구현 | `ssf-implementer` | 계약서 범위만 수정 + 테스트 추가 | 있음 (커밋 안 함) |
| ④ 검토 | `ssf-reviewer` + `ssf-verifier` **한 메시지에서 동시에** | 규칙 대조 / 빌드·테스트·스모크 | 없음 |
| ⑤ 수정 | `ssf-implementer` | 🔴 차단 항목과 검증 실패만 고침 → ④ 다시 (**최대 2회**) | 있음 |
| ⑥ 커밋 | 메인 세션 + **Davidson** | diff 요약·이유·리뷰/검증 결과를 보여주고 승인받아 커밋 | — |

**메인 세션 규칙**
- 메인 세션이 통합자다. 팀 모드에서는 `src/` 를 **직접 고치지 않는다.** ②와 ⑥에서 **반드시 멈춰** Davidson 에게 묻는다.
- 서브에이전트는 메인 대화를 보지 못한다. **넘길 것은 요약하지 말고 원문으로** 붙인다:
  - ③ 구현자 ← 승인된 계약서 원문 + Davidson 의 답 + 이번 변경 단위(노드 이름)
  - ④ 리뷰어 ← 계약서 원문 + 구현 보고의 "리뷰어가 특히 봐야 할 곳"만 (구현 설명은 넘기지 않는다 — 모르는 상태로 봐야 한다)
  - ④ 검증자 ← 바뀐 패키지 목록
  - ⑤ 구현자 ← 계약서 원문 + 🔴 차단 항목 원문 + 검증 실패 줄
- 구현 보고에 "계약 밖 변경 필요"가 있으면 ④로 가지 않고 **②로 돌아가** 계약서를 고쳐 다시 승인받는다.
- 계약서가 노드를 여러 개로 나눴으면 **노드마다 ③~⑥을 반복**한다. 노드 하나 = 커밋 하나(§1-1, §1-2), 원자 묶음은 묶음 하나 = 커밋 하나. 두 번째 노드부터는 ③ 전에 앞 커밋 이후에도 계약서가 맞는지 확인하고, 바뀌었으면 `ssf-contract` 로 그 노드분만 다시 쓴다.
- ⑤를 2번 해도 차단이 남으면 멈추고 Davidson 에게 넘긴다.
- **시뮬**: 계약서 검증 계획에 "시뮬 필요"가 있으면 ④에서 **메인 세션이 직접** 돌린다(리뷰어는 읽기 전용, 검증자는 시뮬을 모른다). 먼저 `tools/sim/ssf_sim.py` 에 같은 변경이 반영됐는지 확인한다 — 수동 동기화 사본이라 안 고쳤으면 노드 코드가 바뀌어도 시뮬 결과는 그대로다. `python3 tools/sim/kaboat_full_course_sim.py` 를 돌리고, `sweep_s1.py --seeds 20` 은 몇 분 걸리므로 Davidson 이 원할 때만 백그라운드로 돌린다. 시뮬이 만든 파일(`kaboat_course_result.png`, 덮어쓴 `tools/sim/out/sweep_s1.csv`)은 커밋에 넣지 않는다.

**스테이징 (⑥)**: `git add -A` 를 쓰지 않는다. 리뷰어가 본 파일만 경로를 지정해 `git add` 한다.

**커밋 메시지 (⑥)**: 무엇을 왜 바꿨는지 + 검증 결과를 **실제 그대로** 적는다.
예: `review 통과 / verify: run_tests 통과, build·lint 미실행(ROS 없음)`.
build·lint 미실행 커밋은 push 전에 Ubuntu 노트북에서 `colcon build && colcon test` 를 돌린다.

## 3. 동시에 돌려도 되는 것 / 안 되는 것

- ✅ **읽기 전용 작업은 동시에** 돌려도 된다: 여러 노드의 구독·발행 전수 조사, ④의 리뷰어와 검증자.
- 🚫 **구현자 둘을 동시에 돌리지 않는다.** 같은 launch·yaml·테스트 파일을 동시에 고치게 되고, §1-1 이 막으려는 "어느 변경 때문인지 모르는 상태"가 된다.
- 🚫 **구현자에 `isolation: worktree` 를 쓰지 않는다.** 워크트리는 현재 작업 상태가 아니라 기본 브랜치에서 갈라져서, 아직 커밋 안 한 앞 단계 결과가 빠진다.

## 4. 처음 써볼 때

코드를 바꾸지 않는 것부터 시험한다:
1. 리뷰어만: "`ssf-reviewer` 로 HEAD 커밋을 재검토해줘" — 이미 사람이 검토한 커밋에서 뭘 잡는지 본다.
2. 계약서만: 다음에 할 작업 하나를 정해 "`ssf-contract` 로 계약서만 써줘" — ②에서 멈춘다.
3. 그다음 실제 작은 변경 하나로 ①~⑥ 전체를 돈다.

## 5. 이 설정 자체를 고칠 때

역할 파일(`.claude/agents/ssf-*.md`)과 이 문서는 함께 고친다. 실제로 놓친 사례가 생기면
"무엇을 놓쳤나 → 리뷰어 점검 목록 몇 번에 넣을까" 로 한 줄씩 추가한다(감으로 늘리지 않는다).
검증자(`ssf-verifier`)는 CLAUDE.md 를 읽지 않으므로(`omitClaudeMd`), 검증 명령 규칙은 그 파일 안에 직접 적는다.
