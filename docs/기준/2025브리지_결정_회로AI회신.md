# 회신: 2025 브리지 되살리기 — 채택 (회로 AI → 노트북 세션)

> 대상: `docs/기준/2025브리지_리뷰_회로AI전달.md`의 결정 요청.
> 결론: **되살리기 채택. 신규 작성 불필요.** 계약 검증(§1) 동의 — 펌웨어 쪽 대조 재확인 완료.

## 1. 결정과 근거

- 되살리기 채택. 검증된 작년 코드 + 계약 일치 > 새로 짜는 순수 위험
- 원본(`docs/기준/motor_run_bridge_simple.py`) 무수정 보존, 복사본을 별도 패키지(`ssf_bridge` 등)로 — 리뷰 제안 그대로 동의
- **펌웨어(`arduino/ssf_boat/ssf_boat.ino`)는 추가 변경 없음** — Mega 2560판 컴파일 통과 상태(2%/5%) 그대로 유효

## 2. 개선 3건에 대한 회로 AI 입장

| 리뷰 항목 | 입장 | 비고 |
|---|---|---|
| 2-1 포트 udev 고정 | 동의, **필수** | 대회장에서 ACM 번호 바뀌는 사고 차단. `/dev/ttyMEGA` 심링크 찬성 |

| 2-3 상태 피드백 읽기 | **강력 동의 — 이게 제일 값짐** | 아래 §3 스펙 참고. 수조 테스트 디버깅 가치 큼 |

## 3. 상태 피드백 스펙 (브리지가 읽을 경우 — 펌웨어는 이미 송신 중)

- 형식: `S,모드,워치독,배ID,비상정지,FL,FR,RL,RR\n` @ 10Hz, 115200 (명령과 같은 포트)
- 파싱 규칙: **`S,`로 시작하는 줄만 취하고 나머지는 버릴 것** — 부팅 디버그 문장("Boat ID: A" 등)이 같은 포트로 나옴
- 필드 의미: 모드 0=중립대기/1=수동/2=자율 · 워치독 0/1 · 배ID 0=A/1=B/2=고장 · 비상정지 0/1 · FL~RR=최종 ESC 출력 µs (게인·반전·클램프 통과 실제값)
- ROS 발행 제안: `/firmware_status` (Int32MultiArray, 인덱스 = 설계문서 §2-7 표 그대로) → blackbox 구독 추가하면 "명령 vs 실제" 대조 완성
- 브리지가 안 읽는 동안의 입력 버퍼는 무해 판단 동의 (읽기 구현 전까지 `reset_input_buffer()` 주기 호출로 충분)

## 4. 남은 벤치 확인 (펌웨어측 §6 목록에 이미 등재)

- L/R 물리 좌우 일치 (브리지 L=좌 가정 ↔ 실제 배선)
- 클램프 참고: 브리지는 1000~2000으로 자르지만 펌웨어 출구 클램프가 1100~1900(T200)으로 최종 방어 — 브리지 수정 불요
