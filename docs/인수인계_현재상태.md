작년(2025) KABOAT 대회 ROS2 코드를 **올해 새 배 2척(A/B)** 에 재활용한다. 배·아두이노·카메라는 **아직 없다**(2주 내 배 완성 예정).
그래서 **하드웨어 없이 검증 가능한 것부터** 고쳐 왔다. 지금까지 **0~3단계 + 6단계(6a~6d) 완료.** 남은 건 4·5단계(하드웨어 필요).

- ROS2 Humble / Ubuntu 22.04 / Python 3.10 / `colcon build --symlink-install`
- 하드웨어: RPLIDAR A3(2D, 10Hz) + IMU RB-SDA-v1(iAHRS) + GPS ZED-F9P/C94-M8P(RTK) + **OAK-1 W POE(단안, 뎁스 없음)** + Arduino Due(micro-ROS)
- 회피=갭팔로잉 / 도킹=카메라방위+LiDAR전방최소거리+정면FSM / 위치유지=LiDAR거리 bang-bang / 선회=orbit / 게이트=빨강초록 쌍제약

## 1. ⚠️ 환경 현실 (중요)

- **이 편집용 Mac 에는 ROS2 가 없다.** `colcon build` 는 여기서 못 돌린다 → **실제 빌드·실행은 Ubuntu 머신에서.**
- Mac 에서 가능한 검증: **① Python 문법(py_compile) ② 순수 로직 단위 테스트(ROS 비의존, 아래 4장).**
- **numpy/scipy/pandas 도 이 Mac 엔 없다** (fit_dynamics 용). 필요하면 pip 설치 또는 Ubuntu.
- 워크스페이스 실제 경로는 clone 위치에 따라 다르다. **"clone 한 ros2_ws 루트가 워크스페이스"** 로 통일.

## 3. 이미 내린 결정 — **재론 금지** (근거는 CLAUDE.md)

새 세션이 "이거 넣자" 고 다시 들고 오기 쉬운 것들. **왜 안 했는지**가 CLAUDE.md 에 있다.

- **TTC 비상제동: 폐기.** 생값 미분이 노이즈 증폭 → 물보라로 급정지. 이득0/위험막대 (3-2).
- **시간투표 필터: 기본 OFF.** 시드20 재측정 효과 없음. 코드는 남김 (§6, 3단계 [G]).
- **공간 median 필터: 채택 ON.** 감속 신호(_closest_obstacle)에만. 회피 마스크는 안 건드림 (§6).
- **경쟁팀 A/B/E: 이미 구현돼 있음** (목표방위 가중 갭, 최소 갭폭, bbox∩LiDAR). 도입 불필요 (6-2).
- **위치유지 PD(서울대식): 미채택.** `/candidate_angle` 은 각도라 추력을 못 담음 = 아키텍처 변경 (6-2 [D]).
- **게이트 유체장(G)·obstacle_detector(H): 안 함.** 과설계/빌드위험 (6-2).
- **cmd_timeout 0.5s** (3단계에서 3.5→0.5, 전제 성립 후).

## 6. 작업 방식 (지금까지 효과적이었던 것 — 유지)

1. **노드 하나씩, 커밋마다 무엇을 왜.** 통째로 안 갈아엎는다 (CLAUDE.md 1-1).
2. **추측 금지 — 코드/측정으로 확인.** 토픽 이름·프레임·부호는 소스에서 발췌. 성능 주장은 시뮬 측정.
3. **판정/제어 로직은 순수 모듈로 빼서 단위 테스트.** (Mac 에서 실행 가능하게)
4. **정직 보고.** colcon 을 못 돌리면 "못 돌렸다" 고 한다. 효과 없으면 철회한다(TTC/시간투표처럼).
5. **토픽 계약 유지, 하드코딩 금지(파라미터+⚠️실측), time.monotonic().** (CLAUDE.md 1-3/1-4/1-5)
6. **발행자 둘 충돌 조심.** 한 mode 에 두 노드가 /candidate_angle 발행하면 조향이 튄다 (도킹 mode-7 사고).
