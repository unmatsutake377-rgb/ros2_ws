# SSF 자율운항선박 코드 — 전체 문제 우선순위 마스터 리스트

> 대상: 대회 최종본 `ros2_ws.zip` (iahrs, 미션노드 전체) + Arduino 펌웨어
> 근거: 코드 정밀 분석 + KABOAT 2025 경기규정/임무설명서 대조 + 로직 시뮬레이션
> 총 **38개 문제**를 5단계로 분류. 위에서부터 순서대로 처리 권장.

---

## 🔴 LEVEL 0 — 이걸 안 고치면 출전조차 못 함 (규정 위반)

### 1. GPS 웨이포인트 하드코딩 → 규정상 원천 불가 ★최우선★
경기규정 5.2: *"각 구성물의 정확한 위치(GPS 좌표)는 **공개되지 않으며**, 탑재 센서로 직접 인지해야 한다"*
그런데 `north_goal_angle.py`의 `waypoints[]`에 GPS 좌표를 박아놓고 그걸로 항법함.
**좌표를 안 주므로 이 방식 자체가 성립 불가.** → 미션 인지를 LiDAR/카메라 기반으로 전면 전환 (아키텍처 변경).

### 2. 3색 상태 표시등 없음 (검사 8번)
규정 4.2: 원격조종=**초록**, 자율운항=**노란색**, 비상정지=**빨강** 표시등 필수. → 없으면 **보트 검사 탈락 = 경기 참가 불가.**

### 3. 비상스위치 2종 없음 (검사 9·10번)
**버튼식** + **무선식** 둘 다 필수. 추진 전원을 차단해야 함. → 검사 탈락 사유.

### 4. 흘수선 표시 없음 (검사 2번)
100~110% 부력 범위 흘수선 표시 필수.

## 🟠 LEVEL 1 — 미션 수행 자체가 불가능 (기능 부재/불일치)

### 5. 항로추종 — 게이트 색상 불일치
규정: 게이트 = **빨강–초록** 부표 쌍.
코드: `ship_gate`가 `/red_angle` + **`/yellow_angle`(노랑)** 구독. 비전 노드도 **초록 HSV가 주석 처리**돼 초록을 아예 못 봄.
→ 노랑을 초록으로 교체 + 비전에서 green 활성화.

### 6. 탐색 — orbit 기동 미구현 (동작 자체가 다름)
규정: 목표 부표를 **중심으로 원을 그리며 선회**. 방향은 색상별 — **빨강·초록 = 시계 / 흰색 = 반시계**.
코드: `ship_turn`은 부표를 **좌우로 비껴가는** 로직 + 고정각 8초 선회. orbit 아님.
추가로 **흰색 부표 인식 없음** (turn 비전은 red만 인식), 색-방향 매핑도 다름.
→ **신규 작성 필요.** (배점 15%)

### 7. 도킹 — 표식 하드코딩으로 당일 공지 대응 불가
규정: 표식 = 삼각형/원형/네모 × 빨강·초록·파랑·주황·노랑 중 **대회 당일 공지**. 도크 3개 중 목표 선택.
코드: `basic_image_subscriberdock`에 `target_color="red"`, `target_shape="Square"` **하드코딩**.
→ ROS 파라미터화 필수 + 3형상·5색 인식 확보. (배점 15%)

### 8. 위치유지 — 부표 탐지·위치 피드백 없음
규정: **부표를 센서로 탐지**, 5m 이내에서 5초 유지, **2회 수행**. 충돌 시 패널티.
코드: GPS 웨이포인트 기준 5초 정지(PWM 중립 1500)만. 위치 피드백 전무.
**시뮬 결과: 조류 0.5m/s면 5초에 2.5m 밀려 5m 이탈 또는 부표 충돌.** (배점 10%)

### 9. Geofence(가상경계선) 없음 → 실격 위험
규정: 장애물 구간 가상경계선을 확연히 벗어나면 **실격**.
코드: 경계 개념 자체가 없음. → GPS 기반 경계 체크 + 이탈 시 복귀/정지.

## 🟡 LEVEL 2 — 안전·페일세이프 (사고/폭주 위험)

### 10. 소프트웨어 페일세이프 전무
GPS/IMU/LiDAR 끊김, 노드 크래시, 통신 두절 — **모든 경우에 "마지막 명령을 유지하고 계속 주행"**.
유일하게 작동하는 안전장치는 **사람이 RC로 수동 전환하는 것뿐**.

### 11. 펌웨어 워치독 없음
`/Motor_run` 수신이 끊겨도 마지막 AutoR/AutoL을 무한 유지 → 배가 계속 달림.
→ N ms 미수신 시 중립(1500/1500) 복귀 필요.

### 12. 무 RC 시 기본 오토파일럿 (폭주)
부팅 시 `PulsesAuto=0` → `Auto_signal=0 < 1500` → 자동으로 오토 모드.
RC 링크가 끊기면 **사람 개입도, 소프트 정지도 없이** 마지막 명령으로 폭주 가능.

### 13. iahrs — GPS heading이 NaN으로 리셋 안 됨
유효한 GPS heading이 **한 번** 들어오면 이후 계속 IMU yaw를 덮어씀. **GPS가 끊겨도 마지막(stale) 값에 고정**되어 IMU가 영구 무시됨.
추가로 NavPVT heading은 **진행방향(COG)** 이라 정지/저속에선 부정확. 신뢰 임계값 30°도 느슨.

### 14. 미들(M) 스러스터 오토모드 미제어
펌웨어 `timer_callback` 오토 분기에서 `M_signal`을 안 건드림 → 초기값 0 또는 마지막 수동값이 그대로 출력.

## 🟢 LEVEL 3 — 성능·정확도 (점수에 직결)

> 시뮬 결과: **접촉 1회 = 30초 패널티**. 순수 주행이 140초이므로 **접촉 3회면 기록 65% 악화.**
> **속도보다 "안 부딪히는 것"이 압도적으로 중요.**

### 15. LiDAR 노이즈 붕괴 — 물보라 1점에 부표가 사라짐 ★시뮬 확인★
`rear_obstacle_ignore_margin=1.0` 로직: "최근접 장애물과 1m 이상 차이나면 무시".
→ 0.3m짜리 물보라 반사 1점이 최근접으로 잡히면, **1.6m 앞 진짜 부표가 통째로 무시됨.**
시뮬: 장애물 셀 **17개 → 0개**. 수면에서 매우 흔한 상황이라 실전에서 반드시 터짐.

### 16. clearance 0.15m가 너무 작음 → 접촉의 주원인 ★시뮬 확인★
게이트 실통과폭 1.1m(코드 요구 1.05m 충족)여도 **실제로는 충돌**. 조향 오차를 전혀 못 버티는 값.
→ **0.3~0.5m로 상향** 권장.

### 17. detection_distance 1.8m 부족 ★시뮬 확인★
순항 1.2m/s에서 반응시간 **1.5초**뿐. 불규칙 장애물밭 시뮬에서 **8/8 전부 충돌**.
3.0m로 올리면 5/8 통과. 단 **좁은 게이트에선 3.0m가 오히려 악화(접촉 6회)** → **구간별 전환** 필요.

### 18. suppress_spike_edges가 작은 장애물을 침식/삭제
각폭 ±0.5°(3셀) 이하 장애물은 `smooth_spikes`가 노이즈로 보고 **통째로 삭제**. 얇은 기둥·로프 위험.

### 19. 침식 후 3셀 미만이면 안전마진(dilate)이 아예 안 붙음
`dilate_obstacles`의 `min_obstacle_cells=3` 조건 때문에, 침식으로 1~2셀만 남은 장애물은 **배 폭 팽창이 적용되지 않음** → "탐지는 됐는데 여유는 0".

### 20. 시간적 필터 없음
매 스캔 독립 처리. 수면 IR 반사로 `inf` 깜빡임 → 조향 지터. **N프레임 지속성** 필요.

### 21. ship_goal_angle 제어 주기 0.5초 (너무 느림)
IMU는 100Hz인데 방위 오차가 **2Hz**로만 갱신 → 반응 굼뜸. 배가 커지면 사행/오버슈트.
→ 0.05~0.1초로 단축.

### 22. 감속 로직이 제거됨
현 `motor_control`은 장애물/목표 거리 기반 감속을 안 함(순항 고정 1360). 장애물 근처에서도 속도 유지 → 충돌 여유 감소.

### 23. mode2_detection_distance가 죽은 코드
`mode2_detection_distance = base = 1.8`로 동일 → wp_mode==2(도킹)에서 탐지거리 전환이 **아무 효과 없음**.

### 24. yaw_error / candidate_angle 신선도 체크 없음
상류가 멈춰도 마지막 값을 무한 사용 → 조용한 방위 드리프트.

## 🔵 LEVEL 4 — 이식성 (새 배 A/B 대응)

### 25. 펌웨어 `It_is_Aship` 오타 → B배 분기가 죽어 있음
주석은 `A배=0, B배=2`인데 코드는 `if (It_is_Aship == 1)` 검사. **값 2를 넣어도 분기가 안 걸려 B배가 A배 범위를 사용.**

### 26. motor_control PWM 전부 하드코딩
`base_pwm=1360`, 후진 `1590`, 정지 `1500`이 코드 상수. **배별(A/B) 튜닝을 코드 수정으로만 가능** → ROS 파라미터화 필요.

### 27. LiDAR half_width / clearance 하드코딩
`half_width=0.45`, `clearance=0.15`가 `__init__` 상수. 배 폭이 다르면 재튜닝 필요한데 파라미터가 아님.

### 28. navpvt 토픽 네임스페이스 불일치
iahrs는 `/ublox/navpvt` 구독, ublox 노드는 `/ublox_gps_node/navpvt` 발행 → **이름이 안 맞아 GPS heading이 실제로 안 들어옴.**

### 29. zed_f9p.yaml이 로버가 아니라 **베이스(고정국)** 설정
`tmode3: 1` + survey-in = 정지 기지국용. **움직이는 배에 쓰면 안 됨.** F9P용 로버 설정을 새로 만들어야 함.

### 30. 시리얼 포트 udev 의존
`/dev/ttyLiDAR`, `/dev/IMU`, `/dev/ttyGPS` 모두 udev 심볼릭 링크. **새 노트북엔 규칙이 없으면 장치를 못 잡음.**

### 31. 카메라 인덱스 하드코딩 + GUI 의존
`cv2.VideoCapture(6)` 고정. `cv2.imshow`/`waitKey`가 매 프레임 호출 → 헤드리스 환경 불가/성능 저하.

### 32. depth–color 정렬(align) 없음 + 각도식 매직넘버
`real_x=(rel_x/80.0)*0.09*(distance/0.5)` — 카메라 내부파라미터 대신 상수. 카메라/해상도 바뀌면 깨짐.

## ⚪ LEVEL 5 — 코드 위생 (당장 위험은 아님)

### 33. 비전 노드 `node.pipeline.stop()` — 존재하지 않는 속성
gate/dock/turn 노드 `main()`에 있음 → 종료 시 AttributeError.

## 📌 처리 순서 요약

| 순서 | 무엇을 | 왜 |
|---|---|---|
| **1** | GPS 의존 제거 → 센서 기반 인지 | 규정상 필수. 안 하면 미션 전체가 무의미 |
| **2** | 표시등 + 비상스위치 (하드웨어) | 없으면 검사 탈락 = 출전 불가 |
| **3** | LiDAR 노이즈 버그 + clearance 상향 | 접촉 = 30초 패널티. 점수 직결 |
| **4** | 페일세이프 (워치독, 신선도 체크) | 새 배는 크고 무거움. 폭주 = 사고 |
| **5** | 탐색 orbit / 게이트 초록 / 도킹 파라미터화 | 각 15% 배점 |
| **6** | 위치유지 피드백 + geofence | 10% + 실격 방지 |
| **7** | A/B 배 파라미터 분리, 펌웨어 오타 | 두 배 운용 |
| **8** | 코드 위생 정리 | 유지보수 |

## ⚠️ 시뮬레이션 한계 (정직하게)
배 선회 응답·순항속도(1.2m/s)는 **가정값**. 게이트 폭·부표 간격은 규정에 없어 추정.
→ **절대 수치보다 상대 비교**(1.8m vs 3.0m, 접촉 0회 vs 3회)를 신뢰할 것. 새 배 실측 후 재실행 권장.
