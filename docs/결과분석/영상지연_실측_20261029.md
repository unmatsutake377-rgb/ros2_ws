# 수동 조종 영상(D455 → MacBook) 실측 기록 — 2026-10-29

> 결론: **424x240 · 30 fps · 1000 kbps · 수신 지터버퍼 80 ms** 가 "실시간으로 보기 좋다"(팀장 판정). 스크립트 기본값으로 반영.
> 사용 설명: `docs/절차/수동조종_영상_설명서.md`

## 환경
| 항목 | 값 |
|---|---|
| 송신 | 1번배 노트북 `ssfb-IdeaPad-Slim-3-15IAH8`, D455(USB, Bus 004 `8086:0b5c`), v4l2 직접 모드 |
| 수신 | 팀장 MacBook Air (Apple 칩, macOS), Homebrew gstreamer, `cam_view.sh` |
| 망 | 같은 실내 공유기 (MacBook `192.168.0.61`). Tailscale·LTE·물가 거리는 **미시험** |
| 대역(2.4/5 GHz)·신호 | 미기록 |

## 진행 순서와 결과

| # | 단계 | 결과 |
|---|---|---|
| 1 | MacBook 설치 | `brew` 없음 → Homebrew 설치. gstreamer 설치 후 3개 요소 "No such element" — **Anaconda 의 옛 gstreamer(플러그인 30개)가 PATH 앞**. `conda config --set auto_activate_base false` 로 해결. 첫 스캔 경고(GIRepository·GTK3/4 중복)는 무해 |
| 2 | MacBook 루프백(videotestsrc → 127.0.0.1) | 수신 준비 확인. 방화벽 꺼짐(State 0) |
| 3 | Ubuntu → MacBook 테스트 패턴 | 패킷 도착(시계 흐름) 그러나 회색 — 테스트 명령에 `key-int-max`·`config-interval` 이 없어 중간 합류 수신기가 못 풂. 옵션 넣어 해결 |
| 4 | `cam_stream.sh` 첫 실행 | `YUYV 를 내는 /dev/video 노드가 없다` 반복 — 1번배 노트북에 `v4l-utils` 미설치 → apt 설치 |
| 5 | 재실행 | 화면은 오는데 **검정**(시계 둘은 흐름) — 스크립트가 **내장 웹캠 video0**(YUYV, 번호가 앞) 을 잡음. D455 노드: video2 Z16 · video4 GREY/UYVY/Y8I/Y12I(IR) · **video6 YUYV(컬러)** |
| 6 | `CAM_DEV=/dev/video6` | D455 영상 나옴. **지연은 문제 없음**(체감), 그러나 계속 깨짐 |
| 7 | 원인 추적 | Ubuntu 에 **video0 송신이 아직 살아 있었다** → 두 영상이 같은 포트로 섞임. 원인: gst-launch 가 Ctrl-C 를 처리하고 정상 종료 → 재시작 루프가 3초 뒤 다시 켬(Mac 에서 가짜 gst 로 재현) |
| 8 | 하나만 남긴 뒤 640x480 · 1500 kbps | 흔들 때 깨짐 |
| 9 | 640x480 · 3000 kbps | 그래도 계속 깨짐 → 압축 부족보다 패킷 손실 쪽 |
| 10 | **424x240 · 1000 kbps + 수신 80 ms** | **"딱 이 정도가 실시간으로 보기 좋다" — 채택** |
| 11 | Tailscale, 같은 공유기 (10-29) | `tailscale ping` 직접 연결 192.168.0.1:41641 **9 ms** |
| 12 | Tailscale, 배 노트북 핫스팟 · MacBook 학교 WiFi (10-29) | 직접 연결 **71 ms** |
| 13 | **Tailscale, LTE 핫스팟 두 대 (서로 다른 폰, 10-30)** | 직접 연결 223.39.212.181:41641 ping **113 ms**. 영상(424x240 · 1000 kbps · 80 ms) **정상 유지 — 깨짐·멈춤 없음**, 지연 약 110 ms 체감(팀장). **대회 기본 구성으로 채택**, 지터버퍼 80 ms 유지 |
