준비 단계 — 검증할 눈부터 만든다

0단계 · ssf_tools

블랙박스 + 헬스체크

🎥 경기 중 모든 걸 기록하고, 출발 전 센서를 점검하는 도구

이걸 제일 먼저 넣었습니다. 이건 배를 조종하지 않고 구경만 하는 노드라 아무것도 망가뜨릴 수 없습니다. 그런데 이후 모든 수정을 확인하는 눈이 됩니다.

블랙박스 — 경기 중 배의 모든 상태를 0.1초마다 CSV로 기록. 규정상 5번 도전 가능한데, 왜 실패했는지 알아야 다음 회차에서 고칩니다.
헬스체크 — 출발 전 "센서 다 살아있나?"를 한 줄로 알려줌. 센서 하나 죽은 채 출발하면 배가 물 위에 멈춰섭니다.

항법 체인 — 배가 방향을 잡는 부분

1단계 · ship_goal_angle

"어느 쪽으로 틀지" 계산기

🧭 목표 방향 − 뱃머리 방향 = 얼마나 틀어야 하나

버그켜자마자 거짓말 — 센서 값이 오기도 전에 "완벽 정렬! 직진!"이라고 발표했습니다. → 값이 실제로 올 때까지 입을 다물게 고침.
버그센서가 죽어도 계속 떠듦 — IMU(방향센서)가 죽었는데 마지막 값으로 계속 말해서, 안전장치가 "살아있구나" 착각. → 센서가 조용하면 이 노드도 입을 다물게 고침. 그 침묵이 "고장" 신호가 됩니다.
제가 틀렸던 것: "0.5초에 한 번 계산은 너무 느리다"고 했는데, 시뮬로 재보니 속도를 10배 올려도 아무 차이가 없었습니다. 주장을 철회했습니다. (20Hz로 올리긴 했지만, 그게 성능을 올린 건 아닙니다.)
2단계 · motor_control

"각도"를 "모터 힘"으로 바꾸는 번역기

⚙️ 체인의 맨 끝. 여기서 실제 모터가 움직입니다.

복구감속이 끊겨 있었음 — 작년엔 장애물이 코앞이어도 전속력이었습니다. 이 노드가 장애물 거리를 아예 안 듣고 있었어요. → 장애물 1.2m 안이면 속도를 70%까지 줄이게 연결.
추가명령 끊기면 정지 — 위에서 명령이 안 오면 3.5초 뒤 중립(정지).
버그제자리 도는 명령이 반대로 — "오른쪽으로 돌아"가 왼쪽으로 돌았습니다. 도킹 탐색이 반대로 훑을 뻔했습니다.
개선진짜 제자리 선회로 — 작년 "선회"는 순항 속도로 큰 원(반경 2m)을 그려서 도크에 부딪혔습니다. 이제 제자리에서 돕니다.
추가모터 좌우 힘 차이 보정 — 두 모터 출력이 조금 다르면 배가 게처럼 옆으로 갑니다. 물 위에서 5분 측정하면 자동으로 보정값을 뽑는 도구도 만들었습니다.
클로드 코드가 저를 잡은 것: 제가 "제자리 선회 중에도 감속하라"고 했는데, 그러면 배가 뒤로 밀리며 돕니다. 계산해보니 맞아서, "전진할 때만 감속"으로 규칙을 고쳤습니다.
둘이 함께 버린 것 (TTC 급정지): "부딪힐 것 같으면 급정지" 기능을 제가 넣었었는데, 시뮬로 재보니 물보라 한 번에 배가 35초 중 28초를 멈춰섰습니다. 이득 0, 위험 막대 → 삭제.
3단계 · ship_direction

중앙 판단 — 장애물을 피하고 안전을 지킴

🚢 가장 중요한 노드. 여기서 회피와 페일세이프를 결정합니다.

구조 개선"침묵" 문제 해결 — 전에는 라이다가 끊기면 이 노드가 아무 명령도 안 냈습니다(완전 침묵). → 라이다가 오든 안 오든 항상 명령을 내게 구조를 바꿨습니다. 이제 "침묵 = 이 노드가 죽음"이라는 뜻이 됩니다.
추가단계적 감속 — 센서가 0.7초 끊기면 속도 70%, 3초 끊기면 정지. 시뮬로 재보니 접촉이 24→14회로 줄었습니다.
회귀IMU 감시가 사라졌었음 — 코드를 새로 짜다가 실수로 1단계에서 만든 안전장치를 무력화했습니다. 시뮬이 잡아냈습니다(IMU 죽어도 배가 안 멈춤). 바로 복구.
버그이상한 센서값에 노드가 죽음 — 라이다가 깨진 데이터를 보내면 0으로 나누기 오류로 노드가 죽었습니다. (작년 코드에도 있던 버그) 방어 코드 추가.
제가 또 틀렸던 것 (시간 필터): "물보라 걸러내는 필터를 넣으라"고 했는데, 단일 시드로 판단한 실수였습니다. 20번 돌려보니 효과가 0이고 오히려 배가 느려져서, 기능은 남기되 기본 꺼짐으로 뒀습니다.

미션 노드 — 실제 점수를 따는 부분

6a · ship_dock + north_goal_angle

🚨 죽어 있던 도킹을 살림 (점수 15%)

두 노드를 반드시 동시에 고쳐야 하는 한 쌍

최악의 버그도킹이 1년간 침묵 — 도킹 노드가 엉뚱한 번호(9번)를 기다리고 있어서, 실제 도킹(7번)에서 아무 일도 안 했습니다. 배는 멀쩡히 돌아다녔고 도킹만 안 했으니 아무도 몰랐습니다. → 7번으로 고침.
개선카메라 깊이 안 씀 — 새 카메라(OAK-1)는 거리를 못 잽니다. 그래서 거리는 전부 라이다로. 도크는 넓어서 카메라와 라이다 방향이 어긋나므로, "정면에 뭔가 얼마나 가까운가"만 봅니다.
왜 동시에? 도킹을 살리는 순간, 다른 노드가 같은 채널에 "무시해"를 계속 보내고 있어서 둘이 싸웁니다. 그래서 한쪽을 살리면서 다른 쪽의 방해를 같이 꺼야 합니다.
6a-2 · geofence

경기장 밖으로 안 나가게 (이탈 = 실격)

🧱 경계선을 "보이지 않는 벽"으로 만듦

추가경계가 가까우면 그 방향을 가짜 장애물로 만들어서, 기존 회피 로직이 알아서 피하게 했습니다. 새 로직을 안 만든 게 핵심입니다.
제가 걱정한 것 → 클로드 코드가 뒤집음: 제가 "모서리에서 배가 갇힐 것"이라 했는데, 클로드 코드가 "안 갇힌다"고 맞게 반박했습니다. 그런데 제가 다시 확인하니 반대 문제가 있었습니다 — 모서리 대각선으로 빠져나갈 수 있었습니다. 그래서 방식을 "경계를 레이저처럼 쏘는" 방법으로 바꿨고, 시뮬로 모서리에서도 안 나가는 것을 확인했습니다.
6b · ship_gate

게이트(문) 통과

🚩 빨강-초록 부표 사이로 지나가기

버그배선이 뒤엉켜 있었음 — 빨강 신호가 초록 변수로 들어가는 식으로 꼬여 있었습니다. 재작성하며 바로잡음.
추가엉뚱한 짝짓기 방지 — "다음 게이트의 빨강"과 "이번 게이트의 초록"이 같이 보이면 그 중간으로 가버립니다. 두 부표 각도가 말이 되는 범위일 때만 한 쌍으로 인정.
추가통과 개수 세기 — 몇 개 통과했는지 기록(규정: 순서대로).
클로드 코드가 저를 또 잡음: 제가 "옆 노드에 폴백 추가하라"고 했는데, 그러면 또 둘이 싸우는 상황이 됩니다. 클로드 코드가 소스를 확인하고 "그거 넣으면 안 됩니다"라고 막았습니다. 정확했습니다.
6c · ship_turn

부표 선회 (규정 위반이던 것 수정)

🔄 부표를 중심으로 원을 그리며 돌기

규정 위반작년엔 그냥 옆으로 스쳐 지나감 — 규정은 한 바퀴 도는 것인데 작년 코드는 비껴 지나갔습니다. 완전히 새로 짬.
추가흰색 부표 인식 — 빨강·초록은 시계방향, 흰색은 반시계방향(규정). 작년엔 빨강만 봤습니다.
6d · ship_back

위치 유지 (한자리 버티기)

🅿️ 부표 근처에서 5초간 안 밀리고 버티기

버그가짜 위치유지 — 작년엔 "그냥 5초간 가만히". 물살이 있으면 2.5m나 밀려나 실패합니다. → 거리를 재면서 밀리면 되돌아오게 고침.
지뢰이 노드가 자기를 "ship_turn"이라 등록 — 복붙 실수로 이름이 겹쳐 있었습니다. 설정값이 엉뚱한 노드로 갈 뻔했습니다. → 이름 바로잡고, 전체 노드 이름을 전수 검사(나머지는 정상).

🎯 지금 어디까지 왔나

이제 시뮬이 아니라 진짜 장비로 돌려봤습니다. 노트북을 새로 세우고 LiDAR·IMU·GPS 를 붙여, 대회 때 칠 명령 그대로 실행했습니다.

가장 중요한 것 — 실물로만 나온 버그가 8건. 시뮬레이션과 단위테스트가 전부 통과하는데도 남아 있던 것들입니다. "테스트 통과 = 안전" 이 아니라는 걸 이번에 확실히 배웠습니다.

특히 무서웠던 것 셋

사망센서가 고장났다 돌아올 때 배가 죽었다
LiDAR 가 1초 튀었다가 정상으로 복구되는 순간 회피 노드가 죽었습니다. 그러면 모터가 멈추고 아무도 되살리지 않아 배가 물 위에 영구 정지합니다. 고장이 아니라 회복이 배를 죽이는 형태였습니다.
사망대회 명령이 한 번도 뜬 적이 없었다
전체를 한 번에 켜는 명령을 처음 그대로 실행해 보니 2초 만에 전부 꺼졌습니다. 파일 하나를 못 찾아 생긴 오류가 이미 켜진 노드 15개까지 같이 죽였습니다. 그동안 노드를 하나씩만 켜서 확인해 와서 아무도 몰랐습니다.
사망GPS 가 안 잡혔는데 엉뚱한 방향으로 갔다
GPS 수신기는 위성을 못 잡아도 "위치 0, 0" 을 계속 보냅니다. 그걸 진짜 위치로 믿고 아프리카 앞바다에서 대회장까지의 방향을 배에 주고 있었습니다. 값이 47.96° 라 그럴듯해 보여서 눈으로는 절대 못 잡습니다.

밖에 나가서 확인한 것

확인GPS 정확도 1.5cm 달성
보정 신호(RTK)를 받아 ±1.5cm 까지 나왔습니다. 두 걸음(1.93m) 이동이 구분됩니다. 일반 GPS 는 오차가 3~5m 라 이 정도는 묻힙니다.
확인IMU 방향 부호 확정
배 뜨면 확인하려던 것 중 하나를 미리 끝냈습니다. 이게 반대면 배가 정반대로 갑니다.
확인좌표 찍는 도구 실사용
대회장에서 쓸 도구를 미리 돌려봤습니다. 일부러 틀린 값을 넣어보니 제대로 거부했습니다.
배운 것 하나 더 — 기준국은 '지금 있는 곳' 기준으로 골라야 한다. 대회장이라고 생각한 좌표를 기준으로 골랐더니, 실제 시험 장소에서 199km 떨어져 있었습니다. 가까운 곳(11km)으로 바꾸니 바로 정확도가 나왔습니다.

지금 막혀 있는 것

딱 네 가지이고, 전부 소프트웨어 밖입니다.

① 팀원 회신 전달 — 문서는 다 썼는데 아직 안 보냄. 가장 오래 멈춰 있음
② 카메라 USB 케이블 — 지금 것은 속도가 느린 종류라 영상이 아예 안 옴
③ 배 — 장착 각도·조향 방향은 배가 있어야 확인
④ 아두이노 — 모터 제어 최종 연결
