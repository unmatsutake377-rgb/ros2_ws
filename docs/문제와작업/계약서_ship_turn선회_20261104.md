### 문제 3 — 부호: `orbit_logic` 은 **우 양수** 로 쓰였고 입·출력은 **좌 양수**: **(a) 사실 (b) 사실(식 틀림, 영향 작음) (c) 무관**

규약 확인: `/image_angle` 좌 양수(`vision_geom.py:69-81`), `/candidate_angle` 좌 양수(`ship_direction.py:719-720` `80 + c_raw` = LiDAR 80 초과 = 좌조향; 계약서_geofence부호·계약서_ship_gate부호 에서 확정), LiDAR `a−80` 좌 양수(`ship_direction.py:131,364`). `ship_turn._lidar_dist_at` 의 `80 + rel`(`:208`)은 좌 양수와 **일치**(이 부분은 옳다). 틀린 곳은 `orbit_logic.py:9,51,56-57` "+ = 우현".

(a) `orbit_steer` — 수치 예(함수 직접 호출, `k=30, limit=45, R=3`):

| 입력(좌 양수) | 현행 출력 | ship_direction 매핑 | 실제 동작 |
|---|---|---|---|
| ORBIT 진입 틱: rel=0, dist=4, CW | **−60** | 80−60 = **20 (우조향)** | 배가 오른쪽으로 꺾여 부표가 **좌현**으로 → 부표를 왼쪽에 두고 도는 **CCW** = 반대 |
| 반경 정확, 부표 우현(rel=−90), CW | **−180** | raw 180 → 80+180 = 260 → **범위 밖 → STOP_HOLD**(`:722-729`) | 설계상 정상 자세에서 정지 |
| rel=0, dist=3, CW | −90 | 80−90 = −10 → **STOP_HOLD** | — |
| 수정식(`−orbit_steer(−rel)` = `rel + 90·s − s·gain`): rel=0, dist=4, CW | **+60** | 140 (좌조향) | 왼쪽으로 꺾여 부표가 **우현**으로 → CW ✓ |
| 수정식: rel=−90, dist=3, CW | 0 | 80 (직진) | 접선 ✓ |

→ **사실**: 현행은 좌 양수 입력에서 CW 요청 시 CCW 로 돈다(규정 빨강·초록=시계 위반). 덤: 접선 명령이 ±90° 근처면 `ship_direction` 매핑 범위(0~160 = ±80°)를 넘어 STOP_HOLD 가 난다 — 수정 후에도 ORBIT 진입(rel≈0)에서 `90 − gain` 이 80 을 넘는 경우(dist−R < 1/3 m) 발생 → §5 에서 출력 클램프 제안.

(b) `OrbitProgress.update(wrap360(yaw + rel))`(`ship_turn.py:291`) — 나침반 yaw(CW+) 와 좌 양수 rel 로 월드 방위는 `yaw − rel` 이 맞다(계약서_geofence부호 와 같은 식). **사실(식 틀림)**. 영향: 정상 선회에선 rel≈일정이라 `Δ(yaw±rel) ≈ Δyaw` 로 둘 다 ~360 — 완료 판정은 우연히 맞는다. 제자리 요잉(부표 고정, yaw 0→40, rel = yaw) 수치: `yaw+rel` 진행각 **80**, `yaw−rel` **0** → 요잉·왕복 시 **2배 과계수**로 조기 COOLDOWN 가능. 테스트 `test_progress_*` 는 월드 방위를 직접 넣어 이 합성식을 안 본다.

(c) SEARCH 의 `spin = SPIN_LEFT if CCW else SPIN_RIGHT`(`:259`) — SPIN 5000/6000 은 `ship_direction` 이 rel 없이 그대로 통과(`:712-714`)시키므로 부호 버그와 **무관**(사실). 탐색 방향은 임의 선택이라 변경 불필요.

### 덤 — 테스트 러너: `test_orbit_logic.py:17-22` `check()` 는 **assert 를 던진다**(ship_gate 와 다름) → pytest 가 실패를 잡는다. 단 현재 테스트 `:55-89` 7건은 **우 양수**(CW·부표 +90 → 접선 0)를 고정하고 있어 (C) 수정 시 전부 뒤집어야 한다.

| **(B) LiDAR 방위 추적** | ORBIT 중 카메라 rel 이 None 이면 예상 방위 `exp = 직전 유효 rel`(없으면 `−90·s`) 주변 `±lidar_track_window_deg` 에서 거리 `≤ lidar_track_max_m` 인 **최근접 빔**을 부표로 → `(rel, dist)`. 순수 함수 `lidar_track(ranges, angle_min_deg, inc_deg, expected_rel, window, max_m) -> (rel, dist) or None` 을 `orbit_logic.py`(또는 새 `lidar_track.py`)에. 찾으면 `last_seen_t` 갱신(lost 규약 유지) | ORBIT 전체 구간 방위 확보 → 한 바퀴 가능. 거리도 같은 빔에서 → `_lidar_dist_at` 호출 불필요 | ① **수조 벽**(6×6 m: 부표 중앙, 벽까지 3 m = 반경과 같다) 이 창 안 최근접이 될 수 있음 → max_m 과 "직전 rel 연속성" 으로 완화, 수조에선 벽 쪽 반원이 위험 ② 부표 2개 이상(대회 WP3·4·5)이 창 안에 들면 **가까운 쪽으로 갈아탐** → 창 25° + 연속성으로 완화, 완전 제거는 못 함 ③ 실 `/scan` 범위·LiDAR 높이≠부표 높이(§8) 면 못 봄 → 그땐 (A) 로 폴백해 2 s 뒤 SEARCH(안전 쪽) ④ 자기 선체·마스트 반사가 ±90° 에 있으면 ⚠️ 미확인 | 함수 1 + 노드 ~15줄 + 파라미터 2 + 테스트 |

**추천: (C) + (A) + (B) 모두, 커밋 순서 C→A→B.** 이유: (C) 없이는 살아나도 반대로 돈다(규정 위반). (A) 만으론 규정 달성이 구조적으로 불가(부표가 FOV 밖이 정상 자세). (B) 가 본 수정이고 (A) 는 (B) 가 실패하는 틱(벽/높이/범위)의 안전 폴백. 추가 권장(같은 커밋 1 또는 2): 발행 전 steer 를 `±80` 으로 클램프 — `ship_direction` 이 범위 밖을 STOP_HOLD 로 바꾸는 걸(§0-3 표) ship_turn 이 모르고 있다.

(B) 설계 세부(사람 결정 뒤 구현자용): LiDAR 인덱스→rel 은 `a − 80`(`_lidar_dist_at :208` 과 동일 프레임). 창 밖 최근접 금지(창 안에서만). 연속 매칭: 직전 LiDAR rel 을 다음 `expected_rel` 로. 카메라 rel 이 다시 들어오면 카메라 우선. `dist` 는 매칭 빔의 거리. 하네스(`FastWorld.lidar_scan`, 부표 반지름 `K.BUOY_R`, 360°)로 그대로 검증 가능.
