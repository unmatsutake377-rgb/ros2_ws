## 왜 지금 하나

`ship_direction.yaml` 의 `half_width: 0.45` 는 **배가 완성되기 전에 넣은 임시값**이다
(`CLAUDE.md` §8 이 아직 "선폭 실측 필요" 로 남겨두고 있다). 코드는 이렇게 쓴다:

```python
min_required_width = half_width * 2 + clearance      # = 0.45*2 + 0.25 = 1.15m
```

즉 **배 폭을 0.9m 로 보고 1.15m 짜리 갭을 요구한다.** 설계값(0.58 / 0.43m)이 맞다면
실제 필요는 0.78 / 0.63m 라 **47~83% 과다**다. 시뮬에서 관찰된
**"좁은 게이트에서 후진 반복"** 의 원인 후보다 — 지나갈 수 있는 문을 못 지나간다고 판단한다.

🚨 **값만 바꾸면 안 된다.** `clearance: 0.25` 는 **`half_width 0.45` 를 전제로 스윕한 값**이다
(0.20→접촉 1.7회 / **0.25→0.2회** / 0.30→0.8회 / 0.45→807초 폭주). 폭을 줄이면 그 전제가 깨진다.

🚨 **"최대 폭" 의 정의 — 이걸 틀리면 배가 부표를 친다.**

- **가장 튀어나온 것까지** 포함한다. 선체만 재지 마라.

  갑판이 더 넓으면 **둘 다** 적어라: `갑판 ____ / 수면부근 ____`

# 작업: `half_width` 를 실측값으로 바꾸고, 그 전제가 깨진 값들을 다시 맞춘다

## 0. 전제·규칙

- 🚨 **추측으로 숫자를 채우지 마라.** [입력] 이 `?` 면 그 항목은 **건너뛰고 "미입력" 으로 보고**한다.

- 🚨 **값 하나만 바꾸고 끝내지 마라.** `half_width` 는 `clearance` 스윕의 전제다. §2 를 반드시 한다.

## 1. 실측값 반영

`src/ship_direction/config/ship_direction.yaml`:

- `half_width` 를 **[입력] A 의 최대 폭 ÷ 2** 로 바꾼다.
  - **두 배 공통 단일값이다**(배별 분기 없음) → **넓은 쪽 배**를 기준으로 잡는다. 안전 쪽이다.
  - 갑판 폭과 수면부근 폭이 다르면 **큰 쪽**을 쓴다.
- 주석에 **실측값·측정일·무엇을 포함한 폭인지**를 남긴다. 다음 사람이 "이게 선체만인가" 를 안 묻게.

## 2. 🚨 `clearance` 재검토 — 여기가 핵심이다

`clearance: 0.25` 는 `half_width 0.45` 에서 스윕한 값이다. 폭이 줄면 **갭 요구가 함께 줄어**
더 좁은 문으로 들어가려 든다. **접촉이 늘 수 있다.**

**[입력] B 에 시뮬 위치가 있으면:**
1. 시뮬의 배 폭 상수(`HALF_WIDTH` 등)를 같은 실측값으로 바꾼다. **한쪽만 바꾸면 무의미하다.**
2. `clearance` 를 **0.20 / 0.25 / 0.30 / 0.35 / 0.45** 로 스윕한다.
   시드는 **20개 이상** — `CLAUDE.md` §6 의 `temporal_frames` 항목이
   **"단일 시드로 판단한 착시"** 로 한 번 틀렸다. 같은 실수를 하지 마라.
3. 지표: **접촉 횟수 · 전진 거리 · 폭주(과보수로 못 나아감) 여부.** 셋을 같이 본다.
4. 결과 표를 `CLAUDE.md` §6 에 **기존 스윕을 지우지 말고 나란히** 넣는다 —
   "옛 폭 0.45 기준" / "새 폭 ___ 기준" 으로 둘 다 남겨야 나중에 비교가 된다.

**[입력] B 가 `없음` 이면 — 재스윕을 못 한다. 대신 이렇게 한다:**
1. **시뮬이 없다는 사실 자체를 문서에 적어라.** `CLAUDE.md` §6 머리에
   **"이 표의 수치는 저장소에 없는 시뮬에서 나왔다 — 재현 불가"** 를 명시한다.
   지금은 검증된 값처럼 읽히는데 **재현할 방법이 없다.** 그게 더 위험하다.
2. `half_width` 는 실측으로 바꾸되, **`clearance` 는 건드리지 마라.**
   근거 없이 올리면 과보수(폭주), 내리면 접촉이다. **모르면 그대로 두는 게 맞다.**
3. 대신 **물 위 확인 항목**으로 등록한다(§4).

## 3. 선회 시 쓸고 가는 폭 — 계산해서 보고만 해라 (코드 변경 금지)

지금 모델은 **정지 상태 폭**만 본다. 그런데 갭을 지나며 각도를 틀면 실제 통과 폭은 더 넓다.
[입력] A 의 길이 `L` 과 폭 `W` 로 대략 이렇게 본다:

```
선회각 θ 로 통과할 때의 유효 폭 ≈ W·cos θ + L·sin θ
```

- 예: `L=1.7 · W=0.58` 에서 `θ=15°` 면 **≈ 1.00m** — 정지 폭 0.58m 의 **1.7배**다.
- **이 값을 계산해 보고만 해라.** `half_width` 에 자동으로 반영하지 마라 —
  갭 통과는 대개 직진으로 정렬한 뒤 들어가므로 항상 적용되는 여유가 아니다.
- 보고에 넣을 것: θ = 0·10·15·20° 에서의 유효 폭 표, 그리고
  **"현재 `min_required_width` 로 그 각도 통과가 가능한가"** 판정.
