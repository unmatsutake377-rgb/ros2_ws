# S1 — `half_width` 0.45 → 0.29 재스윕 (2026-09-23)

## 왜
`ship_direction.yaml` 의 `half_width: 0.45` 는 작년 배(폭 0.9m) 값. 올해 1번배 폭 0.58m, 2번배 0.43m.
코드는 `min_required_width = half_width*2 + clearance` 로 갭을 고르므로 0.45 면 1.15m 갭을 요구 → 좁은 게이트에서 후진 반복.
`clearance 0.25` 는 0.45 기준 스윕값이라 폭만 바꾸면 안 되고 재스윕 필요.

## 시뮬 정합 (스윕 전에 고친 것)
`~/Desktop/SSF 노드 파일/ssf_sim.py` 가 노드와 어긋나 있었다. 노드(yaml) 기준으로 맞춤:

| 상수 | 시뮬(전) | 노드 yaml | 시뮬(후) |
|---|---|---|---|
| `CLEARANCE` | 0.15 | 0.25 | 0.25 |
| `MIN_OBSTACLE_CELLS` | 3 | 1 | 1 |
| `REAR_OBSTACLE_IGNORE_MARGIN` | 1.0 (활성) | 제거됨([C] 증명된 결함) | `None` (비활성) |

시뮬에 아직 없는 노드 기능: 시간 투표 [G], geofence 병합 [H]. 물보라 오탐이 없는 시뮬이라 결과에는 영향 없음.

## 한계
- 시뮬 접촉 모델은 반경 `half_w` 원. 실제 배는 길이 1.66m 라 선회 중 측면 접촉은 안 잡힌다. 수조에서 게이트 2m 통과로 확인 필요.
- 장애물 구간 접촉 ~1회는 시뮬 장애물 밀도(4m 열마다 2개, ±3.5m 난수) 때문. 실제 코스 밀도 확인 전까지 "0회" 목표는 못 세운다.
- 2번배는 `half_width: 0.215 / clearance: 0.35` 가 시뮬 최적. 배별 yaml 분리가 필요해지면 그때 적용.
