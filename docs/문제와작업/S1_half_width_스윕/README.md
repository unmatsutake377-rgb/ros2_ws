# S1 — `half_width` 0.45 → 0.29 재스윕 (2026-09-23)

## 왜
`ship_direction.yaml` 의 `half_width: 0.45` 는 작년 배(폭 0.9m) 값. 올해 1번배 폭 0.58m, 2번배 0.43m.
코드는 `min_required_width = half_width*2 + clearance` 로 갭을 고르므로 0.45 면 1.15m 갭을 요구 → 좁은 게이트에서 후진 반복.
`clearance 0.25` 는 0.45 기준 스윕값이라 폭만 바꾸면 안 되고 재스윕 필요.

## 시뮬 정합 (스윕 전에 고친 것)
`~/Desktop/SSF 노드 파일/ssf_sim.py` 가 노드와 어긋나 있었다. 노드(yaml) 기준으로 맞춤:

| 상수 | 시뮬(전) | 노드 yaml | 시뮬(후) |
|---|---|---|---|
| `CLEARANCE` | 0.15 | 0.25 | 0.25 |
| `MIN_OBSTACLE_CELLS` | 3 | 1 | 1 |
| `REAR_OBSTACLE_IGNORE_MARGIN` | 1.0 (활성) | 제거됨([C] 증명된 결함) | `None` (비활성) |

시뮬에 아직 없는 노드 기능: 시간 투표 [G], geofence 병합 [H]. 물보라 오탐이 없는 시뮬이라 결과에는 영향 없음.

## 한계
- 시뮬 접촉 모델은 반경 `half_w` 원. 실제 배는 길이 1.66m 라 선회 중 측면 접촉은 안 잡힌다. 수조에서 게이트 2m 통과로 확인 필요.
- 장애물 구간 접촉 ~1회는 시뮬 장애물 밀도(4m 열마다 2개, ±3.5m 난수) 때문. 실제 코스 밀도 확인 전까지 "0회" 목표는 못 세운다.
- 2번배는 `half_width: 0.215 / clearance: 0.35` 가 시뮬 최적. 배별 yaml 분리가 필요해지면 그때 적용.

## 09-28 정정·보강

- 🚨 **0.58/0.43m 는 줄자 실측이 아니다.** 출처 = 팀 치수 + STL(1번배는 1000mm 축소 모델 ×1.66). 위 본문의 "실측" 표기는 틀렸다. yaml·문서 라벨 "설계값" 으로 정정.
- 시뮬 저장소 이관 → `tools/sim/`. 이 폴더의 스크립트는 이관 전 사본(기록용). 앞으로는 `tools/sim/sweep_s1.py`.
- **시드 20 재스윕** (폭 5단계 × clearance 6단계 × dd 2 × 게이트 2 = 2400런, `tools/sim/out/sweep_s1.csv`):

| 폭(m) | half_w | 최적 clearance | 그때 접촉 | 정체 |
|---|---|---|---|---|
| 0.43 | 0.215 | 0.35 | 0.36 | 0% |
| 0.50 | 0.25 | 0.30 | 0.85 | 0% |
| **0.58** | **0.29** | **0.25** | **1.32** | **0%** |
| 0.64 | 0.32 | 0.25 | 1.44 | 0% |
| 0.70 | 0.35 | 0.20 | 2.23 | 0% |

최적점의 갭 요구(`half_w*2+clr`)가 0.78~0.90m 에 모인다. 줄자 실측 폭이 0.58~0.64 면 clearance 0.25 그대로, 0.70 이상이면 0.20.

- **선회 유효 폭** `W·cosθ + L·sinθ` (보고만, 코드 반영 안 함):

| | 0° | 5° | 10° | 15° | 20° |
|---|---|---|---|---|---|
| 1번배 W0.58 L1.66 | 0.58 | 0.72 | 0.86 | 0.99 | 1.11 |
| 2번배 W0.43 L1.70 | 0.43 | 0.58 | 0.72 | 0.86 | 0.99 |

판정: 현재 갭 요구 0.83m 는 1번배가 **약 9° 이내로 정렬**했을 때만 맞다. 게이트(2m − 부표 0.4 = 여유 1.6m)는 20° 비스듬해도 통과. 장애물 사이 1m 안팎 틈은 정렬 없이 들어가면 측면 접촉 가능 — 시뮬이 못 잡는 영역이라 수조 게이트 시험에서 확인.
