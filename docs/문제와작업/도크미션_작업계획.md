# 도크 미션 — 현황 정리 및 작업 계획 (2026-07-24)

> 근거: `ship_dock.py`·`basic_image_subscriberdock.py` 정독(최신 커밋), KABOAT 2025 채점 데이터(도킹 성공 2/24팀, 성공 시 사실상 만점), 우승팀 접근법 대조.
> 이 문서의 "즉시 작업" 절은 그대로 Claude Code 작업지시로 사용한다.

---

## 1. 현재 상태 요약

**제어(ship_dock) — 특화 완료 수준.**
head-on FSM(INIT→SEARCH→ALIGN→APPROACH→CONTACT→BACKOFF), 제자리 선회 정렬 2회(진입+standoff 3m 정밀 재정렬), 25° 초과 시 재정렬 복귀, LiDAR 전방 섹터 최소거리(각도 정합 문제 원천 회피), 거리 미상 시 접근 중단, mode 7 매 틱 발행 계약. 2025 우승팀(도킹 1위) 접근법과 동급 + 방어 설계는 그 이상.
알려진 이론적 한계 1건: 표식 "정면 정렬"이지 도크 슬립 "축 정렬"이 아님 → 측면 접근 시 비스듬 진입 가능. 우승팀도 동일 수준으로 1위였으므로 수용하되, 실해역 테스트 항목으로 등재(§3).

**인식(subscriberdock) — 미션 요구 미달. 여기가 병목.**
미션 규칙: 표식 = 형상(삼각/원/사각) × 색 조합, **당일 공지**. 현 코드는 목표가 하드코딩(`red`/`Square`), 단일 프레임 즉시 발행(시간 안정화 없음), 꼭짓점 수 기반 분류(사각4~6/원7+ 경계 취약), HSV가 특정 조명 캘리브레이션 잔재 + 5색 중 3색만 활성, y범위 필터 하드코딩, `main()`에 죽은 `pipeline.stop()` 호출.

## 2. 즉시 작업 (배 없이 지금 — Claude Code 지시)

기존 계약(토픽 불변, yaml 파라미터화, monotonic, 순수 로직 분리+테스트, 독립 커밋) 유지.

### D1. 목표 표식 파라미터화 — 최우선
`target_color`·`target_shape` 하드코딩 제거 → `config/dock_vision.yaml` 파라미터로. 유효값 검증(색 5종·형상 3종 외 값이면 ERROR 로그 + 발행 중단 — 오타로 조용히 아무것도 못 찾는 것 방지). 당일 아침 입력 절차를 docs에 1문단으로(어느 파일, 어느 키, 확인 방법).

### D2. N프레임 시간 안정화
동일 (색,형상) 판정이 연속 N프레임(파라미터 `confirm_frames`, 기본 3) 이상일 때만 유효 발행. 미달 시 기존 grace/센티널 규약 유지. 판정 로직은 순수 함수 분리 + 테스트(오탐 1프레임 삽입 시 발행 불변 검증).
**연동**: `confirm_frames`·`grace_period_s`를 yaml로 빼서 "열화 환경에서는 N을 올린다"가 파라미터 조정으로 가능하게(§4 팀원 제안의 실효 흡수 지점).

### D3. 도형 분류 강건화 (최소 개입)
epsilon(0.0315)·면적 하한(80)·extent(0.4)·y범위(0.15/0.55)를 전부 yaml 파라미터로. 원/사각 경계는 꼭짓점 수 단독 대신 원형도(circularity = 4πA/P²) 보조 지표 추가(임계 파라미터). 분류 함수를 순수 함수로 분리 + 테스트(합성 도형 이미지로 3형상 × 회전·스케일).

### D4. T7 하네스 상태 확인 및 완성
`tools/dock_eval.py`(rosbag → 프레임별 판정 → 형상×색 혼동행렬 CSV) — **현재 존재 여부부터 보고**하고, 없으면 이번에 구현. D2·D3의 파라미터 튜닝은 이 하네스의 수치로만 결정한다(감으로 조정 금지). 작년 rosbag 자산으로 1차 실행.

### D5. 잔가지 정리
`main()`의 `node.pipeline.stop()` 제거(존재하지 않는 속성 — 종료 시 예외). HSV 5색 슬롯(orange/yellow/white) 주석 해제 + 값은 `⚠️ 야외 캘리브레이션 필요` 표시의 자리표시자로(§3 연계).

### D6. 라이다 노이즈 카운트 로깅 (팀원 제안 축소 채택분)
median 필터가 기각한 점 개수를 회전당 카운트로 blackbox에 기록(관측만, 행동 없음). 목적: 실해역·우천 데이터로 "노이즈 수 ↔ 기상 열화" 상관을 검증한 뒤에만 모드 전환 논의를 재개한다.

**완료 보고**: 변경 파일, 테스트 결과, D4 혼동행렬 1차 수치(작년 rosbag 기준).

## 3. 실기·당일 대기 항목 (벤치 체크리스트 등재)

- HSV 5색 야외 캘리브레이션(맑음/흐림 2조건, hsv 튜닝 노드 사용) — 소프트웨어로 못 하는 유일한 핵심.
- y범위 필터 실측(거리별 표식 화면 높이) 후 파라미터 확정.
- 측면 접근 시나리오 실해역 테스트(축 정렬 한계의 실영향 확인).
- 도크 규격 공지 후 `contact_dist_m`·`backoff_dist_m` 확정.
- `image_positive_is_left` 부호 벤치 검증(기존 항목 재확인).
- 당일 아침: D1 절차로 공지 조합 입력 → 표식 인쇄물로 5m 검증 1회.

## 4. 보류 (폐루프 이후 재논의)

팀원 제안의 가중치 융합 FSM(우천 감지 모드 전환, 카메라-라이다 동적 가중치): 설계 감각(히스테리시스·2단계 검증·가중치 상한)은 우수하나, 도크 병목(표식 분류)은 카메라 단독 과제라 가중치로 해결 불가 + "1프레임 물방울" 가정은 렌즈 맺힘·파도 롤링과 상충 — D6 데이터로 검증 후 내년 시즌 1순위 후보. 렌즈 발수 코팅/후드는 기구팀 전달.
