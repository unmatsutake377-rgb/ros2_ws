## 0. 결론 먼저 (코드 확인 결과)

1. **"카메라 2개"는 fused 에서 사실상 D455 하나다.** perception_fusion 은 OAK 를 색 붙이기에만 쓴다(`perception_fusion.py:104-107`, `fusion_logic.py:92-107`). 그 색 입력인 검출기 3종은 mode 5 에서 모두 꺼져 있다(vision.yaml `active_wp_modes` [0,1]/[2,3]/[7]). 또 LiDAR나 뎁스 덩어리가 없는 OAK 방위는 물체로 만들지 않는다(`fusion_logic.py:12`, `:350-380`). 그래서 mode 5 의 /fused_objects 는 모든 물체가 color_id 0 이고, 정보는 LiDAR 와 D455 뎁스에서만 나온다.
   - 저장소 문서에서 "v3"는 도리도리 대책 v3(색 다수결 LowMap + 회전 가드)를 가리킨다(`계약서_거리융합_20261112.md:6,49-50`). v3 의 색 다수결은 OAK 빨강 검출이 있어야 돈다. 사용자가 말한 'v3'가 이 뜻인지는 사람이 확인해야 한다(아래 결정 F0).
2. **예전 "(2) fused 어댑터 불가" 판정은 반만 뒤집을 수 있다.**
   - /avoid_detections 를 대신해 빨강 색으로 도리도리 지도를 채우는 용도로는 지금도 불가다. 이유는 그대로다: 색이 없고, 색마다 물체 하나이고, 거리 없는 물체는 빠진다.
   - 그러나 `src_id == 1`(depth 단독)은 "LiDAR 가 못 보는 물체"라는 뜻이다. 이 값을 낮은 장애물 판정 기준으로 쓰면 색이 필요 없다. 근거:
     - depth-only 덩어리는 src 1 로 나온다(`fusion_logic.py:373-375`).
     - LiDAR 와 짝이 지어졌어도 뎁스가 더 가까우면 src 1 + flags bit0 으로 나온다(`:310-313`). 예: 낮은 장애물 뒤에 부표가 있는 경우.
   - 대가가 있다. OAK 기여가 0 이고, 색 다수결이라는 오검출 방어가 사라진다. D455 행 띠 기하 실측이 선행 조건이다(위험 1).
3. **D455 가 낮은 장애물을 보는지는 장착 높이·피치에 달려 있고, 지금은 미확인이다.** 행 띠 0.4~0.6(`perception_fusion.yaml:35-36`)과 424×240(`launch_files.launch.py:243`)으로 계산하면 광축 ±약 6.3° 만 본다. 이 값은 D455 VFOV 58° 사양 가정이다(미확인).
   - 피치 0, 높이 h: 낮은 장애물이 d ≥ 9.0·(h − 장애물 높이) 일 때만 띠에 들어온다. 예: h 0.6, 장애물 0.15 → 약 4~6 m 에서만 보이고, 가까워지면 띠 밖으로 사라진다. 그래서 지도 기억이 필수다. 수면은 띠 하단 9.0·h(약 5.4 m)부터 들어온다.
   - 마스트 설계값 "D455 아래 −15°"(`docs/전달용/하드웨어_배치_요구사항.md:21`): 띠가 수면 약 1.5~3.9 m(h 0.6)를 정면으로 본다. 뎁스가 수면을 유효값으로 내면 **src 1 유령 장애물이 계속 생긴다**.
4. **추천 의미는 (a2) "fill 형" fused 다.** 평소에는 지금과 같은 20000 이고 ship_direction (C) LiDAR 회피를 그대로 쓴다. depth 단독 확정 장애물이 진로 앞에 있을 때만 ship_avoid 가 (B) 안전 헤딩으로 넘겨받고, 지나면 다시 20000 이다.
   - 기준 방위는 WP 방위 `/north_goal_angle_tp` 를 쓴다. 그래서 **ψ0 고정 문제(core.py:236)에 의존하지 않는다.**
   - depth 단독 물체가 없으면 lidar 와 비트 단위로 같은 출력이다.
5. **오늘 밤(11-14 시험 전) 권고**는 셋 중 하나다.
   - (T1) src 변경 없이 11-14 에 rosbag 으로 D455 데이터만 모은다.
   - (T2) U1(C3)+U2(fused 배관, 기본 lidar)만 넣는다. C4 전에는 fused 를 골라도 20000 이라 동작이 변하지 않는다.
   - fused 를 물 위에서 실제로 켜는 것은 시뮬과 D455 수면 데이터를 본 뒤에 한다.

### (a2) 상세 설계 (구현자용 — 숫자에 "미확인"이 붙은 것은 시뮬로 정한다)

- **지도:** `core.LowMap` 재사용, 별도 인스턴스. 넣는 조건은 아래를 모두 만족하는 물체다.
  - `src_id == 1`
  - flags bit1(LiDAR stale) 아님
  - `conf ≥ fused_min_conf`
  - `age_s ≤ fused_max_age_s`
  - `range_m ≤ fused_max_range_m`
  - |yaw rate| ≤ `fused_max_yaw_rate_dps`
  
  red 플래그는 모두 True 로 넣고, 확정은 `fused_confirm_n` 만 본다.
  - LiDAR 로 지우지 않는다(계획서_장애물지도 R1).
  - 회전 중에는 넣지 않는 이유: 30°/s × age 0.3 s = 방위 9° 오차가 생긴다.
- **인수 조건:** 아직 안 지나친 확정 트랙이 tp 방향 직진 예측 경로에서 선체 여유 < `clear_low` 이고, 거리 ≤ `fused_trigger_m` 이다.
- **해제 조건:** 그 트랙이 선체 뒤로 지나감(`s_o < s_b − (half_l + low_r)`, `core.py:374` 와 같은 판정). 이때 20000 으로 돌아간다.
- **인수 중 출력:** `_drive_step` 의 안전 헤딩 탐색(±max_steer, step_deg)을 쓰되 기준 방위는 `wrap180(yaw − tp)` 로 바꾼다.
  - 장애물 = 확정 트랙(low_r) + 원시 /scan 점(1° 칸 최솟값으로 줄임, 3.5 m 안) + 노란부표 군집.
  - 안전 헤딩이 하나도 없으면 50000(C5③ 와 같은 문제 — 시뮬로 50000/20000 결정).
- **넘겨받는 순간 주의:** ship_direction (C) 옆 잠금 상태와 ship_avoid 의 편 선택이 다를 수 있다. 시뮬로 확인한다.

- **위험** (조용히 깨질 수 있는 곳)
  1. **수면 유령 장애물.** D455 행 띠가 수면을 보면 src 1 물체가 계속 생기고, fused 는 존재하지 않는 장애물을 피해 (B)로 넘겨받는다.
     - 피치 −15° 설계(`하드웨어_배치_요구사항.md:21`)에서는 띠가 수면 약 1.5~3.9 m(h 0.6 가정)이다.
     - 띠·높이는 미실측이다(`perception_fusion.yaml:35-36`, `fusion_logic.py:182-216`).
     - doridori_sim 의 D455 모델은 띠 기하가 없다. ±43.5°·6 m 안이면 항상 거리를 준다(`doridori_sim.py:66,460-461`). 그래서 시뮬은 이 위험을 못 본다.
  2. **뎁스 사망이 드러나지 않음.** 뎁스만 죽으면 /fused_objects 는 계속 오고 src 1 만 사라진다(`fusion_logic.py:342-354`). 그러면 fused 는 조용히 lidar 와 같아진다. 동작은 안전한 쪽이지만, `/fusion_status` 를 안 보면 "fused 로 시험했다"는 기록이 거짓이 된다. 2번배 D455·허브 시험 여부도 미확인이다(`launch_files.launch.py:260`).
  3. **(B) 인수 중 키 큰 장애물과 경계.** (B)에는 LiDAR 회피가 없고 geofence 정지 가드만 있다(`ship_direction.py:1030-1074`). 원시 /scan 가드를 빠뜨리면 기존 위험 2 가 fused 에서 재현된다. `lidar_buoys.py:23-25` 는 넓은 군집을 버리므로 그것만 쓰면 안 된다.
  4. **이동 구간 mode 5 인수.** U1 없이 U2 를 넣거나 zone 게이팅을 빼면, 도크 정렬 6 m(mode 5, `waypoints.yaml:44`) 앞의 낮은 도크 구조물에서 인수가 일어나 정렬점에서 비켜 간다. 또 zone 은 `geofence_avoid_polygon` 을 채워야 켜지는데(빈 값이면 늘 false), 이 폴리곤은 (C) 경로의 장애물 구간 벽(실격 방어)도 함께 켠다(`geofence_rays.py:170-175`). 두 효과가 묶여 있다.
  5. **처리량과 시간 어긋남.** 원시 /scan 점 × 13 헤딩 × 4 예측점 hull_clear 를 Python 10 Hz 로 돌리면 틱이 밀릴 수 있다(1° 칸으로 줄일 것). /fused_objects age 최대 0.5 s × 이동 0.7 m/s ≈ 0.35 m 위치 오차가 생긴다. 회전 중 방위 오차는 yaw_rate × age 다. GPS 안테나와 LiDAR 원점 레버암, D455 장착 오프셋(`cam_*` 0.0)은 미실측이다.
  - (참고) 형식 사본이 5곳이 된다. ship_back 의 `test_fused_match.py:221` COPIES 는 ship_turn·ship_gate 만 보므로, ship_avoid 사본은 **ship_avoid 자체 테스트**에서 perception_fusion `fusion_logic.py` 와 ship_back `hold_logic.py` 를 경로로 읽어 비교해야 한다(다른 패키지 수정 없이).
