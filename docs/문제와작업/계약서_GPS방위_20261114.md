# 변경 계약서: `yaw_mux` 에 `heading_source: gps_cog` 추가 (GPS 도플러 진행방향 → `/imu/yaw`, 2번배만, 파라미터 하나로 되돌림)

> 상태: **승인됨** (11-14, 2번배 세션, `ssf-contract` 작성). 본문 Q1~Q8 + 부록 R 결정은 아래 '결정' 두 섹션.
> 배경: 2번배 11-14 종합 주행에서 IMU(지자기 융합) 방위 오차가 방향 따라 −66°→+150° 로 변해 WP2 반대로 187 m 이탈.
> 도플러 진행방향은 RTK 없이도 궤적 방향과 중앙 2.0~2.7° 일치. 실제 주행 구간 속도 비율: ≥0.3 m/s 87%, ≥0.5 m/s 83%, ≥0.8 m/s 68% (Q3 근거).
> 메인 세션 확인: 위험 2(`ship_direction.py:803-826` [N] 교착), `yaw_mux.py:169`(ST_OK 일 때만 발행), 위험 1(`core.py:757-778` 도리도리가 `pose.yaw` 로 SPIN 폐루프) 코드로 확인함.

## 사용자(2번배 담당)가 정한 규칙
1. 전진 중이고 속도가 충분할 때만 도플러 COG 로 갱신.
2. 정지 중엔 시간 제한 없이 마지막 방위를 유지하고 계속 발행(충돌로 도는 경우 제외).
3. 1 Hz 사이는 직전 두 COG 의 회전 속도로 예측해 더 자주 발행.
4. 미션 사이 직진 구간은 진행 방향 = 뱃머리 방향.
5. 후진·제자리 선회 중엔 갱신 안 하고 마지막 방위 유지.
6. 이 모드에서 IMU 값은 배제.

노드 하나 `ssf_heading/yaw_mux` (같은 패키지 `heading_logic.py`·`config/`·`test/` 까지). §1-1 원자 묶음(비전 묶음·6a)에 안 걸림. `active_wp_mode(s)`·`/candidate_angle` 발행자·토픽 이름 불변.

커밋 순서(각 중간 상태가 안전한 이유):
1. **C1 코드+테스트** (`heading_logic.py`, `yaw_mux.py`, `ssf_heading.yaml` 새 키 추가, `test_heading_logic.py`) — 기본값 `imu_relative` 그대로라 두 배 다 동작 불변. 새 구독(`/desired_angle`, 조건부 `/north_goal_angle_tp`)은 기존 발행자가 있는 토픽이라 침묵 구간 없음.
2. **C2 2번배 전환** (`ssf_heading_B.yaml` 에 `heading_source: "gps_cog"` 한 줄 + `test_boat_config.py` 허용 키 조정) — 되돌리기 = 이 줄 하나. install/config 가 src 로 심링크라 재빌드 없이 launch 재시작만. `heading_source` 는 init 에서 한 번 읽음(`yaw_mux.py:44`) → `ros2 param set` 으로는 안 바뀜.

## 특수 상수·모드·규약
- `/desired_angle` 5000(SPIN_RIGHT)·6000(SPIN_LEFT)을 yaw_mux 가 읽게 됨 → 상수 정의 파일 하나 증가. §1-8 대로 공유 모듈 안 만듦, ssf-reviewer 6번 점검 대상.
- CLAUDE.md §3 은 6000 을 "발행 노드 없음, 예약"이라 적었지만 ship_dock(`ship_dock.py:411,488`)·ship_avoid(`core.py:777`)가 6000 을 냄 → 문서 낡음.
- 260/180(후진)은 `/desired_angle` 이 아니라 `/motor_reverse` 로 거름(규칙 5). 50000(정지)은 따로 안 거름 — 속도 게이트가 막음.
- yaw_mux 는 PWM 을 해석하지 않음. `Motor_run` 디코드 금지(규약 복제, `motor_control.py:140-143` 취지).
- 자기편각: COG 는 진북 → `SOURCE_IS_MAGNETIC[gps_cog] = False` (`heading_logic.py:41`, `test_magnetic_table_covers_every_source` 가 강제).
- `mount_offset_deg`·`invert_yaw` 를 gps_cog 에 적용 금지 — B 로컬 40.3 이 적용되면 40° 틀어짐. `_correct()` 를 안 거치는 분기로(cog_offset 과 같은 이유, `heading_logic.py:394`).
- `gps_vel_frame: enu` 는 ublox 코드와 맞음. ZED-F9P 가 `firmware7plus` 경로를 타는지는 ⚠️ 미확인이나, 도플러↔궤적 2~2.7° 일치가 사실상 프레임 확인.
- CLAUDE.md §3 "`heading_source: cog_offset` 사용 금지"와는 **별개 모드**(IMU·오프셋 추정기 안 씀). 그 줄은 건드리지 않고 gps_cog 줄을 따로 추가(C5).

## 위험
1. 🚨 **ship_avoid fused 도리도리 고장.** SPIN 을 `/imu/yaw` 로 닫는데(`core.py:760,771-777`) gps_cog 는 선회 중 방위를 고정 → 오차가 안 줄어 `dori_timeout_s` 25 s(`ship_avoid.yaml:53`)까지 제자리 선회 후 중단, 이후 DRIVE 는 돈 만큼 틀린 방위. 지도 배치도 yaw 사용(`ship_avoid.py:229,247`). B 작업트리 `geofence_avoid_polygon` 이 채워져 있어(`north_goal_angle_main.yaml:11`, 미커밋) WP6→7 에서 fused 가 실제로 켜짐(Q4).
2. **출발 교착.** 첫 유효 COG 전에 발행 안 하면 ship_goal_angle 이 `/yaw_error` 를 안 냄 → ship_direction [N] 이 '`/yaw_error` 한 번도 못 받음 + 20000' 을 50000 으로 바꿈(`ship_direction.py:808-826`, `failsafe.py:220-231`) → 배가 안 움직여 COG 영영 안 생김. 토너먼트(전부 mode 8 = 20000)와 게이트가 안 보이는 WP0(`ship_gate.py:313`)에서 확정적으로 걸림(Q1).
3. **선회 직후·후진 관성.** `/motor_reverse` 는 순간 PWM 기준 → 후진 명령이 끝나도 뒤로 밀리는 동안 COG 는 180° 반대인데 게이트는 이미 false. 0.5 m/s 넘게 밀리면 채택됨. 종합 런 후진 595행·경기 1684행으로 실제 발생. `geofence_stop` [I](`ship_direction.py:956-996`)·north 광선(`north_goal_angle.py:687`)이 그 yaw 로 돌아 거짓 정지/경계 누락 가능(Q5).
4. **gate=off 가 healthcheck 에 안 잡힘.** 검사가 `hs.startswith("cog_offset:")` 뿐(`healthcheck.py:295`) → gps_cog 에서 게이트를 끄면 `/health_ok` true 유지(C3).
5. **HOLD 가 healthcheck 에서 묻힘.** 현재 `/heading_status` 끝에 ` n=… R=… off=… rej=…` 가 붙어(`yaw_mux.py:201-205`) `endswith(":OK")`(`healthcheck.py:240`)가 늘 거짓 → 정상일 때도 매번 `⚠️ heading_status=…` (기존 결함, 진단 전용). HOLD 를 드러내는 수단은 yaw_mux 주기 WARN 과 `/heading_status` 문자열. blackbox 는 `/heading_status` 미기록(`blackbox.py:87-143`).
- (부가) ship_turn ORBIT: 속도가 임계 아래면 yaw 고정 + rel ≈−90 고정 → 진행각이 안 쌓임 → `orbit_max_sec` 60 s(`ship_turn.yaml:21`)로 끝남. 임계 0.8 이면 위험 커짐.
- (부가) `/fix`·`/fix_velocity` 는 같은 NavPVT 콜백 → GPS 가 죽으면 north `goal_stale_sec` 2.0 → `/yaw_error` 정지 → 페일세이프 경로 그대로. '무기한 유지'가 실제로 걸리는 건 GPS 는 살아 있고 배가 느리거나 후진·선회 중일 때뿐.
- (부가) 작업트리 `ssf_heading_B.yaml` 에 미커밋 로컬값 `mount_offset_deg: 40.3` → C2 커밋 때 딸려 들어가지 않게 부분 스테이징 필요(Q6).

## 구현 요구(계약)
- **표본 채택 조건**: 속도 ≥ `gps_cog_min_speed_mps`, `reverse_state` False, 최근 `/desired_angle` 이 5000/6000 아님, 선회·후진 종료 뒤 settle 경과, finite. 후진 상태 모름(None)이면 `cog_require_reverse_gate` 일 때 거부, `/desired_angle` 모름도 거부(Q5).
- **회전율**: 직전 두 채택 표본(간격 ≤ fresh)으로, ±max_rate 클램프, `predict_max_sec` 까지만 외삽.
- **거부·선회 시작 시** 그 순간 출력값에서 **얼림**(마지막 COG 로 되돌아가며 튀지 않게).
- **상태와 발행**: HOLD 에서도 `/imu/yaw` 발행 — 지금은 `status == ST_OK` 일 때만 발행(`yaw_mux.py:169`)이라 고침. HOLD 는 `SILENT_STATES` 에 안 넣음. HOLD 가 N 초 넘으면 throttle WARN, OK 복구 시 INFO(호출 지점 분리, §1-7). gps_cog 는 IMU 슬롯을 읽지 않음(테스트로 보장).

### 융합 규칙 (추천안, 확정은 R-Q2·R-Q3)
- **카메라**: 프레임 쌍마다 회색·1/`cam_downscale` 축소·ROI 띠(자기 선체·물 제외) → `cv2.phaseCorrelate`(Hanning). Δ = −atan(dx·scale / fx). fx 는 **camera_info 에서**(hfov 로 지어내지 않음, 없거나 K 무효면 카메라 무효 + ERROR 1회 후 5 s 간격). 응답 ≥ `cam_min_response`, |Δ| ≤ `cam_max_step_deg` 만 채택.
- **라이다**: r ∈ [0.5, 20] m, finite. 각도는 매 스캔 `angle_min`/`angle_increment`(918A 0.223°, 80BF 0.250°). 거친 단계 1° 점유 히스토그램 원형상관(±`lidar_max_step_deg`) → 고운 단계 2D 점대점 ICP(회전 + 평행이동 ≤ 0.3 m, 10회, numpy 전수 최근접, scipy 등 새 의존성 없음). 채택: 점 ≥ 30, 각도 퍼짐 ≥ 30°, 잔차 ≤ `lidar_max_residual_m`.
- **둘 다 유효**: 라이다 스캔 구간마다 같은 구간 카메라 Δ 합과 비교. |차| ≤ `agree_tol_deg` → 카메라 값(src 3). 넘으면 seg 끊고 발행 정지 → yaw_mux 얼림.
- **카메라만**: 카메라(src 1). **라이다만**: 라이다(src 2, 11 Hz 계단).
- **둘 다 무효**: `max_gap_sec`(0.3) 이하면 직전 회전율로 메움, 넘으면 seg 끊음.

### 입력 규약 (코드 확인)
**Δ 의 부호**
- `/imu/yaw_raw` 는 드라이버가 CW 로 뒤집은 값(`iahrs_driver.cpp:231-232`). 부팅 0점화(`:247-261`, launch `:501` False)·GPS 덮어쓰기(`:269-272`, launch `:502` False) 꺼짐.
- `invert_yaw` 는 그 CW 변환이 틀렸을 때의 탈출구(`heading_logic.py:22-23,130`) → **Δ 에 반드시 반영**: `Δ_i = ang_diff(_cog_frame_yaw(r_i), _cog_frame_yaw(r_{i-1}))` = s·Δr (`heading_logic.py:658-665` 재사용).
- `mount_offset_deg`·편각은 상수라 Δ 에서 상쇄 → 무관(B 로컬 40.3 무관).

**적분 방식**
- 샘플마다 Δ 누적(직전 **원시 샘플** 대비). 출력 = 앵커 + ΣΔ, `wrap360`. ΣΔ 는 unwrapped → 360° 넘는 선회 보존.

**튐 처리**
- |Δ_i| > `gps_cog_imu_max_step_deg` 인 샘플은 그 Δ 만 버린다. 한 샘플 튀었다 돌아오면 두 Δ 를 다 버려 순증 0, 기준 계단이면 그 한 샘플만 손실.
- °/s 기준은 쓰지 않는다(Float64 에 stamp 없음, 큐 몰림 시 dt≈0 거짓 거부).
- 이유: 드라이버 `SendRecv` 는 응답이 잘려도 `len` 을 돌려줘 초기화 안 된 `data[2]` 를 낼 수 있다(`iahrs_driver.cpp:186-197,221-223`). 녹화본 ±82° 튐의 원인인지는 ⚠️ 미확인. NaN·inf 는 `is_finite`(`heading_logic.py:517-518`).

**IMU stale**
- 보조 중 IMU 가 `stale_sec`(0.5, `yaw_mux.py:60`) 넘게 안 오면 보조 종료, 마지막 IMU 샘플 시점 값에서 멈춤(안 튐).
- 기동 시작 순간 IMU 없음/stale → 보조 시작 안 함 → C1 얼림.
- `stale_sec` 재사용은 B-Q3(IMU 출력·후진·선회·보조 네 곳 결합, C1 리뷰 권고 3 의 연장).

**`imu_relative` 보호**
- `update_imu` 의 `_imu` 슬롯·`_turn_rate_dps`(`heading_logic.py:516-524`) 그대로. gps_cog 분기 `heading()`(`:620-625`)는 계속 `_imu` 를 읽지 않음. Δ 는 `update_imu` 에서 추적기로 밀어 넣는다.
