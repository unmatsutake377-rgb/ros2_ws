# 계획서: 장애물 지도(두 층) — 도리도리 카메라 지도 + 주행 중 LiDAR 갱신 + 신뢰도 누적으로 회피 강화

- 작성 2026-11-13 (맥 세션, 사용자 아이디어 정리). 상태: **계획 — 계약서·구현 전**. 일정: **대회 뒤**(src 동결·실측 0회).
- 범위: 장애물 회피(mode 5, 이후 토너먼트 mode 8 검토). 이 문서는 무엇을·어떤 순서로·무엇으로 판단할지 정한다. 코드 변경은 이 계획의 시뮬 결과로 계약서를 따로 쓴 뒤.
- 관련: `계약서_도리도리회피_20261112.md`(ship_avoid, 미승인), `계약서_인식융합_20261112.md`(perception_fusion `/fused_objects`, 11-13 대회 켬), `계약서_카메라장애물_20261111.md`(브랜치 feat/vision-obstacle).

## 1. 아이디어 (사용자 11-13)
1. 도리도리(멈춰서 좌우 둘러보기)로 카메라 거리를 구해 **위에서 본 지도**를 그린다. 지도는 네모 칸으로, **갈 수 있는(장애물 없는) 칸**을 표시한다.
2. 도리도리 사이 이동 거리를 반영해 지도를 갱신한다(배가 움직여도 장애물은 땅에 고정).
3. 주행하면서 **LiDAR 측정값을 지도에 반영**하고, 도리도리할 때마다 **신뢰도를 조절**해 지도를 점점 정확하게 만든다.
4. 지도에 저장한 장애물 위치·거리 + 주행 중 LiDAR·카메라 2개 신뢰도 기반 거리로 주행 → **아웃-인-아웃을 매끄럽게**.

## 2. 핵심 규칙 (반드시)
| # | 규칙 | 이유 |
|---|---|---|
| R1 | 🚨 **낮은 장애물 층은 LiDAR 수치로 고치지 않는다.** LiDAR 의 '빔'(빔이 지나간 칸) 증거는 낮은 층에 **넣지 않는다**. 낮은 층을 칠하고 지우는 건 카메라(OAK 색·방위 + D455 뎁스)뿐 | LiDAR 빔은 낮은 빨간 장애물 위로 지나간다 → "비었다"로 잘못 지운다. 도리도리를 만든 이유(LiDAR 가 못 보는 장애물)가 통째로 사라진다 |
| R2 | 안 본 칸은 **'모름'** — '비어 있음'이 아니다. 주행 가능 = **확실히 빈 칸만** | 안 본 곳으로 들어가 충돌 |
| R3 | 지도 갱신은 **위치를 믿을 때만**: RTK FIXED + IMU 신선. FLOAT·끊김이면 갱신 멈춤(읽기는 계속, 시간이 지나면 신뢰도 감쇠) | 위치가 틀리면 장애물이 엉뚱한 칸에 박힌다 |
| R4 | 증거는 **누적하고 서서히 잊는다**(시간 감쇠) — 한 번의 관측으로 칸을 확정하거나 지우지 않는다 | 물보라·반사 한 번으로 거짓 장애물/거짓 빈 칸 방지 |
| R5 | 지도는 **보조**다. ship_direction 의 원래 LiDAR 갭 회피·페일세이프(SensorWatch L1/L2)는 그대로 | 지도가 틀려도 지금보다 나빠지지 않게 |
| R6 | 거리는 sim·실측 근거 없는 값으로 정하지 않는다 — 가정값은 ⚠️ 표시 | 침묵하는 오차 방지 |

## 3. 지도 구조
- **좌표**: 세계 고정(로컬 평면 = 출발 첫 RTK fix 기준 동·북 m). 배 자세 = RTK 위치 + `/imu/yaw`.
- **칸**: 0.25 m ⚠️(배 반폭 0.29 m·장애물 크기·카메라 오차로 시뮬에서 정함), 장애물 구간 30×12 m 면 120×48 칸.
- **두 층**(R1):
  | 층 | 담는 것 | 칠하는 센서 | 지우는 센서 |
  |---|---|---|---|
  | 높은 층 | 부표·벽·도크·다른 배 | LiDAR + 카메라 | LiDAR(빔) + 카메라 |
  | 낮은 층 | 낮은 빨간 장애물 | 카메라만 | **카메라만** (LiDAR 빔 무시) |
- **칸 값**: 층마다 점수 L(로그 오즈). L>+θ_occ = 막힘, L<−θ_free = 빔, 그 사이 = 모름. 시작은 0(모름).
- **주행용 합성**: 막힘 = 높은 층 막힘 OR 낮은 층 막힘. 갈 수 있음 = 두 층 모두 '빔'(R2) — 모름이 하나라도 있으면 갈 수 없음.

## 4. 갱신 규칙
| 관측 | 높은 층 | 낮은 층 |
|---|---|---|
| LiDAR 빔이 물체에 맞음(끝점 칸) | + w_L·occ | — (넣지 않음) |
| LiDAR 빔이 지나감(끝점 앞 칸들) | − w_L·free | **— (R1, 넣지 않음)** |
| 카메라 물체(색·방위 + 뎁스/행 거리) — 노랑·부표 | + w_C·occ | — |
| 카메라 물체 — 빨강 낮은 장애물 | — | + w_C·occ |
| 카메라 정지 촬영(도리도리)에서 시야 안·거리 안인데 물체 없음 | − w_C·free(약하게) | − w_C·free(약하게) |
| 시간 경과 | L ← L·decay | L ← L·decay(더 느리게 ⚠️ — 다시 볼 기회가 적다) |
- 무게: w_L > w_C(뎁스) > w_C(행 추정) ⚠️. 카메라 무게는 §5 자동 보정으로 조절. 한 번 관측의 상한·L 상한을 둔다(포화 방지).
- 카메라 거리 오차를 칸에 퍼뜨린다: 거리 σ(뎁스 ~z², 행 추정 ~피치 오차)만큼 방사 방향 여러 칸에 나눠 더한다.

## 5. 신뢰도 자동 보정 ("도리도리할 때마다 정확도가 오른다")
- **둘 다 보는 물체**(노란 부표·흰 부표 — LiDAR 에도 보이는 높은 물체)에서 카메라 거리 − LiDAR 거리를 계속 모은다.
  → 카메라의 치우침(배율·상수)과 흔들림(σ)을 추정 → 카메라 거리 보정 + w_C 조절(흔들림 크면 낮춤).
- 소스별 신뢰도 식은 perception_fusion 과 같은 계열(유효율 × (1 − 0.5·MAD항 − 0.5·점프율)), 소스·거리대별로.
- 🚨 보정은 **높은 물체에서만 배운다**(R1: 낮은 장애물은 LiDAR 참값이 없다). 배운 보정을 낮은 층 카메라 거리에 적용.
- 보정값은 배별·날씨별로 다를 수 있다 → 로그로 남기고 매 경기 처음부터 배우되 범위를 제한(⚠️ 상·하한).

## 6. 주행에 쓰는 법 (두 단계)
- **단계 A — 가짜 LiDAR 로 섞기(작은 변경)**: 지도 '막힘' 칸을 배 기준 각도별 최근접 거리로 바꿔 `/virtual_obstacle_state` 로 낸다 → ship_direction (C) 경로에서 LiDAR 와 min 병합(도리도리 계약서 단위 ①). '모름' 칸은 넣지 않는다(지금 LiDAR 회피가 맡음 — R5).
- **단계 B — 경로 계획(매끄러운 아웃-인-아웃)**: '갈 수 있음' 칸 위에서 회피 시작→끝 경로 탐색(A*) → 곡선 다듬기 → 다음 목표 방향을 ship_direction 목표각으로. 계획이 없거나 오래되면 단계 A 로 되돌림.
- 도리도리 시점: 지금 규칙(낮은 장애물 하나 지날 때마다 + 확정 장애물이 앞에 없으면 3 m 마다) 유지, 지도에 **'모름' 칸이 진행 방향에 있을 때만** 도리도리하도록 줄이는 안을 시뮬로 비교(멈춤 시간 = 기록 손해).

## 7. 노드·토픽 (계약서에서 확정)
- 지도는 `ship_avoid` 의 `LowMap`(GPS 세계좌표 점 목록 + 칼만, confirm_n 3, red_ratio 0.6)을 **두 층 칸 지도**로 확장하거나 새 모듈 `obstacle_grid`(순수 로직) 신설 — 계약서에서 결정.
- 입력: `/scan`(높은 층), `/fused_objects`(perception_fusion — 카메라·LiDAR 물체), 도리도리 정지 촬영 결과, `/ublox_gps_node/fix`(RTK 상태), `/imu/yaw`, `/wp_mode`.
- 출력(안): `/virtual_obstacle_state`(단계 A), `/obstacle_grid`(관측용 OccupancyGrid 또는 Float32MultiArray — 블랙박스·rviz), `/avoid_state`.
- `/candidate_angle` 발행자 중복 금지(mode 5 원자 묶음 — 도리도리 계약서 §2 ③).

## 9. 위험
1. 카메라 거리 오차가 지도에 남는다 — §4 σ 분산 + §5 보정 + R4 감쇠.
2. 위치 오차(RTK FLOAT·IMU 방위 기준 변경 — 1번배 IMU 는 USB 전원 기준 상대각) → 지도가 통째로 밀림. R3 + 방위 기준 확인 절차(§9-0g).
3. 수면 반사·물보라로 거짓 장애물 → 높은 층은 LiDAR 빔이 지워 주지만 **낮은 층은 R1 때문에 LiDAR 로 못 지운다** → 낮은 층 확정 조건을 더 엄격히(confirm_n·색 다수결·뎁스 일치).
4. 도리도리 멈춤 시간 = 기록 손해 — §6 시점 조건.
5. CPU: 120×48 칸 × 두 층, 10 Hz 갱신은 가볍다(⚠️ 배 노트북 실측).
6. 지도가 틀리면 회피가 더 나빠질 수 있다 → R5(LiDAR 갭 회피 유지, 지도는 min 병합만), 스위치 기본 꺼짐.
