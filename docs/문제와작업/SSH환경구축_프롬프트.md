## 왜 보류인가

배 노트북(= SSH 서버)은 여기 있는데 **붙을 기기(클라이언트)가 없다.**
노트북이든 태블릿이든 폰이든, 물가에서 조작할 기기가 생기면 그때 시작한다.

## 아래를 그대로 던지면 된다

```
SSF 자율운항선박 대회용 Ubuntu 노트북에 SSH 원격 접속 환경을 구축해줘.

## 왜 필요한가
배가 물에 뜨면 이 노트북은 방수 케이스 안에 들어가서 화면·키보드를 쓸 수 없다.
그런데 대회 중에 launch를 띄우고, 로그를 보고, 웨이포인트를 찍어야 한다.
SSH가 유일한 조작 통로다. CLAUDE.md 3-3에 "배는 SSH로 띄운다 = 헤드리스다"가
이미 전제로 깔려 있고(debug_view 기본 false가 그 때문), boat_boot.sh도 헤드리스면
xset을 건너뛰게 돼 있다.

## 현재 상태 (2026-08-07 확인)
- 배 노트북: Ubuntu 22.04.5 / hostname `ssfb-IdeaPad-Slim-3-15IAH8` / 사용자 `ssfb`
- `openssh-client`만 설치됨. **`openssh-server`는 없음**, ssh 서비스 inactive
- `ufw` 방화벽 active
- `avahi-daemon` active (mDNS 가능 → `호스트명.local` 접속 여지 있음)
- 무선만 사용(유선 포트 없음). 실내는 공유기, 야외는 휴대폰 핫스팟
- 워크스페이스 `~/ros2_ws`, ROS2 Humble, 빌드 완료 상태
- sudo는 비밀번호가 필요하고 CLI로는 입력이 안 된다 → `pkexec`로 GUI 인증 창을 띄워 처리할 것

## 해야 할 일
1. `openssh-server` 설치·활성화
2. 방화벽에서 SSH 허용 (ufw)
3. 접속 확인 — 다른 노트북에서 실제로 붙어보고, 원격에서
   `ros2 launch launch_files launch_files.launch.py`와
   `ros2 run north_goal_angle waypoint_recorder`가 정상 동작하는지 검증
   (waypoint_recorder는 키 입력이 필요하므로 SSH 세션에서 Enter/q가 먹는지 반드시 확인)
4. 주소 문제 해결책 제시 — 아래 참고

## 🚨 반드시 고려할 것

**주소가 매번 바뀌면 대회 당일 접속을 못 한다.**
핫스팟이 주는 IP는 재접속마다 달라질 수 있다. 실내 공유기에서는 192.168.0.52였고
야외 핫스팟에서는 172.20.10.2였다. 대안(고정 IP / mDNS `.local` / 핫스팟 DHCP 예약 등)을
장단점과 함께 제시하고, 이 팀 상황에 맞는 걸 추천해줘.
mDNS는 클라이언트 OS에 따라 동작이 다르니 실제로 되는지 확인이 필요하다.

**보안.**
SSH를 켠다는 건 원격 접속을 허용한다는 뜻이다. 대회 전용 노트북이라 과한 방어는
불필요하지만, 최소한 비밀번호 로그인 허용 여부·키 인증 사용 여부는 근거를 대고 정해줘.
※ 이 노트북에는 이미 GitHub용 SSH 키가 있다(`~/.ssh/id_ed25519`, 암호 없음).
  그건 '나가는' 인증용이고 이번 건은 '들어오는' 접속이라 별개다. 혼동하지 말 것.

**되돌릴 수 있게.**
`boat_boot.sh`가 런타임 설정만 만지고 재부팅하면 원복되는 것과 같은 철학이다.
영구 설정을 바꿀 때는 무엇을 바꿨는지 기록하고, 되돌리는 방법도 남겨줘.

## 작업 방식
- 실물로 검증할 것. "설치했으니 되겠지"는 안 된다.
  이 프로젝트는 실물 검증에서만 나온 버그를 8건 잡았다.

- 체크리스트(`docs/문제와작업/소프트_작업체크리스트.md`)의 SSH 항목도 갱신.
```

## 일부러 정하지 않은 것

아래 둘은 **네트워크 환경이 정해져야 답이 나온다.** 미리 못박으면 틀린 전제로 작업하게 된다.

| 항목 | 왜 미정인가 |
|---|---|
| 고정 IP vs mDNS vs DHCP 예약 | **대회장에 WiFi 가 있는지, 핫스팟만 쓸지** 아직 모른다 |
| 비밀번호 로그인 허용 여부 | 위 선택과 운용 방식(누가 붙는지)에 딸려 온다 |

## 시작 전 다시 확인할 것

```bash
dpkg -l | grep openssh-server        # 설치 여부
systemctl is-active ssh avahi-daemon # 서비스 상태
sudo ufw status                      # 방화벽
ip -4 -br addr                       # 현재 IP
```
