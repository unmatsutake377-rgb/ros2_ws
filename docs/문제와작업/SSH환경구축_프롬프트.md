## 왜 보류인가

배 노트북(= SSH 서버)은 여기 있는데 **붙을 기기(클라이언트)가 없다.**
노트북이든 태블릿이든 폰이든, 물가에서 조작할 기기가 생기면 그때 시작한다.


---

## 🚨 먼저 읽을 것 — 전제가 바뀌었다 (2026-08-07 추가)

아래 프롬프트는 **"WiFi(휴대폰 핫스팟)로 붙는다"** 를 전제로 쓰여 있다.
**그 전제로는 코스를 커버하지 못한다.** 착수 전에 이 절을 반드시 반영할 것.

### 거리 문제

| | 거리 |
|---|---|
| 대회 코스 (`waypoints.yaml`) | 남북 106m · 동서 65m · **최대 116m** |
| 휴대폰 핫스팟 실외 실효 | **약 20~30m** (5GHz 는 더 짧다) |

**핫스팟으로는 안 된다.**

### 🚨 더 큰 문제 — NTRIP 도 같은 링크를 쓴다

```
캐스터(인터넷) ──▶ 배 노트북 ──▶ F9P     RTCM 5.4Hz, 경기 내내 계속
```
네트워크가 끊기면 **FIXED(±1.5cm) → float(±10cm) → 단독(±3~5m)** 으로 떨어진다.
SSH 끊김은 "못 본다" 지만, **NTRIP 끊김은 "배가 엉뚱한 데로 간다"** 이다.

### 안전은 SSH 에 걸려 있지 않다 (과대평가 금지)

| 통로 | 역할 | 끊기면 |
|---|---|---|
| **RC 조종기 (FS-i6)** | 수동 제어·비상 | 별도 무선. SSH 와 무관 |
| SSH | 설정·로그 관찰 | 못 봄. **배는 자율로 계속 간다** |
| NTRIP | RTK 보정 | 정밀도 저하 🚨 |
| blackbox | 기록 | **로컬 저장이라 영향 없음** |

### 경기 중 SSH 는 필수가 아니다 — 필수는 '웨이포인트 녹화'다

| 시점 | 배 위치 | 핫스팟으로 되나 |
|---|---|---|
| launch 띄우기 · `/health_ok` 확인 | **물가(출발 전)** | ✅ |
| **웨이포인트 녹화** | **코스 각 지점** | ❌ **여기가 진짜 요구사항** |
| 경기 중 로그 관찰 | 코스 전역 | ❌ (있으면 좋은 것) |

### 후보

| 방안 | 거리 | NTRIP | SSH(외부→배) |
|---|---|---|---|
| 휴대폰 핫스팟 | 20~30m | ❌ | ❌ |
| 실외 WiFi AP(지향성) | 100~300m | ✅ | ✅ |
| **LTE 라우터(배에 탑재)** | 셀 커버리지 | ✅ | ⚠️ **CGNAT** — 아래 |

**LTE 가 유력하다.** 단 통신사 LTE 는 대부분 **CGNAT(사설 IP)** 라
배가 밖으로 나가는 건 되지만(그래서 NTRIP 은 됨) **밖에서 배로 들어올 주소가 없다.**
→ 메시 VPN(Tailscale 등) 또는 역터널(VPS 경유) 한 겹이 필요하다.

### 🚨 Tailscale 위로는 **SSH 만** 된다 — ROS2 토픽은 안 넘어간다 (2026-08-10 추가)

0트랙(폰 온보드)을 채택했으니 미리 못 박는다. **배와 물가 노트북이 서로 다른 인터넷을
쓰게 되므로, 두 대는 같은 랜이 아니다.**

| | Tailscale 위에서 |
|---|---|
| **SSH** | ✅ TCP 한 줄. 그냥 된다 |
| **ROS2 토픽(DDS)** | ❌ **안 된다** — 탐색이 멀티캐스트라 VPN 을 못 넘는다 |

물가 노트북에서 `ros2 topic list` 를 치면 **에러 없이 빈 목록**이 나온다.
"브릿지가 죽었나" 를 뒤지게 되는 전형적인 침묵 실패다. **고장이 아니라 원래 그렇다.**

**그래서 이렇게 쓴다:**
```
blackbox · mission_monitor · waypoint_recorder  →  전부 배 노트북에서 실행
물가 노트북                                      →  SSH 로 그 화면을 본다
```
덤으로 이게 **대역폭도 유리하다.** DDS 로 토픽을 끌어오면 약 2Mbps(`/scan` 실측 1.5Mbps)가
링크를 지나가는데, SSH 는 글자만 오가서 약 0.05Mbps 다. 그 차이가 NTRIP 몫으로 남는다.

⚠️ `tmux` 필수 — SSH 가 끊기면 그 세션에서 돌던 blackbox 도 같이 죽는다(SIGHUP).
   116m 물 위에서 링크는 한 번은 깜빡인다. `tmux` 로 띄우면 배에서 계속 돌고 다시 붙으면 된다.
   (배 노트북에 아직 **미설치** — `sudo apt install -y tmux`)

굳이 물가에서 토픽을 직접 받고 싶다면 유니캐스트 피어 설정(Fast DDS XML 프로파일)이 필요하다.
**권하지 않는다** — 얻는 게 없고 대역폭만 더 쓴다.
  메시 VPN 이 간단하지만 **물가 기기도 인터넷이 있어야 한다**(폰 테더링이면 됨).

💡 **USB 동글보다 WiFi 를 뿌리는 라우터를 권한다.** 노트북 USB 포트가 카메라·LiDAR·허브로
   이미 빠듯하다(포트 부족으로 실제로 고생했다). 라우터가 WiFi 를 뿌리면 포트를 안 쓴다.
💡 **가능하면 5GHz** 로 몰면 조종기(2.4GHz)와 대역 경쟁이 준다.

### 착수 전 확인할 것

- [ ] **대회장 셀 커버리지** — 물 위·방파제 안쪽·다리 밑은 약할 수 있다. 답사 때 폰으로 확인
- [ ] 라우터 급전 방식(배터리 내장 / USB) · 방수 · 안테나 위치 (**회로팀과 상의**)
- [ ] **통신 거리 실측** — 절차는 `docs/절차/boat_launch_checklist.md` §"통신 거리 시험".
      조종기와 SSH 를 **동시에** 시험해야 한다(둘 중 하나만 되면 좌표를 못 찍는다)

## 왜 필요한가
배가 물에 뜨면 이 노트북은 방수 케이스 안에 들어가서 화면·키보드를 쓸 수 없다.

## 현재 상태 (2026-08-07 확인)

4. 주소 문제 해결책 제시 — 아래 참고

## 🚨 반드시 고려할 것

**주소가 매번 바뀌면 대회 당일 접속을 못 한다.**
핫스팟이 주는 IP는 재접속마다 달라질 수 있다. 실내 공유기에서는 192.168.0.52였고
야외 핫스팟에서는 172.20.10.2였다. 대안(고정 IP / mDNS `.local` / 핫스팟 DHCP 예약 등)을
장단점과 함께 제시하고, 이 팀 상황에 맞는 걸 추천해줘.
mDNS는 클라이언트 OS에 따라 동작이 다르니 실제로 되는지 확인이 필요하다.

**보안.**
SSH를 켠다는 건 원격 접속을 허용한다는 뜻이다. 대회 전용 노트북이라 과한 방어는
불필요하지만, 최소한 비밀번호 로그인 허용 여부·키 인증 사용 여부는 근거를 대고 정해줘.
※ 이 노트북에는 이미 GitHub용 SSH 키가 있다(`~/.ssh/id_ed25519`, 암호 없음).
  그건 '나가는' 인증용이고 이번 건은 '들어오는' 접속이라 별개다. 혼동하지 말 것.

**되돌릴 수 있게.**
`boat_boot.sh`가 런타임 설정만 만지고 재부팅하면 원복되는 것과 같은 철학이다.
영구 설정을 바꿀 때는 무엇을 바꿨는지 기록하고, 되돌리는 방법도 남겨줘.

## 일부러 정하지 않은 것

아래 둘은 **네트워크 환경이 정해져야 답이 나온다.** 미리 못박으면 틀린 전제로 작업하게 된다.

| 항목 | 왜 미정인가 |
|---|---|
| 고정 IP vs mDNS vs DHCP 예약 | **대회장에 WiFi 가 있는지, 핫스팟만 쓸지** 아직 모른다 |
| 비밀번호 로그인 허용 여부 | 위 선택과 운용 방식(누가 붙는지)에 딸려 온다 |

## 시작 전 다시 확인할 것

```bash
dpkg -l | grep openssh-server        # 설치 여부
systemctl is-active ssh avahi-daemon # 서비스 상태
sudo ufw status                      # 방화벽
ip -4 -br addr                       # 현재 IP
```
