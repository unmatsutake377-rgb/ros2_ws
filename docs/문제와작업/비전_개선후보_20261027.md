## 0. 한 줄 결론
검출기 뼈대(HSV 단일 출처, 모드 게이팅, 각도식, 면적 최대 선택, 방위각만 발행)는 맞다. 고칠 가치가 있는 건 **①확인-N 로직의 깜빡임 기아, ②하드코딩 남은 것 4개, ③부표에 사각형 검사 강제, ④카메라 자동노출·자동WB, ⑤측정 수단 부재** 다. 전부 OpenCV·파라미터 범위 안이고 새 패키지 없음.

|---|---|---|---|
| image_topic | /camera/camera/color/image_raw | depthai 컬러 토픽(도착 후 확인) | vision.yaml + ssf_tools.yaml (원자 묶음) |

**놓쳤던 것 6개**
1. 🚨 **`hsv.blue` 기본값 `[130,18,160, 175,60,200]`** — S 18~60, V 160~200 = **채도 낮은 회청색 = 흐린 하늘·수면 반사**. 파란 도킹 표식(선명한 파랑 S≥120)은 오히려 못 잡고 하늘은 잡는다. dock 전용(미검증)이라 지금 영향은 없지만 당일 "파랑" 공지가 나오면 사고. 실외 캘리브 1순위.
2. **빨강(H 0~5) 과 주황(H 3~20) 이 H 3~5 에서 겹침** — 도킹 표식이 주황인 날 빨강 표식도 후보가 된다(둘 다 공지 색일 수 있음). 겹침 없애고 S·V 로 가르거나 경계 H 를 실측으로 확정.
3. **흰색 = 하늘** — `S≤40·V≥220` 은 흐린 하늘과 같은 값. 지금은 y_zone_lo 0.15 가 하늘을 잘라 주지만 **OAK 11° 하향 틸트에선 하늘 띠가 더 작고, D455 0° 에선 더 크다** → 카메라별 y_zone 없이는 한쪽에서 오탐.
4. **모션 블러** — 롤링셔터 + 파도 진동 + 자동노출(어두우면 노출 길어짐) → 윤곽 뭉개져 꼭짓점·면적 흔들림. 수동 노출 짧게(1/500 s 급) 고정이 HSV 안정보다 먼저일 수 있음. P1 #5 와 함께 실험.
5. **렌즈 물방울·역광** — OAK 는 IP67 이지만 마스트 꼭대기라 물보라 직격, 물방울 하나가 화면 일부를 뿌옇게 만듦. 짧은 후드 + 발수 코팅. D455 도 동일.
6. **BEST_EFFORT 프레임 드롭** — 드롭이 나면 "연속 N" 은 깨지지만 "창 N/M" 은 버틴다. A1 이 OAK(PoE, 드롭 가능성↑)에서 더 중요해진다.

**같이 지켜야 할 것**: image_topic 을 바꾸는 날은 vision.yaml 3곳 + ssf_tools.yaml 을 **한 커밋**(CLAUDE.md §1 원자 묶음). 두 카메라 드라이버를 동시에 띄워도 검출기는 image_topic 하나만 보므로 충돌 없음 — 비교 측정은 토픽만 바꿔 가며.
