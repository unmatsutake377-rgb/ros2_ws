## 0. 문제 실재 확인 — 버그 있음 (heading_logic.py :329 → :222 → :384)
- 추정기 입력(:329) `estimator.update(imu_yaw, …)` — `imu_yaw` 는 `update_imu`(:309)에서 wrap360 만 거친 **원시 r**(invert·mount 미적용).
- 표본(:222) `a = COG − r`. 출력(:384) `_correct(wrap360(r + off))` = `inv(r + off) + mount` (편각은 SOURCE_IS_MAGNETIC[cog_offset]=False 라 0).
- 물리 모델: 진짜 뱃머리 H = s·r + m (s=±1 invert, m mount), 게걸음 c, COG = H + c.
  - **invert=false**: off = m + c 로 수렴 → 출력 **H + c + m** = mount 만큼 고정 오차. 예 m=37, H=90 → 출력 127(+37°).
  - **invert=true**: 표본 a = 2H + c − m 이 헤딩에 따라 변함. 한 방향 직진이면 R≈1 로 수렴(1 Hz·반감기 60 s 에서 약 37 s), 출력 오차 = **m − 2·COG₀**(수렴 구간 방향 의존). 예: m=0 동쪽 → **180° 정반대**, 북쪽 → 0(한 방향 벤치는 우연히 통과), m=37 동쪽 → 217°. 섞인 구간이면 R≈0 → NOT_CONVERGED(침묵), 헤딩 차 약 26° 안이면 틀린 평균에 수렴. 수렴 뒤 방향을 바꾸면 2표본째 R≈0.87 로 침묵하지만 선회 중·직후 약 2 s 는 틀린 값을 OK 로 냄.
  - 부수: invert=true 면 ssf_heading.yaml 의 gps_vel_frame 벤치 절차("정북·정동 off 동일하면 프레임 정상")가 off 를 180° 다르게 보여 **프레임 오류로 오진**.
- 선회율(:313)은 원시 미분을 abs 로만(:216) 써 invert 무관.

| 소스 | 맞는 식 | 지금 코드 |
|---|---|---|
| imu_relative | inv(r) + mount, 편각 0 | 맞음(:359→:395→:92-93) |
| cog_offset | inv(r) + off̂, off̂ = 원형평균(COG − inv(r)) = mount + c, 편각 0, invert 는 **추정 전** | 틀림(:329·:384) |
| dual_gps | 기선방위 + 안테나 기선 오프셋, IMU invert·mount 해당 없음, 편각 0 | IMU invert·mount 적용 — 잠복(yaw_mux 가 update_dual_gps 안 부름, N3) |
| imu_absolute | inv(mag) + mount + 편각 | 순서 맞음, invert 공유 타당성 ⚠️ 미확인(N4) |

mount 와 COG 오프셋은 완전히 겹친다(둘 다 상수항). 고치는 방법 둘, 출력은 같다(H + c):
- **(a)** 추정기에 inv(r), 출력 inv(r) + off, cog_offset 에서 mount 미사용 — off 의미 "mount + 게걸음"(invert=false 면 지금과 같음).
- **(b)** 추정기에 inv(r) + mount, 출력 inv(r) + mount + off — off 의미 "게걸음 + mount 실측 오차 ≈ 0".
- 어느 쪽이든 편각 금지.
