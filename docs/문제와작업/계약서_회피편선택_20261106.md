# 변경 계약서: ship_direction (C) 갭 후보 정렬에 편 유지 히스테리시스·가로지름 벌점 추가 (발견 8)

작성 2026-11-06 (ssf-contract). 근거: `docs/문제와작업/시뮬3자유도_발견_20261106.md` 발견 8.
상태: 2026-11-06 팀장 승인 — 결정: ① cross_dist_m 파라미터 삭제(벌점은 마스크 안 모든 덩어리) ② _side_prev 리셋 제안안(후보 ≤1·wp_mode 변경·(0)(A)(B)·STOP 틱 모두 None, 시뮬 수치 재검증 수용) ③ 정중앙 지터는 dead-band 없이 시뮬 관찰만 ④ ssf_sim.py·gap_selection_figure.py 는 옛 규칙 유지, README 에 'full_course_sim 이 기준' 명기 ⑤ 코드 기본값 == yaml = 켬(40.0/90.0) ⑥ 문서는 코드 반영 뒤 82번 등으로.

## 핵심 요약
노드 하나(`ship_direction`)의 `_compute` (C) 후보 정렬 키만 바뀐다. 토픽·QoS·특수 코드·§6 값은 불변.
코드에서 확인한 사실 셋:
1. `cross_dist_m 4.0` 은 `detection_distance 3.0/2.0` 보다 커서 **현재 값으로는 무조건 참(no-op 필터)**.
   마스크 셀은 정의상 r < detection_distance(`ship_direction.py:931`). 발견 8 "4 m·6 m 같음" 이 그 증거.
2. 시제품은 `_side_prev` 를 (A)(B)(0) 경로·wp_mode 변경에서 **리셋하지 않았다**. 리셋 규칙을 넣으면 시제품
   수치(46→20)와 달라질 수 있어 시뮬 재실행 필수.
3. `tools/sim/ssf_sim.py:214` 외에 `tools/gap_selection_figure.py:125` 도 후보 정렬 사본(보고서 그림 Ⅲ-3).

## 변경 단위
`ship_direction` 하나. 원자 묶음 아님. 한 커밋에 들어갈 파일:
- `src/ship_direction/ship_direction/ship_direction.py` — 순수 함수 호출 + `_compute` + 파라미터 + 상태 `_side_prev`
- `src/ship_direction/ship_direction/gap_select.py` (신규, ROS 비의존) 또는 `failsafe.py` 에 추가
- `src/ship_direction/config/ship_direction.yaml` — 같은 값(소수점)
- `src/ship_direction/test/test_gap_select.py` (신규)
- `tools/sim/README.md` 동기화 상태 줄 (`ssf_sim.py` 는 결정 4 에 따름)

순수 함수 2개:
- `obstacle_blobs(binary, angle_array, distance_array) -> [(중심각, 최근접거리)]` — 팽창 **전** 이진 마스크 기준
- `rank_candidates(candidates, prev_side_angle, obstacles, side_hysteresis_deg, cross_penalty_deg, forward_deg=LIDAR_FORWARD_DEG) -> sorted list`
  - `n = len(candidates)` 를 **정렬 전에** 잡는다(list.sort 중 len 은 0 — 시제품에서 실제 걸린 버그).
  - 키 = `(angle_diff + 벌점, -arc)`. 벌점 0.0/0.0 이면 기존 `(x[0], x[1])` 과 비트 동일.
  - 히스테리시스: n ≥ 2 이고 prev 가 있고 `(cand-80)*(prev-80) < 0` 이면 `+side_hysteresis_deg`.
  - 가로지름: 후보각과 80 사이 **열린 구간**에 장애물 중심각이 하나라도 있으면 `+cross_penalty_deg`.
