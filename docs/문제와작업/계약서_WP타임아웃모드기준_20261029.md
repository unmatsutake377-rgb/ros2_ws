# 변경 계약서: north_goal_angle 웨이포인트 타임아웃을 목록 순번(wp_idx) 기준에서 wp_mode 기준(파라미터 + yaml)으로 바꾼다

> ssf-contract 작성 2026-10-29. 상태: **Davidson 승인 대기** (방향 동의, "문제 실재 확인 후 진행")
>
> 🐧 **Ubuntu 확인 (10-29, 위험 1 실측)**: Humble rclpy 에서 `declare_parameter('wp_timeout_sec', [120.0, 90.0])` 에
> yaml `[120, 90]` → `InvalidParameterTypeException`(INTEGER_ARRAY vs DOUBLE_ARRAY) **노드 사망**.
> yaml `[120.0, 90]`(섞임) → **`Couldn't parse params file` 로 rcl 초기화 실패** — 그 파일의 다른 파라미터까지 전부 못 싣는다.
> `[120.0, 90.0]` 만 정상. → yaml 타입 테스트(전 원소 float)는 필수, 섞인 배열도 잡을 것.

## 0. 문제 실재 확인 — **실제로 있다**

- 순번 규칙 `north_goal_angle.py:418-422`: `wp_idx in (3,4,5)` → 90 s, `<= 6` → 120 s, 그 밖 None. 상수 `:69-70` 하드코딩(§1-4 위반).
- `waypoints.yaml:20-30` 순번↔모드: WP6·WP7 모두 mode 5·dwell 50 인데 WP6 만 120 s, WP7~WP10 타임아웃 없음.
- 작년 9bff661 도 같은 목록·같은 규칙(`:81-85`) — 3·4·5 = 부표 3개(mode 3) 정확 대응. `<= 6` 이 WP7 을 일부러 뺀 건지 실수인지 ⚠️ 미확인(같은 회피 구간 반만 걸려 실수 쪽).
- 타임아웃이 하는 일(`:413-435`): WP 진입부터 잼(`wp_enter_time`, AUTO 아니면 `:403` 리셋). 만료 → 위치 무관 `wp_idx += 1`, LOS 시작점·적분·`t_start`·`wp_enter_time` 리셋. **fix 없이 진행하는 유일한 수단**(`:438`). `/wp_remaining_time` 은 타임아웃 있는 WP 에서만(`:424-426`) — 구독은 mission_monitor 관측용뿐.
- dwell 과 도착: `dist < arrive_r` 가 dwell 초 **연속**이어야 도착(`:440-456`), 반경 벗어나면 `t_start` 리셋. 반경 mode 7 = 2.0 m, 그 밖 2.5/3.5/4.5 m(`los_logic.py:75-83`). 타임아웃 시계에 dwell 포함 → timeout ≤ dwell 이면 도착 경로 막힘.
- **WP7 갇힘**: mode 5 에서 north 는 20000, ship_direction 은 자율 회피 — 정지 명령이 없어 반경 2.5~4.5 m 안에 50 s 연속 머무르려면 원을 그려야 함(가능 여부 ⚠️ 미확인). **GPS stale·없음이면 확정적으로 갇힘**(도착 판정 꺼짐 `:442`).
- **mode 7(WP8·9)도 갇힘 (새로 확인)**: ship_dock 은 mode 7 에서 항상 candidate 를 냄(INIT·DONE=STOP_HOLD, SEARCH=SPIN) → GPS 좌표로 안 감. SEARCH 25 s 안에 표식 못 찾으면 DONE → STOP_HOLD 무한(`ship_dock.py:248-250, 317-318`). WP8 좌표 2 m 안이 아니면 north 는 못 넘어가고 배 영구 정지. 단 도킹 뒤 남은 게 WP10(토너먼트)뿐이라 "의도된 끝"일 수도 — 사람 판단.
- "규정 미션 시간" 근거 없음: CLAUDE.md §3 "회피(50초)·도킹(60초)" 는 작년 dwell 값. 규정 정량 조건은 위치유지 5 m/5 s 뿐(`KABOAT2025_미션대조_시뮬결과.md:10`), 제한시간 900 s(`KABOAT2025_규정분석_전코스시뮬.md:26`).

**제안의 부작용**
1. 현재 목록에서 모드 0·1·2·3·5 를 지금 값(120/120/120/90/120)으로 두면 WP0~6 동작은 비트 단위로 같다. 바뀌는 건 WP7(무제한 → 120 s)과 7·8 결정분.
2. WP7 이 120 s 로 만료되면 장애물 지대 한가운데서 mode 7 전환 가능 → ship_dock INIT STOP → SEARCH 선회. 지금 WP7 도착 때와 같은 경로라 새 위험 아님.
3. 같은 모드 WP 가 연속이면 누적(mode 3 = 3×90, 5 = 2×120, 7 = 2×T). "모드 기준"은 WP 하나당 값.
4. 모드 8 에 타임아웃을 두면 목록 끝 → north 는 `:354` 에서 발행 전부 멈춤 → ship_goal_angle 2 s 뒤 `/yaw_error` 정지 → ship_direction L2 정지("주행 종료"가 페일세이프 경로).
5. WP0~7 타임아웃 합 870 s — 900 s 제한에 근접. 타임아웃은 생존 장치, 값 낮추기는 범위 밖.
