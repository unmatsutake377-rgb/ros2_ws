# 도킹 표식 — 순광·역광에서 계속 찾을 수 있나 (합성 시험, 2026-11-08)

팀장 질문: "도킹할 때 도형·색깔, 햇빛이 정면으로 들어올 때랑 역광일 때 계속 서칭 가능한지".

⚠️ **실측이 아니다.** 실외 영상(rosbag)은 아직 없다. 실제 dock 검출 파이프라인(HSV → medianBlur 3 → 외곽선 →
`classify_shape` → y 띠)을 그대로 복제하고, 조명만 물리 모델로 바꿔 넣은 합성 영상 결과다.
빨강 반사율만 10-31 OAK 실내 사진에서 역산했고(표식 중심 sRGB 92,13,9 / 벽 168), 나머지 색·자동노출 거동·플레어 세기는 가정값이다.
재현: `python3 tools/sim/dock_sun_stress.py` (Mac, cv2 필요, 약 1분).

## 2. "계속 서칭" 동작

- 못 찾으면 ship_dock 은 SEARCH 에서 제자리 선회를 계속한다. `search_timeout_sec` 60 s 가 지나면 DONE(포기) → 다음 WP.
- ALIGN·APPROACH 중 놓치면 grace 2 s 동안 마지막 각도를 쓰고, 그 뒤 SEARCH 로 돌아간다.
- 🚨 역광은 **배 방향이 아니라 도크와 해의 방향**으로 정해진다. 표식면이 그늘이면 아무리 돌아도 표식은 어둡다 → 60 s 내내 못 찾고 포기할 수 있다.
- dock 노드는 **3 연속** 검출이 필요하다. 깜빡이면 확정이 안 된다(vision.yaml 주석의 "깜빡임 기아"). 11-08 에 `confirm_window` 파라미터를 넣었다(기본 3 = 동작 불변, 벤치 뒤 5 후보).

## 4. 할 일 (전부 실측 뒤 결정)

1. **실외 녹화** — 표식 색별로 순광·역광 각 60 s, 2/5/8 m (비전_개선후보 §34 와 같은 항목). `basic_image_subscriberhsv` 로 HSV 실측.
2. **노출·화이트밸런스 고정 실험** — OAK 는 자동노출·자동 WB 가 켜진 상태(설정 파일에 노출 항목 없음). 수동 노출 몇 값 비교. depthai-ros 의 수동 노출 파라미터 이름은 Ubuntu 에서 확인 필요.
3. **`hsv.blue` 교체** — 파랑 공지가 나오면 지금 값으로는 못 찾는다. 실측 HSV 로 yaml 교체(현장 조정표 방식).
4. **대회 당일 아침**: 공지된 표식 색을 그 시각 해 방향에서 찍어 HSV 확인 → 그 색 한 줄만 yaml 에서 조정 → 재시작.
5. 렌즈 후드(플레어), dock `confirm_window` 도입(코드 변경 = 팀 모드)은 후보.

## 5. 조명과 별개로 찾은 것 — 작은 사각을 원으로 오인 (11-08)

화면 30 px 이하 사각은 픽셀 계단 때문에 원형도가 0.82~0.86 으로 재져 `circle_circularity_min` 0.82 에서 원으로 분류됐다
(사각 정답률 12~25 px 40~60 %). 0.87 로 올려 95~100 %, 원·삼각 불변. 16 px 이하 45° 마름모는 0.87 에서도 원. 재현 `python3 tools/sim/dock_shape_sweep.py`. 반영: 계약서_도킹비전_사전수정_20261108 항목 A.
합성 스크립트 `dock_sun_stress.py` 는 이제 vision.yaml dock 절을 읽는다 — 위 §1·§3 표는 0.82·옛 파랑 값 시절 결과다.
