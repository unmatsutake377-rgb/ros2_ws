  · 🚨 **Tailscale 위로는 SSH 만 된다 — ROS2 토픽은 안 넘어간다**(DDS 탐색이 멀티캐스트).
    물가에서 `ros2 topic list` 가 **에러 없이 빈 목록**을 뱉는다. 고장이 아니다.
    → blackbox·mission_monitor·waypoint_recorder 는 **배에서 돌리고 SSH 로 본다**
    → 덤으로 대역폭도 유리하다: DDS 약 2Mbps(/scan 실측 1.5Mbps) vs SSH 약 0.05Mbps
  · ⏸ 0트랙 필수 검증: 밀폐 박스 고온 1시간+ · 핫스팟 자동꺼짐 해제 · 5GHz 지원(RC 2.4GHz 보호)
  · 안전은 이 링크에 안 걸려 있다 — 비상 제어는 **RC**, 기록은 blackbox 로컬
  · [x] **`tmux` 설치 완료 (08-12, 3.2a)** — 분리 세션 생존 확인.
    SSH 가 끊겨도 배에서 계속 돌고, 다시 붙으면 그 화면이 그대로 있다:
    `tmux new -s mon` / 끊긴 뒤 `tmux attach -t mon`
- 🚨 **통신 거리 실측 필요** — 조종기 **FS-i6 / 수신기 FS-iA6**(확정).
  **iA6 는 텔레메트리가 없어 RSSI 를 못 본다** → 끊기고 나서야 안다. 실측이 유일한 근거.
  웨이포인트 녹화는 **조종기와 SSH 가 동시에** 116m 를 덮어야 한다(하나만 되면 못 찍는다).
  절차: `docs/절차/boat_launch_checklist.md` §"통신 거리 시험" — **System-ID 보다 먼저**
- 🚨 **아두이노가 USB 에서 간헐적으로 떨어진다 (08-12, 원인 미해결)**
  커널 로그: `USB disconnect, device number 24` → 즉시 `new device number 25` (재열거).
  전체 launch(18노드) 구동 중 약 24초 시점에 발생. 단독 실행 3/3 · 다음 회차 4/4 는 무사 —
  **간헐적**이다.
  · autosuspend 는 **원인 아님** 확인(`power/control=on` = 이미 비활성)
  · 위상: `Bus3 ─ 허브 ─ 허브 ─ 아두이노` (**허브 2단**). 같은 물리 허브의 USB3 쪽에 카메라.
    허브 서술자는 자체전원이라 주장하나 싸구려 허브는 이 값을 자주 거짓말한다
  · 🚨 **가르는 실험: 아두이노를 노트북 포트에 직접 꽂고 전체 launch 재시험.**
    무사하면 허브·전원 문제로 확정된다
  ✅ **소프트웨어 쪽은 대응 완료** — 브릿지가 끊김을 감지해 핸들을 버리고 자동 재연결한다
     (아래 참고). 끊겨도 장치가 돌아오면 스스로 복구한다.
- 🚨 **카메라 자동보정이 '자동' 이다** — `enable_auto_white_balance`·`enable_auto_exposure` 둘 다 ON.
  launch 절 제목은 "Auto Exposure/WhiteBalance **OFF**" 라고 적혀 있었는데 **거짓이었다**(08-12 정정).
  자동 WB 는 화면 구성에 따라 같은 부표의 H 를 민다 → 색 실측의 전제가 흔들린다.
  ⚠️ 단 정지 장면 A/B 에서는 차이가 없었다(ΔH 0.0) → **근거 없이 끄지 않았다.** 야외 재판정 항목.
- 🚨 **`rgb_camera.controls.saturation: 120` 은 한 번도 먹은 적이 없다** — 존재하지 않는 이름이라
  조용히 무시됐고 실제 값은 기본 **64** 였다(08-12 발견, 이름 정정).
  🚨 **120 으로 바꾸지 말 것** — 08-12 검출 검증(빨강·초록 100%)은 전부 **64 에서** 나온 결과다.
  바꾸려면 다시 측정해야 한다.
- **`hfov_deg` 는 해상도에 딸려 있다** — 현재 **80.32°** = 컬러 640x480 기준(08-12 실측).
  `rgb_camera.color_profile` 을 바꾸면 **여기도 같이** 바꿔야 한다. 안 바꾸면 에러 없이 각도만 틀어진다.
  근본 해법은 camera_info 의 fx 를 런타임에 읽는 것 — 미적용(후속 검토)
