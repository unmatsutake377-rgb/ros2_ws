## 7. 위험 — 조용히 깨지는 지점

1. **1글자 수정의 되돌림**: `yaw + rel` → `yaw - rel` 이 "오타 수정"으로 되돌아가도 에러 없음. → north 비대칭 테스트(§8-②)가 유일한 방어. 주석에 "🚨 `-` 가 맞다(계약서_geofence부호_20261104)" 명시.
2. **이중 수정 → 재거울**: 나중에 누가 (b) 를 추가 적용하면 다시 뒤집힌다. ship_direction 규약 고정 테스트(§8-③)로 소비자 측 의미를 못박는다.
3. **avoid_sim 생성기 미동기화**: `avoid_sim.py:81` 가 CW+ 로 남으면 수정 후 시뮬이 36/40 급으로 **악화된 것처럼** 보인다(`tools/` 는 메인 세션 담당).
4. **문서 예제 부호**: `north_goal_angle.py:21`, `ship_direction.py:139`, `CLAUDE_상세.md:683-687` 의 "북벽 −45° / 동벽 +45°" 는 CW+ 기준. (a) 뒤엔 북벽 +45(좌)/동벽 −45(우). 코드엔 영향 없지만 다음 사람이 이 주석을 믿고 다시 뒤집을 수 있다.
5. **실물 IMU 방향 미확정(§8)**: `invert_yaw` 가 틀리면 geofence 는 또 거울이 된다 — 이번 수정과 별개로 **야외 확인 순서가 ① `/imu/yaw` CW 확인 → ② geofence 측 확인** 이어야 한다(§9). 거꾸로 하면 두 오류가 상쇄돼 "맞아 보이는" 상태로 대회에 나간다.
6. **도킹 영향(현재 거울 상태의 실제 증상)**: `_geofence_blocks` candidate 경로 — 경계가 **조향 반대쪽**(예: 좌로 트는데 경계가 우현 2 m)이면 `diff` 가 작아져 **거짓 STOP_HOLD(접안 실패)**, 경계가 **조향 쪽**이면 `|diff|>60` 이라 **정지 안 함(이탈·실격)**. 수정 후 둘 다 정상. SPIN 단계는 영향 없음. 도크가 경기장 가장자리일 때만 발현(CLAUDE.md :139 "도킹 중 정지 원인" 그대로).
