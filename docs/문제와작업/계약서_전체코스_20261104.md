## 2. 결함별 설계 (권고)
1. **LOS 지나침**: along-track s ≥ 경로 길이 L 이고 거리 ≥ 도착 반경이면 현위치→WP 직접 방위, xte 0(ILOS 동결). 반경 안에서는 기존 LOS. 통과선 방식(수직선 넘으면 도착)은 dwell 무의미·10 m 옆 통과도 도착이라 기각.
2. **dwell**: 9bff661 에 50/60 이 근거 없이 존재(고정 반경 3 m, WP7 이후 시간 초과 없던 코드) — 의미 ⚠️ 미확인. 값만 줄임: mode 5(WP6·7·접근점) 1.0, mode 7 1.0. recorder_prompts {5: 1.0, 7: 1.0}, dock_wp 기본 dwell 1.0. WP10(mode 8) 사람 결정.
   - **새 결함**: mode 2·3 에서 north 도착 반경 2.5 m 와 ship_back 유지 거리 2.5±0.4 가 겹쳐 north 가 WP 를 넘기며 위치유지를 끊음. → dwell 은 '담당 노드가 손 뗀 동안'만 셈(north 가 받은 마지막 /candidate_angle 이 신선한 20000 이거나 1.0 s 넘게 무수신). `dwell_wait_modes` [2, 3], mode 7 제외.
3. **도킹**: 접근점(mode 5) 2개를 waypoints.yaml 기본에 자리표시값으로(⚠️ 현장 교체 주석, 머리말 수정). WP8 = 목표 칸 입구(mode 7, dwell 1.0), WP9 = 이탈점(6 m 접근점 좌표, mode 7, dwell 1.0) — dock_wp.py 가 출력. 7→7 미리셋 유지. ship_dock **TRANSIT** 상태 신설: 모드 진입 후 20000 발행(GPS 주행), /goal_distance 가 신선(≤ 2.0 s)하고 `dock_engage_dist_m` 미만이면 INIT. 🚨 진입 후 1.0 s 지난 수신분만 사용(직전 WP 거리 배제). 모르면 TRANSIT 유지. **DONE 은 STOP_HOLD 대신 20000.** 표식 단독·LiDAR 전방거리 진입은 오검출 위험으로 기각.
4. **위치유지 타이머**: SEARCH 시간 초과로 DONE 래치하지 않음(SEARCH·DONE 둘 다 20000 이라 효과는 '더 안 찾기'뿐, 진행은 north 시간 초과). 스위치 `search_timeout_ends`(기본 false).
5. **탐색 색**: SEARCH→HOLD 획득은 비전 색 확인으로만. LiDAR 최근접은 HOLD 유지 중 직전 비전 방위가 lost_sec 안일 때 보조로만. 스위치 `lidar_acquire`(기본 false). 3→3 미리셋 유지(DONE 은 HOLD 성공에서만). 검출기 색은 U5.
6. **candidate 신선도**: `candidate_stale_sec` 1.0(north 주기 0.5 s × 2). stale → **20000**(GPS+LiDAR 회피) 권고, 진입 1회 ERROR + 5 s 주기 ERROR. control_cb 에서 _compute 전 순수 함수 effective_candidate(). 180 의 0.5 s 규칙 유지(0.5~1.0 s STOP, 그 뒤 20000). wp_mode 바뀌면 candidate 20000·candidate_t None.
