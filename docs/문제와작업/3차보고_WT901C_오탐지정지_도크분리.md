# 🚨 최우선: WT901C는 **현재 드라이버로 통신이 안 됩니다**

모델명을 알려주셔서 확인해보니 **중대한 문제**가 있습니다.

**현재 `iahrs_driver`가 쓰는 통신 방식 (코드 확인):**
```cpp
write(serial_fd, "e\n", 2);        // ASCII 명령 "e\n" 전송
...
char* p = strchr(buf, '=');        // 응답에서 '=' 문자를 찾아 파싱
```
이건 **Withrobot사의 iAHRS** 프로토콜입니다. ASCII 명령을 보내면 `e=1.23,4.56,7.89` 같은 텍스트로 답하는 방식입니다.

**그런데 WT901C(WitMotion)는 완전히 다릅니다:**
- 명령을 기다리지 않고 **바이너리 패킷을 자동으로 계속 흘려보냅니다**
- 패킷 형식: `0x55 0x53` (헤더+각도타입) + 데이터 8바이트 + 체크섬
- **`"e\n"` 명령에 응답하지 않고, `=` 문자도 없습니다**

**→ 지금 드라이버로는 WT901C에서 데이터를 한 글자도 못 읽습니다. 드라이버를 새로 작성해야 합니다.**

**확인해주세요:** 작년에 실제로 쓴 IMU가 WT901C가 맞나요, 아니면 **Withrobot iAHRS**였나요?
- 작년에도 WT901C였다면 → 이 드라이버로는 절대 작동 안 했을 텐데, 어떻게 돌았는지 확인 필요
- 작년은 iAHRS였고 **올해 WT901C로 바꾸는 것**이라면 → **새 드라이버 작성 필요** (WitMotion 0x55 패킷 파서)

**좋은 소식:** WT901C는 **9축(가속도+자이로+지자기)** 이 맞습니다. 지자기로 **절대 방위**를 내므로 **GPS heading 보정이 완전히 불필요**합니다.

**⚠️ 단, 지자기는 자기 간섭에 취약합니다.** 모터·배터리·금속에서 **최대한 멀리, 가능한 높게** 장착하라고 하드웨어 파트에 요청하세요. 안 그러면 방위가 통째로 틀어집니다.

// iahrs_driver.cpp — 이 블록을 삭제합니다

# ✅ 오탐지 정지 방지 — 우려하신 부분, 설계로 막았습니다

**"고장이 아닌데 고장으로 판단해서 멈추는 참사"** 를 막기 위해 4중 방어를 넣었습니다.

## 설계

| 방어 | 무엇을 막나 |
|---|---|
| **① monotonic 시계** | 시스템 시각 점프로 인한 오판 |
| **② ARMED 플래그** | 시작 직후 타임스탬프가 0이라 즉시 정지하는 함정 |
| **③ 히스테리시스 (연속 3회)** | CPU 지터·순간 드롭아웃 |
| **④ 자동 복구 (연속 3회 정상)** | 한 번 멈추면 영영 못 가는 문제 |
| **⑤ 넉넉한 임계값** | L3 정지 = **3초** = LiDAR 스캔 **30회** 연속 누락 |

## 검증 결과 — 정상 상황에서 오탐지 정지 **0회** ✅

| 상황 (고장 아님) | 결과 |
|---|---|
| CPU 지터 (스캔 20% 누락) | 23.6m 정상 주행, **오탐지 정지 없음** ✅ |
| 순간 드롭아웃 (0.4초씩 반복) | 23.5m 정상 주행, **오탐지 정지 없음** ✅ |

## 진짜 고장에서는 정확히 정지 ✅

| | 접촉 | 결과 |
|---|---|---|
| 페일세이프 OFF | 1회 | 부표벽 뚫고 y=48m 폭주 |
| 페일세이프 **ON** | **0회** | **8.3초에 정지**, 부표벽 앞에서 멈춤 |

## ⚠️ 발견한 잠재 위험 — 전 노드가 **벽시계(`time.time()`)** 사용

코드를 뒤져보니 `ship_direction`, `ship_turn`, `ship_dock`, `ship_gate` **전부 `time.time()`** 을 쓰고 `monotonic`은 **0회**입니다.

**정직하게 말씀드리면, 제가 처음 생각한 것보다는 위험이 작습니다.** 히스테리시스가 있으면 대부분의 시각 점프는 걸러집니다. 다만:
- 시각이 **뒤로** 점프하면 → 페일세이프가 **그만큼 지연**됩니다 (5초 뒤로 가면 5초 늦게 멈춤 = 6m 더 진행)
- NTP 최초 동기화 때 실제로 몇 초~몇 시간 점프할 수 있습니다

**`time.monotonic()`으로 바꾸는 건 비용이 0이고 위험을 완전히 없앱니다.** 안 할 이유가 없습니다.

## 🔴 가장 위험한 함정: 시작 직후 자동 정지

**이게 진짜 조심해야 할 부분입니다.** 타임스탬프 초기값을 `0.0`으로 두면:
```python
self.t_lidar = 0.0
age = time.monotonic() - 0.0   # → 엄청나게 큰 값!
→ 즉시 L3 정지 → 배가 출발조차 못 함
```
**ARMED 플래그**(첫 데이터를 받은 센서만 감시)가 반드시 필요합니다. 이거 하나 빠뜨리면 **경기 시작하자마자 배가 안 움직입니다.**

# 도크 판별 분리 — **호환성 완전히 유지됩니다** ✅

결론부터: **`ship_dock`은 한 줄도 안 고쳐도 됩니다.**

## 현재 구조
```
비전(dock) ──/image_angle, /image_distance──▶ ship_dock
   (빨간 사각형만 찾아서 각도·거리 발행)
```

## 새 구조 (제안)
```
비전(dock) ──/dock_markers (전체 목록)──▶ 선택노드 ──/image_angle, /image_distance──▶ ship_dock
   (보이는 표식 전부 인식)              (파라미터와 일치하는 것 선택)      (기존 토픽 그대로!)
```

**핵심: 선택 노드가 `/image_angle`, `/image_distance`를 그대로 발행합니다.** `ship_dock` 입장에서는 아무것도 안 바뀝니다.

## 새 토픽 형식 (커스텀 메시지 없이)
`Float32MultiArray` 하나면 됩니다:
```
data = [색ID, 모양ID, 각도, 거리,   색ID, 모양ID, 각도, 거리,   ...]
        ─── 표식 1 ───           ─── 표식 2 ───
```
- 커스텀 msg를 안 만들어도 되니 **빌드 의존성이 안 꼬입니다**
- `ssf_interfaces`를 건드릴 필요도 없습니다

## 이점
1. **`ship_dock` 수정 0** — 호환성 완벽
2. **도크 3개를 동시에 보고** 그중 목표를 고를 수 있음 (지금은 불가능)
3. 준비 기간에 **3형상 × 5색을 전부 튜닝**해두고, 당일엔 파라미터만 변경
4. 대회장에서 **소스 코드를 안 건드림**

**→ 위험 없이 가능합니다. 진행하시길 권합니다.**

# RC 두절 (12번) — **건드리지 않겠습니다**

말씀대로 두겠습니다. 다만 **잔여 위험만 명확히 기록**해둡니다:

현재 펌웨어는 **"RC 신호 없음"과 "사용자가 자율 선택"을 구분하지 못합니다.** 둘 다 `Auto_signal = 0 < 1500` → 자율입니다.

**실질적으로는 원하시는 동작(RC 끊겨도 자율 계속)과 같으므로 당장 문제는 없습니다.** 다만 작년처럼 배가 멀어져 RC가 끊긴 뒤, **다시 가까워졌을 때 수동 전환이 제대로 되는지**는 실제로 테스트해보시길 권합니다. (수신기가 신호를 다시 잡으면 `PulsesAuto`가 갱신되어야 하는데, 수신기 설정에 따라 다릅니다)

안전망은 **무선 비상스위치**(규정 필수)와 **geofence**로 확보하세요.
