# 08-19 작업 기록 — 좌측 스러스터 무반응 · 접촉기 자기유지 실패

## 1. 좌측 스러스터 2개 무반응 (신규 발견)

### 증상
자율 모드에서 브릿지 명령(`L<µs>,R<µs>`)을 좌·우 따로 보내 시험했다.
**3회 재현, 결과 동일.**

| 시험 | 아두이노 출력 (FL,FR,RL,RR) | 실제 |
|---|---|---|
| ① 좌측만 `L1580,R1500` | `1580,1500,1580,1500` ✅ | **아무 반응 없음** 🚨 |
| ② 우측만 `L1500,R1580` | `1500,1580,1500,1580` ✅ | 우측 2개 회전 ✅ |

워치독 `0`, 각 구간 30줄(3초 × 10Hz) — 명령은 3초 내내 정상 수신·출력됐다.

### 확정된 것
**펌웨어는 무죄다.** 좌·우에 완전히 대칭인 신호를 냈고 상태줄이 그걸 증명한다.
`esc[0].attach(11)` / `esc[1].attach(12)` 둘 다 부팅부터 1500µs 를 송출한다.

좌측 ESC **2개가 동시에** 죽었다 = 둘이 공유하는 것 하나가 끊겼다.
공유하는 것은 **핀 11 신호선**이다.

### 🎯 원인 위치 확정 — 08-20 전압 실측

```
핀 12         0.373V      ✅ 기준값 (우측은 도는 것 확인됨)
핀 11         0.373V      ✅ 아두이노 정상 — 핀 사망 후보 제거
좌측 앞 ESC   0V          🚨
좌측 뒤 ESC   0.15V → 0V  🚨 시간에 따라 변함
```

**결론: 핀 11 ~ 좌측 ESC 사이 배선 불량.**
좌측 앞·뒤가 둘 다 죽었으므로 **두 갈래로 나뉘기 전(또는 분배점 자체)** 한 곳이 범인이다.
**한 군데만 고치면 둘 다 살아난다.**

#### 0.15V → 0V 가 핵심 단서
```
완전히 잘린 선  →  항상 0V, 불변
접촉 불량       →  어중간한 값 + 시간에 따라 변함   ← 실측이 이것
```
깨끗한 단선이 아니라 **접촉 불량(냉납 / 갈라진 납땜)** 이다.
🚨 대회 중이면 **달리다 한쪽이 갑자기 멈추는** 고장이다. 미리 찾은 것이 다행.

#### 지점 특정 방법 — 도통 모드
**USB 를 뽑고**(아두이노 켜진 채로 재면 값이 오염된다) 도통 모드로:
1. 핀 11 ↔ 좌측 앞 ESC 신호 접점
2. 핀 11 ↔ 좌측 뒤 ESC 신호 접점
3. 핀 11 ↔ 분배 지점

**안 울리는 첫 구간이 범인.**
⭐ 재면서 **선을 살살 흔들 것.** 접촉 불량은 가만히 있으면 붙어 있다가 흔들면 끊긴다.
소리가 끊겼다 이어졌다 하는 자리가 그 지점이다.

### (이전 계획) 멀티미터, 배터리 불필요
아두이노는 USB 로 돌아가므로 배터리도 초록 버튼도 필요 없다.
**DC 전압 2V 범위**, 검은 탐침은 아두이노 GND 고정.

| | 측정점 | 예상 |
|---|---|---|
| ① | 핀 11 | 0.37V |
| ② | 핀 12 (기준값 — 우측은 도는 게 확인됨) | 0.37V |
| ③ | 좌측 ESC 커넥터의 신호선 | 0.37V |

> 0.37V 인 이유: 1500µs 펄스 / 20ms 주기 = 7.5%, 5V × 0.075.
> 멀티미터는 평균을 읽는다. **0.3~0.4V 면 신호 정상.**

| ① | ③ | 결론 |
|---|---|---|
| 0V | — | 핀 11 출력 사망 → 다른 핀으로 이설 |
| 0.37V | 0V | 핀 11 ~ 좌측 ESC 배선 끊김 → 기판 납땜 |
| 0.37V | 0.37V | 신호 도착 → 좌측 ESC 또는 전원 문제 |

### 전원 문제가 아님을 확정한 논거 — 그룹 경계 (08-19)

배터리는 2개이고, **배터리 하나당 ESC 2개를 「위/아래」로 나눠** 먹인다.
신호는 핀별로 **「좌/우」** 로 나뉜다. **두 경계가 서로 어긋난다.**

```
전원 그룹 (배터리별) :  { 위 2개 }   { 아래 2개 }
신호 그룹 (핀별)     :  { 좌 2개 }   { 우 2개 }
관찰된 고장 그룹     :  { 좌 2개 }   ← 신호 그룹과 일치, 전원 그룹과 불일치
```

좌측 2개는 **서로 다른 배터리**에서 전원을 받는다.
전원 문제라면 좌측 2개가 함께 죽을 수 없다 — 「위 2개」나 「아래 2개」가 죽었어야 한다.

**→ 신호 문제 확정. 접촉기 문제와는 무관하다.**
(ESC 삑 소리 개수를 셀 필요도 없어졌다. 좌측 ESC 전원단자 측정도 불필요.)

### 시험 중 알게 된 것
- ESC 는 **전원 인가 시점에 중립(1500)을 봐야 시동**된다.
  초록 버튼을 시험 시작 후에 누르면 4개 전부 무반응이 된다 — 한 번 이걸로 오진할 뻔했다.
  시험 스크립트에 **중립 유지 6초**를 넣어 해결했다.
- 아두이노는 USB 전원이라 **접촉기가 열려 있어도 상태줄은 정상으로 나온다.**
  시리얼만 봐서는 추진 전원이 살았는지 알 수 없다. 눈과 귀가 유일한 확인 수단이다.

시험 스크립트: `side_test.py` (세션 스크래치패드. 필요하면 `tools/` 로 옮길 것)

## 2. 접촉기 자기유지 실패 — 접촉기 무죄 확정

**MD-30a 본체를 교체했는데도 초록 버튼(수동 조작자)을 눌러야만 붙었다.**

부품을 바꿔도 증상이 같으므로 **접촉기는 원인이 아니다.**
08-18 측정과 일치한다:

```
A1 ↔ 6번        = 0.024V   ← 코일에 전압 없음
컨버터 input ⊕  = 0.02V    ← 컨버터에 전기가 아예 안 들어감
```

컨버터가 고장난 게 아니라 **컨버터까지 전기가 안 간다.**
원인은 `회로_신규설계.md` §10 재배선 목록 2번(컨버터 입력이 접촉기 「뒤」에 있음)이다.

### 코일 저항 실측 — 08-19
```
A1 ↔ A2 = 48Ω
```
**끊김도 단락도 아니다 → 코일 정상.** 접촉기 무죄가 저항으로도 확인됐다.

> A1/A2 는 몸체 각인. 주회로(1/2/5/6)보다 나사가 작고 **선이 얇다.**
> 보조접점 미배선이므로 **선이 꽂힌 얇은 단자가 둘뿐이면 그게 A1·A2.**

### 코일 정격 — 08-19 라벨 확인
```
몸체 표기 : DC 24V
실측 저항 : 48Ω
→ 0.5A / 12W
```
12W 면 코일이 미지근해진다 — 정상이다.

### 🚨 컨버터 사양 확인 — 입력 범위가 배터리와 안 맞는다 (08-20)

제조사 사양표:

| 항목 | 값 |
|---|---|
| **Input voltage** | **11 ~ 16 Vdc** 🚨 |
| Output voltage | 24 V |
| Output current | 3 A |
| Output power max | **72 W** (240W 아님 — 이전 기록 정정) |
| Efficiency | 95% |
| 보호등급 | IP68 |

```
배터리 실측 : 16.7V  ← 범위 초과 🚨
              14.7V  ← 범위 안
4S 만충      : 4.2V × 4 = 16.8V   ← 만충하면 항상 초과
```

**일시적 문제가 아니다. 경기 시작할 때마다 규격 밖 전압이 걸린다.**

#### 컨버터가 0V 를 내는 유력한 원인
- **과전압 보호로 출력 정지** — 입력이 범위를 벗어나면 스스로 끊는다
- **이미 손상** — 16.7V 를 계속 받아 내부가 상했을 수 있다

지금까지 "컨버터에 전기가 안 간다"로 봤으나, **전기는 갔는데 컨버터가 거부한** 것일 수 있다.

#### 확인 방법
스러스터를 잠깐 돌려 배터리를 **15V 대로 낮춘 뒤** 코일 `A1↔A2` 전압 재측정.
- 24V 나옴 → 과전압 보호였음. 컨버터 생존
- 0V 그대로 → 손상됐거나 다른 원인(비상정지 버튼 / 무선 릴레이 개방)

#### 🎯 근본 대책 — 컨버터 교체 권장
```
필요 : 입력 9~36V (넓은 범위) / 출력 24V / 1A 이상이면 충분(코일 0.5A)
현재 : 입력 11~16V / 출력 24V / 3A   ← 4S 배터리에 쓰면 안 되는 물건
```
3A 는 과사양이다. **입력 범위가 넓은 작은 것**으로 바꾸는 게 싸고 확실하다.

**`A1 ↔ 6번` 측정 시 기대값이 이걸로 확정됐다:**

| 읽힌 값 | 뜻 |
|---|---|
| 24V | 정상. 접촉기가 붙어야 함 |
| 12V 근처 | 컨버터가 승압 못 하고 입력을 통과시키는 중 |
| 0V | 08-18/19 현재 상태 — 컨버터에 전기가 안 감 |

> 🚨 코일이 0.5A 를 먹으므로 **무부하 측정은 의미가 없다.**
> 컨버터가 무부하에선 24V 를 내도 부하가 걸리면 주저앉을 수 있다.
> **코일이 연결된 상태에서** 잴 것.

### 🎯 데이터시트 확보 — 배선이 꼬인 근본 원인 (08-20)

제조사 도면(`직류 전자접촉기 MD-30a, 60a, 100a` — 접점구성 + 회로도)에서 확정:

```
A1 ─coil─ A2      13│21      1⊖ │ 5⊕      43│31
                  14│22      2⊕ │ 6⊖      44│32
```

| 단자 | 정체 |
|---|---|
| A1 / A2 | 코일 (DC 24V, 실측 48Ω) |
| 13-14, 43-44 | **NO** ×2 |
| 21-22, 31-32 | **NC** ×2 |
| 1-2, 5-6 | 주접점 2극 (**세로 짝이 한 극**) |

`2a2b` 이므로 **비상정지 감지(핀 38)에 쓸 NC 접점이 두 개 남는다.**

#### 🚨 `⊕`·`⊖` 표시는 "여기에 플러스선/마이너스선"이 아니다

**전류가 흘러야 할 방향** 표시다. 들어오는 쪽이 `⊕`, 나가는 쪽이 `⊖`.
직류 접촉기는 아크를 자기력으로 밀어 끄기 때문에 방향이 정해져 있다.

```
5 ⊕ ──[접점]── 6 ⊖      전류 5 → 6
2 ⊕ ──[접점]── 1 ⊖      전류 2 → 1
```

**6번은 `⊖` 로 적혀 있지만 플러스 선이 지나가는 자리다.**

→ 이 표시를 "6번에 마이너스선"으로 읽으면 배선이 통째로 어긋난다.
**현 배선이 정확히 그렇다 — 6번에 배터리 B `⊖` 가 물려 있다.**
이 프로젝트에서 배선이 계속 꼬였던 근본 원인으로 보인다.

#### 올바른 배선 (배터리 2개의 `(+)` 를 각각 한 극씩 끊는다)

```
배터리 A ⊕ ──→ 5번  [접점]  6번 ──→ ESC(A쪽) ⊕
배터리 B ⊕ ──→ 2번  [접점]  1번 ──→ ESC(B쪽) ⊕
배터리 ⊖ 는 접촉기를 거치지 않고 ESC 로 직결
```

두 극 모두 전류가 `⊕` 표시로 들어가 `⊖` 표시로 나간다 — 극성 정합.

| | 현 상태 | 고칠 것 |
|---|---|---|
| 배터리 B | `⊖` 를 6번에서 끊음 🚨 | `⊕` 를 2번 → 1번으로 |
| 배터리 A | 2번에 `⊕` | 5번 → 6번으로 |
| 컨버터 입력 `⊕` | ESC `⊕` 줄 = 접촉기 **뒤** | 배터리 `⊕` 쪽 = 접촉기 **앞** |

⚠️ 제품 판매 페이지(cafe24)에는 사양표가 없다(이미지만). **코일 소비전력·동작전압범위
(보통 정격의 85~110%)는 아직 미확보.** 필요해지면 LS 카탈로그를 따로 찾을 것.


### 목표 회로도 (08-20 확정)

```
[추진 전력]
배터리 A ⊕ ── 접촉기 5→6 ──→ ESC(A) ×2 ⊕
배터리 A ⊖ ──────직결──────→ ESC(A) ×2 ⊖
배터리 B ⊕ ── 접촉기 2→1 ──→ ESC(B) ×2 ⊕
배터리 B ⊖ ──────직결──────→ ESC(B) ×2 ⊖

⊖ 는 배터리마다 따로다. 굵은 전원선으로는 안 이어져 있고
**아두이노 신호 GND 라는 가는 선으로만** 이어진다.
→ 그래서 ⊖ 를 접촉기로 끊으면 "완전히 안 끊기는" 애매한 상태가 된다.
  얼마나 새는지 예측할 수 없고, 비상정지는 예측 불가면 없는 것과 같다.
  ⊕ 를 끊으면 그 옆길 자체가 없다.

[제어 회로]  — 한 줄 직렬 (08-20 납땜 완료)
컨버터 OUT ⊕ → A1 [코일 48Ω] A2 → 릴레이 COM–NC → 비상정지 NC → 컨버터 OUT ⊖
                                       ↑                  ↑
                                   무선 정지          버튼 정지
                              하나만 열려도 코일이 죽는다

컨버터·릴레이 IN 은 배터리 A 에서 딴다.
🚨 반드시 접촉기 5번보다 **배터리 쪽**. 뒤에서 따면 순환에 빠져 영원히 안 붙는다.

[신호]
아두이노(USB 전원) 핀 13 → 좌측 ESC ×2
                     핀 12 → 우측 ESC ×2
전원 그룹(배터리 A/B) 과 신호 그룹(좌/우) 이 어긋난다 — 좌측 무반응을 신호 문제로
확정한 근거가 이것이다.
```

### 남은 확인
- 초록 버튼 누른 채 `A1 ↔ 6번` 전압
  - 누르면 24V / 떼면 0V → 컨버터가 접촉기 「뒤」에서 급전 = 배선 문제 확정
  - 이 경우 **3초 누르고 떼면 접촉기가 그대로 붙어 있어야 한다** (자기유지 성립)
- ESC 전원단자 ↔ 6번 으로 14.7V(배터리 B) 기준 잡고 컨버터 입력 분기점 재측정

### 초록 버튼(수동 조작자)에 대해
- 배터리·ESC 에 전기적 손상은 없다. EC5 ⊕↔⊖ 저항 정상(B 0.9kΩ / A OL) — 단락 아님
- 다만 **접점이 조금씩 상한다.** 손으로 누르면 코일보다 천천히 닫혀 아크가 길다
- **반쯤 누르는 것이 제일 나쁘다** — 접촉저항이 올라가 그 지점이 탄다. 누르려면 끝까지
- 스러스터가 도는 상태에서 떼면 아크가 크다 → **자율 모드(중립)에서 조작할 것**
- 진단용으로 몇 번은 문제없다

## 3. 🚨 핀 13 은 쓰면 안 된다 — 부트로더가 스러스터를 돌린다 (08-25)

### 무슨 일이 있었나

좌측 ESC 신호를 **핀 13** 으로 옮긴 뒤 시험하는 중, **읽기 전용 스크립트를 돌렸는데
좌측 앞 스러스터가 세게 돌았다.** 명령은 하나도 보내지 않았다.

```
시리얼 포트를 여는 것만으로  →  아두이노가 재시작
재시작하면                   →  부트로더가 2초간 동작
🚨 부트로더는 핀 13 을 깜빡인다  ←  핀 13 = Mega 내장 LED 핀 = 좌측 ESC 신호선
```

**ESC 가 그 깜빡임을 명령으로 받아들였다.**

### 이 위험은 계속 재발한다

| 언제 | 결과 |
|---|---|
| 시리얼 모니터를 열 때 | 재시작 → 좌측 스러스터가 튄다 |
| 펌웨어를 업로드할 때 | 재시작 → 튄다 |
| USB 를 꽂을 때 | 재시작 → 튄다 |

**노트북을 연결할 때마다 스러스터가 튀는 배가 된다.** 물 위에서도 작업대에서도 위험하다.

### 🚨 08-20 판단이 틀렸다 — 기록으로 남긴다

08-20 에 핀 13 으로 옮기면서 주석에 이렇게 적었다:

> ⚠️ 핀 13 은 Mega 의 내장 LED 핀이라 부트로더가 부팅 때 깜빡인다. ESC 가 그 구간에
> 유효하지 않은 펄스를 보지만 **시동을 안 할 뿐**이고 부팅이 끝나면 정상 신호로 시동된다.

**"시동을 안 할 뿐" 이 틀렸다.** 위험을 알아보고도 "괜찮을 것"으로 넘겼다.
도통으로 "좌측 = 핀 13" 을 확인한 것은 **기판이 그렇게 만들어져 있다**는 뜻이지
**그 자리가 옳다**는 뜻이 아니었다. 작년 Due 기판 배치를 그대로 따라간 것이 원인이다.

### 조치 — 핀 11 로 되돌린다

```
기판의 좌측 ESC 신호선  :  핀 13  →  핀 11 로 이설 (실물 납땜)
펌웨어                 :  PIN_ESC_LEFT 13 → 11
```

핀 11 은 내장 LED 가 없어 부트로더가 건드리지 않는다. 지금 비어 있다.

### 그 밖에 08-25 에 확인된 것

- 지난주 업로드된 것이 **`IBUS_PROBE=1` 진단 빌드**였다 — 여러 플래그로 연속 컴파일한 뒤
  마지막 산출물을 올린 실수. `IBUS_PROBE` 는 Serial1(= **핀 19, 모드 스위치 핀**)을 쓴다.
  상태줄도 3.3Hz 로 떨어져 있었다. → **깨끗한 빌드로 재업로드 완료** (상태줄 9.0Hz 정상)
  **앞으로 업로드 명령에 빌드 플래그를 명시하고, 업로드 직후 상태줄을 확인할 것.**
- 좌우 분리 시험: 펌웨어는 정확히 출력했으나(각 구간 30줄) **좌측은 돌지 않았다.**
- 시험 후 **좌측 앞이 1500 에서 계속 살짝 돌았다.** 아두이노는 5초 내내 정확히 1500 고정.
  → 신호는 도달하는데 **ESC 중립 캘리브레이션이 어긋났을** 가능성. 핀 11 이설 후 재확인할 것.
  (미실시 시험: 좌측만 1300 역방향 → 반대로 돌면 배선 정상 + 캘리브레이션 문제 확정)

### 다음에 할 일
1. 좌측 ESC 신호선을 **핀 11 로 이설** (납땜)
2. 펌웨어 `PIN_ESC_LEFT` **13 → 11**
3. 좌우 분리 시험 재실시
4. 좌측이 1500 에서 도는 증상이 남으면 **ESC 스로틀 캘리브레이션**

## 4. ✅ 접촉기 자기유지 성공 (08-25)

**배터리 A 를 `⊕` 차단(5번→6번)으로 바꾸고 컨버터·릴레이 급전을 접촉기 앞으로 옮긴 뒤,
배터리를 꽂으니 초록 버튼 없이 접촉기가 스스로 붙었다.**

```
원인 확정 :  컨버터는 멀쩡했다. 배선이 잘못돼 전기가 안 갔던 것이다.
```

### 🚨 그래도 컨버터 교체는 필요하다 — 지금 된다고 끝난 게 아니다

```
현재 배터리 전압 : 16V 아래로 추정  →  컨버터 규격(11~16V) 안 → 동작
만충 16.8V       : 규격 밖          →  과전압 보호로 다시 안 붙을 수 있다
```

**대회 당일 아침, 배터리를 막 충전해서 꽂는 그 순간이 가장 위험하다.**

⭐ **만충 시험을 반드시 할 것.** 배터리를 만충(16.8V)해 꽂았을 때도 붙으면 현 컨버터로 버틸 수 있고,
안 붙으면 새 컨버터가 필수임이 확정된다. 주문품 도착 전에 알아두면 좋다.

### 주문 완료 (08-25)
- 컨버터: 입력 9~20V / 출력 24V / IP68 (알리익스프레스)
  → 도착하면 **상세페이지의 `Input voltage` 가 `9-20V` 인지 실물 라벨로 재확인**할 것

### 다음
- 비상정지 2종 단독 동작 확인 (버튼만 / 리모컨만 각각 떨어져야 함) — 08-25 확인 예정
- 좌측 ESC 신호선 핀 13 → 11 이설 (부트로더 위험, §3)

### ✅ 비상정지 2종 동작 확인 (08-25)

```
무선 (리모컨만 누름)   →  접촉기 차단  ✅
유선 (버튼만 누름)     →  접촉기 차단  ✅  · 머리를 돌려 복귀시키면 다시 통전
```

**각각 단독으로 작동한다.** 08-20 이전에는 릴레이와 비상정지가 **병렬**이라
둘 다 눌러야만 멈췄다 — 사실상 비상정지가 없는 상태였다.
직렬 재납땜(§2 목표 회로도)의 효과가 실물로 확인됐다.

⚠️ 무선은 토글 방식일 수 있다. 그러면 **리모컨을 실수로 다시 누르면 배가 살아난다.**
비상정지 후 사람이 접근할 때는 **배터리를 분리**하는 것이 최종 안전이다.
(모드 점퍼 `1-2=M / 2-3=T / OPEN=1` 실제 설정은 아직 미확인)

### 대회 규정 항목 진행 상황
```

✅ 무선 비상정지 (검사 9·10번)
✅ 유선 비상정지
⬜ 접촉기 21/22 → 아두이노 핀 38 + GND   — 노트북이 비상정지 상태를 아는 것
```

## 6. 수동 모드 확인 + 미해결 항목 (08-25)

### ✅ 수동 조종 자체는 정상

```
1900,1900,1900,1900   전진 최대
1100,1100,1100,1100   후진 최대
1900,1100,1900,1100   제자리 선회
1100,1900,1100,1900   반대 선회
```

스로틀·조향이 제대로 섞이고 끝값(1100~1900)도 정확하다. 믹싱 로직 문제 없음.

### 🚨 트림이 어긋나 있다 — 손을 떼도 중립이 아니다

```
정지 상태 출력 :  1572, 1492, 1572, 1492
분해          :  스로틀 +34   조향 +38
ESC 데드밴드   :  ±25
```

**둘 다 데드밴드를 넘는다 → 가만히 둬도 스러스터가 돈다.**
`tools/trim_watch.py` 가 좌우 출력을 스로틀/조향 성분으로 분해해 보여준다.
```
스로틀 = (좌+우)/2 − 1500      조향 = (좌−우)/2
```

**스로틀은 트림 버튼으로 안 잡힌다 — 왼쪽 스틱 위아래는 래칫 축이라 손으로 옮겨야 한다.**
조향(오른쪽 스틱 좌우)은 자동복귀 축이라 트림 버튼이 맞다.
⚠️ FS-i6 트림은 4개인데 우리가 쓰는 건 2개뿐이다. 안 쓰는 트림을 눌러도 삑 소리는 똑같이 난다
   → 누를 때 **화면의 어느 막대가 움직이는지** 볼 것.

### 🚨 좌/우 배정이 뒤바뀐 것으로 의심된다 — 최우선 확인 항목

```
정지 시 핀 11 계통 = 1572 (데드밴드 초과 → 돈다)
정지 시 핀 12 계통 = 1492 (데드밴드 안 → 안 돈다)
사용자 관찰       : 실제로 도는 쪽은 「우측」
→ 핀 11 이 물리적으로 우측일 가능성
```

펌웨어는 `PIN_ESC_LEFT = 11` 이다. **반대라면 자율 주행에서 배가 정반대로 조향한다.**
물에 띄우기 전 반드시 확정할 것 — 반대면 `PIN_ESC_LEFT`/`PIN_ESC_RIGHT` 두 줄만 맞바꾼다.

**확정 방법:** `tools/pin_test.py` 를 돌리고 **각 구간에서 물리적으로 어느 쪽이 도는지**만 본다.
(08-25 시험에서 "둘 다 돌았다"까지만 받아서 이 답을 못 얻었다 — 다음엔 좌/우를 명시해서 받을 것)

### 🚨 ESC 시동이 느리다 — 반복 확인됨

```
전원 인가 직후  →  우측이 안 돎
잠시 후         →  돌기 시작
```

짧은 시험(시동 6초)에서 "안 돈다"고 두 번 오판했다. **시동 대기를 12초로 늘리자 정상 동작.**

## 7. 🎯 좌/우 배정 확정 — 뒤바뀌어 있었다 (08-25)

`tools/pin_test.py` 로 한 핀씩만 구동해 눈으로 확인:

```
핀 11 만 1580  →  물리적 우측 2개 회전
핀 12 만 1580  →  물리적 좌측 2개 회전
```

**펌웨어는 `PIN_ESC_LEFT = 11` 이었다 → 정확히 반대였다.**

```c
// 수정 후
#define PIN_ESC_LEFT    12
#define PIN_ESC_RIGHT   11
```

교체 후 재시험: **① 좌측 명령 → 좌측 2개 · ② 우측 명령 → 우측 2개.** 일치 확인.

### 왜 이게 중요한가
`CLAUDE.md` §8 이 경고하던 **"조향 좌/우 부호 — 배선이 반대면 모든 게 무의미하다. 가장 흔한 사고"**
가 실제로 있었다. 이대로 물에 띄웠으면 **자율 주행에서 배가 정반대로 조향**했을 것이고,
갭-팔로잉·게이트·도킹이 전부 반대로 동작했을 것이다. 시뮬로는 절대 못 잡는다.

⚠️ 상태줄 `S,...,FL,FR,RL,RR` 의 의미는 불변이다(0번=좌, 1번=우). 핀 번호만 맞바꿨으므로
`ssf_bridge` 계약은 영향 없다.

### 확정 방법이 중요했다
"좌측만 돌려봐라" 로는 확정이 안 된다 — **이름표 자체가 의심 대상**이기 때문이다.
`pin_test.py` 가 **좌/우 이름을 쓰지 않고 핀 번호로만** 구동하고, 어느 쪽이 도는지를
사람이 눈으로 보고 매핑하는 구조라 답이 나왔다. 배정이 확정된 뒤 스크립트 표시는 좌/우로 되돌렸다.

## 8. 🚨 시리얼 포트를 열면 아두이노가 재시작한다 (08-25)

### 증상
수동에서 스러스터가 돌고 있을 때, **읽기 전용 스크립트를 돌리자 삑 소리와 함께 멈췄다.**
명령을 보내서가 아니라 **포트를 여는 것만으로 보드가 재시작**한 것이다.

```
포트 open  →  DTR 토글  →  아두이노 리셋
           →  모드가 「대기」부터 시작 → 출력 1500
           →  ESC 재시동 (그 삑 소리)
           →  스러스터 정지
```

### 대회에서 문제가 된다
```
브릿지가 연결/재연결될 때마다  →  아두이노 재시작  →  스러스터 정지 + ESC 재시동 대기
```
ESC 시동에 **15~25초**가 걸린다(08-25 실측). 경기 중이면 그동안 배가 표류한다.

### `-hupcl` 로는 못 막는다 — 시험함
```
stty -F /dev/ttyACM0 -hupcl   →  설정은 됐지만 여전히 리셋됨
```
`hupcl` 이 아니라 **pyserial 이 포트를 열 때 DTR 을 건드리는 것**이 원인이다.
아두이노는 DTR 을 리셋 신호로 받도록 설계돼 있어 소프트웨어만으로는 완전히 막기 어렵다.

### 대책
| | 방법 | 비고 |
|---|---|---|
| ① | **브릿지가 포트를 한 번 열고 경기 내내 닫지 않는다** | 지금 구조에서 가장 중요. 리셋이 처음 1회로 끝난다 |
| ② | 출발 절차: 브릿지 실행 → **ESC 시동 15~25초 대기** → 출발 | `docs/절차/boat_launch_checklist.md` 에 넣을 것 |

🚨 **소프트팀 전달 필요:** `ssf_bridge` 가 죽었다 다시 뜨면 그때마다 배가 멈춘다.

## 9. RC 채널 배정 — 스로틀·조향이 뒤바뀌어 있었다 (08-25)

### 격리 측정 결과 (`tools/stick_probe.py`)
한 축씩만 움직이며 좌·우 출력을 성분 분해했다.
```
스로틀 성분 = (좌+우)/2 − 1500      조향 성분 = (좌−우)/2
```

| 움직인 축 | 반응한 채널 | 폭 |
|---|---|---|
| 왼쪽 스틱 **좌우** | 핀 3 (당시 스로틀로 읽힘) | 288 |
| 오른쪽 스틱 **상하** | 핀 2 (당시 조향으로 읽힘) | 196 |

팀 규약은 **오른쪽 상하 = 전후진 / 왼쪽 좌우 = 좌우회전** 이므로 **정반대**였다.

### 조치 — 두 #define 을 맞바꿈 (업로드 완료)
```c
#define PIN_RC_THROTTLE  2    // 오른쪽 스틱 상하 (구 3)
#define PIN_RC_STEER     3    // 왼쪽 스틱 좌우 (구 2)
```
둘 다 인터럽트 가능 핀(2·3)이라 제약 없음. 5가지 빌드 전부 컴파일 통과.

### ⚠️ 아직 확인 못 한 것 — 내일 이어서
1. **바꾼 뒤 채널이 맞는지 재확인** — 08-25 마지막 시험은 스틱 움직임이 너무 작아(폭 40) 판정 불가
2. **`THROTTLE_INVERT_RC` / `STEER_INVERT_RC`** — 둘 다 `true` 인데 **옛 채널 기준으로 정한 값**이다.
   채널을 바꿨으니 방향이 반대일 수 있다. 반드시 재확인할 것
3. **트림** — 정지 시 스로틀 +32~40 / 조향 0~40

### 🎯 다음 시험은 **배터리를 빼고** 할 것
```
트림이 +36 이라 가만히 있어도 스러스터가 돈다
→ 스틱을 밀어도 "이미 돌던 게 빨라지는" 것이라 눈으로 구분이 안 된다
→ 위험해서 끝까지 못 밀고, 그래서 폭이 작아 판정도 안 된다
```
**배터리를 빼면 스러스터가 안 도니 마음껏 끝까지 밀 수 있다.**
숫자만 보면 되므로 추진 전원이 전혀 필요 없다. 폭 300 이상 나오면 판정이 확실해진다.

⚠️ 08-25 에 "살짝만 미십시오" 라고 안내한 것이 시험을 두 번 무효로 만들었다.
   **판정이 목적일 때는 배터리를 빼고 끝까지** 가 맞다.

## 10. 🎯 스러스터 추력 방향이 대각선으로 어긋나 있다 (08-27)

### 실측
자율 모드에서 **네 개에 똑같이 `1750`** 을 20초 송출하고 바람 방향을 확인했다.

```
        전진 ✅      후진 🚨
앞  :    우앞         좌앞
뒤  :    좌뒤         우뒤
```

**같은 쪽 두 개가 정반대로 민다 → 순 추력이 상쇄된다.**

```
좌측 : 앞이 뒤로, 뒤가 앞으로   →  합계 ≈ 0
우측 : 앞이 앞으로, 뒤가 뒤로   →  합계 ≈ 0
```

### 이것이 "수동이 이상하다" 의 답이다
아두이노도 ESC 도 정상이었다. 명령은 네 개에 똑같이 나갔고(상태줄로 확인),
ESC 4개도 같은 명령에 같은 **회전** 방향으로 반응했다(08-27 확인).
**어긋난 것은 추력 방향**이다 — 프로펠러 감김(CW/CCW)과 모터 배선이 안 맞는다.

T200 은 회전 반작용 상쇄를 위해 CW·CCW 프로펠러를 쌍으로 쓴다.
**그때 모터 배선도 같이 뒤집어야 추력이 같은 방향이 된다.** 그게 안 돼 있었다.

### 🎯 원인 확정 (08-27) — 배선은 통일, 프로펠러는 2종

```
ESC↔모터 3선 순서 : 네 개 모두 동일 (흰-초-파)   → 모터 회전 방향도 모두 같다
프로펠러          : 만져보니 생김새가 다르다 (CW / CCW 2종)
→ 같은 회전인데 물을 반대로 민다
```

| 프로펠러 | 필요한 모터 회전 | 필요한 배선 |
|---|---|---|
| CW | 시계 | 흰-초-파 |
| CCW | 반시계 | **흰-파-초** (두 개 맞바꿈) |

**프로펠러가 2종이면 배선도 2종이어야 한다.** 지금은 프로펠러만 섞이고 배선은 통일돼 있다.

```
지금 :  프로펠러 2종 + 배선 1종  →  추력 어긋남 🚨
정상 :  프로펠러 2종 + 배선 2종  →  추력 일치   ✅
```

🚨 **"왜 두 개만 색 순서가 다르지?" 하고 되돌리면 다시 고장 난다.**
바꾼 자리에 물리적 표시(테이프·유성펜)를 남길 것.

### 조치 — `좌앞` 과 `우뒤` 를 뒤집는다
```
🚨 배터리 분리 후
좌앞 ESC ↔ 모터 3선 중 아무 두 개 맞바꾸기
우뒤 ESC ↔ 모터 3선 중 아무 두 개 맞바꾸기
```
브러시리스는 3선 중 둘을 바꾸면 회전이 반대가 된다. **배선 교체가 표준**이다.
**대안: 프로펠러를 같은 종류로 통일** — 배선은 그대로 두어도 되지만
**회전 반작용 상쇄가 사라진다**(배가 한쪽으로 돌려는 힘이 남는다).
물에 닿는 부품을 분해해야 하고 CW/CCW 를 헷갈릴 위험도 있다. **배선 교체를 권한다.**

> 브러시리스 3상선에는 **극성이 없다.** 서보 신호선(흰/빨/검)과 달리 순서를 지킬 필요가 없고,
> 두 개를 맞바꾸면 회전만 반대가 된다. 이것이 방향을 바꾸는 표준 방법이다.

### 고친 뒤 확인
`tools/hold.py 1750 1750 20` 을 다시 돌려 **네 개가 전부 같은 방향**인지 볼 것.

### 왜 여태 몰랐나
- 지금까지는 **"도는가 / 안 도는가"** 만 봤다. 방향은 물 밖에서 티가 안 난다
- 좌/우 배정, 핀 번호, RC 채널을 먼저 잡느라 여기까지 못 왔다
- 🚨 **물에 띄웠으면 "명령은 맞는데 배가 안 나간다" 로 한참 헤맸을 문제다**

### 도구 수정 (08-27)
`tools/hold.py` 에 **ESC 시동 대기 25초**를 넣었다. 없어서 "1600 을 보냈는데 아무것도
안 돈다" 로 한 번 오진했다 — `pin_test.py` 에는 있었는데 `hold.py` 에만 빠져 있었다.
**포트를 열면 보드가 재시작하므로 시동 대기는 매 실행마다 필요하다.**

### "상선 순서를 지켜야 한다" 는 T200 에 해당 없다 — 제조사·자료 확인 (08-27)

팀 내에 **"흰-초-파 순서를 무조건 지켜야 한다 / 극성을 안 지켜서 ESC 가 터졌다"** 는 이야기가 있어
근거를 확인했다. **다른 상황 이야기다.**

#### 제조사 문서 (BlueRobotics)
```
"세 선의 순서는 상관없다(the order does not matter).
 모터 방향이 원하는 것과 반대면 아무 두 개를 맞바꿔라."
```
ESC 펌웨어·설정 변경 불필요. 납땜·총알단자·나사단자 모두 가능.

#### 순서가 중요한 건 **센서 있는(sensored) 모터**다
| | 선 구성 | 방향 전환 |
|---|---|---|
| 센서리스 | 굵은 3선만 | ✅ 두 선 맞바꿈. 안전 |
| 센서 있음 | 3선 + **얇은 Hall 케이블** | 🚨 Hall 과 짝이 어긋나면 전류 급증 → 부하 시 손상 |

**T200 은 Hall 센서가 없다.** ESC 가 역기전력으로 위치를 추정하므로 "틀린 조합"이 존재하지 않는다.

#### 실제로 ESC 를 태우는 것
| 원인 | 결과 |
|---|---|
| **배터리 ⊕⊖ 역접속** | 🚨 MOSFET·커패시터 즉시 파괴. **이것이 "극성"** |
| 통전 중 모터선 탈착 | 역기전력 스파이크 → 소자 손상 |
| 상선끼리 단락 / 접촉 불량 | 아크 → 손상 |
| **상선 순서 (센서리스)** | ✅ 회전 방향만 바뀜 |

#### 작업 전 확인 (1분)
```
ESC ↔ 스러스터 사이에 얇은 다발(5~6가닥)이 있는가?
  없다 → 센서리스 확정. 진행
  있다 → 중단하고 재검토
```

### 프로펠러 정/역방향 판정 (08-27)
BlueRobotics: *"시계방향 프로펠러는 시계방향으로 돌 때 정방향 추력을 낸다"*
→ **정방향 추력이 나오면 그것이 그 프로펠러의 정방향.**

| 명령 1750 | 추력 | 판정 |
|---|---|---|
| 좌뒤 · 우앞 | 전진 | ✅ 정방향 (약 5.25 kgf) |
| 좌앞 · 우뒤 | 후진 | 🚨 역방향 (약 4.1 kgf, 20% 약함) |

배선을 고치면 **네 개 모두 전진 시 정방향**이 된다 — 추력도 반작용 상쇄도 설계대로 돌아온다.

### 🚨 그다음에 확인할 것 — 브릿지 계약과 어긋난다
```
실물   :  1750(>1500) = 전진
펌웨어 머리말 / 브릿지 계약 :  "1500=중립, <1500=전진"
```
**`motor_control` 은 1500 미만을 전진으로 보낸다.** 지금 실물과 반대다.
수동만 고치면 **자율에서 배가 뒤로 간다.**
스러스터 방향을 통일하고 `1750=전진` 을 확정한 뒤 이 계약도 함께 맞출 것.

### 내일 작업
```
대상 : 좌앞 · 우뒤   (좌뒤 · 우앞은 그대로)

1. 배터리 둘 다 분리 · 접촉기 떨어진 것 확인
2. 2~3분 대기 (ESC 커패시터 방전)

6. 🚨 바꾼 자리에 표시 (테이프·유성펜) — 안 하면 나중에 "색이 다르네" 하고 되돌린다
7. tools/hold.py 1600 1600 12  →  이상 없으면  1750 1750 20
   → 네 개 전부 같은 방향이면 완료

### 진행 상황 — 좌앞 배선 교체 완료 (08-27)

```

### ① 🚨 자율 규약이 실물과 반대였다 — `ssf_bridge` 에서 반전

```
motor_control 규약 :  1500=정지, <1500=전진, >1500=후진   (base_pwm=1360, reverse_pwm=1590)
실물(08-27 실측)   :  >1500 = 전진
→ 이대로 자율을 켜면 배가 뒤로 간다
```

**`ssf_bridge._send` 에서 시리얼로 내보낼 때만 1500 대칭 반전.**
```python
pwm_l, pwm_r = 3000 - pwm_l, 3000 - pwm_r     # 파라미터 invert_thrust_direction (기본 true)
```
- ROS 쪽(`Motor_run`·`/motor_reverse`·blackbox)은 **규약 그대로**
- `motor_control` 은 손대지 않았다 — 시뮬 검증 로직 보존 (CLAUDE.md §1)
- `steer_invert` 불변 — 축 전체가 뒤집히며 차동 부호도 함께 맞는다
- 수동(RC)은 이 경로를 안 탄다

검산: 중립 1500→1500 · 순항 1360→1640 · 후진 1590→1410 ·
전진+우회전 1300,1400→1700,1600 · 제자리선회 1400,1600→1600,1400
테스트 `src/ssf_bridge/test/test_thrust_invert.py` 10개 추가 → **38개 전부 통과**

🚨 **스러스터 배선을 다시 뒤집으면 `invert_thrust_direction` 을 false 로 되돌릴 것.**

### ② 🎯 수동에서 "가만히 둬도 돈다" 의 진짜 원인 — 스틱 중립이 1500 이 아니었다

```
실측 (30초, 손 뗀 상태, 표본 28)
  thr : 중앙값 1480,  범위 1456~1484,  진동폭 28
  str : 중앙값 1442,  범위 1436~1468,  진동폭 32
```

펌웨어는 `snapPulse − 1500` 으로 편차를 냈다 → **손을 떼도 −20 / −58 이 남아**
데드밴드(20)를 뚫고 명령이 계속 나갔다. **데드밴드가 무력했다.**

```c
const int RC_CENTER_THROTTLE_US = 1480;   // ⚠️ 조종기 실측
const int RC_CENTER_STEER_US    = 1442;   // ⚠️ 조종기 실측
const int RC_DEADBAND_US        = 30;     // 진동 ±16 을 덮게 (구 20)

thr = applyDeadband(snapPulse(0) - RC_CENTER_THROTTLE_US);
str = applyDeadband(snapPulse(1) - RC_CENTER_STEER_US) * STEER_SCALE_N / 10;
```

**결과: 수동에서 24초 내내 `1500,1500,1500,1500` 유지 확인 ✅**

⚠️ **조종기 개체·트림에 종속된 값이다.** 바꾸면 재측정해야 한다 →
부팅 로그에 찍게 했다: `RC CENTER: thr=1480 str=1442 deadband=30`

> 물리 트림으로 1500 에 맞출 수 있으면 그쪽이 낫다. 트림 버튼을 못 찾아 코드로 처리했다.

### ③ 오경보 정정 — 모드 채널은 정상이다
"왼쪽 스틱 상하가 모드를 바꾼다"고 판단했으나 **틀렸다.**
`RC_DEBUG` 로 원시 펄스를 보니 왼쪽 스틱 상하는 어느 채널도 안 건드렸다.
앞선 관측의 `대기` 는 포트 open 시 보드 재시작 직후 상태였고, 모드 변화는 SwD 조작이었다.
**스틱→모드 연동 버그는 없다.**

### ④ 🚨 시험 중단 — 조종기 배터리 방전
```
TX 표시 깜빡임 · 건전지 거의 없음
→ 송신 끊김 → 수신기가 마지막 값을 계속 유지
→ 스틱을 움직여도 thr/str 이 ±12 진동만 (값은 있는데 안 변함)
```
**실전 위험을 그대로 보여준 사례다.** 마지막 값이 중립 근처라 안 움직였을 뿐,
전진 중이었으면 배가 계속 전진했을 것이다.

### 다음에 이어서
```
1. 조종기 AA 4개 교체
2. 스틱 방향 확정   오른쪽 위=전진?  ·  왼쪽 우=우회전?
   → 반대면 THROTTLE_INVERT_RC / STEER_INVERT_RC 뒤집기
   (둘 다 08-18 값인데 08-25 채널 교체 후 재확인 안 됨)
3. 🚨 FS-i6 페일세이프 설정 (RX Setup → Failsafe) — ④의 근본 대책
4. 깨끗한 빌드로 되돌리기 (현재 RC_DEBUG 빌드가 올라가 있음)
5. 출발 전 점검에 **조종기 배터리 잔량** 추가
```

## 13. 🎯 배터리 연결 순서가 ESC 시동을 좌우한다 (2026-09-03)

### 증상과 원인
자율 전진·후진 시험에서 **우측 2개가 안 돌았다.** 신호(핀 11 = 0.3V)도 배선도 정상이었는데 —
**배터리 연결 순서** 문제였다 (사용자가 직접 발견).

```
5·6번 배터리 = 컨버터·릴레이 급전  →  꽂는 순간 접촉기가 닫힌다
```

| 순서 | 결과 |
|---|---|
| **1·2번 먼저 → 5·6번 나중** | 접촉기 닫히는 순간 4개 동시 전원 인가 → 전부 중립 보고 시동 ✅ |
| 5·6번 먼저 → 1·2번 나중 | 1·2번 쪽 ESC 가 **늦게** 전원 인가 → 그 시점 신호가 중립이 아니면 시동 거부 🚨 |

ESC 는 **전원 인가 순간 중립(1500)을 봐야 시동**된다(08-25 확인). 늦게 꽂힌 쪽이
시험 도중(비중립 송출 중)에 전원을 받으면 그 세션 내내 죽은 것처럼 보인다.
**"우측이 죽었다" 는 오진이었다 — 시동 누락이었다.**

### 🏁 출발 절차 확정
```
1. 1·2번 쪽 배터리 먼저 연결   (접촉기 열려 있어 아무 일 없음)
2. 5·6번 쪽 배터리 연결        (접촉기 닫힘 — 4개 동시 전원 인가)
3. ESC 시동 15초 대기 (삑 소리 4개 확인)
4. 그 다음 출발
```
`docs/절차/boat_launch_checklist.md` 에 반영할 것.

### 확인 결과 (자율 모드)
```
전진 1600 : 4개 전부 회전 ✅
후진 1400 : 4개 전부 회전 ✅     ← 후진 4개 동시 확인은 이번이 처음
```
**전진·후진 양방향 4개 동시 구동 확정. 추진부 완전 검증 완료.**

## 14. 🎉 수동 모드 완성 (2026-09-03)

### 최종 실측 — 스틱 → 명령 방향 (배터리 불필요, 숫자로 검증)

| 조작 | 출력 (좌/우) | 뜻 | 판정 |
|---|---|---|---|
| 오른쪽 스틱 [위] | 1900 / 1900 | +400 전진 | ✅ |

**스틱→명령, 명령→추력 두 단계가 모두 검증됐으므로 조합도 성립한다.**

### 두 INVERT 플래그를 모두 해제했다
```c
THROTTLE_INVERT_RC = false;   // 09-03 (구 true — 08-18 옛 채널 기준)
STEER_INVERT_RC    = false;   // 09-03 (구 true — 같은 이유)

🚨 **교훈: 채널을 바꾸면 반전 플래그도 반드시 재확인.** 08-25 채널 교체 때 밀린 확인이
오늘까지 왔다. 스틱 위=후진, 오른쪽=좌회전인 채로 물에 나갈 뻔했다.

### 수동 모드 확정 명세 (대회 기준)
```
오른쪽 스틱 위/아래  =  전진 / 후진
왼쪽 스틱 좌/우      =  좌회전 / 우회전 (제자리 선회)
스틱 중립           =  정지 (RC_CENTER 1480/1442 보정 + 데드밴드 30)
모드 스위치 SwD      =  위 수동 / 아래 자율 (조종기 켜면 수동 시작)
```

부하 중 셀 전압이 경고선 아래로 → **즉시 분리 (올바른 조치)**.
오늘 시험을 많이 돌려 소모가 컸다. 충전 후 재사용.

## 15. 🎉 FS-i6 페일세이프 설정 완료 (2026-09-03)

### 검증 실측
```
스틱 위 유지        →  1900 / 1900
조종기 전원 OFF     →  **즉시 1500 / 1500** · 모드 수동 유지   ✅
```
설정 전에는 같은 시험에서 **1900 이 25초간 그대로 유지**됐다(수신기가 마지막 값을 물고 있음).

### 설정 내용 (RX Setup → Failsafe)
- Ch1~Ch6 전부 **명시적으로 Off → ON** 전환, 스틱 중립·SwD 위 상태에서 저장(CANCEL 길게)
- 결과: 링크 두절 시 스로틀·조향 = 중립, 모드 = **수동** (Ch6 −100% = SwD 위)

### ⚠️ 걸렸던 함정
Failsafe 화면의 `%` 표시는 **실시간 스틱 위치**를 함께 보여준다.
값이 보인다고 ON 인 게 아니다 — **채널마다 Off→ON 을 명시적으로 바꾸고 저장**해야 한다.
1차 시도에서 이걸 놓쳐 "설정했는데 안 먹는" 상태였다.

### 이것으로 닫힌 위험
```
09-01 : 조종기 배터리 방전 → 수신기가 굳은 값 송출 (마침 중립이라 무사)
09-03 : 같은 증상 재발
→ 전진 중에 끊겼다면 배가 계속 전진했을 상황. 이제 자동으로 멈춘다.
```
⚠️ 조종기 트림·채널·설정을 바꾸면 페일세이프 저장값도 다시 확인할 것.

## 16. 🚨 새 컨버터 도착 전까지의 주의사항 (2026-09-03)

> 만충 시험은 생략한다 — 어차피 컨버터를 교체하기로 했다(입력 9~20V 주문 완료).
> **도착 전까지는 현 컨버터(입력 11~16V)로 운용하므로 아래를 지킬 것.**

### 배터리를 만충(16.8V)으로 꽂지 말 것
```
현 컨버터 입력 상한 : 16V
4S 만충            : 16.8V   ← 범위 밖
→ 과전압 보호로 출력이 죽으면 접촉기가 안 붙는다 (한 달 헤맨 그 증상 재발)
→ 최악의 경우 컨버터가 상한다
```
**시험 전 배터리를 조금 쓰거나, 충전을 16V 아래(셀당 4.0V ≈ 스토리지 충전)에서 멈출 것.**

### 접촉기가 안 붙으면 — 의심 순서
```
1. 배터리 전압부터 잰다  →  16V 이상이면 그게 원인 (컨버터가 거부 중)
2. 스러스터를 잠깐 돌려 15V 대로 낮추고 재시도
3. 그래도 안 붙으면 코일 회로(A1↔A2 전압) 확인
```

### 배터리 연결 순서 (§13 확정 — 항상 지킬 것)
```
1·2번 쪽 먼저  →  5·6번 쪽 나중  →  삑 4개 확인  →  15초 대기
```

### 새 컨버터 도착 시 교체 절차
```
1. 배터리 전부 분리
2. 구 컨버터 IN ⊕/⊖, OUT ⊕/⊖ 4선 위치 사진 촬영
3. 신품으로 같은 배선 (IN → 배터리 5·6쪽 접촉기 앞 분기 / OUT ⊕ → A1 / OUT ⊖ → 비상정지)
4. 도착 실물 라벨에서 Input voltage 가 9~20V 인지 재확인 — 페이지와 실물이 다른 경우가 있다
5. 시험: 만충 배터리로 접촉기 자기유지 + 비상정지 2종
→ 이게 되면 만충 주의사항(위)은 폐기
```

## 19. 🎉 LED 스트립 해결 — **데이터 방향이 반대였다** (2026-09-08)

### 결론부터

**스트립은 처음부터 멀쩡했다. 죽은 LED 도, 전원 부족도 아니었다.**
`DIN` 이라고 믿었던 쪽이 실제로는 `DOUT`(나가는 끝)이었다.
**데이터를 며칠 동안 나가는 쪽에 밀어 넣고 있었다.**

```
우리가 "1번"  이라 부르던 쪽  =  실제 DOUT   ← 여기에 신호를 넣고 있었다
우리가 "34번" 이라 부르던 쪽  =  실제 DIN    ← 정답
```

### 이 하나로 그동안의 증상이 전부 설명된다

| 증상 | 원인 |
|---|---|
| "불이 하나만 켜져있는데" | 데이터 핀 보호 다이오드로 칩 1~2개만 기생 급전 |
| "색깔이 계속 바뀌는데" | 정상 데이터가 아니므로 색이 무의미 |
| "밝기를 바꿔도 안 변한다" | 밝기 명령 자체가 전달되지 않음 |
| "1개였다가 2개" | 기생 급전량에 따라 개수가 흔들림 |
| "첫 LED 가 손상된 듯" | **오진.** 멀쩡했다 — 잘라내지 않은 게 다행 |

### 🚨 이 오진들을 남겨 둔다 (같은 함정을 또 판다)

며칠에 걸쳐 아래를 차례로 의심했고 **전부 틀렸다.**

1. **"AA 3개로는 34개를 못 버틴다"** → 사용자가 "작년엔 됐다"고 반박. 철회.
   실제 원인은 **AA 홀더 접점 산화**(1.6V)였고 지우개 청소로 해결됐다(§17).
2. **"첫 LED 가 손상됐다"** → 데이터 방향 문제였다. 잘라내라고 권했는데 안 하길 잘했다.
3. **"핀 16 에 아무것도 안 꽂혀 있다"** → 배선은 맞았다. Mega 의 14~21 구간은
   숫자보다 `TX2/RX1` 같은 이름이 크게 찍혀 있어 번호를 놓치기 쉽다. **핀 16 = `TX2`**.
4. **"전원이 0V 다"** → 측정 실수. 다시 재니 4.8V.

**공통점: 증상 하나로 원인을 단정했다.** 스트립은 전원·데이터·GND 세 가지가
동시에 맞아야 켜지는데, 하나만 의심하고 나머지를 검증하지 않았다.

### 진단을 가른 측정 — 이 순서가 정답이었다

```
① 스트립 앞쪽 5V ↔ GND   → 4.8V   → 전원 들어옴
② 스트립 끝쪽 5V ↔ GND   → 4.9V   → 전원이 끝까지 감
   ∴ 전원은 무죄. 남는 건 데이터 사슬뿐
③ 데이터선을 반대쪽 끝으로 이동     → 34개 전부 점등
```

**"어디까지 가는가" 를 두 지점에서 재는 것**이 핵심이었다.
한 지점만 재면 "전원 정상" 으로 끝나고 아무것도 못 가린다.

### 최종 배선 (확정)

```
아두이노 5V   (POWER 헤더) ──▶ 스트립 5V
아두이노 GND  (POWER 헤더) ──▶ 스트립 GND
아두이노 핀 16 (= TX2)     ──▶ 스트립 DIN   ← "IN" 이라고 표시해 둘 것
```

전원을 **아두이노에서 뽑는다.** 별도 AA 홀더를 쓰지 않는다 —
접점 산화·전압 부족·GND 분리로 이 프로젝트에서 가장 많은 시간을 잡아먹은 경로다.

### 🚨 그 대가: 밝기 상한 40 (수신기와 같은 5V 레일)

**아두이노 5V 는 RC 수신기가 같이 쓴다.** 스트립이 전류를 끌면 수신기가 함께 죽는다.

```
USB 급전 폴리퓨즈        0.5A
보드 0.1 + 수신기 0.05 + 스트립

스트립은 색마다 다르고 자율 모드의 노랑(255,170,0)이 최대다 (채널 2개 점등)
  밝기 60 → 노랑 0.27A → 합계 0.42A   여유 16% (폴리퓨즈는 더워지면 더 내려감. 빠듯)
  밝기 40 → 노랑 0.18A → 합계 0.33A   ✅ 채택
```

**밝기 40 을 넘기려면 먼저 전원을 분리해야 한다.** 그냥 올리면 수신기가 죽어
**수동 조종을 잃는다.**

⚠️ 별도 전원으로 옮길 때 **두 전원을 동시에 물리지 말 것** — 전압이 달라 역류한다.
반드시 하나를 뗀 뒤 다른 하나를 붙인다.

### 검증

```
스위치 [아래] → 자율 → 노랑     ✅ 상태줄 55/55 가 모드 2, 색 일치 확인
스위치 [위]   → 수동 → 초록
```

**LED 색은 모드에서만 나온다.** 조종기가 꺼져 있으면 대기 = 소등이 정상이다.
"조종기 켰는데 불이 안 들어와" 를 확인할 때는 **조종기부터 켜고 모드를 확인**할 것.

### 남은 일

- [ ] 세 가닥(5V·GND·DIN) **납땜 고정** — 점퍼는 물 시험 중 흐트러진다(그렇게 배선이 어긋났다)
- [ ] DIN 쪽 끝에 **"IN" 표시** — 눈으로 구분이 안 되고, 번호는 우리 쪽 오해였다
- [ ] 주광 시인성 확인. 부족하면 **전원 분리 후** 밝기 상향

### 참고 — 핀 18 은 비어 있다

`M` 소켓이 핀 18 인데, 모드는 08-18 에 **핀 19 로 이설**했고 그 뒤 임자가 없다.
경기 펌웨어에서 핀 18 은 아무 데도 쓰이지 않는다
(`SCAN_PINS`·`Serial1` 은 전부 진단 빌드 전용). **LED 를 여기 꽂으면 안 된다.**

## 20. ✅ 비상정지 표시등 완료 — 접촉기 b접점 → 핀 38 (2026-09-09)

대회 요구사항이었고 §19 까지 유일하게 남아 있던 표시등 항목이다. **선 두 가닥으로 끝났다.**

### 왜 접촉기에서 따는가 (버튼이 아니라)

비상정지는 **유선 버튼**과 **무선 릴레이** 두 갈래인데, 둘 다 코일 회로를 끊어
접촉기를 떨어뜨린다. **접촉기가 모든 경로의 종착점**이다.

| 감지 지점 | 잡히는 범위 |
|---|---|
| **접촉기 보조접점** | 유선·무선·코일고장·컨버터고장·배선단선 **전부** |
| 버튼에서 직접 | 유선만. 게다가 24V 코일 회로라 절연 회로가 필요 |
| 무선 릴레이에서 | 무선만 |
| ESC 전원 분압 | 🚨 배터리 16V 가 아두이노에 직결 — 저항 하나 잘못되면 보드 사망 |

버튼을 감시하면 **"아무도 안 눌렀는데 전원이 나간 상태"** 를 초록으로 표시한다.
접촉기를 보면 그것도 빨강으로 잡힌다.

### 보조접점 찾기 — 각인을 읽지 말고 재라

MD-30a 는 **보조접점 2a2b 내장**(별매 블록 아님). **양쪽 옆면에 4개씩, 총 8개**다.
처음엔 "얇은 단자 4줄" 이라고 설명했는데 **한군데 모여 있지 않아** 사용자가 못 찾았다.

이 프로젝트는 단자 각인 오독으로 이미 여러 번 시간을 날렸다(⊕/⊖ 방향 표시).
**도통이 아니라 Ω 모드로, 두 상태에서 재는 것**이 정답이었다.

```
🚨 배터리 두 개 모두 분리한 뒤

가만히 둔 상태(접촉기 떨어짐)   →  0.3Ω   = 닫힘
초록 버튼 누름(접촉기 붙음)     →  OL     = 열림
        ∴ 값이 뒤집히는 쌍 = b접점(NC) 확정
```

⚠️ **도통(🔊) 모드를 쓰면 안 된다** — `A1-A2`(코일)가 약 48Ω 이라 계기에 따라 삐 소리가 난다.
Ω 모드로 숫자를 보면 안 헷갈린다.
⚠️ 한 번만 재면 "그냥 이어진 선" 과 구분이 안 된다. **반드시 두 상태에서** 잰다.

### 배선 (완료)

```
접촉기 b접점 한쪽   ──▶  아두이노 핀 38
접촉기 b접점 다른쪽 ──▶  아두이노 GND      (극성 없음. 무전압 접점)
                         두 선은 꼬아서 — 전원 케이블 노이즈 대비
```

### 논리 — 펌웨어 가정과 그대로 맞았다 (부호 수정 불필요)

```
정상 운전 (접촉기 붙음)   →  b접점 열림  →  핀38 풀업 HIGH  →  estop=0  →  모드색
비상정지   (접촉기 떨어짐) →  b접점 닫힘  →  핀38 GND  LOW   →  estop=1  →  🔴 빨강
```

`pinMode(PIN_ESTOP_SENSE, INPUT_PULLUP)` + `digitalRead(...)==LOW` 가정이 실물과 일치.

### 검증 결과

| 상태 | 상태줄 estop | 샘플 | 떨림 | 스트립 |
|---|---|---|---|---|
| 접촉기 붙음 | `0` | 133/133 | **0회** | 초록(수동) |
| 비상정지 누름 | `1` | 62/62 | **0회** | 🔴 빨강 |

노이즈로 인한 채터링 없음. 빨강은 모드색보다 우선이라 대기 상태에서도 나온다.

### 남은 개선 (선택)

- **1kΩ 풀업 저항**을 5V ↔ 핀38 사이에 추가. 내부 풀업(20~50kΩ)은 0.2mA 도 안 흘려서
  접촉기 보조접점의 **최소 개폐 전류**에 못 미친다 — 장기적으로 접점 산화막이 안 뚫려
  접촉이 불안정해질 수 있다. 1kΩ 이면 약 5mA 가 흘러 접점을 '닦아' 준다.
- 여분 b접점 `31-32` 가 남아 있다(같은 동작). 13/14·43/44 는 a접점.

### ⚠️ 이 신호는 표시등 전용이다

`estop` 은 **LED 색과 상태 보고에만** 쓰인다. 스러스터 제어에는 관여하지 않는다 —
배를 세우는 것은 접촉기가 물리적으로 전원을 끊는 것이다.
그래서 이 신호에 노이즈가 타도 최악의 경우가 "빨간불이 잠깐 깜빡임" 이고, 위험하지 않다.

LiDAR · IMU · GPS · 아두이노      →  허브                    (전부 12Mbps 시리얼)
```

처음엔 반대로 꽂혀 있었다(카메라가 허브, 직결 포트는 아두이노). 시리얼 장치는 허브를
몇 단 거쳐도 무해하므로 **직결 포트는 카메라 몫**이다.

### 🚨 라이다는 반드시 정상 종료(SIGINT)할 것

점검 중 `SL_RESULT_OPERATION_TIMEOUT` 이 두 번 났는데, **드라이버를 SIGKILL 로 죽인 게 원인**이었다.

```
강제 종료 → 라이다에 정지 명령이 안 감 → 스캔 상태로 남음 → 다음 실행이 시간초과
복구      → USB 를 뽑았다 꽂으면 된다
```

대회장에서 "어제 되던 라이다가 안 된다" 로 헤매기 쉬운 함정이다. **Ctrl+C 로 끌 것.**

### 무해한 오류 (무시해도 된다)

```
Failed to open scan_element ... in_anglvel_x_en : Permission denied
```

**D455 내장 IMU** 의 권한 문제다. 우리는 별도 IMU(RB-SDA-v1)를 쓰므로 무관하고,
`launch_files.launch.py` 는 이미 `enable_gyro/accel: False` 로 끄고 있다.

## 23. 🚨 수신기 전압 저하 — 아두이노를 허브에 꽂으면 안 된다 (2026-09-10)

### 증상

조종기(FS-i6)에 **RX 저전압 경보**. 텔레메트리 `IntU1` 값:

```
아두이노를 허브에 연결  :  4.09V   ← FS-iA6B 최소 동작 4.0V. 여유 0.09V
아두이노를 노트북 직결  :  4.70V   ← 정상
```

**RC 자체는 4.09V 에서도 동작하고 있었다.** 경보만 떴다 — 그래서 놓치기 쉽다.
조금만 더 처지면 수신기가 꺼지고 **수동 조종을 통째로 잃는다.**

### 원인

수신기는 **자체 배터리가 없고 아두이노 5V 를 쓴다.** 그 5V 는 노트북 USB 에서 온다.

```
노트북 5V → [버스전원 허브] → [허브] → 아두이노 → 수신기
             단계마다 전압 강하가 누적된다
```

허브가 **버스 전원식(자체 전원 없음)** 이라 장치를 여럿 물리면 전압이 처진다.

### 🔒 USB 포트 배치 — 이대로 고정할 것

| 장비 | 자리 | 이유 |
|---|---|---|
| **아두이노 Mega** | **노트북 직결** | 🚨 **수신기 전원이 여기 달려 있다.** 처지면 조종 상실 |
| 카메라 D455 | **허브 가능** | 뎁스를 끈 뒤로는 허브에서도 30.0fps·오류0·끊김0 |
| LiDAR · IMU · GPS | 허브 | 전부 12Mbps 시리얼. 허브 몇 단을 거쳐도 무해 |

**[09-10 재측정] 카메라는 허브로 보내도 된다.** §22 에서 뎁스를 끈 뒤 부하가 줄어
허브(SuperSpeed 5000M) 경유로도 **30.0fps · 최대공백 0.03s · 오류 0 · USB 끊김 0** 이 나왔다.
→ **노트북 직결 포트는 아두이노가 가져간다.** 직결을 다투던 문제가 해소됐다.
⚠️ 단 **뎁스를 다시 켜면** 허브로는 확실히 못 버틴다(직결에서도 못 버텼다). 그때는 재설계할 것.
→ **전원 공급형(powered) 허브**를 하나 구하면 이 제약이 사라진다. 자체 전원이 있어 전압이 안 처진다.

### 밝기 조정 이력 (같은 5V 레일을 LED 가 나눠 쓴다)

```
09-08  60 → 40   아두이노 5V 채택. 수신기와 공유하므로 여유 확보
09-10  40 → 25   RX 저전압 경보(4.09V). 조종 상실보다 어두운 게 낫다
09-10  원인이 허브로 밝혀짐 → 직결로 4.70V 회복
09-10  25 → 40   되돌림. **실측 IntU1 = 4.70V 로 25 일 때와 동일**
```

### ✅ LED 는 무죄였다 — 오진 기록

밝기 25 와 40 에서 **IntU1 이 4.70V 로 같았다.** 이 레일에서 LED 밝기의 영향은
측정 한계 이하다. 즉 저전압의 원인은 처음부터 **허브 경유 하나**였다.

**증상(전압 저하)을 보고 가장 최근에 바꾼 것(LED)을 의심한 것**이 오진의 경로였다.
§19 의 LED 소동(첫 LED 손상 오진 등)과 같은 유형이다 —
**바꾸지 않은 쪽(전원 경로)을 먼저 재는 습관**이 필요하다.
`IntU1` 은 배선만 바꿔가며 비교할 수 있는 값이라 이 판별에 특히 좋다.

⚠️ 밝기를 올리려면 **IntU1 을 보면서** 올릴 것. 4.5V 아래로 내려가면 되돌린다.
근본 해결은 **LED 전원 분리**(3칸 홀더 4.5V) 또는 **아두이노 VIN 급전**이다.

### 진단에 쓴 방법

조종기 텔레메트리 `IntU1` = 수신기가 실제로 받는 전압. **멀티미터 없이 읽을 수 있는 값**이라
배선을 바꿔가며 비교하기 좋다. 배 조립 후 점검 항목에 넣을 것.
