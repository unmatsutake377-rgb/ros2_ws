## 0. 결론

1. **미션 5 를 "그대로" 쓰려면 검출기 색만 바꿔서는 안 된다.**
   - 흰 부표는 키가 커서 LiDAR 에 보인다(R1 폐기와 같은 상황). 그런데 core 는 LiDAR 부표 근처의 카메라 검출을 버린다(`core.py:313-316`).
   - 버리지 않고 지도에 넣는 곳도 있는데, 단안 거리 오차 때문에 0.35 m 밖으로 빗나간 검출이다. 이것은 엉뚱한 자리에 유령 장애물로 들어간다.
   - LiDAR 가 본 흰 부표는 노란 벽 계산에 섞인다(`walls` `:342-352`, `wall_points` `:354-364`).
   - 칸 세기(`:383-400`)와 out-in-out 은 늘지 않는다.
   - 결론: 검출기 색 바꾸기(W1)와 core 의 "LiDAR 군집에 카메라 색 붙이기"(W2)가 둘 다 필요하다.
2. **거리 융합은 기존 perception_fusion 을 확장하는 것을 추천한다(안 a).**
   - 이미 분리된 노드이고, ship_back·ship_turn·ship_gate 가 `distance_source` 로 구독하는 구조가 있다(11-12 요구와 같음).
   - 새 노드(안 b)를 만들면 LiDAR 군집기·D455 처리·형식 사본이 한 벌 더 생긴다.
   - ship_avoid 의 range_fusion 공용화(안 c)는 패키지 간 import 를 만든다. 그러면 package.xml 이 바뀌어 §1-8 위험이 생기고, Q4 "자체 완결" 결정과도 어긋난다.
3. **미션 검출기 3종(gate·turn·dock)은 단안 공식에 넣을 정보를 내지 않는다.**
   - 셋 다 Float32 방위만 낸다(`/red_angle` `/green_angle` `/image_angle`).
   - 방위는 hfov 기반이고, 세로 위치는 무게중심 vY 로 y_zone 판정에만 쓴다. 바닥 행(v_bottom)·camera_info 는 없다.
   - 묵은 방위를 grace 시간 동안 다시 낸다(gate `:230`, dock `:257`). 삼각측량에 넣으면 독이 된다.
   - 그래서 **OAK 다중 물체 검출 토픽 `/oak_detections` 를 새로 만든다**(D1). 기존 세 검출기는 건드리지 않는다.
4. **삼각측량은 미션 노드에서 거의 기여하지 못한다.** 정면 접근(gate·turn APPROACH·back·dock)에서는 방위가 변하지 않아 시차가 0 이다. 옆으로 지나는 물체에서만 값이 나온다. 그래도 넣되 기본은 꺼 둔다.
5. **ship_avoid U4·U6 은 취소하고 공용 노드로 대체할 것을 추천한다.** 흰 부표가 LiDAR 에 보이므로 미션 5 거리의 1순위는 LiDAR 다. 카메라 거리는 공용 노드 `/fused_objects` 에서 받는다(새 단위 A5, 나중).
6. **오늘은 기본값을 바꾸지 않는다.**
   - `distance_source` 는 fill 유지, avoid_mode 는 fused 유지다. 폴리곤이 비어 있어 zone 이 늘 false 이므로 미션 5 배 동작은 lidar 와 같다.
   - 오늘 가능한 src 변경은 W1(검출기 색 파라미터)뿐이다. 폴리곤이 비어 있는 동안은 배 동작이 바뀌지 않는다.

### A-2. "그대로" 의 최소 변경

**W1 (비전 검출기 단독)**
- `image_subscriber_avoid` 에 `obstacle_color`(기본 `"white"`, 허용 = hsv_ranges 색)를 추가한다. `COLOR_CLS = {obstacle_color: 0, 'yellow': 2}` 로 만든다.
- cls 0 의 뜻을 "빨강"에서 **"장애물(설정 색)"** 으로 바꾼다.
- **VER 은 올리지 않는다.** 배열 배치와 cls 값 집합 {0,2}가 그대로이고, ship_avoid 는 cls 0 을 '장애물 표'로만 쓴다(`core.py:317` `cls == 0`). VER 을 올리면 ship_avoid 파서와 같은 커밋으로 묶어야 한다.
- obstacle_color == yellow 면 부팅 ERROR + 기본값.
- 새 cls 번호(예: 1=흰)를 쓰는 안은 비추천이다. core 가 (0,2) 밖을 조용히 버리기 때문에(`core.py:293`) 검출기를 먼저 바꾸면 침묵한다.
- **W1 만 들어간 상태도 안전하다.** 폴리곤 `[]`(`north_goal_angle.yaml:68`, `_main.yaml:11`)이면 zone 이 false 이고 코어가 돌지 않는다.

**W2 (ship_avoid 단독, 필수 — W1 만으로는 "그대로"가 아니다)**
- ① `core.py:313-316` 을 바꾼다. 카메라 검출을 **방위로** LiDAR 부표에 연관시키고(`obstacle_match_deg`), LowMap 에 **LiDAR 위치**(R = LiDAR σ)와 cls 색 표를 넣는다. 그러면 흰 트랙은 LiDAR 위치에서 확정되고 노랑은 확정되지 않는다.
- ② 확정된 장애물 트랙과 겹치는 LiDAR 부표는 `walls`·`wall_points`·`obstacles` 의 buoy 목록에서 뺀다. 이중 계산과 벽 오인을 막는다.
- ③ 장애물 반경 `low_r` → 흰 부표 반경(⚠️ 실측). `buoy_r` 폭 검사는 흰 지름이 들어가게 한다(노랑과 반경이 다르면 `obstacle_r` 를 따로 둔다).
- ④ `obstacle_requires_lidar`(기본 true): LiDAR 연관이 없는 흰 검출은 지도에 넣지 않는다. 흰 HSV 오검출(햇빛 반사·물보라·하늘·물가 건물·자기 선체)을 막는 **가장 강한 최소 대책**이다. 하늘은 단안 수평선 검사(`core.py:39`)가 이미 버린다.
- ⑤ 방위 연관은 OAK→선체 yaw 오프셋(U3 리뷰 W3, 1번배 약 −4°)에 걸린다. `cam_yaw_offset_deg` 가 없으면 허용 오차를 4° 넘게 잡아야 한다(⚠️ 배별 값 — 아래 G-4).
- 테스트 `test_core.py:74`(LiDAR 근처 검출은 low 아님)는 뜻이 뒤집히므로 고쳐 쓴다.

### B-2. 위치 결정 — perception_fusion 확장 (안 a, 추천)

- **입력 추가**
  - `/oak_detections`(D1)
  - `/ublox_gps_node/fix`(기선)
  - `/imu/yaw`(세계 방위)
  - `/imu/data`(피치, 단안). 코드는 발행하지만(`iahrs_driver.cpp:81`) 11-02 실기에서는 미발행이었다. 런타임 발행 여부 ⚠️ 미확인.
- **소스와 σ**

  | 소스 | 거리 | σ |
  |---|---|---|
  | LiDAR | 군집 | 작음(≈0.05) |
  | D455 | 기존 | σ = k·d² |
  | 단안 | `ground_plane_range` 식을 perception_fusion 안에 사본 | `ground_plane_sigma` |
  | 삼각측량 | 색별 세계 방위 광선 버퍼, GPS 위치 차 기선 ≥ `tri_min_baseline_m` · 시차 ≥ `tri_min_parallax_deg` | 기선·방위 σ |

- **연관:** LiDAR 원점 방위 ± `fusion_margin_deg`. 단안·삼각측량 물체는 OAK 장착값으로 LiDAR 원점으로 옮긴다(⚠️ 실측).
- **결합: 역분산 가중 + 게이팅.**
  - LiDAR 가 있으면 사실상 LiDAR 가 지배한다(σ 비).
  - 카메라 값이 LiDAR 와 3σ 넘게 어긋나면 처리를 `disagree_policy` 로 정한다. 기본 `min` 은 지금 동작이다. `lidar` 는 카메라 값을 버리고 LiDAR 를 쓰는 추천안이다(G-5).
  - LiDAR 가 없으면 카메라 소스끼리 쌍별로 게이팅한 뒤 가중한다. 모두 어긋나면 min + 감점 + flags bit0(기존 규칙).
- **형식:** `/fused_objects` VER 1·STRIDE 8 **유지**.
  - `src_id` 4 mono, 5 tri 를 추가한다(단일 카메라 소스일 때만. 둘 이상이면 2 fused).
  - flags 에 기여 소스 비트(bit2 lidar, bit3 depth, bit4 mono, bit5 tri)를 넣는다. 배치가 같아 VER 을 올릴 필요가 없다.
  - 미션 노드 사본은 4·5 를 모른다 → `allowed` 밖 → match None → LiDAR 로 되돌린다. 닫힌 쪽 실패라 **사본 동시 변경이 필요 없다**.
  - 노드 사본 일치 테스트(`test_fused_match.py:259-268`)는 키 4개만 비교하므로 깨지지 않는다.
- **스위치:** `use_mono`·`use_triangulation` 기본 false. 그래서 P1 단독으로는 출력이 지금과 비트 동일하다.

### B-3. 미션 노드 공통 패턴

- 구독은 이미 있다(`distance_source != 'lidar'` 이면 `/fused_objects`, BEST_EFFORT d1).
- 바꿀 것은 기본값 `fill` → `fused` 다. 위치는 코드 리터럴, yaml, `test_fused_match`(back `:438,479` / gate `:452,494` / turn `:441,485`), 카탈로그(`ssf_param_catalog.yaml:46-62` advice·check 문구).
- 선택: `FUSED_SRC_IDS` 에 `mono`·`tri` 이름 추가(사본 3벌 + 테스트). 기본 `fused_allowed_sources` 는 `[lidar, fused, depth]` 로 둔다. 단일 카메라 소스 거리는 기본에서 빠지고, 여러 소스 합의(src 2)로만 들어온다.
- **fused 의 뜻:** `/fused_objects` 먼저, 맞는 물체가 없거나 conf<0.5 면 노드 자기 LiDAR ±3°. perception_fusion 이 꺼졌거나 stale 이면 LiDAR + 5 s 주기 WARN 이다. 즉 지금 lidar 와 같은 동작이다.
- 파라미터 콜백이 어느 노드에도 없다(grep 0). 그래서 앱에서 바꾸면 **launch 재시작**이 필요하다.

### B-4. ship_dock 포함 시 필요한 것

- 새 코드가 필요하다(약 200줄 + 테스트 250줄): `distance_source`(기본 **lidar**), `/fused_objects` 파서(**5번째 사본**), 전방 ±15° 안 물체 최소 질의(색 무관).

### 단안(수면 교점) 규격
1. 픽셀 (u, v_bottom) 왜곡 보정(camera_info D, plumb_bob/rational — 계수 0 이면 생략) → 정규 좌표 x=(u−cx)/fx, y=(v−cy)/fy.
2. 카메라 광선 c=(x, y, 1)(x 오른쪽, y 아래, z 앞) 을 선체 수평 좌표로: 피치 θ(아래 +) · 롤 ρ(우현 아래 +) 회전. 장착 피치·롤(⚠️ 실측) + IMU 피치·롤(/imu/data — 런타임 발행 ⚠️ 확인, 없으면 장착값만 + WARN).
3. 수면 교점: 회전 후 아래 성분 w_down ≤ sin(0.5°)·|c| 이면 None(수평선 위·근처). t = h / w_down, 수평 성분 (앞 f, 옆 s) → **수평 거리 = t·√(f²+s²)**, **방위 = atan2(−s, f)(좌 +)** — 피치·롤 반영된 방위로 다시 냄.
4. σ: 피치·롤 각 σ, 픽셀 σ(바닥 검출 ±px), 높이 σ(σd/d = σh/h) 를 1차 전파로 합침(수치 미분 허용). 정지(hold) 시 σθ 작게, 주행 시 크게(기존 pitch_sigma_hold/move 유지).
5. 테스트: 정면·측면(20°·32°)·롤 3°·피치 오차에서 해석해(기하 합성)와 일치, 수평선 None, σ 단조.
### 삼각측량 규격
1. 같은 물체(색 + 방위 연관 트랙) 의 세계 방위 광선 버퍼: 관측마다 (t_capture = 수신 − age_s, 카메라 위치 = GPS 안테나 위치 + 레버암 회전 보정(⚠️ 실측), 세계 방위 α = yaw(t) + 카메라 방위(선체 기준, OAK yaw 오프셋 포함)).
2. 두 광선(P1,α1)(P2,α2) 교점 — 2×2 선형계 P1 + t1·u1 = P2 + t2·u2. 조건: 기선 b ≥ tri_min_baseline_m(0.8), 시차 |α2−α1| ≥ tri_min_parallax_deg(5), t1·t2 > 0(앞쪽), 두 관측 시간차 ≤ tri_max_dt_s(⚠️, yaw 상대 드리프트 상쇄 위해 짧게 — 기본 3.0 제안). 셋 이상이면 최소제곱 교점.
3. σ: 방위 σ(픽셀+yaw)·위치 σ(RTK — FIXED 아니면 쓰지 않음)를 교점 야코비안으로 전파. 근사 σd ≈ d²·σα/(b·sinγ).
4. 정면 접근(시차 0)·정지·제자리 회전(기선 0)에선 내지 않음(모르면 침묵).
5. 테스트: 합성 궤적(옆 지나가기)에서 참값 일치, 정면 접근 미발행, 기선·시차 하한 경계, GPS 비FIXED 미사용.
### 융합에서
- LiDAR 가 있는 물체: LiDAR 우선(G-5). 카메라 값은 연관·색·검증용.
- LiDAR 없는 물체: 단안·D455·삼각측량을 쌍별 게이팅 후 역분산 가중, 전부 어긋나면 기존 규칙(min + 감점 + bit0).
