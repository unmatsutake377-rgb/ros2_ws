## 0. 배경

- 카메라 역할(확정): **OAK-1 PoE = 자율 비전**, **D455 = 수동 조종용 실시간 화면**.
- 팀장 보고: D455 수동 조종 화면에 **지연이 크다**. 실측값은 아직 없다 → 이번 세팅에서 원인을 가른다.
- 수신측(물가)은 **팀장 MacBook Air** 로 확정, 10-29 설치 완료: Homebrew gstreamer, `avdec_h264`·`clockoverlay`·`rtph264depay` 확인.
  (Anaconda 의 옛 gstreamer 가 먼저 잡히던 문제 → conda 자동활성 끔. 절차 §0-B 에 기록.)

## 1. 설치 (한 번만) — 절차 §0-A 그대로

```bash
cd ~/ros2_ws && git pull
sudo apt install -y gstreamer1.0-tools gstreamer1.0-plugins-base gstreamer1.0-plugins-good \
     gstreamer1.0-plugins-bad gstreamer1.0-plugins-ugly gstreamer1.0-libav gstreamer1.0-x \
     v4l-utils python3-gi gir1.2-gstreamer-1.0 gir1.2-gst-plugins-base-1.0 chrony
chmod +x tools/cam_*.sh tools/cam_*.py
for e in x264enc clockoverlay avdec_h264 rtpjitterbuffer; do gst-inspect-1.0 $e >/dev/null && echo "$e ok"; done
/usr/bin/python3 -c "import gi; gi.require_version('Gst','1.0'); gi.require_version('GstApp','1.0'); from gi.repository import Gst, GstApp; print('gi ok')"
```
- 넷 다 `ok` + `gi ok` 여야 한다. `gstreamer1.0-x` 빠지면 clockoverlay 없음(`cam_stream.sh` 헤더 의존 목록도 이번에 보강).
- `which python3` 가 conda/pyenv 면 `/usr/bin/python3` 로 명시.
- `sudo` 는 사람이 직접(비밀번호).

## 2. 확인 순서

### 2-1. 루프백 (배 노트북 혼자, 네트워크 무관)
```bash
# 터미널 1
/usr/bin/python3 tools/cam_bench_rx.py --secs 30
# 터미널 2 — 가상 소스
/usr/bin/python3 tools/cam_bench_tx.py --host 127.0.0.1 --secs 25
# 터미널 2 — 실 D455 (camera.launch.py 꺼 둘 것: 장치 점유)
/usr/bin/python3 tools/cam_bench_tx.py --host 127.0.0.1 --secs 25 --source v4l2 \
  --dev $(v4l2-ctl --list-devices | grep -A3 -i realsense | grep video | head -1 | tr -d ' ')
```
기록: 가상/실카메라 각각 `fps · p50 · p90 · bad`. 둘 차이 = **D455 캡처 지연**(무선과 무관).

### 2-2. 실링크 (MacBook 이 같은 방에 있을 때 — 팀장과 맞춰서)
- MacBook IP: 팀장이 `tailscale ip -4` 로 알려준다(같은 WiFi 면 `ipconfig getifaddr en0`).
- `tailscale status` 에서 MacBook 이 `direct` 인지 `relay` 인지 기록. relay(DERP) = 수십~수백 ms 추가.
- 수동 조종 상황(카메라 노드 없음): `./tools/cam_stream.sh <MacIP>` (v4l2)
- 자율 스택이 D455 를 잡고 있을 때: `./tools/cam_stream.sh <MacIP> ros`
- MacBook 쪽: `./tools/cam_view.sh` — 좌상단 시계(배 시각)와 우하단 시계(Mac 시각) 차이 ≈ 지연(양쪽 NTP 맞을 때).

## 3. 지연 원인 가르기 — 결과로 답해 줄 것

| # | 질문 | 어떻게 |
|---|---|---|
| 1 | 팀장이 지연을 본 화면이 **무엇이었나** — cam_view.sh 인가, 원격 데스크톱/rqt/rviz 인가 | 팀장에게 확인. 원격 데스크톱·rqt 경유면 그 자체가 지연 원인(이 스크립트 경로가 아님) |
| 2 | 루프백 실카메라 p50 | §2-1. 200 ms 넘으면 캡처 병목 → `640 480 15` 로 낮춰 비교 |
| 3 | Tailscale direct / relay | `tailscale status`, `tailscale ping <MacIP>` 의 `via DERP` 여부 |
| 4 | **ros 모드에서 지연이 시간이 갈수록 커지는가** | 5분 켜 두고 두 시계 차이를 1분마다 기록. 커지면 원인 후보 = `cam_stream_ros.py` appsrc 에 큐 상한·leaky 가 없음(줄 54). 고치려면 계약 필요 — 결과만 보고 |
| 5 | 배 CPU | `top` 에서 gst/python 프로세스 % |
| 6 | 저조도 | 실내 어두운 곳에서 지연이 늘면 D455 자동노출(노출시간↑ → fps↓) |

결과는 `docs/결과분석/영상지연_실측_20261029.md` (또는 측정 날짜)에 표로. 그 후 Mac 세션이 원인별 조치를 정한다.
