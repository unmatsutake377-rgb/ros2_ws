# 변경 계약서: ship_dock APPROACH 재정렬(→ALIGN) 전이에 거리 하한 `realign_min_dist_m` 추가

작성 2026-11-03 (ssf-contract, 읽기 전용). 상태: **승인 대기** — 구현 전 Davidson 확인.

배경: `tools/sim/dock_sim.py` 500 런 중 실패 3 런(`tools/sim/out/dock_sim.csv` success=0 행: lost_dist 1.04 / 1.04 / 1.02)이 전부 접안 직전에 APPROACH→ALIGN 제자리 선회 → 관성 전진 → 표식 유실 → SEARCH 25 s → DONE. 원인은 `ship_dock.py:285-294` 의 두 재정렬 전이에 거리 하한이 없는 것.

## 변경 단위
- **노드 하나: `ship_dock`** (원자 묶음 아님). 토픽·메시지 타입·QoS·`active_wp_mode`·특수 상수 전부 불변 → 6a 묶음(`north_goal_angle`)·비전 묶음에 안 걸린다.
- 같은 커밋에 들어가는 것: `ship_dock.py` + `config/ship_dock.yaml` + (추가 시) 순수 로직 모듈·테스트 + 재생성된 시뮬 산출물 + 보고서 Ⅲ-4.5 문단·표 Ⅲ-9 APPROACH 행. 나눌 노드가 없으므로 순서 문제 없음.
- `tools/sim/ssf_sim.py`·`kaboat_full_course_sim.py` 는 `ship_dock` 을 모델링하지 않는다(grep 0건) → 동기화 사본 없음. `dock_sim.py` 는 실제 `ship_dock.py` 를 import(`dock_sim.py:86-87`)하고 파라미터를 yaml 에서 읽으므로(`:79-84`) 코드 변경이 자동 반영된다 — **단, yaml 에 새 키를 안 넣으면 시뮬은 코드 기본값으로 돈다.**

## 제안 로직 (APPROACH 블록 `ship_dock.py:284-296`)
```
if dist <= contact: CONTACT                                  # 그대로, 맨 앞
in_floor = dist < realign_min_dist_m                         # 신규
if not in_floor and (not standoff_aligned) and dist <= standoff and |angle| > align_tol: ALIGN(1회)
if not in_floor and |angle| > realign_tol: ALIGN
publish(angle)                                                # 하한 안에서는 표식 방위로 조향하며 그대로 접근
```
### 대안 비교
| 안 | 내용 | 평가 |
|---|---|---|
| (a) standoff 1회 재정렬만 하한 | 시뮬 실패 3 런은 전부 이 분기 | 25° 분기가 남는다. 1.5 m 에서 25° = 좌우 0.70 m(칸 반폭 0.5 m 밖) — 제자리 선회로는 좌우 오차를 못 줄이고 같은 관성 유실 경로만 남긴다 |
| **(b) 둘 다 하한** (추천) | 파라미터 1개 `realign_min_dist_m` 로 두 분기 공통 | 실패 메커니즘이 같다(가까울수록 좌우 오차가 각도로 증폭: 1.0 m 에서 0.15 m = 8.5°). 하한 안 제자리 선회는 어느 분기든 v·τ ≈ 1.0 m/s × 0.5 s ≈ 0.5 m 를 더 가 카메라 최소거리 0.7 m(`dock_sim.py:99`) 아래로 떨어진다 |
| (c) standoff 조건을 `dist <= standoff and dist > contact + margin` | 새 파라미터 없이 | margin 을 하드코딩하면 §1-4 위반, 파라미터화하면 (a) 와 같음. 25° 분기 미해결 |
| (참고 d) standoff 진입 틱에 1회 판정 후 `standoff_aligned=True` | 파라미터 없음 | 2~3 m 구간에서 재정렬한 251 런(CSV)의 동작을 바꿔 영향이 가장 크다. 비추천 |

**추천 (b), 기본값 1.5** = contact 1.0 + 0.5(≈ 감속 후 속도 1.4×0.7 m/s × τ 0.5 s, 시뮬 가정). CSV 기준 영향: 마지막 APPROACH→ALIGN/SEARCH 전이가 1.5 m 안이었던 런 20/500(성공 17, 실패 3; 1.2 m 안 12) 의 동작이 "선회"에서 "조향 접근"으로 바뀐다. 나머지 480 런(2~3 m 구간 251 런 포함)은 영향 없음. → 재실행 때 **접안 수만이 아니라 head_err·lat_err 중앙값/최대가 나빠지지 않는지** 함께 본다.

## 위험 (조용히 깨질 수 있는 지점)
1. **비스듬 접안**: 하한 안에서 |θ| > 25° 여도 조향만 하며 진입 → 1.5 m·25° 는 좌우 0.7 m 라 목표 칸(폭 1 m) 대신 칸막이에 닿을 수 있다. 시뮬의 `bumped` 는 선수 y<0(정면 벽)만 본다(`dock_sim.py:208-209, 221`) — **칸막이 접촉은 시뮬이 못 잡는다**.
2. **하한 ≤ contact 로 설정되면 조용히 무효**(`ship_dock.py:280` 이 `:285` 보다 먼저). 부팅 검사 없으면 "고쳤는데 그대로" 가 된다.
3. **하한 안 표식 유실 경로는 그대로 SEARCH(선회)** (`:272-274`). 시뮬은 수직 화각·표식 높이를 모델링하지 않고 0.7 m 까지 보인다고 가정(`dock_sim.py:99`) — 실물은 더 멀리서 표식이 화면 밖으로 나갈 수 있어 같은 실패가 다른 분기로 재현될 수 있다. 이번 범위 밖, 수조에서 확인.
4. **yaml 만 고치면 대회 실행에 반영 안 됨**(`launch_files.launch.py:307`). 반대로 코드만 고치면 `dock_sim.py` 는 yaml 값(없으면 기본값)으로 돌아 시뮬 통과가 대회 설정을 보증하지 않는다 → 둘 다 1.5.
5. **시뮬 가정 의존**: 1.5 = contact + v·τ 는 τ 0.5 s·k_v 0.010·감속 0.7·도크 3 m/칸 1 m·카메라 0.7~12 m 가정 위의 값(`dock_sim.py:94-106`). 실측 추력 응답이 다르면 여유 0.5 도 다시 잰다.
6. **보고서 불일치**: `통합_Ⅲ소프트웨어.md:229` 의 497/500·중앙값 11 s·"대회 전 보완 항목" 문장과 `:222` 표 Ⅲ-9 APPROACH 행, 그림 `docs/전달용/배치도/dock_sim.png`(추적 중) 이 코드와 어긋난다 → 같은 변경에서 갱신.
