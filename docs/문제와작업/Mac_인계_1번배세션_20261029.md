## 1. F10 — `yaw_mux` `gps_rate_hz` 5.0 → **1.0** (팀장 결정 10-29)

**왜**: 실제 GPS 는 두 rover 설정 모두 `rate: 1.0`(`zed_f9p_rover.yaml:30`, `c94_m8p_rover.yaml:17`), 10-28 실측 `/fix` 1.0 Hz.
`gps_rate_hz` 는 `yaw_mux.py:70,102-106` 시작 검사(표본 상한 n_max ≥ `cog_min_samples` 인지)에만 쓰인다 → **동작 불변**, 검사와 문서가 현실에 맞게 될 뿐.

**바꿀 곳**
| 파일 | 지금 | 바꿀 값 |
|---|---|---|
| `src/ssf_heading/config/ssf_heading.yaml:76` | `gps_rate_hz: 5.0` | `1.0` (소수점 — 정수면 yaw_mux 사망, 10-29 실측) |
| `src/ssf_heading/ssf_heading/yaw_mux.py:70` 코드 기본값 | `5.0` | `1.0` (yaml 과 같게, CLAUDE §1-4) |
| `docs/기준/CLAUDE_상세.md:482` | "현재값(5Hz, half_life 60s) → n_max ≈ 433 ≫ 30. … 수렴까지 직진 약 6초" | "1 Hz, half_life 60 s → n_max ≈ 87 > 30. 수렴까지 직진 약 30 초(5 Hz 면 약 6 초)" |
| `docs/문제와작업/과제_목록_전체.md` F10 | 결정 대기 | ✅ 반영 커밋 |

**검산**(Ubuntu 쪽에서 미리): n_max = 1/(1−0.5^(dt/half_life)), dt = 1 s, half_life = 60 s → 87.1. `cog_min_samples` 30 보다 커서 시작 ERROR 없음.
`imu_relative`(현 기본)는 무관. `cog_offset` 은 F11 고치기 전까지 사용 금지라 지금 실효 영향 없음.
**검증**: `tools/run_tests.sh ssf_heading`, 그리고 Ubuntu 에서 `ros2 launch ssf_heading ssf_heading.launch.py boat:=A` 시작 로그에 포화 ERROR 없는지 + `ros2 param get /yaw_mux gps_rate_hz` = 1.0.
팀 모드 필요 없음(설정값·주석·문서, 동작 불변) — 판단은 Mac 세션에 맡김.

## 2. F11 — `cog_offset` 오프셋 이중 적용: **계약 작성, GPS C2 다음 수정** (팀장 결정 10-29)

- 위치: `heading_logic.py:384` `return self._correct(wrap360(val + off)), ST_OK` — `_correct` 가 `mount_offset_deg` 를 추정 오프셋 위에 또 더하고, `invert_yaw` 를 추정 뒤에 뒤집는다. 추정기는 뒤집기 전 원시 yaw 를 씀(`:221`). 출처: `계약서_배별IMU설정_20261029.md` 위험 2.
- 순서: GPS C1(완료) → GPS 실물 시험 → GPS C2 + healthcheck → **F11 계약·구현**.
- 그 전까지: CLAUDE.md §3 헤딩 규칙에 "`heading_source: cog_offset` 사용 금지" 한 줄 넣어 둠(3bd8803).
