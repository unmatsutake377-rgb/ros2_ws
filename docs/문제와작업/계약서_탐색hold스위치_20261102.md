# 변경 계약서: wp_mode 3(탐색) 행동 스위치 `search_behavior:=orbit|hold` (기본 orbit = 현 동작)

작성 2026-11-02 (ssf-contract). 상태: **승인 대기** — "사람이 정해야 할 것" 답 받은 뒤 구현.

배경: KABOAT 2026 안내문 코스도에 "탐색 = 특정 색상 부표 탐지 후 그 위치에서 위치유지". 2025 규정은 원 선회. 대회장에서 확인되면 launch 인자 하나로 바꾼다.

## 변경 단위
원자 묶음 아님. 노드별 3단계, 각 중간 상태가 안전한 순서:
1. `ship_back`: `active_wp_mode`(int, 기본 2) → `active_wp_modes`(int[], 기본 `[2]`) + yaml 키 개명. 리셋 조건은 `prev != cur and cur in modes`(위험 2).
   - `src/ship_back/ship_back/ship_back.py:69,116,199`, `src/ship_back/config/ship_back.yaml:4`
2. `ship_turn`: 비활성 수단 추가(기본 = 활성). **`-1` 센티널 금지**(위험 1). 권장 `enabled`(bool, 기본 true).
   - `src/ship_turn/ship_turn/ship_turn.py:72,105,132,214`, `src/ship_turn/config/ship_turn.yaml`
3. `launch_files.launch.py`: `DeclareLaunchArgument('search_behavior', default_value='orbit', choices=['orbit','hold'])` + ship_turn/ship_back Node 를 `_yaw_mux` 식 `OpaqueFunction`(21~42행 패턴)으로 띄워 인자 → 파라미터 dict. 순수 함수 `search_behavior_params(behavior)` 로 떼어 ROS 없이 테스트(`test_boat_config.py` 의 `_load_func` 패턴).
   - `launch_files.launch.py:74-79(인자), 268·271(두 Node, 현재 parameters= 없음), 244-250(주석)`
   - 이 단계를 1·2보다 먼저 하면 구 노드가 새 파라미터를 미선언으로 조용히 버려 hold 에서 mode 3 발행자 0 → **반드시 마지막**.
4. 문서(같이): `docs/기준/CLAUDE_상세.md:513-527`(wp_mode 표), `docs/절차/boat_launch_checklist.md:68`(launch 명령), `src/color_shape_detector/config/vision.yaml:112-116` 주석. CLAUDE.md·좌측스러스터 문서는 안 건드림.

## 특수 상수·모드
- orbit(기본): 2→ship_back / 3→ship_turn. hold: 2,3→ship_back, ship_turn 침묵. 검출기 turn `active_wp_modes [2,3]`·`wp_color_map 3→red` 변경 없음.
- ship_back 이 mode 3 에서도 20000/50000/REVERSE_REL 180 을 낸다 — mode 2 와 같은 값. SPIN 5000/6000 은 hold 에서 안 나옴.
- north_goal_angle: mode 3 timeout 90 s, WP 전진은 GPS 도착반경 + dwell 로 ship_back 상태와 무관. `hold_dist_m 2.5` 여전히 ⚠️ 실측.
- ship_direction: mode 3 특별취급 없음. 추력 방향·ssf_bridge 비접촉.

## 기본값 = 현 동작 보장
① 코드 기본값(`[2]`, 3, true)이 지금 값과 동치 ② orbit 분기가 그 값만 넘기는지 정적 테스트 ③ Ubuntu: `ros2 param get` 확인 ④ `/wp_mode 3` 주입 → 2 s 뒤 `/candidate_angle` 5000(ship_turn SEARCH) = 전과 동일; hold 면 20000→ship_back 값만.

## 위험
1. `-1` 센티널 = ship_turn 부팅 초기값(`self.wp_mode = -1`) → `/wp_mode` 첫 수신 전 게이트 통과 → SPIN 5000 발행. 센티널 방식 금지.
2. ship_back DONE 래치: 모드 전이 때만 리셋. 연속 mode 3 WP 에선 첫 부표만 유지. 리스트화 때 `prev not in modes` 로 쓰면 2→3 전이에서 리셋 안 됨 → `prev != cur and cur in modes` 필수.
3. 색: mode 3 검출은 red 만. 대상이 다른 색이면 비전 0 → LiDAR 전방 ±30° 최근접에 붙는다. `wp_color_map` 은 코드 하드코딩.
4. 관측 도구: healthcheck 매핑 3→ship_turn(`ssf_tools.yaml:63-64`) — hold 에서 뜻이 틀리나 ship_turn 이 떠 있으면 거짓경보 없음. check_params 는 hold 에서 `[2,3]`≠yaml `[2]` 불일치 보고.
5. 빈 리스트 파라미터 `[]` 는 rclpy 타입 추론 실패 가능 → 쓰지 말 것.
