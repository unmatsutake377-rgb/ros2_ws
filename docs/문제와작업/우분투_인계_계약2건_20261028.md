## 1. 도킹 검출기 — 무효 목표가 모드 게이트보다 먼저 발행되는가

현상 재현(카메라만 있으면 됨, 배 불필요):
```bash
# 터미널 1 — 도킹 목표 형상을 일부러 오타로
ros2 run color_shape_detector basic_image_subscriberdock --ros-args \
  --params-file src/color_shape_detector/config/vision.yaml -p target_shape:=Squre
# 터미널 2 — 탐색 검출기 (모드 2·3 의 /image_angle 정상 발행자)
ros2 run color_shape_detector basic_image_subscriberturn --ros-args \
  --params-file src/color_shape_detector/config/vision.yaml
# 터미널 3 — 모드 3 (탐색)
ros2 topic pub /wp_mode std_msgs/Int32 "{data: 3}" -r 2
# 터미널 4
ros2 topic echo /image_angle
```

| 볼 것 | 계약서 예상(현재 코드) | 결과 |
|---|---|---|
| 모드 3 에서 `/image_angle` 에 10000 이 섞이나 | **섞인다** (dock 이 게이트 전에 매 프레임 발행) | ____ |
| `ship_turn` 을 같이 띄우면 부표를 잡았다 놓쳤다 하나 | 10000 이 오면 `buoy_rel = None` (`ship_turn.py:138-139`) | ____ |
| `/wp_mode` 를 끊으면 dock 이 계속 10000 을 내나 | 낸다 | ____ |
| 오타를 고치면(`Square`) 모드 3 에서 10000 이 사라지나 | 사라진다 | ____ |

결정할 것(계약서 "사람이 정해야 할 것"): 모드 7 무효 목표 때 10000(A) / 침묵(B), 주기 ERROR, 순수 함수 위치·정적 순서 테스트, 문서 정정 커밋 방식.

## 2. GPS 신선도 — fix 가 끊겨도 방위가 계속 나오는가

| 시험 | 방법 | 계약서 예상(현재 코드) | 결과 |
|---|---|---|---|
| ① USB 분리 | 대회 launch 중 GPS USB 를 뽑는다 | 드라이버 프로세스는 **안 죽고**(async_worker 재시도) `/ublox_gps_node/fix` 만 끊김. `/north_goal_angle_tp` 는 **마지막 위치로 계속** 나옴 | ____ |
| ② 드라이버 kill | `pkill -f ublox_gps_node` | `OnProcessExit → Shutdown` 때문에 **대회 launch 전체가 내려갈** 수 있음 (⚠️ 미확인) | ____ |
| ③ 장치 없이 부팅 | GPS 를 뽑은 채 대회 launch | `"Failed to initialize."` 후 노드 종료 → launch 전체 종료? (⚠️ 미확인) | ____ |
| ④ 다시 꽂기 | ① 뒤 재연결 | `/fix` 복구, 방위 갱신 재개 | ____ |

```bash
ros2 topic hz /ublox_gps_node/fix
ros2 topic echo /north_goal_angle_tp
ros2 topic echo /geofence_state --once
ros2 topic echo /failsafe_level
```

이미 정한 것: `last_fix_t` 는 **GPSFilter 가 받아들인 프레임에서만** 갱신.
결정할 것: `gps_stale_sec`(제안 2.5), stale 방침(tp·distance·geofence 정지 / wp_mode·20000·남은시간·타임아웃 진행 유지), 잘못된 값 처리, healthcheck 표시, CLAUDE.md "죽은 토픽" 문구.
②③ 이 "전체 launch 종료" 로 확인되면 그것도 별도 계약 후보다(GPS 하나 때문에 배 전체가 꺼짐).
